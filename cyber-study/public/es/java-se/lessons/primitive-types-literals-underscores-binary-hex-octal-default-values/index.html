Tipos primitivos, literales (guiones bajos, binario/hex/octal) y valores por defecto

Java tiene ocho tipos primitivos, y guardan valores directos en lugar de referencias a objetos. Cuatro son tipos enteros, todos con signo: byte (8 bits, de -128 a 127), short (16 bits), int (32 bits) y long (64 bits). Dos son tipos de punto flotante: float (32 bits) y double (64 bits). char es un valor de 16 bits sin signo que guarda una unidad de código UTF-16 (formato de transformación Unicode de 16 bits), lo que significa que va de 0 a 65 535 y puede participar en operaciones aritméticas. Por último, boolean solo admite true o false. A diferencia de C, en Java un boolean nunca es un número, así que if (1) no compila y no existe cast entre boolean y ningún tipo numérico.

El tipo de un literal lo decide la forma en que lo escribes, no la variable que lo recibe. Un número entero simple como 42 es un literal int, así que un valor demasiado grande para int necesita el sufijo L: long big = 3_000_000_000L; compila, pero el mismo número sin L es un error de compilación con un mensaje como "integer number too large", aunque el destino sea un long. Usa una L mayúscula, porque una l minúscula se parece al dígito 1. Un número con punto decimal o con exponente, como 3.14 o 1e3, es un literal double, así que float f = 3.14; falla y debes escribir 3.14f o hacer un cast. Se permite un sufijo d o D, pero es opcional. Los literales de carácter usan comillas simples, como 'A', el escape '\n' o el escape Unicode '\u0041', mientras que el texto entre comillas dobles es un String, no un char.

Los literales enteros pueden escribirse en cuatro bases, y el prefijo te dice cuál. Decimal es la predeterminada. Un 0 inicial significa octal, base 8, así que 017 es 15. Un prefijo 0x o 0X significa hexadecimal, base 16, así que 0x1F es 31 y las letras de la A a la F pueden ir en mayúscula o minúscula. Un prefijo 0b o 0B significa binario, base 2, así que 0b101 es 5. La regla del octal es la trampa clásica: 010 es 8, no 10, y 09 no compila porque 9 no es un dígito octal. Siempre que veas un número que empieza con cero y tiene más dígitos, detente y conviértelo antes de hacer cualquier otra cosa.

Los guiones bajos pueden separar dígitos para mejorar la legibilidad, como en 1_000_000 o 0b1010_0101. No afectan el valor. La única regla que debes recordar es que un guion bajo debe estar entre dos dígitos. Por eso son ilegales: un guion bajo al inicio o al final (_100 en realidad es un nombre de variable, y 100_ es un error), un guion bajo junto a un punto decimal (1_.5, 1._5), uno justo antes de un sufijo (10_L, 2.0_f) y uno justo después del prefijo 0x o 0b (0x_FF). Varios guiones bajos seguidos están bien (1__000), y también uno después del cero inicial de un literal octal (0_17), porque ese cero cuenta como dígito.

Los valores por defecto se aplican solo a los campos, es decir, a las variables de instancia y estáticas, y a los elementos de un arreglo. Los campos numéricos toman cero por defecto (0, 0L, 0.0f, 0.0), char toma '\u0000' (el carácter nulo), boolean toma false, y todo tipo de referencia, incluidos String y los tipos envoltorio como Integer, toma null. Los arreglos reciben estos valores por defecto en el momento en que se crean con new, por eso new int[3] contiene tres ceros.

Las variables locales nunca reciben un valor por defecto. Una variable declarada dentro de un método, un constructor o un bloque debe estar asignada de forma definitiva antes de leerse, y el compilador lo verifica con un análisis de flujo. Si declaras int total; y luego solo la asignas dentro de una rama if, leerla después produce el error "variable total might not have been initialized". Al examen le gusta esconder esto dentro de una rama o un bucle, así que sigue cada camino desde la declaración hasta la primera lectura. Declarar una variable local sin leerla nunca no es un problema.

int[] nums = new int[3];          // {0, 0, 0}
boolean[] flags = new boolean[2]; // {false, false}
int x;
// System.out.println(x);        // does not compile: x not initialized
int hex = 0xFF, oct = 010, bin = 0b11;
System.out.println(hex + oct + bin); // 255 + 8 + 3 = 266
long ok = 3_000_000_000L;
float f = 2.5f;
char c = 'A' + 1;                 // 'B': constant expression fits in char

En resumen, la mayoría de las preguntas del examen sobre este tema son en realidad preguntas de si compila o no. Cuando veas un bloque de código, revisa cada literal en busca de un cero inicial, un sufijo L o f faltante y un guion bajo en un lugar ilegal, y luego comprueba si cada variable local está asignada en todos los caminos antes de usarse. Solo cuando sabes que el código compila tiene sentido calcular lo que imprime. Este orden de revisión ahorra tiempo y evita que elijas una salida para un código que nunca se ejecutaría.

Términos clave

Primitive type (tipo primitivo)
Uno de los ocho tipos de valor integrados (byte, short, int, long, float, double, char, boolean) que no son objetos.
Literal
Un valor fijo escrito en el código fuente, como 42, 3.5f, 'x' o 0b1010.
Octal literal (literal octal)
Un literal entero con un 0 inicial, que se lee en base 8, por lo que 010 equivale a 8.
Hexadecimal literal (literal hexadecimal)
Un literal entero con prefijo 0x o 0X, que se lee en base 16, por lo que 0x1F equivale a 31.
Default value (valor por defecto)
El valor que recibe automáticamente un campo o elemento de arreglo: 0, false, '\u0000' o null. Las variables locales no tienen ninguno.
Definite assignment (asignación definitiva)
La regla del compilador según la cual una variable local debe asignarse en todos los caminos antes de leerse.
Ejemplo real

Un servicio de pagos guarda montos en centavos como long. Un desarrollador escribe long limit = 5_000_000_000; y la compilación falla, porque el literal sigue siendo un literal int y está fuera de rango. Agregar L (5_000_000_000L) lo corrige, y los guiones bajos mantienen el número legible en la revisión de código.

Consejo para el examen: Revisa cada literal numérico en busca de tres cosas: un 0 inicial (octal), un sufijo L o f faltante en un valor que lo necesita, y un guion bajo que toque un prefijo, un sufijo o un punto decimal. Luego comprueba que cada variable local esté asignada en todos los caminos antes de leerse.

Comprueba lo que sabes

¿Compila float price = 9.99;?

No. 9.99 es un literal double, y asignar un double a un float es una conversión de estrechamiento. Escribe 9.99f o haz un cast con (float).

¿Qué imprime System.out.println(012 + 0x10);?

26. 012 es 10 en octal y 0x10 es 16 en hexadecimal.

¿Cuál de estos es legal: 1_000, _1000, 0x_10, 1000_L?

Solo 1_000. Los demás ponen un guion bajo al inicio, justo después del prefijo 0x o justo antes del sufijo L.

¿Cuál es el valor de un campo de instancia boolean que nunca se asigna?

false. Los campos reciben valores por defecto, y el valor por defecto de boolean es false.
