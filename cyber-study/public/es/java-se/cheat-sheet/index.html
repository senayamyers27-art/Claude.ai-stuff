Dominio 1: Handling date, time, text, numeric and boolean values (12%)

Consejos para el examen

  • Revisa cada literal numérico en busca de tres cosas: un 0 inicial (octal), un sufijo L o f faltante en un valor que lo necesita, y un guion bajo que toque un prefijo, un sufijo o un punto decimal. Luego comprueba que cada variable local esté asignada en todos los caminos antes de leerse.
  • Cuando veas == entre dos variables Integer, revisa si ambos valores están entre -128 y 127. Si lo están, espera true; si no, espera false. Si uno de los lados es un primitivo, es una comparación numérica simple.
  • Evalúa los operandos estrictamente de izquierda a derecha, anotando en papel el valor de cada variable después de cada ++ o --. En la asignación compuesta, recuerda el cast oculto: compila donde la forma larga no compilaría.
  • Cuando una pregunta asigna un resultado aritmético a byte, short o char, busca la promoción a int. Solo compila con un cast, con una asignación compuesta o cuando toda la expresión es una constante que cabe.
  • Antes de elegir una respuesta, anota el tipo de retorno de cada llamada a Math. La mayoría de las preguntas sobre Math son en realidad preguntas de error de compilación porque round devuelve long o pow devuelve double.
  • Busca llamadas a métodos de cadena cuyo valor de retorno no se asigna. Como String es inmutable, la variable original no cambia, y normalmente ese es todo el sentido de la pregunta.
  • Sigue un mismo objeto StringBuilder a través de cada línea, aplicando cada llamada aunque su resultado no se asigne. Luego revisa la aritmética de índices: todos los métodos de rango usan un final exclusivo.
  • La posición del delimitador de cierre controla la sangría: si está en su propia línea y más a la izquierda que el contenido, la diferencia se convierte en espacios iniciales. Si está en la última línea de contenido, no hay salto de línea final.
  • Cuando una llamada a un método de fecha y hora no se asigna, el objeto no cambia. Comprueba también que el método exista en ese tipo: LocalDate no tiene plusHours, y LocalTime no tiene plusDays.
  • Recuerda Period para fechas (P...Y...M...D) y Duration para tiempos (PT...H...M...S). Al cruzar un cambio de horario de verano, plusDays conserva la hora del reloj de pared, mientras que plusHours(24) conserva el tiempo transcurrido exacto.

Términos clave

Primitive type (tipo primitivo)
Uno de los ocho tipos de valor integrados (byte, short, int, long, float, double, char, boolean) que no son objetos.
Literal
Un valor fijo escrito en el código fuente, como 42, 3.5f, 'x' o 0b1010.
Octal literal (literal octal)
Un literal entero con un 0 inicial, que se lee en base 8, por lo que 010 equivale a 8.
Hexadecimal literal (literal hexadecimal)
Un literal entero con prefijo 0x o 0X, que se lee en base 16, por lo que 0x1F equivale a 31.
Default value (valor por defecto)
El valor que recibe automáticamente un campo o elemento de arreglo: 0, false, '\u0000' o null. Las variables locales no tienen ninguno.
Definite assignment (asignación definitiva)
La regla del compilador según la cual una variable local debe asignarse en todos los caminos antes de leerse.
Wrapper class (clase envoltorio)
Una clase inmutable como Integer o Double que contiene un valor primitivo como objeto.
Autoboxing
La conversión automática de un primitivo a su envoltorio, que el compilador realiza mediante valueOf.
Unboxing
La conversión automática de un envoltorio a su primitivo; lanza NullPointerException si la referencia es null.
Integer cache (caché de Integer)
Un conjunto de objetos Integer, al menos de -128 a 127, que Integer.valueOf reutiliza, lo que hace que == parezca funcionar con valores pequeños.
parseInt vs valueOf
parseInt devuelve un int primitivo; valueOf devuelve un objeto Integer, posiblemente tomado de la caché.
Operator precedence (precedencia de operadores)
Las reglas que deciden qué operador de una expresión sin paréntesis se aplica primero.
Postfix increment (incremento postfijo)
x++: la expresión produce el valor anterior y luego x aumenta en uno.
Prefix increment (incremento prefijo)
++x: x aumenta en uno primero, y la expresión produce el valor nuevo.
Compound assignment (asignación compuesta)
Un operador como += que combina una operación con una asignación y convierte el resultado al tipo del operando izquierdo.
Short-circuit evaluation (evaluación de cortocircuito)
&& y || omiten evaluar el operando derecho cuando el operando izquierdo ya determina el resultado.
Widening conversion (conversión de ensanchamiento)
Una conversión automática a un tipo de mayor rango, como de int a long o de float a double.
Narrowing conversion (conversión de estrechamiento)
Una conversión a un tipo de menor rango, que necesita un cast explícito salvo que sea una constante de tiempo de compilación que quepa.
Numeric promotion (promoción numérica)
La regla por la que los operandos de los operadores aritméticos se convierten a un tipo común de al menos int antes de la operación.
Compile-time constant (constante de tiempo de compilación)
Una expresión cuyo valor conoce el compilador, como un literal o una variable final inicializada con un literal.
Truncation (truncamiento)
Descartar la parte fraccionaria cuando se hace cast de un valor de punto flotante a un tipo entero, siempre hacia cero.
Math.round
Redondea al número entero más cercano con las mitades hacia el infinito positivo; devuelve long para un argumento double e int para un float.
Math.floor / Math.ceil
Devuelven el double igual o justo por debajo (floor) o igual o justo por encima (ceil) del argumento, moviéndose hacia el infinito negativo o positivo.
Math.pow
Eleva una base double a un exponente double y siempre devuelve un double.
Overloading by type (sobrecarga por tipo)
abs, max y min tienen versiones para int, long, float y double, así que el tipo del resultado sigue a los tipos promovidos de los argumentos.
Immutability (inmutabilidad)
La propiedad de que el estado de un objeto no puede cambiar después de su creación; los métodos de String devuelven cadenas nuevas en su lugar.
String pool
Un área de la JVM que guarda una única copia compartida de cada literal de cadena y de cada cadena constante de tiempo de compilación.
substring(begin, end)
Devuelve los caracteres desde begin hasta end, sin incluir end.
strip vs trim
strip quita los espacios en blanco Unicode iniciales y finales; trim solo quita los caracteres hasta U+0020.
isBlank
Devuelve true si una cadena está vacía o solo contiene caracteres de espacio en blanco.
StringBuilder
Una secuencia de caracteres mutable y no sincronizada cuyos métodos cambian el objeto en el mismo lugar.
Method chaining (encadenamiento de métodos)
Llamar un método sobre el resultado de otro; funciona con StringBuilder porque los métodos que lo modifican devuelven this.
replace(start, end, str)
Elimina los caracteres de start a end (exclusivo) e inserta str en ese lugar.
Capacity (capacidad)
La cantidad de almacenamiento que un StringBuilder tiene reservada, que es independiente de su longitud actual.
StringBuffer
Una clase más antigua y sincronizada con los mismos métodos que StringBuilder, pensada para usarse desde varios hilos.
Text block (bloque de texto)
Un literal String de varias líneas delimitado por tres comillas dobles, cuyo contenido empieza en la línea siguiente al delimitador de apertura.
Incidental whitespace (espacio en blanco incidental)
La sangría inicial común que el compilador quita de cada línea de un bloque de texto.
Essential whitespace (espacio en blanco esencial)
La sangría que supera el mínimo común, que el compilador conserva como parte de la cadena.
Line continuation (continuación de línea)
Una barra invertida al final de una línea de un bloque de texto, que elimina el salto de línea para que la línea siguiente se una a ella.
\s escape (escape \s)
Un escape para un único espacio que sobrevive a la eliminación de los espacios en blanco finales.
LocalDate
Una fecha inmutable (año, mes, día) sin hora del día y sin zona horaria.
LocalTime
Una hora del día inmutable sin fecha ni zona, que da la vuelta a la medianoche cuando le sumas horas.
LocalDateTime
Una fecha y hora sin zona, así que no identifica un único instante global.
ZonedDateTime
Una fecha y hora con un ZoneId, que identifica un momento exacto y aplica el desfase y las reglas de horario de verano de esa zona.
Instant
Un punto en la línea de tiempo UTC medido desde el epoch 1970-01-01T00:00:00Z.
Period
Una cantidad de tiempo basada en fechas, en años, meses y días, que se imprime como P1Y2M3D.
Duration
Una cantidad basada en tiempo guardada como segundos y nanosegundos, que se imprime como PT2H30M.
DST gap (hueco de horario de verano)
La hora local que se salta cuando los relojes se adelantan; una hora dentro de ella se desplaza hacia adelante la duración del hueco.
DST overlap (solapamiento de horario de verano)
La hora local que se repite cuando los relojes se atrasan; ZonedDateTime mantiene por defecto el desfase anterior.
ISO-8601
La notación estándar internacional que usa toString en java.time, como 2025-03-09 y PT1H30M.

Dominio 2: Controlling program flow (8%)

Consejos para el examen

  • Ignora la sangría. Cuenta las sentencias: sin llaves, solo una sentencia pertenece al if o al else, y cada else se une al if sin pareja más cercano.
  • Encuentra por dónde entra la ejecución al switch y luego sigue hacia abajo pasando todas las etiquetas hasta llegar a un break o a la llave de cierre. Un default en medio también hace fall-through.
  • En una expresión switch, busca tres errores: un default faltante con selectores int o String, una rama de bloque sin yield, y un return o break usado para salir de la expresión.
  • Lee los case con patrones de arriba hacia abajo y elige el primero que coincide, revisando también la guarda. Un selector null lanza NullPointerException a menos que haya una etiqueta case null.
  • Ordena los case con patrones de lo específico a lo general: subtipos antes que supertipos, con guarda antes que sin guarda, constantes antes que patrones de tipo y default al final.
  • Revisa si la condición se evalúa antes o después del cuerpo: while y for pueden ejecutarse cero veces, do-while siempre se ejecuta al menos una vez. Revisa también que do-while termine con punto y coma.
  • Pregúntate a qué bucle se refiere cada break o continue. Sin etiqueta, siempre es el bucle más interno; con etiqueta, es el bucle que lleva esa etiqueta. Recuerda que continue en un bucle for igual ejecuta la actualización.
  • Trata if(false) y while(false) de forma distinta: el primero compila y el segundo no. Para las variables locales, sigue cada camino, incluido un bucle que se ejecuta cero veces y un if sin else.

Términos clave

Conditional expression (expresión condicional)
El operador ternario cond ? a : b, que se evalúa a uno de dos valores según un boolean.
Dangling else (else colgante)
La regla de que un else se asocia con el if sin pareja más cercano, sin importar la sangría.
Boolean condition (condición booleana)
Una expresión de tipo boolean o Boolean, el único tipo que aceptan if, while y el operador ternario.
Empty statement (sentencia vacía)
Un punto y coma solo; después de if(...) se convierte en todo el cuerpo del if.
Flow scoping (alcance por flujo)
La regla de que una variable de patrón declarada en una prueba instanceof solo está en alcance donde se sabe que la coincidencia tuvo éxito.
Fall-through (caída a través)
En un switch con dos puntos, la ejecución que continúa hacia las sentencias de los case posteriores porque ningún break, return o throw la detuvo.
case label (etiqueta case)
Una constante de tiempo de compilación que marca un punto de entrada en un switch; los duplicados y los valores no constantes no compilan.
default label (etiqueta default)
El punto de entrada usado cuando ningún case coincide; puede aparecer en cualquier parte del switch, y el fall-through sigue aplicando después de ella.
Selector expression (expresión selectora)
El valor en switch(...) que se compara con las etiquetas case; en un switch clásico puede ser char, byte, short, int, sus envoltorios, String o un enum.
Compile-time constant (constante de tiempo de compilación)
Un literal, una constante de enum o una variable final inicializada con una expresión constante, lo único permitido como etiqueta case.
Switch expression (expresión switch)
Un switch que se evalúa a un valor; debe ser exhaustivo y, con etiquetas de flecha, nunca hace fall-through.
Arrow label (etiqueta de flecha)
case X -> ..., una etiqueta cuyo lado derecho es una sola expresión, un bloque o un throw, sin fall-through.
yield
Una sentencia que entrega el valor de una expresión switch desde dentro de un bloque o de un grupo con dos puntos.
Exhaustiveness (exhaustividad)
El requisito de que una expresión switch maneje todos los valores posibles de su selector.
Multiple labels (múltiples etiquetas)
Varias constantes listadas con comas en un solo case, como case 6, 7 ->, que comparten una rama.
Type pattern (patrón de tipo)
Un patrón como String s que coincide cuando el valor es instancia del tipo y lo vincula a una variable de ese tipo.
Record pattern (patrón de record)
Un patrón como Point(int x, int y) que coincide con un record y extrae sus componentes mediante los métodos de acceso.
Guard (guarda)
Una cláusula when después de un patrón que agrega una condición booleana; si es false, el switch prueba el siguiente case.
case null
Una etiqueta que permite que un switch con patrones maneje un selector null en lugar de lanzar NullPointerException.
Unnamed pattern (patrón sin nombre)
El guion bajo _ usado en un patrón de record para un componente que no necesitas, disponible desde Java 22.
Dominance (dominancia)
Un case está dominado cuando un case anterior coincide con todos los valores con los que él podría coincidir, lo que lo hace inalcanzable y es un error de compilación.
Exhaustive switch (switch exhaustivo)
Un switch cuyos case cubren todos los valores posibles del selector, obligatorio para expresiones switch y switch con patrones.
Unconditional pattern (patrón incondicional)
Un patrón que coincide con todos los valores del tipo del selector, como case Object o para un selector Object.
Sealed type (tipo sellado)
Una clase o interfaz cuya cláusula permits enumera todos los subtipos directos permitidos, lo que permite al compilador revisar la exhaustividad.
MatchException
La excepción de tiempo de ejecución que lanza un switch exhaustivo si encuentra un valor que sus case compilados no cubren, como un subtipo agregado recientemente.
while loop (bucle while)
Un bucle que evalúa su condición antes de cada iteración, así que su cuerpo puede ejecutarse cero veces.
do-while loop (bucle do-while)
Un bucle que ejecuta su cuerpo una vez antes de evaluar la condición, así que siempre se ejecuta al menos una vez; termina con punto y coma.
Enhanced for loop (bucle for mejorado)
for (T x : source), que visita cada elemento de un arreglo o Iterable sin índice.
Iterable
La interfaz que permite usar un objeto como fuente de un bucle for mejorado; Map no la implementa.
Infinite loop (bucle infinito)
Un bucle cuya condición nunca se vuelve false, como while(true) o for(;;), del que normalmente se sale con break o return.
break
Termina el bucle o switch más interno que lo contiene, o la sentencia etiquetada que nombra.
continue
Salta el resto de la iteración actual del bucle más interno, o del bucle etiquetado que nombra; en un bucle for la actualización igual se ejecuta.
Label (etiqueta)
Un identificador seguido de dos puntos colocado antes de una sentencia para que break o continue puedan apuntar a ella.
Nested loop (bucle anidado)
Un bucle dentro de otro bucle; un break o continue sin etiqueta afecta solo al interno.
Unreachable statement (sentencia inalcanzable)
Una sentencia que el compilador puede demostrar que nunca se ejecutará, lo cual es un error de compilación en Java.
Definite assignment (asignación definida)
La regla del compilador según la cual una variable local debe asignarse en cada camino antes de leerse.
Constant expression (expresión constante)
Una expresión que el compilador puede evaluar, como true o una variable final que contiene un literal, usada en el análisis de alcanzabilidad.
Missing return statement (falta la sentencia return)
El error que se informa cuando un método que no es void puede llegar a su final sin devolver un valor.
Constant variable (variable constante)
Una variable final de tipo primitivo o String inicializada con una expresión constante, que el compilador puede tratar como una constante.

Dominio 3: Using object-oriented concepts in Java (20%)

Consejos para el examen

  • Lo estático se ejecuta una vez, el padre antes que el hijo. Para cada objeto nuevo: los inicializadores y el cuerpo del constructor del padre, luego los inicializadores del hijo y después el cuerpo del constructor del hijo. Los inicializadores se ejecutan en el orden del código fuente.
  • En un prólogo, está permitido usar parámetros, variables locales, llamadas estáticas, lanzar excepciones y asignar campos de esta clase. No está permitido leer campos, llamar a métodos de instancia, usar super.x, hacer return ni poner super(...) dentro de un bloque.
  • Los métodos de instancia siguen al objeto; los campos y los métodos estáticos siguen al tipo de la referencia. Para la sobrescritura, revisa la firma, el retorno covariante, que el acceso no sea más restrictivo y que no haya excepciones comprobadas nuevas o más amplias.
  • Los métodos de interfaz son public, se escriba o no, así que las implementaciones deben ser public. Los métodos estáticos de interfaz solo se llaman mediante el nombre de la interfaz, y los defaults duplicados deben resolverse con una sobrescritura.
  • Los accesores de un record se llaman como los componentes (name(), no getName()). En un constructor compacto reasigna los parámetros, nunca this.field, y nunca declares una lista de parámetros. Los constructores adicionales deben delegar con this(...).
  • Toda subclase permitida necesita exactamente uno de final, sealed o non-sealed, a menos que sea un record o un enum. El código del módulo sin nombre debe mantenerlas en el mismo paquete, y permits solo se puede omitir cuando todas las subclases están en el mismo archivo.
  • Los constructores de un enum son privados y se ejecutan una vez por constante al inicializar la clase. valueOf distingue mayúsculas y lanza IllegalArgumentException, los ordinales empiezan en 0 y la lista de constantes necesita punto y coma cuando le siguen miembros.
  • Crear una clase interna desde fuera requiere un objeto externo: outer.new Inner(). Una clase anidada estática usa new Outer.Nested(). Las variables locales capturadas deben ser efectivamente final, y las clases locales o anónimas no admiten modificadores de acceso.
  • Después de &&, la variable de patrón se puede usar; después de ||, no. Con una prueba negada cuyo bloque siempre hace return o lanza una excepción, la variable está en alcance después de la sentencia if. instanceof siempre es false para null.
  • Con var, revisa cada línea buscando un uso en un campo o parámetro, un inicializador faltante, un inicializador null o {arreglo}, o varias variables en una sola declaración; cada uno es un error de compilación. Para la inmutabilidad, busca una copia defensiva faltante.
  • Cuenta objetos alcanzables, no variables. Dibuja las referencias en papel línea por línea, recuerda que los ciclos sin raíz son elegibles y que System.gc() no garantiza nada.

Términos clave

Default constructor (constructor por defecto)
El constructor sin argumentos que el compilador agrega solo cuando una clase no declara constructores.
Static initializer (inicializador estático)
Un bloque static { } que se ejecuta una vez cuando la clase se inicializa.
Instance initializer (inicializador de instancia)
Un bloque { } en el cuerpo de la clase que se ejecuta para cada objeto nuevo, antes del cuerpo del constructor pero después del constructor de la superclase.
Pass by value (paso por valor)
Java copia cada argumento en el parámetro; para los objetos, el valor copiado es la referencia.
Class initialization (inicialización de la clase)
El paso único, en el primer uso activo de una clase, que ejecuta sus inicializadores de campos estáticos y sus bloques static en orden textual.
Prologue (prólogo)
Las sentencias de un constructor antes de la llamada explícita a super(...) o this(...), que no pueden usar el objeto que se está construyendo.
Epilogue (epílogo)
Las sentencias después de la llamada explícita al constructor, donde el objeto puede usarse normalmente.
Early construction context (contexto de construcción temprana)
El prólogo y los argumentos de la llamada al constructor, donde las referencias a la instancia actual están restringidas.
Explicit constructor invocation (invocación explícita de constructor)
Una sentencia super(...) o this(...) que encadena a otro constructor; debe ser una sentencia de nivel superior y aparecer como máximo una vez.
Flexible constructor bodies (cuerpos de constructor flexibles)
La característica de Java 25 que permite sentencias antes de una llamada explícita a super(...) o this(...).
Overriding (sobrescritura)
Redefinir un método de instancia heredado con la misma firma; el tipo del objeto en tiempo de ejecución decide qué versión se ejecuta.
Overloading (sobrecarga)
Declarar métodos con el mismo nombre pero listas de parámetros distintas; el compilador elige uno según los tipos de los argumentos.
Hiding (ocultamiento)
Declarar un método estático o un campo con el mismo nombre que uno del padre; el tipo de la referencia decide cuál se usa.
Covariant return type (tipo de retorno covariante)
El tipo de retorno de un método que sobrescribe, cuando es un subtipo del tipo de retorno del método sobrescrito.
ClassCastException
La excepción de tiempo de ejecución que se lanza cuando se aplica un downcast a un objeto que no es instancia del tipo de destino.
Abstract method (método abstracto)
Un método sin cuerpo que las subclases concretas o las clases que implementan deben implementar.
Default method (método default)
Un método de instancia de interfaz con cuerpo que las clases que implementan heredan y pueden sobrescribir; es implícitamente public.
Static interface method (método estático de interfaz)
Un método que pertenece a la propia interfaz, que solo se llama como InterfaceName.method() y no se hereda.
Private interface method (método privado de interfaz)
Un método auxiliar con cuerpo que solo es visible dentro de la interfaz.
Class wins rule (regla de que gana la clase)
Cuando un método de una superclase y un default de interfaz tienen la misma firma, se usa el método de la superclase.
Record component (componente de record)
Un nombre y un tipo en el encabezado de un record; cada uno se convierte en un campo private final y un accesor public.
Canonical constructor (constructor canónico)
El constructor cuyos parámetros coinciden en orden con los componentes del record y que asigna cada campo.
Compact constructor (constructor compacto)
Un constructor canónico escrito sin lista de parámetros, usado para validar o normalizar parámetros antes de que los campos se asignen automáticamente.
Accessor method (método accesor)
El método public generado con el nombre de un componente, como x(), que devuelve su valor.
java.lang.Record
La superclase implícita de todo record, razón por la cual un record no puede extender otra clase.
Sealed class (clase sellada)
Una clase o interfaz que permite solo los subtipos directos nombrados en su cláusula permits, o declarados en el mismo archivo.
permits clause (cláusula permits)
La lista de clases o interfaces que pueden extender o implementar directamente un tipo sellado.
non-sealed
Un modificador para una subclase permitida que reabre la jerarquía para que cualquier clase pueda extenderla.
Exhaustive hierarchy (jerarquía exhaustiva)
Un conjunto cerrado de subtipos que permite al compilador verificar que un switch maneje todos los casos sin un default.
Unnamed module (módulo sin nombre)
El módulo del código normal del classpath; allí, los tipos sellados deben mantener sus subclases permitidas en el mismo paquete.
Enum
Una clase especial con un conjunto fijo de instancias con nombre declaradas al inicio de su cuerpo.
values()
Un método estático generado que devuelve un arreglo nuevo con todas las constantes del enum en orden de declaración.
valueOf(String)
Devuelve la constante con el nombre exacto dado, distinguiendo mayúsculas de minúsculas, o lanza IllegalArgumentException.
ordinal()
La posición, empezando en cero, de una constante en su declaración.
Constant-specific body (cuerpo específico de constante)
Un cuerpo de clase unido a una constante del enum que implementa o sobrescribe métodos solo para esa constante.
Static nested class (clase anidada estática)
Una clase declarada static dentro de otra clase; no necesita una instancia externa y se crea con new Outer.Nested().
Inner class (clase interna)
Una clase miembro no estática cuyas instancias están ligadas a una instancia externa y pueden acceder a sus miembros.
Local class (clase local)
Una clase con nombre declarada dentro de un método o bloque, visible solo dentro de ese bloque.
Anonymous class (clase anónima)
Una clase sin nombre declarada e instanciada en una sola expresión, que extiende una clase o implementa una interfaz.
Effectively final (efectivamente final)
Una variable local que nunca se reasigna después de inicializarse, lo que permite usarla desde clases locales, clases anónimas y lambdas.
Pattern matching for instanceof (pattern matching con instanceof)
Una comprobación instanceof que además enlaza el valor a una nueva variable del tipo comprobado cuando coincide.
Pattern variable (variable de patrón)
La variable declarada por un patrón, como s en o instanceof String s.
Flow scoping (alcance por flujo)
La regla según la cual una variable de patrón está en alcance solo donde el compilador puede demostrar que la coincidencia tuvo éxito.
Record pattern (patrón de record)
Un patrón como Point(int x, int y) que comprueba un tipo record y enlaza sus componentes.
Definite matching (coincidencia definitiva)

Dominio 4: Handling exceptions (8%)

Consejos para el examen

  • Memoriza la división: los subtipos de RuntimeException y Error son unchecked; cualquier otra Exception es checked. IOException y FileNotFoundException son checked; NumberFormatException es unchecked.
  • El valor de retorno queda fijo cuando se ejecuta el return del try; finally se ejecuta después y solo puede reemplazarlo haciendo su propio return. Un return o throw en finally oculta cualquier excepción anterior, y solo una salida de la JVM salta finally.
  • En un multi-catch, revisa dos cosas: que ningún tipo de la lista sea subclase de otro y que la variable nunca se asigne. Cualquiera de los dos errores es un error de compilación.
  • Subclase antes que superclase, siempre. Una excepción checked específica solo se puede atrapar si algo en el try puede lanzarla; Exception, Throwable y los tipos unchecked siempre están permitidos.
  • Sigue el orden: abrir en el orden de declaración, cuerpo, cerrar en orden inverso, luego catch y luego finally. Las variables de recurso son final y no son visibles en catch ni en finally.
  • En try-with-resources, la excepción del cuerpo gana y las excepciones de cierre pasan a ser suprimidas. En un finally simple, una nueva excepción reemplaza a la original, que se pierde.
  • En una sobrescritura, las excepciones checked permitidas son: las mismas, más específicas, menos o ninguna. Nunca nuevas y nunca más amplias. Las excepciones unchecked siempre están permitidas.
  • La clase padre lo decide todo: extends Exception significa checked, extends RuntimeException significa unchecked. Los constructores no se heredan, así que escribe cada uno que necesites y llama a super.

Dominio 5: Working with arrays and collections (10%)

Consejos para el examen

  • Para binarySearch con un valor ausente, busca el índice donde se insertaría, niégalo y resta uno. Si el arreglo no está ordenado, la respuesta es "indefinido".
  • Aprende los pares de la cola: add/offer, remove/poll, element/peek. El primero de cada par lanza una excepción si falla; el segundo devuelve false o null. push y pop en un Deque trabajan en el frente.
  • Modificar una colección de List.of, Set.of o Map.of compila pero lanza UnsupportedOperationException. Arrays.asList permite set pero no add ni remove, y escribe en el arreglo.
  • Revisa primero el tipo de referencia: las referencias Set y Collection no tienen getFirst. Luego revisa la implementación: TreeSet y TreeMap rechazan addFirst y putFirst, las listas no modificables rechazan cualquier cambio y las colecciones vacías lanzan NoSuchElementException.
  • Revisa qué valor de retorno se pregunta: putIfAbsent devuelve el valor anterior (null cuando insertó), mientras que merge y computeIfAbsent devuelven el valor actual. Un resultado null de la función de merge elimina la clave.
  • Lee las cadenas de comparadores de izquierda a derecha y aplica reversed() a todo lo que tiene antes en la cadena. compareTo y compare devuelven un valor negativo, cero o positivo, no solo -1, 0 y 1.
  • En un TreeSet o TreeMap, que compareTo devuelva 0 significa duplicado, sin importar equals. headSet excluye su límite y tailSet lo incluye; lower/higher son estrictos, mientras que floor/ceiling no lo son.
  • Las preguntas del examen suelen mostrar list.add(...) sobre un List<? extends Algo> y preguntar si compila. No compila (excepto con null). Con ? super, agregar el tipo de la cota compila, pero asignar el resultado de get() a algo más específico que Object no compila.
  • En un List<Integer>, un argumento int simple siempre significa índice. Busca Integer.valueOf, una conversión a Integer o a Object, o una variable Integer para reconocer la versión por valor.

Dominio 6: Working with streams and lambda expressions (16%)

Consejos para el examen

  • Asocia los nombres de método con las interfaces: get para Supplier, accept para Consumer, apply para Function y los operadores, test para Predicate. Las preguntas suelen llamar al método equivocado, como predicate.apply(x), que no compila.
  • Revisa tres cosas en cada pregunta sobre lambdas: las reglas de paréntesis para los parámetros, las llaves con return y punto y coma, y si alguna variable local capturada se reasigna en cualquier parte del método, incluso después de la lambda.
  • Recuerda que range excluye el final y rangeClosed lo incluye, y que un stream es de un solo uso. Una pregunta que guarda un stream en una variable y llama a dos operaciones terminales sobre él termina en IllegalStateException.
  • Sigue las preguntas de salida elemento por elemento, no operación por operación, y comprueba si hay alguna operación terminal. Vigila también sorted sobre un stream infinito, que se queda colgado incluso con un limit posterior.
  • Conoce los tipos de retorno: count es long; min, max, findFirst, findAny y reduce de un argumento devuelven Optional; los métodos match devuelven boolean; y allMatch sobre un stream vacío es true.
  • toMap sin función de fusión lanza IllegalStateException con una clave duplicada. counting() produce Long y averagingX produce Double; las respuestas del examen suelen usar Integer en su lugar.
  • average() siempre devuelve OptionalDouble, sum() en un IntStream devuelve int y OptionalInt usa getAsInt(). Las respuestas que asignan average() a un double o llaman a get() sobre un OptionalInt no compilan.
  • La trampa clásica: orElse(expensiveCall()) ejecuta expensiveCall() aunque el Optional tenga un valor; orElseGet no. Además, Optional.of(null) lanza una excepción de inmediato, mientras que ofNullable(null) queda vacío.
  • Distingue fold de scan por el tamaño de la salida: fold emite un elemento al final y scan emite uno por cada elemento de entrada. En las ventanas, fixed no se solapa y su última ventana puede ser corta; sliding se solapa.
  • En preguntas de salida con streams paralelos, el orden de forEach es impredecible y findAny es impredecible, pero collect/toList mantienen el orden de encuentro. Un reduce con un valor inicial que no es identidad da un resultado distinto en paralelo.

Dominio 7: Packaging and deploying Java code (7%)

Consejos para el examen

  • exports controla el acceso ordinario y se aplica en tiempo de compilación y de ejecución; opens controla la reflexión solo en tiempo de ejecución. Si la firma de un método exportado usa tipos de otro módulo, esa dependencia debería ser requires transitive.
  • Ten claro a quién pertenece cada directiva: uses va en el consumidor, provides ... with va en el proveedor, y el paquete de la interfaz debe exportarlo quien la define. El paquete de la implementación no necesita exportarse.
  • Los módulos automáticos provienen de JAR simples en el module path; el módulo sin nombre proviene de cualquier cosa en el class path. Los módulos con nombre pueden requerir módulos automáticos, pero nunca el módulo sin nombre.
  • La sintaxis para ejecutar es java -p path -m module/package.Class. Recuerda que -d significa directorio de salida para javac pero describe-module para java.
  • Una ambigüedad causada por dos imports de módulo solo se informa donde se usa el nombre simple, y un import de un solo tipo la corrige. Recuerda también que los imports de módulo traen tipos de los módulos requeridos de forma transitiva.
  • Si una clase tiene main(String[]) y main(), se elige la versión con String[]. Un main private no se puede lanzar, y un main de instancia necesita un constructor sin argumentos no privado.
  • En el modo de código fuente se lanza la primera clase de nivel superior del archivo, los argumentos que siguen al nombre del archivo van a main y no se producen archivos de clase. El soporte de varios archivos encuentra otras clases como archivos fuente según el directorio del paquete.
  • Asocia cada herramienta con su tarea: jar empaqueta, jdeps analiza, jlink construye un runtime. jlink funciona solo con módulos con nombre, nunca con módulos automáticos ni con el class path.

Dominio 8: Managing concurrent code execution (9%)

Consejos para el examen

  • El método de Runnable es run(), devuelve void y no puede lanzar excepciones comprobadas. daemon() y priority() están disponibles en los builders de plataforma; los hilos virtuales siempre son daemon.
  • Los hilos virtuales mejoran la escalabilidad de las tareas bloqueantes con mucha I/O, no la velocidad pura de la CPU. No los agrupes en pools; en su lugar, limita el acceso a los recursos escasos con un Semaphore. Siempre son hilos daemon.
  • execute devuelve void y solo acepta un Runnable; submit devuelve un Future. shutdown no espera, awaitTermination espera y close() hace ambas cosas. Las excepciones dentro de una tarea te llegan envueltas en ExecutionException desde get().
  • Llamar a run() no crea un hilo, así que Thread.currentThread() dentro de él es quien llamó. Llamar dos veces a start() lanza IllegalThreadStateException. A menos que el código use join u otra herramienta de coordinación, el orden de la salida entre hilos es impredecible.
  • volatile da visibilidad pero no atomicidad, así que count++ sobre un volatile sigue siendo inseguro. Los métodos de instancia synchronized bloquean this y los estáticos bloquean el objeto Class; dos métodos solo se excluyen entre sí si usan el mismo lock.
  • incrementAndGet devuelve el valor nuevo y getAndIncrement el anterior. Desbloquea siempre en finally, y solo después de un lock o tryLock exitoso; desbloquear un lock que no tienes lanza IllegalMonitorStateException.
  • Modificar un ArrayList mientras lo iteras lanza ConcurrentModificationException; un CopyOnWriteArrayList no, y el bucle ve la instantánea anterior. ConcurrentHashMap rechaza claves y valores null. put/take se bloquean, offer/poll no.
  • Los hilos en deadlock están en BLOCKED o WAITING; los hilos en livelock están en RUNNABLE y ocupados. La solución estándar para el deadlock en las opciones de respuesta es adquirir los locks en un orden coherente.
  • Los scoped values no tienen método set; la única forma de cambiar el valor visible es volver a enlazarlo en un alcance anidado. get() fuera de cualquier enlace lanza NoSuchElementException, así que usa isBound u orElse cuando el valor pueda faltar.

Dominio 9: Using the Java I/O API (6%)

Consejos para el examen

  • Resolver una ruta absoluta la devuelve sin cambios, relativize lanza IllegalArgumentException al mezclar rutas absolutas y relativas, y normalize nunca consulta el disco. La mayoría de los métodos de Path no requieren que el archivo exista.
  • createDirectory falla si el directorio existe o si falta el padre; createDirectories maneja ambos casos. copy y move fallan con un destino existente a menos que se indique REPLACE_EXISTING. delete lanza una excepción para un archivo inexistente; deleteIfExists devuelve false.
  • readAllLines devuelve un List y cierra el archivo; lines devuelve un Stream que debes cerrar. writeString sin opciones trunca el contenido existente, y APPEND solo falla si el archivo no existe.
  • list es un solo nivel y excluye el directorio de inicio; walk es recursivo e incluye el directorio de inicio; find requiere maxDepth y un BiPredicate que recibe atributos. Todos devuelven streams que deben cerrarse.
  • Las señales de fin de datos difieren: read() devuelve -1, readLine() devuelve null. Las clases que terminan en Stream manejan bytes; Reader y Writer manejan caracteres. Cerrar el envoltorio exterior cierra el stream interno, y cerrar un writer hace flush.
  • System.console() puede devolver null, así que el código de examen que llama a un método sobre él sin comprobarlo puede lanzar NullPointerException. readPassword devuelve char[], y System.out y System.err son PrintStream mientras que System.in es un InputStream.
  • En la deserialización, los campos transient y static no se leen del stream, los inicializadores de campo no se ejecutan y no se llaman los constructores de la clase Serializable; solo se ejecuta el constructor sin argumentos de la primera superclase no serializable. Los records se reconstruyen mediante su constructor canónico.
  • Los recursos se cierran en orden inverso, antes de catch y finally. Una excepción de close después de una excepción del cuerpo queda suprimida, no se lanza. Files.lines, list, walk y find devuelven streams que debes cerrar; readAllLines y writeString no lo necesitan.

Dominio 10: Implementing localization (4%)

Consejos para el examen

  • La forma de cadena es idioma_PAÍS, con el idioma en minúsculas y el país en mayúsculas, siempre con el idioma primero; la etiqueta de idioma usa guion. Locale.setDefault cambia solo la JVM. Usa Locale.of en lugar de los constructores obsoletos.
  • Orden: locale solicitado (idioma_país y luego idioma), luego locale por defecto (idioma_país y luego idioma), luego el base. Para claves que faltan, solo se buscan los padres del bundle elegido, nunca los bundles del locale por defecto.
  • Conoce qué fábrica usar, que el porcentaje multiplica por 100, que el redondeo por defecto es HALF_EVEN, y que parse lanza la excepción verificada ParseException pero acepta texto con basura al final después de un número válido.
  • Sin cambiar los dígitos fraccionarios, los formatos compactos redondean a un número entero usando HALF_EVEN, así que 1 234 567 es 1M, 1500 es 2K y 2500 es 2K. Los números menores que 1000 se imprimen sin cambios en inglés de Estados Unidos.
  • MM es el mes y mm son los minutos; HH es formato de 24 horas y hh de 12 horas; yyyy es el año calendario y YYYY el año basado en semanas. Formatear un LocalDate con letras de hora lanza UnsupportedTemporalTypeException, y un análisis fallido lanza la excepción no verificada DateTimeParseException.
  • Los marcadores empiezan en cero y se pueden reutilizar o reordenar. Un apóstrofo solo rompe el patrón, así que escribe dos comillas simples. Los números se formatean con la agrupación del locale incluso sin tipo de formato, y los argumentos faltantes dejan el texto del marcador sin cambios.

Términos clave

Locale
Un objeto que identifica un idioma y, opcionalmente, un país y una variante, usado por las clases sensibles al locale.
Language code (código de idioma)
Un código ISO 639 en minúsculas, como en o fr, que forma la primera parte de un locale.
Country code (código de país)
Un código ISO 3166 en mayúsculas, como US o CA, que identifica la región de un locale.
Locale.of
El método de fábrica para crear un Locale a partir de un idioma y, opcionalmente, un país y una variante, que reemplaza a los constructores obsoletos.
Default locale (locale por defecto)
El locale que usa la JVM cuando no se indica ninguno, inicializado desde el sistema operativo y modificable con Locale.setDefault.
Locale.Category
Un enum con DISPLAY y FORMAT que permite locales por defecto separados para el texto de la interfaz de usuario y para el formato.
Resource bundle
Un conjunto de recursos clave-valor específicos de un locale, cargado por nombre base y locale con ResourceBundle.getBundle.
Base name (nombre base)
El prefijo común de una familia de bundles, como Messages, al que se agregan sufijos de locale como _fr_CA.
Default (base) bundle (bundle por defecto o base)
El archivo de bundle sin sufijo de locale, usado como respaldo final y raíz de toda cadena de padres.
Parent chain (cadena de padres)
La secuencia de bundles menos específicos, como de fr_CA a fr y al base, en la que se busca una clave que falta en el bundle elegido.
MissingResourceException
Una excepción no verificada que se lanza cuando no se encuentra ningún bundle o cuando una clave falta en el bundle y en sus padres.
ListResourceBundle
Una clase abstracta para bundles escritos como clases Java; un bundle de clase se prefiere sobre un archivo properties con el mismo nombre.
NumberFormat
Una clase abstracta sensible al locale para formatear y analizar números, que se obtiene mediante métodos de fábrica.
getCurrencyInstance
Devuelve un NumberFormat que formatea valores como moneda para un locale, con su símbolo y sus decimales estándar.
getPercentInstance
Devuelve un NumberFormat que multiplica por 100, no muestra dígitos fraccionarios por defecto y agrega un signo de porcentaje.
HALF_EVEN
El modo de redondeo por defecto, que redondea las mitades exactas al dígito par más cercano.
ParseException
Una excepción verificada que se lanza cuando un texto no se puede analizar como número o fecha.
DecimalFormat
Un NumberFormat concreto que formatea usando un patrón de símbolos 0, #, coma y punto.
CompactNumberFormat
Una subclase de NumberFormat que formatea números en formas cortas específicas del locale, como 1K o 1 thousand.
NumberFormat.Style.SHORT
El estilo compacto que usa sufijos abreviados como K, M y B en inglés de Estados Unidos.
NumberFormat.Style.LONG
El estilo compacto que escribe completa la magnitud, como thousand o million.
getCompactNumberInstance
El método de fábrica de NumberFormat que devuelve un formateador compacto para un locale y un estilo.
setMaximumFractionDigits
Un método de NumberFormat que establece cuántos dígitos pueden aparecer después del punto decimal; los formatos compactos usan cero por defecto.
DateTimeFormatter
Una clase inmutable y segura para hilos que formatea y analiza valores de java.time usando constantes ISO, estilos localizados o patrones.
FormatStyle
Un enum con SHORT, MEDIUM, LONG y FULL que se usa para disposiciones de fecha y hora específicas de cada locale.
ofPattern
Crea un formateador a partir de letras de patrón como yyyy-MM-dd HH:mm, opcionalmente con un Locale.
withLocale
Devuelve una copia de un formateador que usa otro Locale, ya que los formateadores son inmutables.
DateTimeParseException
Una excepción no verificada que se lanza cuando un texto no se puede analizar como fecha u hora.
UnsupportedTemporalTypeException
Se lanza cuando el formato requiere un campo que el valor no tiene, como las horas en un LocalDate.
MessageFormat
Una clase de java.text que construye mensajes que respetan el locale sustituyendo argumentos en marcadores de posición indexados.
Placeholder (marcador de posición)
Un elemento {n} de un patrón que se reemplaza por el argumento n, opcionalmente con un tipo de formato como number o date.
Format type (tipo de formato)
La segunda parte de un marcador de posición, como number, date, time o choice, que controla cómo se formatea el argumento.
Quoting (uso de comillas)
En MessageFormat, una comilla simple inicia una sección literal; dos comillas simples producen un apóstrofo.
ChoiceFormat
Un formato que se usa mediante el tipo choice y que selecciona texto según rangos numéricos, útil para plurales simples.
