Azure Container Registry: niveles Basic, Standard y Premium; replicación geográfica y private endpoints en Premium

Azure Container Registry (ACR) es el registro privado de Azure para imágenes de contenedor y otros artefactos OCI (Open Container Initiative), como los charts de Helm. Tu pipeline de compilación sube imágenes a él, y App Service, Container Apps y AKS (Azure Kubernetes Service) las descargan cada vez que inician o escalan horizontalmente. Mantener el registro en la misma región que tu cómputo hace que esas descargas sean rápidas y que el tráfico se quede en la red de Microsoft, lo cual importa tanto para el tiempo de arranque como para los cargos por transferencia de datos.

Cada registro tiene un nombre de login server con la forma myregistry.azurecr.io, y las referencias de imagen se construyen sobre él, como en myregistry.azurecr.io/orders-api:1.4.2. La parte después del nombre del servidor es el repositorio y la parte después de los dos puntos es la etiqueta (tag). Creas un registro con az acr create --resource-group rg --name myregistry --sku Basic, donde --sku es el nivel. Inicias sesión con tu cliente local de Docker usando az acr login --name myregistry, que usa tu inicio de sesión de Microsoft Entra ID en lugar de una contraseña almacenada. Vale la pena notarlo: incluso el acceso humano al registro se basa en la identidad, lo que prepara el terreno para el patrón de identidad administrada que verás más adelante en este dominio.

ACR tiene tres niveles de servicio, y el dato más importante para el examen es lo que comparten. Los tres admiten las mismas funciones básicas: subir y descargar imágenes, autenticación con Microsoft Entra, ACR Tasks para compilaciones en la nube, webhooks y permisos con alcance de repositorio. Así que una pregunta que solo requiere compilaciones, webhooks o inicio de sesión con Entra no exige subir de nivel. Los niveles se diferencian principalmente en el almacenamiento incluido, en el rendimiento (cuántas descargas y subidas simultáneas funcionan bien) y en un conjunto de funciones avanzadas. Basic es el punto de entrada optimizado en costo para aprender y para cargas de trabajo pequeñas. Standard agrega más almacenamiento y rendimiento, y sirve para la mayoría de las cargas de producción. Premium tiene el mayor almacenamiento y rendimiento, y es el único nivel con las funciones empresariales que se describen a continuación.

La replicación geográfica (geo-replication) es la primera función exclusiva de Premium y convierte un registro en un registro multirregión. Agregas una réplica con az acr replication create --registry myregistry --location westeurope. Sigues subiendo una sola vez, al mismo nombre de login server. ACR copia el contenido a cada réplica y los clientes se enrutan a la más cercana. Los beneficios son descargas más rápidas y baratas para el cómputo en varias regiones, porque no hay tráfico de salida entre regiones en cada descarga, y la posibilidad de seguir descargando si una región tiene un problema. La alternativa en los niveles inferiores es un registro separado por región, lo que implica subir varias veces, administrar varios nombres de login server y mantener sincronizados varios manifiestos de implementación.

Los private endpoints (puntos de conexión privados), mediante Azure Private Link, también son exclusivos de Premium. Un private endpoint es una interfaz de red que le da al registro una dirección IP privada dentro de tu red virtual (VNet). Con una zona DNS (sistema de nombres de dominio) privada vinculada a la red, el nombre normal del login server se resuelve a esa IP privada desde dentro de la red, así que tus manifiestos no cambian. Después puedes deshabilitar el acceso desde la red pública para que el registro no sea accesible en absoluto desde internet. En un escenario, esto suele aparecer como un requisito de cumplimiento: las imágenes solo deben descargarse a través de redes privadas.

Premium también incluye algunas otras funciones que conviene reconocer en las opciones de respuesta. Admite reglas de firewall que permiten solo redes seleccionadas, claves de cifrado administradas por el cliente almacenadas en Azure Key Vault y el mayor rendimiento, lo que ayuda a los clústeres grandes que descargan muchas imágenes a la vez durante el escalado horizontal. Si un requisito menciona cualquiera de estas, es otra señal de Premium. Si el requisito solo trata de más almacenamiento o más rendimiento de descarga en una sola región, Standard puede ser suficiente.

Cambiar de nivel es sencillo y no se pierde nada. az acr update --name myregistry --sku Premium sube de nivel en el mismo lugar sin cambiar el login server ni borrar imágenes, y puedes bajar de nuevo más tarde si ya no usas funciones exclusivas de Premium. Por eso, un patrón común es empezar con Basic en desarrollo, ejecutar producción en Standard y pasar a Premium solo cuando aparece un requisito como varias regiones o private endpoints. En el examen, cuando una pregunta pide el nivel menos costoso que cumple un requisito, verifica si el requisito realmente es exclusivo de Premium antes de elegirlo. Frases como 'varias regiones con un solo nombre', 'IP privada', 'sin acceso público' o 'nuestra propia clave de cifrado' son las pistas de Premium; frases como 'webhook', 'compilación en la nube' o 'inicio de sesión con Entra' no lo son.

Términos clave

Login server (servidor de inicio de sesión)
El nombre DNS del registro, como myregistry.azurecr.io, que se usa como prefijo de cada referencia de imagen.
Geo-replication (replicación geográfica)
Una función de ACR Premium que mantiene copias de un registro en varias regiones detrás de un único login server.
Private endpoint (punto de conexión privado)
Una interfaz de red con una IP privada en tu VNet que se conecta de forma privada a un servicio, como un registro Premium.
Repository (repositorio)
Una colección con nombre de imágenes relacionadas en un registro, que se distinguen por etiquetas y digests.
Service tier (SKU) (nivel de servicio)
El nivel del registro, Basic, Standard o Premium, que define el almacenamiento, el rendimiento y el acceso a funciones avanzadas.
Ejemplo real

Un minorista ejecuta su API en Container Apps en East US y West Europe. Con un registro Standard en East US, las réplicas europeas descargaban imágenes a través del Atlántico en cada escalado horizontal. Subieron el registro a Premium, agregaron una réplica en West Europe y un private endpoint en cada VNet, y luego desactivaron el acceso desde la red pública. Las subidas siguen yendo a un solo login server y cada región ahora descarga localmente a través de una IP privada.

Consejo para el examen: Cualquier requisito que mencione varias regiones desde un solo nombre de registro, private endpoints o bloquear el acceso público apunta a Premium; Basic y Standard se diferencian principalmente en almacenamiento y rendimiento.

Comprueba lo que sabes

Una empresa necesita un solo registro que entregue imágenes a clústeres en tres regiones con descargas locales. ¿Qué nivel y qué función?

Premium con replicación geográfica, porque solo Premium puede replicar un registro en varias regiones detrás de un único login server.

¿Puedes subir un registro Basic a Premium sin volver a subir las imágenes?

Sí. az acr update --sku Premium cambia el nivel en el mismo lugar y conserva el login server y todo el contenido.

¿Qué funciones de ACR comparten los tres niveles?

Subir y descargar imágenes, autenticación con Microsoft Entra, ACR Tasks, webhooks y permisos con alcance de repositorio.
