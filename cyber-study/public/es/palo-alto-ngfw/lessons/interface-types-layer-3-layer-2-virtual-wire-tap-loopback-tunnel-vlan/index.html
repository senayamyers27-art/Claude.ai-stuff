Palo Alto Networks Certified Next-Generation Firewall Engineer NGFW-Engineer

Tipos de interfaz: Layer 3, Layer 2, virtual wire, tap, loopback, tunnel, VLAN y aggregate Ethernet (LACP); subinterfaces y etiquetas 802.1Q

Toda implementación de PAN-OS empieza con una decisión sobre cómo se comporta cada puerto físico. El tipo de interfaz decide si el firewall enruta, conmuta, se ubica de forma invisible en el camino o solo observa. Elegir el tipo correcto importa porque controla qué funciones podrás usar después: los protocolos de enrutamiento dinámico, GlobalProtect y la terminación de IP Security (IPsec) necesitan interfaces Layer 3, la mayoría de los diseños de traducción de direcciones de red (NAT) las usan, y una interfaz tap nunca puede bloquear nada. Cuando heredas un firewall, la primera pantalla que debes leer es Network > Interfaces, cuyas pestañas Ethernet, VLAN, Loopback y Tunnel muestran de un vistazo el tipo, la zona y el router de cada puerto. Un puerto cuya columna Interface Type todavía no dice nada útil, o cuya zona está vacía, es un puerto que no dejará pasar tráfico.

Una interfaz Layer 3 tiene una dirección IP, pertenece a un virtual router (o a un logical router en el Advanced Routing Engine) y a una zona Layer 3, y reenvía enrutando. Es el tipo más común y el único tipo físico que admite un servidor de protocolo de configuración dinámica de host (DHCP), protocolos de enrutamiento dinámico y la terminación de redes privadas virtuales (VPN), y es el lugar habitual para NAT. Una interfaz Layer 2 no tiene dirección IP; el firewall conmuta tramas entre las interfaces Layer 2 que comparten un objeto de red de área local virtual (VLAN), y al mismo tiempo aplica la política de seguridad entre zonas Layer 2. Esto te permite segmentar hosts de una misma subred sin cambiar su gateway.

Un virtual wire (vwire) une exactamente dos interfaces como un "bump in the wire" (un punto intermedio en el cable): sin direcciones IP, sin aprendizaje de direcciones de control de acceso al medio (MAC) y sin enrutamiento. Lo insertas en un enlace existente sin cambiar ningún direccionamiento y aun así obtienes App-ID, prevención de amenazas y política de seguridad, porque el firewall está completamente en el camino de reenvío. Un vwire puede pasar tráfico etiquetado, y su campo Tag Allowed limita qué etiquetas VLAN acepta. Una interfaz tap es distinta en un aspecto crucial. Recibe una copia del tráfico desde un puerto Switched Port Analyzer (SPAN) o puerto espejo de un switch, así que da visibilidad, como resultados de App-ID y registros de amenazas, pero no puede bloquear, porque los paquetes reales nunca pasan por el firewall. El modo tap se usa a menudo en una prueba de concepto en la que nadie quiere arriesgar el tráfico de producción.

Varias interfaces son lógicas en lugar de físicas. Una interfaz loopback es una interfaz Layer 3 que siempre está activa, útil para acceso de administración, proxy del sistema de nombres de dominio (DNS), un portal de GlobalProtect o una dirección de origen estable que no dependa de un solo cable. Una interfaz tunnel, por ejemplo tunnel.1, es el extremo lógico para IPsec basado en rutas, GlobalProtect o Generic Routing Encapsulation (GRE); la asignas a una zona y a un router igual que un puerto físico Layer 3, y las rutas que apuntan a ella envían el tráfico al túnel. Una interfaz VLAN, como vlan.10, le da una dirección IP a una VLAN Layer 2 para que sus hosts puedan enrutarse hacia redes Layer 3, de forma muy parecida a una interfaz virtual conmutada en un switch. Las tres necesitan una zona y, en los tipos Layer 3, una asignación de router antes de hacer algo útil.

Una interfaz aggregate Ethernet (AE), como ae1, agrupa varios puertos físicos de la misma velocidad y el mismo medio en un solo enlace lógico, para tener más ancho de banda y redundancia. Creas el grupo en Network > Interfaces > Ethernet > Add Aggregate Group, y luego configuras el Interface Type de cada puerto miembro como Aggregate Ethernet y lo asignas al grupo. Link Aggregation Control Protocol (LACP) es opcional pero recomendado: negocia la membresía con el switch y detecta un miembro mal conectado o con falla, para que el tráfico no se pierda por un enlace muerto. Luego el grupo AE recibe un tipo, como Layer 3, Layer 2 o virtual wire, y toda la configuración (dirección IP, zona, subinterfaces) se hace en el grupo, no en los miembros. Los miembros simplemente se convierten en carriles anónimos del grupo.

Las subinterfaces permiten que un puerto físico o AE transporte muchas redes usando etiquetas VLAN IEEE 802.1Q. En un puerto Layer 3 creas ethernet1/3.20 con la etiqueta 20 y su propia dirección IP, zona y router, que es el diseño clásico de "router on a stick" frente a un puerto troncal de un switch. Las interfaces Layer 2 y vwire también admiten subinterfaces; en un vwire te permiten poner distintas VLAN en distintas zonas. Por convención, el número de la subinterfaz coincide con la etiqueta, pero lo que realmente importa es el campo de la etiqueta. Si el troncal del switch envía la VLAN 20 y tu subinterfaz tiene la etiqueta 21, no llega nada, aunque la interfaz aparezca como activa.

Veamos un ejemplo práctico. Un hospital quiere prevención de amenazas en el enlace entre su switch de núcleo y un router antiguo, pero nadie puede cambiar el direccionamiento del router este trimestre. Configuras ethernet1/5 y ethernet1/6 como un virtual wire, colocas cada lado en su propia zona Virtual Wire y conectas el firewall en línea. El firewall aplica de inmediato App-ID y los perfiles de amenazas sin ningún cambio de IP ni de enrutamiento. Más adelante el hospital agrega una red de invitados en el mismo troncal, así que añades subinterfaces vwire con la etiqueta 50 en una zona Guest separada, y el tráfico de invitados ahora tiene sus propias reglas mientras las VLAN clínicas conservan las suyas.

Los errores comunes siguen un patrón. La gente espera que una interfaz tap bloquee (solo observa), intenta configurar una dirección IP en los puertos miembros de un AE en lugar de en el grupo ae, etiqueta una subinterfaz con una VLAN distinta de la del troncal del switch, de modo que el tráfico nunca llega, y supone que una interfaz loopback o tunnel funciona sin asignación de zona y router.

Las preguntas del examen suelen describir un requisito y pedir el tipo de interfaz, así que aprende las palabras clave. "Sin cambios en la red", "sin direcciones IP" o "en línea y transparente" apuntan a virtual wire. "Solo monitorear", "puerto SPAN" o "nunca debe afectar el tráfico" apuntan a tap. "Enrutar entre subredes", "NAT", "IPsec" o "GlobalProtect" apuntan a Layer 3. "Conmutar entre hosts de una subred mientras se aplica política" apunta a Layer 2. "Agrupar puertos para ancho de banda y conmutación por error" apunta a aggregate Ethernet con LACP, y "varias VLAN en un puerto físico con zonas distintas" apunta a subinterfaces con etiquetas 802.1Q.

Términos clave

Virtual wire (cable virtual)
Un par de interfaces unidas para que el firewall inspeccione el tráfico de forma transparente, sin direcciones IP, enrutamiento ni conmutación.
Tap interface (interfaz tap)
Una interfaz alimentada por un puerto SPAN o espejo de un switch que da visibilidad y registros, pero no puede aplicar políticas ni bloquear.
Aggregate Ethernet (AE)
Una interfaz lógica que agrupa varios puertos físicos de la misma velocidad, opcionalmente negociada con LACP, para tener ancho de banda y redundancia.
LACP
Link Aggregation Control Protocol (protocolo de control de agregación de enlaces), que negocia un grupo agregado con el equipo vecino y retira los miembros con falla o mal conectados.
Subinterface (subinterfaz)
Una interfaz lógica sobre un puerto padre que maneja una etiqueta VLAN 802.1Q, con su propia zona y direccionamiento.
Tunnel interface (interfaz de túnel)
Una interfaz lógica Layer 3 usada como extremo de un túnel IPsec basado en rutas, GRE o GlobalProtect.
Loopback interface (interfaz loopback)
Una interfaz lógica Layer 3 siempre activa que se usa para servicios como administración, proxy DNS o un portal de GlobalProtect.
VLAN interface (interfaz VLAN)
Una interfaz Layer 3 asociada a una VLAN Layer 2 para que sus hosts puedan enrutarse hacia otras redes.
Ejemplo real

Un hospital quiere prevención de amenazas en el enlace entre su switch de núcleo y un router antiguo, pero nadie puede cambiar el direccionamiento del router este trimestre. Configuras ethernet1/5 y ethernet1/6 como un virtual wire en dos zonas Virtual Wire, conectas el firewall en línea y este empieza a aplicar App-ID y los perfiles de amenazas sin ningún cambio de IP ni de enrutamiento. Cuando se agrega una VLAN de invitados al mismo troncal, las subinterfaces vwire con su etiqueta colocan a los invitados en su propia zona.

Consejo para el examen: Si una pregunta dice que el firewall debe agregarse "sin cambios en la red" o "sin direcciones IP", la respuesta es virtual wire. Si solo debe observar y nunca bloquear, es tap. El enrutamiento, NAT y la terminación de VPN requieren Layer 3.

Comprueba lo que sabes

¿Qué tipo de interfaz da solo visibilidad y nunca puede bloquear tráfico?

Tap, porque recibe una copia espejada del tráfico desde un puerto SPAN y no está en el camino de reenvío.

¿Qué aporta LACP a un grupo aggregate Ethernet?

Negocia el grupo con el switch vecino y detecta los enlaces miembros con falla o mal conectados para retirarlos de uso.

¿Cómo transportas la VLAN 30 y la VLAN 40 en un puerto Layer 3 con zonas separadas?

Crea dos subinterfaces Layer 3 (por ejemplo ethernet1/2.30 y ethernet1/2.40) con las etiquetas 802.1Q 30 y 40, cada una con su propia dirección IP y zona.

¿Dónde configuras la dirección IP de un grupo aggregate Ethernet?

En la interfaz ae (o en sus subinterfaces), no en los puertos miembros, que se configuran con el tipo Aggregate Ethernet.
