Dominio 1: Plan and manage an Azure AI solution (24%)

Consejos para el examen

  • Fíjate en el resultado que pide el escenario: campos con nombre de formularios significa Document Intelligence, líneas de texto simples significa Vision Read, puntuaciones de contenido dañino significa Content Safety y texto generado significa Azure OpenAI.
  • Si la pregunta insiste en un endpoint y una factura para varios servicios precompilados, elige el recurso multiservicio. Si insiste en un nivel Free o en claves separadas por servicio, elige recursos de un solo servicio. Gobernanza compartida con espacios de trabajo separados significa un hub con proyectos.
  • Global significa cualquier región, Data Zone significa dentro de la zona de la UE o EE. UU., Standard significa la región del recurso y Provisioned significa capacidad reservada con latencia predecible. Un error 429 apunta a la cuota o a los límites de velocidad.
  • En una pregunta sobre plantillas, mira kind para identificar el servicio y sku.name para el nivel. customSubDomainName es la propiedad vinculada a la autenticación con Entra ID.
  • Conoce los códigos de estado: 401 problema de credencial, 403 bloqueo de permisos o de red, 404 ruta o nombre de implementación incorrecto, 429 límite de velocidad, 202 operación asíncrona iniciada.
  • Reader es un rol del plano de administración y no puede llamar a las API de IA. Para llamadas sin claves elige una identidad administrada más Cognitive Services User (u OpenAI User para Azure OpenAI). La autenticación con tokens necesita un subdominio personalizado.
  • Rotar sin tiempo de inactividad siempre es cambiar a la otra clave y luego regenerar. Mantener un recurso fuera de internet es un endpoint privado más deshabilitar el acceso de red pública.
  • Conoce los tres parámetros obligatorios del contenedor: ApiKey, Billing y Eula. Sin ninguna conexión a internet significa contenedores desconectados, que necesitan la aprobación de Microsoft y un plan de compromiso.
  • Las métricas son automáticas y sirven para alertas; los registros necesitan una configuración de diagnóstico y van a Log Analytics para usar KQL. Toda alerta notifica a través de un grupo de acciones.
  • Relaciona el escenario con el principio: explicar el uso y los límites de la IA es transparencia, el trato igualitario entre grupos es equidad, la accesibilidad es inclusión y que las personas respondan por los resultados es responsabilidad. Palabras prohibidas concretas significan una lista de bloqueo.
  • 400 con content_filter significa que se bloqueó el prompt; finish_reason content_filter significa que se bloqueó la salida. Un jailbreak en el mensaje del usuario es un ataque en el prompt del usuario; las instrucciones ocultas en los datos son un ataque en documentos.

Términos clave

Azure AI services (servicios de Azure AI)
La familia de API de IA precompiladas de Microsoft para visión, lenguaje, voz, traducción, documentos y seguridad de contenido, que se llaman mediante REST o SDK.
Azure OpenAI
Modelos de OpenAI alojados en Azure para chat, razonamiento, embeddings y generación de imágenes, implementados y administrados mediante Azure AI Foundry.
Azure AI Search
Un servicio de búsqueda que indexa tu contenido para consultas por palabra clave, vectoriales e híbridas, y que es la capa de recuperación habitual en RAG.
Document Intelligence
Un servicio que extrae texto, estructura y campos con nombre de documentos usando modelos precompilados o personalizados.
Content Safety
Un servicio que detecta texto e imágenes dañinos en las categorías de odio, contenido sexual, violencia y autolesiones.
Retrieval augmented generation, RAG (generación aumentada por recuperación)
Un patrón en el que se recuperan pasajes relevantes de tus datos y se entregan a un modelo de lenguaje para fundamentar su respuesta.
Single-service resource (recurso de un solo servicio)
Un recurso de Azure para un solo servicio de IA, con su propio endpoint, claves, nivel de precios y factura.
Multi-service resource (recurso multiservicio)
Un recurso de Azure AI services que expone muchos servicios de IA detrás de un endpoint y un par de claves, con facturación combinada.
Hub
Un contenedor compartido de Azure AI Foundry, construido sobre Azure Machine Learning, que guarda conexiones, seguridad y proceso para varios proyectos.
Project (proyecto)
Un espacio de trabajo de Foundry donde implementas modelos, creas agentes, evalúas y administras los recursos de una aplicación o un equipo.
Connection (conexión)
Una definición guardada y reutilizable de cómo un proyecto llega a otro recurso, como Azure AI Search o el almacenamiento, para que las claves queden fuera del código.
Azure AI Foundry resource (recurso de Azure AI Foundry)
Un recurso de Azure AI services que también admite proyectos de Foundry, la forma más nueva y sencilla de alojar proyectos sin un hub.
Deployment (implementación)
Una instancia con nombre de una versión de modelo dentro de un recurso de Azure OpenAI o Foundry, que se llama por su nombre desde el código.
Tokens per minute, TPM (tokens por minuto)
La unidad de límite de velocidad y de cuota para las implementaciones de pago por uso.
Provisioned throughput unit, PTU (unidad de rendimiento aprovisionado)
Una unidad de capacidad de procesamiento de modelo reservada para implementaciones aprovisionadas.
Data zone (zona de datos)
Un grupo de regiones, como la UE o EE. UU., dentro del cual las implementaciones Data Zone procesan las solicitudes.
Global Standard
Un tipo de implementación de pago por token que puede enviar cada solicitud a cualquier región de Azure con capacidad.
HTTP 429
La respuesta Too Many Requests que se devuelve cuando una implementación supera su límite de velocidad, normalmente con un encabezado retry-after.
kind
La propiedad de la plantilla que establece qué servicio de IA proporciona un recurso Microsoft.CognitiveServices/accounts.
Bicep
Un lenguaje específico de dominio para infraestructura como código en Azure que se compila a plantillas ARM en JSON.
ARM template (plantilla ARM)
Un archivo JSON de Azure Resource Manager que declara los recursos que se van a implementar y sus propiedades.
customSubDomainName
La propiedad que da a un recurso un nombre de endpoint único, necesario para la autenticación con Entra ID y los endpoints privados.
disableLocalAuth
Una propiedad que desactiva la autenticación basada en claves para que solo funcionen los tokens de Microsoft Entra ID.
az cognitiveservices
El grupo de comandos de la CLI de Azure para crear y administrar recursos de Azure AI services, sus claves y sus implementaciones de modelos.
Endpoint
La URL base de un recurso de Azure AI a la que se envían todas las llamadas a la API.
Ocp-Apim-Subscription-Key
El encabezado HTTP que transporta la clave del recurso para la mayoría de los servicios de Azure AI.
api-key
El encabezado HTTP que transporta la clave en las llamadas a Azure OpenAI.
DefaultAzureCredential
Una clase de Azure Identity que encuentra automáticamente una credencial de Microsoft Entra ID en el entorno, la identidad administrada o el inicio de sesión del desarrollador.
Operation-Location
El encabezado que devuelven las operaciones asíncronas y que apunta a la URL que consultas para obtener el resultado.
api-version
Un parámetro de consulta obligatorio que selecciona qué versión de la API REST de un servicio atiende la solicitud.
Managed identity (identidad administrada)
Una identidad de Entra ID para un recurso de Azure cuyas credenciales Azure crea y rota automáticamente.
System-assigned identity (identidad asignada por el sistema)
Una identidad administrada que se crea con un recurso de Azure y se elimina con él.
User-assigned identity (identidad asignada por el usuario)
Un recurso de identidad administrada independiente que se puede adjuntar a varias aplicaciones.
Cognitive Services User
Un rol RBAC que permite a una identidad llamar a las API del plano de datos de los servicios de Azure AI.
Cognitive Services OpenAI User
Un rol RBAC que permite llamadas de inferencia a implementaciones de Azure OpenAI sin derechos de administración.
Custom subdomain (subdominio personalizado)
Un nombre de endpoint único y específico del recurso, necesario para la autenticación con tokens de Entra ID.
Azure Key Vault
Un servicio administrado para guardar y auditar secretos, claves y certificados.
Key Vault reference (referencia de Key Vault)
Un valor de configuración de la aplicación que apunta a un secreto de Key Vault para que la aplicación lo lea sin guardarlo.
Key rotation (rotación de claves)
Reemplazar las claves con regularidad, usando el patrón de dos claves para que los clientes nunca pierdan el acceso.
Private endpoint (endpoint privado)
Una interfaz de red con una IP privada en tu red virtual que se conecta de forma privada a un recurso de Azure.
Private DNS zone (zona DNS privada)
Una zona DNS que hace que el nombre de host normal de un recurso se resuelva a la IP de su endpoint privado dentro de las redes conectadas.
Customer-managed key (clave administrada por el cliente)
Una clave de cifrado que te pertenece, guardada en Key Vault, que se usa para cifrar los datos en reposo de un servicio en lugar de una clave administrada por Microsoft.
Connected container (contenedor conectado)
Un contenedor que procesa los datos localmente pero informa el uso a Azure para la facturación.
Disconnected container (contenedor desconectado)
Un contenedor aprobado para uso totalmente sin conexión bajo un plan de compromiso, sin informe de uso en línea.
ApiKey setting (valor ApiKey)
El valor de inicio del contenedor que contiene la clave del recurso de Azure correspondiente.
Billing setting (valor Billing)
El valor de inicio del contenedor que contiene el endpoint del recurso de Azure al que se le cobra el uso.
Eula=accept
El argumento de inicio obligatorio que confirma la aceptación de los términos de licencia del contenedor.
Microsoft Container Registry
El registro desde el que se descargan las imágenes de contenedor de los servicios de Azure AI.
Metrics (métricas)
Series temporales numéricas, como llamadas, errores, latencia y tokens, que Azure Monitor recopila automáticamente.
Diagnostic setting (configuración de diagnóstico)
Una configuración del recurso que envía registros y métricas a Log Analytics, a almacenamiento o a un event hub.
Log Analytics workspace (área de trabajo de Log Analytics)
Un almacén de Azure Monitor donde los registros se consultan con Kusto Query Language (KQL).
Action group (grupo de acciones)
Un conjunto reutilizable de notificaciones y acciones automatizadas que activan las alertas.
Commitment tier (nivel de compromiso)
Un plan de precios con una tarifa mensual fija por un volumen de uso determinado a una tarifa con descuento.
Budget (presupuesto)
Un umbral de Cost Management sobre el gasto real o previsto que envía alertas.
Responsible AI principles (principios de IA responsable)
Los seis principios de Microsoft: equidad, confiabilidad y seguridad, privacidad y seguridad, inclusión, transparencia y responsabilidad.
Harm categories (categorías de daño)
Las cuatro clasificaciones de Content Safety: odio, contenido sexual, violencia y autolesiones.
Severity level (nivel de gravedad)
Una puntuación que indica qué tan dañino es el contenido dentro de una categoría, y que tu aplicación compara con un umbral.
Blocklist (lista de bloqueo)
Una lista personalizada de términos que Content Safety marca además de sus clasificadores de daño.
Limited Access (acceso limitado)
Una directiva de Microsoft que exige una solicitud y una aprobación antes de usar capacidades sensibles como la identificación facial de Face.
Transparency note (nota de transparencia)
Documentación de Microsoft que describe los usos previstos, las capacidades y las limitaciones de un servicio.
Content filter (filtro de contenido)
La moderación configurable de entrada y salida que se aplica a toda implementación de Azure OpenAI.
Prompt shields
Una función de Content Safety que detecta ataques en el prompt del usuario (jailbreaks) y ataques en documentos (inyección indirecta de prompts).
Jailbreak
Un ataque en el prompt del usuario que intenta que el modelo ignore su mensaje de sistema o sus reglas de seguridad.
Indirect prompt injection (inyección indirecta de prompts)
Instrucciones maliciosas ocultas en el contenido que lee el modelo, como documentos o resultados de herramientas.
Groundedness detection (detección de fundamentación)
Una comprobación que marca la salida del modelo que no está respaldada por el material de origen proporcionado.
Protected material detection (detección de material protegido)
Una comprobación que marca las salidas que coinciden con texto con derechos de autor conocido o con código de repositorios públicos.

Dominio 2: Implement generative AI solutions (18%)

Consejos para el examen

  • Vectores para búsqueda significa un modelo de embeddings; imágenes nuevas significa un modelo de imágenes; lógica difícil de varios pasos sugiere un modelo de razonamiento; todo lo conversacional es un modelo de chat. El código llama al nombre de la implementación, no al nombre del modelo.
  • Las reglas y la persona van en el mensaje del sistema. La memoria en una aplicación de chat viene de reenviar los mensajes anteriores, no de la implementación. El argumento model es el nombre de la implementación. finish_reason length significa subir el máximo de tokens; content_filter significa que la salida fue filtrada.
  • Consistencia significa bajar la temperatura. Respuestas cortadas con finish_reason length significa subir el máximo de tokens. Repetición significa penalización de frecuencia o de presencia. Cambia temperature o top_p, no ambos. Es posible que los modelos de razonamiento no acepten parámetros de muestreo.
  • Cuando el escenario trata de obtener un formato o estilo exacto, la respuesta suele ser ejemplos few-shot o salida estructurada. Las instrucciones y las reglas van en el mensaje del sistema; el contenido debe ir claramente delimitado. Prueba la ingeniería de prompts antes que RAG o el fine-tuning.
  • Datos actualizados, documentos privados y citas apuntan a RAG, no al fine-tuning. Si las respuestas son incorrectas porque falta el pasaje correcto, corrige la recuperación (búsqueda híbrida, clasificación semántica, mejor fragmentación) antes de cambiar el modelo.
  • Las dimensiones del campo vectorial deben coincidir con el modelo de embeddings, y las consultas deben convertirse con el mismo modelo que los documentos. La superposición entre fragmentos evita perder contexto en los límites. HNSW es el algoritmo aproximado predeterminado.
  • Comparar versiones de prompts en un nodo significa variantes; guardar endpoints y claves significa conexiones; un flujo conversacional con historial es un flujo de chat; puntuar un flujo con un conjunto de datos es un flujo de evaluación; publicarlo como API significa un endpoint en línea administrado.
  • Las respuestas que no están respaldadas por el contexto recuperado apuntan a la fundamentación; las respuestas fuera de tema apuntan a la relevancia; la mala legibilidad apunta a la fluidez o la coherencia. Las métricas de coincidencia como F1 y BLEU necesitan ground truth. Medir la seguridad requiere datos de prueba adversarios.
  • Datos que cambian y necesitan citas: RAG. Estilo o formato consistente, o prompts más cortos en una tarea específica: fine-tuning. En todos los casos, prueba primero la ingeniería de prompts. Los datos de fine-tuning de chat son JSONL con un arreglo messages por línea.
  • Crear imágenes significa un modelo de generación de imágenes; hacer preguntas sobre una imagen significa enviarla como parte de imagen a un modelo de chat con visión. Las URL de las imágenes generadas son temporales. Para extracciones estructuradas de gran volumen, prefiere Document Intelligence o Vision.
  • 429 significa límites de velocidad: espera y reintenta, agrega cuota o implementaciones, o usa rendimiento aprovisionado. Los trabajos grandes sin conexión se adaptan a las implementaciones por lotes. Encontrar qué paso causó una respuesta lenta o mala significa seguimiento con Application Insights.

Términos clave

Model catalog (catálogo de modelos)
La lista de Azure AI Foundry con modelos de Microsoft, OpenAI y socios, con fichas de modelo y opciones de implementación.
Model card (ficha de modelo)
La página del catálogo que describe el propósito, la longitud de contexto, las regiones, las opciones de implementación, la licencia y las limitaciones de un modelo.
Reasoning model (modelo de razonamiento)
Un modelo que trabaja internamente un problema antes de responder, lo que mejora la precisión en tareas complejas con mayor latencia y costo.
Embedding model (modelo de embeddings)
Un modelo que convierte texto en un vector numérico que representa su significado, usado para búsqueda y similitud.
Context window (ventana de contexto)
El número máximo de tokens que un modelo puede procesar entre entrada y salida en una solicitud.
Serverless API (API sin servidor)
Una opción de implementación en la que Microsoft aloja el modelo y pagas por token sin administrar el proceso.
System message (mensaje del sistema)
El mensaje de instrucciones que define el comportamiento, las reglas y el formato del modelo durante toda la conversación; en los modelos más nuevos a veces se llama developer message (mensaje del desarrollador).
Stateless API (API sin estado)
Una API que no guarda memoria entre llamadas, así que el cliente debe reenviar el contexto de la conversación cada vez.
finish_reason
Un campo de la respuesta que explica por qué se detuvo la generación: stop, length, content_filter o tool_calls.
Streaming
Devolver los tokens generados de forma incremental a medida que se producen, en lugar de en una sola respuesta final.
Deployment name (nombre de la implementación)
El nombre que le diste a la implementación de un modelo; es lo que pasas en el argumento model al llamar a Azure OpenAI.
usage
El objeto de la respuesta que informa los tokens del prompt, de la respuesta y el total de la solicitud.
Temperature (temperatura)
Un parámetro de 0 a 2 que controla la aleatoriedad; los valores más bajos dan una salida más determinista.
top_p
Muestreo de núcleo: solo se consideran los tokens dentro de la probabilidad acumulada superior p.
Max tokens (máximo de tokens)
El límite de tokens de salida generados; al alcanzarlo, la respuesta se corta con finish_reason length.
Stop sequence (secuencia de detención)
Una cadena que termina la generación cuando el modelo la produce; se pueden definir hasta cuatro, y la cadena no se devuelve.
Frequency penalty (penalización de frecuencia)
Un parámetro que reduce la probabilidad de los tokens en proporción a cuántas veces ya aparecieron.
Presence penalty (penalización de presencia)
Un parámetro que aplica una penalización fija a cualquier token que ya apareció, lo que fomenta temas nuevos.
Few-shot prompting
Incluir ejemplos de entradas y de las salidas deseadas en el prompt para mostrarle al modelo la tarea y el formato.
Zero-shot prompting
Pedirle al modelo que realice una tarea solo con instrucciones y sin ejemplos.
Chain-of-thought (cadena de pensamiento)
Pedirle al modelo que razone paso a paso antes de dar su respuesta final.
Delimiter (delimitador)
Marcadores como comillas triples o etiquetas que separan las instrucciones del contenido que se procesa.
Structured outputs (salidas estructuradas)
Una función del modelo que hace que la respuesta se ajuste a un esquema JSON que tú proporcionas.
RAG
Generación aumentada por recuperación (retrieval augmented generation): recuperar datos relevantes en el momento de la consulta y agregarlos al prompt para fundamentar la respuesta.
Grounding (fundamentación)
Proporcionarle al modelo el contenido de origen en el que debe basar su respuesta.
Ingestion (ingesta)
El proceso previo de extraer, fragmentar, generar embeddings e indexar documentos para la recuperación.
Citation (cita)
Una referencia en la respuesta al documento o fragmento de origen que la respaldó.
Semantic ranking (clasificación semántica)
Una función de Azure AI Search que reordena los mejores resultados con un modelo de lenguaje para mejorar la relevancia.
Security filter (filtro de seguridad)
Un filtro aplicado a las consultas de búsqueda para que los usuarios solo recuperen documentos que tienen permitido ver.
Embedding
Una representación vectorial numérica del texto en la que los significados similares quedan cerca entre sí.
Cosine similarity (similitud de coseno)
Una medida de qué tan similares son dos vectores según el ángulo entre ellos.
Chunking (fragmentación)
Dividir los documentos en pasajes más pequeños, a menudo con superposición, antes de generar embeddings e indexarlos.
HNSW
Hierarchical Navigable Small World: un algoritmo aproximado de vecinos más cercanos que encuentra vectores similares rápidamente en índices grandes; es el predeterminado en Azure AI Search.
Exhaustive KNN (KNN exhaustivo)
Búsqueda exacta de k vecinos más cercanos que compara la consulta con cada vector guardado; es precisa pero lenta a gran escala.
Vectorizer (vectorizador)
Un ajuste del índice que convierte automáticamente el texto de la consulta en embedding en el momento de la consulta, usando un modelo de embeddings configurado.
Flow (flujo)
Un grafo dirigido de nodos de herramientas que define un pipeline de IA generativa en prompt flow.
Variant (variante)
Una versión alternativa del prompt o de los parámetros de un nodo LLM, que se ejecuta lado a lado para comparar.
Connection (conexión)
Una configuración guardada y reutilizable del endpoint y las credenciales de un recurso externo que usan los nodos del flujo.
Evaluation flow (flujo de evaluación)
Un flujo que puntúa las salidas de otro flujo frente a la verdad de referencia o a criterios de calidad.
Chat flow (flujo de chat)
Un tipo de flujo con el historial del chat como entrada integrada y una interfaz de prueba de chat, para aplicaciones conversacionales.
Managed online endpoint (endpoint en línea administrado)
Un endpoint REST hospedado en el que se implementa un flujo, con autenticación, escalado y supervisión.
Groundedness (fundamentación)
Una métrica de evaluación que puntúa si las afirmaciones de la respuesta están respaldadas por el contexto proporcionado.
Relevance (relevancia)
Una métrica de evaluación que puntúa si la respuesta atiende la pregunta del usuario.
Coherence (coherencia)
Una métrica de evaluación que puntúa si la respuesta está organizada de forma lógica y sus ideas se conectan.
Fluency (fluidez)
Una métrica de evaluación que puntúa la gramática, la elección de palabras y la legibilidad.
Ground truth (verdad de referencia)
La respuesta correcta esperada para una entrada de prueba, que usan las métricas de similitud y de coincidencia.
Red teaming
Poner a prueba deliberadamente un sistema con entradas adversarias para encontrar debilidades de seguridad antes que los usuarios reales.
Fine-tuning (ajuste fino)
Entrenar más a fondo un modelo base con tus propios ejemplos para producir una versión personalizada del modelo.
JSONL
JSON Lines: un formato de archivo con un objeto JSON por línea, que se usa para los datos de entrenamiento de fine-tuning.
Epoch (época)
Una pasada completa de entrenamiento sobre todo el conjunto de datos de entrenamiento.
Validation file (archivo de validación)
Ejemplos reservados que se usan durante el fine-tuning para medir qué tan bien generaliza el modelo.
Overfitting (sobreajuste)
Cuando un modelo aprende sus ejemplos de entrenamiento demasiado de cerca y rinde peor con entradas nuevas.
Image generation model (modelo de generación de imágenes)
Un modelo como DALL-E 3 que crea imágenes nuevas a partir de un prompt de texto.
Multimodal model (modelo multimodal)
Un modelo que acepta más de un tipo de entrada, como texto e imágenes, en la misma solicitud.
Revised prompt (prompt revisado)
El prompt ampliado que DALL-E 3 realmente usó, que se devuelve junto con la imagen generada.
Detail setting (ajuste de detalle)
Una opción que controla cuánto de una imagen de entrada procesa el modelo, equilibrando costo y precisión.
Base64 data URL (URL de datos base64)
Una imagen codificada como texto e incrustada directamente en una solicitud, que se usa cuando la imagen no está en una URL accesible.
Prompt tokens (tokens del prompt)
Los tokens de entrada de una solicitud, incluidos el mensaje del sistema, el historial y el contexto recuperado.
Exponential backoff (espera exponencial)
Reintentar las solicitudes fallidas con tiempos de espera crecientes, normalmente con una variación aleatoria (jitter), para no saturar un servicio.
Tracing (seguimiento)
Registrar cada paso de una solicitud con entradas, salidas, tiempos y uso de tokens para depurar.
AI gateway (gateway de IA)
Una capa como Azure API Management delante de las implementaciones de modelos que balancea la carga, impone límites y registra el uso.
Provisioned throughput (rendimiento aprovisionado)
Capacidad reservada de procesamiento del modelo para cargas de trabajo constantes y de gran volumen con rendimiento predecible.
HTTP 429
El estado Too Many Requests que se devuelve cuando se supera un límite de velocidad, a menudo con un encabezado retry-after.

Dominio 3: Implement an agentic solution (8%)

Consejos para el examen

  • Las tareas de varios pasos que llaman a API o realizan acciones sugieren un agente. Las transformaciones de texto de una sola vez (reescribir, traducir, resumir un documento) sugieren una chat completion simple. Agente = modelo + instrucciones + herramientas.
  • El historial de la conversación vive en el hilo, el comportamiento en el agente y el procesamiento en la ejecución. Para continuar un chat, agrega un mensaje al mismo hilo y crea una nueva ejecución. requires_action significa que tu código debe ejecutar la función y enviar las salidas de las herramientas.
  • Cálculos o gráficas a partir de datos subidos: code interpreter. Respuestas a partir de documentos subidos: file search. Índice empresarial existente: herramienta Azure AI Search. API REST existente con especificación: OpenAPI. Tu propio código en tu app: function calling.
  • El modelo solo propone llamadas; tu código las ejecuta y debe devolver los resultados con el ID de llamada correspondiente. Las descripciones determinan qué función elige el modelo. Para forzar una función, pon tool_choice en esa función.
  • Exponer tus propios métodos al modelo en Semantic Kernel significa un plugin con kernel functions. AutoGen se asocia con conversaciones multiagente. Agent Service es la opción administrada y hospedada. Microsoft Agent Framework unifica Semantic Kernel y AutoGen.
  • Un agente principal que delega en especialistas corresponde a connected agents o handoff. Agentes que revisan el trabajo de otros es group chat o maker-checker. Un orden fijo de pasos es orquestación secuencial. Un análisis independiente en paralelo es concurrente.
  • Las acciones riesgosas o irreversibles necesitan aprobación humana aplicada en código. Limita el daño con permisos de herramientas de mínimo privilegio. Para averiguar qué llamada a herramienta salió mal necesitas tracing. Las instrucciones escondidas en documentos requieren Prompt Shields más herramientas con poder limitado.
  • Las apps llaman a los agentes hospedados mediante el project endpoint con Entra ID, idealmente con una managed identity. Los agentes basados en frameworks se implementan como cualquier app (Container Apps, App Service, Functions). Guarda los IDs de thread por usuario y condiciona las promociones a una ejecución de evaluación.

Dominio 4: Implement computer vision solutions (13%)

Consejos para el examen

  • Una oración para toda la imagen es caption; oraciones con cuadros para regiones son dense captions; palabras sueltas son tags; dónde están las cosas es objects; detectar personas no es identificarlas; las miniaturas en relaciones de aspecto definidas son smart crops.
  • Texto en fotos y escenas apunta a Vision Read; documentos largos, tablas y campos de formularios apuntan a Document Intelligence. Read devuelve líneas y palabras con polígonos y confianza por palabra. Hacer buscables archivos escaneados durante la indexación apunta al OCR skill de Azure AI Search.
  • Exactamente una etiqueta por imagen: multiclase. Varias etiquetas por imagen: multietiqueta. Ubicación o conteo: detección de objetos. Sin conexión o edge: dominio compacto.
  • La precisión trata de cuántas predicciones fueron correctas; el recall, de cuántos casos reales se encontraron. Subir el umbral cambia recall por precisión. mAP es la métrica principal para la detección de objetos.
  • Reentrenaste pero la app no cambia: la nueva iteración no se publicó con el nombre que llama la app. Uso sin conexión: exportar, lo que requiere un dominio compacto. Las llamadas de predicción usan la clave de predicción, no la de entrenamiento.
  • La detección y los atributos de calidad están disponibles; la identificación y la verificación necesitan aprobación de Limited Access; la inferencia de emoción, edad y género se retiró. Elige la función menos sensible que cubra la necesidad.
  • Transcripciones que se pueden buscar, texto en pantalla, temas y escenas de videos grabados apuntan a Video Indexer. Reconocer rostros específicos o celebridades en video sigue requiriendo aprobación de Limited Access. Las imágenes fijas apuntan a Image Analysis o Custom Vision.
  • Conceptos generales, sin entrenamiento: Image Analysis. Tus propias categorías a escala, medibles o sin conexión: Custom Vision. Preguntas abiertas o razonamiento sobre una imagen: un modelo multimodal. Formularios: Document Intelligence. Rostros: Face. Video grabado: Video Indexer. Imágenes dañinas: Content Safety.

Una característica de Image Analysis que devuelve una oración que describe toda la imagen.

Dominio 5: Implement natural language processing solutions (18%)

Consejos para el examen

  • Positivo o negativo en general es sentimiento; qué aspecto gusta o disgusta es minería de opiniones. Clasificar entidades es NER; resolver a qué cosa real se refiere una entidad es vinculación de entidades. Texto corto y ambiguo: agrega una pista de país a la detección de idioma.
  • Enmascarar datos personales en texto: detección de PII con redactedText. Restringir qué tipos se enmascaran: filtro de categorías. Datos de salud: domain phi. Chats y llamadas: PII conversacional. Datos que no pueden salir de tu red: el contenedor de PII.
  • Varios idiomas de destino en una llamada: múltiples parámetros to. 401 con una clave regional: agrega el encabezado Ocp-Apim-Subscription-Region. Archivos completos con formato: traducción de documentos con Blob Storage. Terminología de dominio: Custom Translator con un ID de categoría. Solo cambiar el sistema de escritura: transliterate.
  • Un comando corto: recognize once. Audio largo en vivo: reconocimiento continuo con eventos. Miles de archivos almacenados: transcripción por lotes. Un archivo grabado, rápido: fast transcription. Un resultado Canceled suele indicar problemas de credenciales, región o conexión.
  • Velocidad y tono: prosody. Pausas: break. Fechas, números y deletreo: say-as. Pronunciación exacta: phoneme o un léxico. Abreviaturas: sub. Emoción o estilo: mstts:express-as. Guardar en archivo: AudioConfig con un nombre de archivo.
  • Voz en vivo a otro idioma: SpeechTranslationConfig con add_target_language y un TranslationRecognizer. Una palabra de activación: reconocimiento de palabras clave con un modelo de palabra clave personalizado (archivo .table) en el dispositivo. Entender comandos: coincidencia de patrones para unas pocas frases fijas, CLU para lenguaje natural.
  • Entradas fuera de alcance que caen en una intención real: agrega ejemplos a None. Un conjunto fijo de valores con sinónimos: entidad de lista. Patrones como códigos: entidad regex. Tipos comunes como fechas: entidad precompilada. Valores que varían según el contexto: entidad aprendida. Intenciones confundidas: expresiones más variadas y equilibradas.
  • Preguntas aclaratorias de seguimiento: prompts de varios turnos. Palabras equivalentes en todo el proyecto: sinónimos. Respuestas equivocadas a preguntas no relacionadas: sube el umbral de confianza y define una respuesta predeterminada. Filtrar por contexto: metadatos. Charla trivial: chit-chat. Requiere un recurso de Azure AI Search.
  • Una categoría por documento: single-label. Cualquier número: multi-label. Tus propios tipos de entidad en documentos largos: custom NER. Tipos estándar como personas y fechas: NER precompilado. Los datos de entrenamiento viven en un contenedor de Blob Storage conectado al recurso de Language. Clase débil: agrega etiquetas variadas y consistentes y vuelve a entrenar.
  • Problemas de vocabulario: datos de texto plano o una lista de frases. Problemas de ruido o acento: audio más transcripciones etiquetadas por personas. Mide con la WER sobre un conjunto reservado. La voz neuronal personalizada necesita aprobación de Limited Access y el consentimiento grabado del talento.

Identificar el idioma de un texto, devuelto como nombre, código ISO 639-1 y puntuación de confianza.

Una entrada opcional de la detección de idioma que ayuda a resolver textos ambiguos.

Ocultar o reemplazar los valores sensibles de un texto para que no queden expuestos.

Traducción de archivos completos en Blob Storage que conserva el formato, ejecutada como trabajo asíncrono por lotes o de forma sincrónica para archivos pequeños.

Un servicio para entrenar modelos de traducción con tus propios documentos paralelos, que se usan mediante un ID de categoría.

Una API REST asíncrona para transcribir grandes conjuntos de archivos de audio almacenados.
Diarization (diarización)
Etiquetar qué hablante dijo cada frase en una transcripción.

Una lista de palabras en tiempo de ejecución que refuerza su reconocimiento sin entrenamiento.
Neural voice (voz neuronal)

El elemento de SSML que ajusta la velocidad del habla, el tono y el volumen.

El elemento de SSML que controla cómo se leen valores como fechas, números y letras.
phoneme
El elemento de SSML que establece la pronunciación exacta con un alfabeto fonético como IPA.

La extensión de SSML de Microsoft que aplica un estilo de habla, como cheerful, en las voces que lo admiten.

La configuración del Speech SDK para traducir voz, con un idioma de reconocimiento de origen y uno o más idiomas de destino.

El reconocedor del Speech SDK que devuelve el texto de origen reconocido y un diccionario translations con claves por idioma.
Intent recognition (reconocimiento de intenciones)
Determinar el propósito de una expresión y extraer sus entidades, mediante coincidencia de patrones o un modelo CLU.
Keyword recognition (reconocimiento de palabras clave)
Detección en el dispositivo de una palabra de activación usando un modelo de palabra clave personalizado antes de que empiece el reconocimiento completo.

La clase del SDK que carga el archivo de modelo de palabra clave .table creado en Speech Studio.
Keyword verification (verificación de palabras clave)
Una comprobación opcional en la nube que confirma una palabra clave detectada para reducir las activaciones falsas.
Intent (intención)
El objetivo o la acción que un usuario expresa en una expresión, como BookFlight.
Entity (entidad)
Un dato de una expresión que la aplicación necesita, como una fecha o un destino.
Utterance (expresión)
Una frase de ejemplo que un usuario podría decir, usada para entrenar y probar el modelo.
None intent (intención None)
La intención integrada que captura las expresiones fuera del alcance de la aplicación.
List entity (entidad de lista)
Un componente de entidad que coincide exactamente con un conjunto fijo de valores y sus sinónimos.
Confusion matrix (matriz de confusión)
Una vista de evaluación que muestra qué intenciones o entidades confunde el modelo entre sí.
Project (proyecto)
Una base de conocimiento de respuesta a preguntas personalizada con pares de pregunta y respuesta construidos a partir de orígenes.
Follow-up prompt (prompt de seguimiento)
Un vínculo de una respuesta a pares relacionados que permite conversaciones de varios turnos.
Synonyms (sinónimos)
Alternativas de palabras a nivel de proyecto que se tratan como equivalentes al comparar preguntas.
Confidence threshold (umbral de confianza)
La puntuación mínima que necesita una respuesta para devolverse; por debajo de ella se usa la respuesta predeterminada.
Alternate questions (preguntas alternativas)
Formulaciones adicionales asociadas a un par específico de pregunta y respuesta.
Chit-chat (charla informal)
Un origen precompilado de pares de charla trivial con una personalidad elegida.
Single-label classification (clasificación de una sola etiqueta)
Clasificación de texto personalizada en la que cada documento recibe exactamente una clase.
Multi-label classification (clasificación multietiqueta)
Clasificación de texto personalizada en la que cada documento puede recibir cero o más clases.
Custom NER
Un modelo entrenado que extrae tus propios tipos de entidad de documentos no estructurados.
F1 score (puntuación F1)
La media armónica de la precisión y el recall, una medida única de la exactitud del modelo.
Precision (precisión)
La proporción de las predicciones del modelo que fueron correctas.
Recall
La proporción de instancias reales que encontró el modelo.
Custom speech (voz personalizada)
Un modelo de voz a texto adaptado con tus datos de texto y audio para lograr mayor exactitud en tu dominio.
Word error rate, WER (tasa de error de palabras)
Las sustituciones, eliminaciones e inserciones divididas entre el número de palabras de una transcripción de referencia.
Custom neural voice (voz neuronal personalizada)
Una función de Limited Access que entrena una voz sintética parecida a la de un talento de voz específico que dio su consentimiento.
Consent statement (declaración de consentimiento)
Una grabación en la que el talento de voz reconoce que su voz se usará para crear una voz sintética.
Custom endpoint (endpoint personalizado)
La implementación de un modelo de custom speech, a la que se hace referencia por su ID de endpoint en SpeechConfig.

Dominio 6: Implement knowledge mining and information extraction solutions (19%)

Consejos para el examen

  • Consultas lentas o disponibilidad: agrega réplicas. Índice más grande o indexación lenta: agrega particiones. Extraer datos de Azure con una programación: indexador. Planifica el nivel desde el principio: no se puede bajar de nivel y la subida en el mismo lugar se limita a servicios elegibles.
  • Relaciona la función de consulta con el atributo: $filter necesita filterable, $orderby necesita sortable, las facetas necesitan facetable, el texto completo necesita searchable y aparecer en los resultados necesita retrievable. El autocompletado necesita un suggester.
  • El texto escaneado necesita imageAction en generateNormalizedImages más la skill de OCR. Enriquecer más que unos pocos documentos requiere un recurso de Azure AI services adjunto. Los valores enriquecidos llegan al índice mediante asignaciones de campos de salida.
  • Tu propio modelo o tu propia búsqueda durante la indexación significa una skill personalizada Web API. El endpoint debe aceptar y devolver un arreglo values con recordId coincidentes y un objeto data.
  • Las consultas difusas, por proximidad, con realce, con regex y por campo necesitan queryType full. Los filtros son OData con operadores de palabras (eq, ge, and), no símbolos como == o &&.
  • Códigos exactos más significado: búsqueda híbrida. Mejor orden de los primeros resultados y respuestas extraídas: clasificación semántica con una configuración semántica y queryType semantic. Las consultas deben usar el mismo modelo de embeddings que los documentos.
  • Análisis en Power BI: proyecciones de tabla. JSON jerárquico para otros sistemas: proyecciones de objeto. Imágenes extraídas: proyecciones de archivo. Tablas relacionadas que deben unirse: el mismo grupo de proyección.
  • Solo texto: read. Tablas, casillas y estructura sin campos con nombre: layout. Campos con nombre de documentos comunes: el modelo precompilado correspondiente. 202 más Operation-Location significa que debes consultar hasta obtener el resultado.
  • Diseño fijo: template. Diseños variables de muchas fuentes: neural. Tipos de documento mezclados en un mismo flujo: clasificador personalizado. Un identificador de modelo para varios modelos personalizados: modelo compuesto.
  • Un solo servicio con un esquema de campos para documentos, imágenes, audio y video apunta a Content Understanding. El analizador contiene el esquema; extract, generate y classify son los métodos de campo.

Términos clave

Index (índice)
La colección buscable de documentos y su esquema de campos en Azure AI Search.
Data source (origen de datos)
Un objeto de conexión que le indica a un indexador dónde vive el contenido, como un contenedor de Blob Storage o una tabla de Azure SQL.
Indexer (indexador)
Un rastreador que lee un origen de datos, abre los documentos, asigna campos, ejecuta skillsets y carga el índice, a pedido o con una programación.
Skillset
Un conjunto opcional de pasos de enriquecimiento con IA, como OCR o reconocimiento de entidades, que ejecuta un indexador durante la indexación.
Push API (API de inserción)
El método para enviar documentos JSON directamente a un índice desde tu propio código en lugar de usar un indexador.
Replica (réplica)
Una copia del índice que atiende consultas, que se agrega para obtener rendimiento y disponibilidad.
Partition (partición)
Una unidad de capacidad de almacenamiento e indexación, que se agrega para índices más grandes e indexación más rápida.
Search unit (unidad de búsqueda)
La unidad de facturación de Azure AI Search, igual a réplicas multiplicadas por particiones.
Key field (campo clave)
El único campo Edm.String que identifica de forma única cada documento de un índice.
Searchable
Un atributo que analiza el texto de un campo y lo incluye en la búsqueda de texto completo.
Filterable
Un atributo que permite usar un campo en expresiones $filter.
Sortable
Un atributo que permite usar un campo en $orderby.
Facetable
Un atributo de campo que habilita conteos de documentos por valor para la navegación por facetas.
Retrievable
Un atributo que permite devolver un campo en los resultados de búsqueda.
Analyzer (analizador)
Un componente que divide en tokens y normaliza el texto para la búsqueda de texto completo, como un analizador de idioma.
Suggester
Una definición del índice que habilita el autocompletado y las sugerencias mientras se escribe en los campos elegidos.
Document cracking
El paso del indexador que abre los archivos y extrae texto, metadatos y, si se configura, imágenes.
imageAction
La configuración del indexador que controla la extracción de imágenes; generateNormalizedImages produce imágenes para OCR y análisis de imágenes.
Enrichment tree (árbol de enriquecimiento)
La estructura en memoria que contiene los datos originales y enriquecidos de un documento mientras se ejecutan las skills.
Skill context (contexto de la skill)
El nivel en el que se ejecuta una skill, como una vez por documento o una vez por imagen.
Output field mapping (asignación de campos de salida)
Una asignación que copia los valores enriquecidos del árbol de enriquecimiento a los campos del índice.
Incremental enrichment (enriquecimiento incremental)
Guardar en caché la salida enriquecida para que solo se vuelvan a ejecutar las skills afectadas por un cambio.
Custom skill (skill personalizada)
Una skill que llama a tu propio código, como una Azure Function, durante el enriquecimiento con IA.
WebApiSkill
El tipo de skill que llama a un endpoint HTTPS externo con una interfaz JSON definida.
recordId
El identificador que vincula cada registro de entrada con su salida en la interfaz de la skill personalizada.
values array (arreglo values)
El arreglo de nivel superior de registros que se envía a una skill personalizada y que esta devuelve.
Batch size (tamaño de lote)
El número de registros que el servicio de búsqueda envía a la skill personalizada en cada solicitud.
AML skill (skill AML)
Una variante de skill personalizada que llama a un modelo implementado en Azure Machine Learning o en el catálogo de modelos de Foundry.
queryType
El analizador de consultas: simple (predeterminado), full (Lucene) o semantic.
searchMode
Si debe coincidir cualquier término (predeterminado) o todos los términos del texto de búsqueda.
$filter
Una expresión OData que restringe los resultados según los valores de campos filterable sin afectar la puntuación.
Fuzzy search (búsqueda difusa)
Una consulta Lucene completa que coincide con términos con pequeñas diferencias de ortografía, escrita con ~.
Proximity search (búsqueda por proximidad)
Una consulta Lucene completa que coincide con palabras a una distancia definida entre sí, como "hotel airport"~5.
Facets (facetas)
Conteos de documentos coincidentes por valor o rango de un campo, usados para la navegación por facetas.
Security trimming (recorte de seguridad)
Usar un filtro sobre un campo de identificadores de grupo permitidos para que los usuarios vean solo los documentos que tienen permitido ver.
BM25
La fórmula de relevancia por palabras clave, basada en la frecuencia y rareza de los términos, que usa la búsqueda de texto completo.
Vector search (búsqueda vectorial)
Encontrar los documentos cuyos vectores de embedding están más cerca del vector de la consulta.
HNSW
Hierarchical Navigable Small World, un algoritmo aproximado de vecinos más cercanos que es rápido a gran escala.
Exhaustive KNN (KNN exhaustivo)
Búsqueda exacta de k vecinos más cercanos que compara la consulta con cada vector.
Vectorizer (vectorizador)
Una configuración de un campo vectorial que convierte el texto de la consulta en un vector llamando a un modelo de embeddings.
Hybrid search (búsqueda híbrida)
Combinar consultas por palabras clave y vectoriales en una solicitud, fusionadas con Reciprocal Rank Fusion.
Reciprocal Rank Fusion
Un método que fusiona listas clasificadas puntuando los documentos según sus posiciones en cada lista.
Semantic ranker (clasificador semántico)
Un modelo de segunda etapa que reclasifica los mejores resultados por significado y puede devolver subtítulos y respuestas.
Knowledge store
La salida en Azure Storage de los datos enriquecidos de un skillset, guardada para usos más allá de la búsqueda.
Projection (proyección)
Una definición de qué datos enriquecidos guardar en el knowledge store y con qué forma.
Table projection (proyección de tabla)
Una proyección que escribe los datos enriquecidos como filas en Azure Table Storage.
Object projection (proyección de objeto)
Una proyección que escribe los datos enriquecidos como documentos JSON en Blob Storage.
File projection (proyección de archivo)
Una proyección que escribe archivos binarios, como imágenes normalizadas, en Blob Storage.
Shaper skill
Una skill de utilidad que construye una forma de datos personalizada a partir del árbol de enriquecimiento para su proyección.
Projection group (grupo de proyección)
Un conjunto de proyecciones que comparten claves generadas para que las salidas relacionadas se puedan unir.
Read model (modelo read)
El modelo de Document Intelligence que extrae líneas y palabras de texto impreso y manuscrito de los documentos.
Layout model (modelo layout)
El modelo que extrae texto más estructura: párrafos, tablas, marcas de selección y figuras, con salida opcional en markdown.
Prebuilt model (modelo precompilado)
Un modelo listo para usar que extrae campos con nombre de un tipo de documento común, como facturas o recibos.
Selection mark (marca de selección)
Una casilla de verificación o botón de opción que detecta el modelo layout, con su estado marcado o no marcado.
Operation-Location
El encabezado de respuesta que se devuelve con 202 Accepted y que contiene la URL que se consulta para obtener los resultados del análisis.
Confidence score (puntuación de confianza)
Un valor de 0 a 1 que indica qué tan seguro está el modelo sobre un campo extraído.
Custom template model (modelo personalizado template)
Un modelo de extracción personalizado para documentos con un diseño coherente y fijo.
Custom neural model (modelo personalizado neural)
Un modelo de extracción personalizado de aprendizaje profundo que maneja documentos con diseños variables.
Labeling (etiquetado)
Marcar la ubicación de cada campo en documentos de muestra en Document Intelligence Studio para entrenar un modelo personalizado.
Custom classifier (clasificador personalizado)
Un modelo que identifica los tipos de documento, y divide los archivos combinados, antes de la extracción.
Composed model (modelo compuesto)
Varios modelos personalizados agrupados bajo un ID de modelo que enruta cada documento al que mejor coincide.
Model ID (identificador de modelo)
El identificador que se usa para llamar a un modelo entrenado o precompilado en la operación analyze.
Content Understanding
Un servicio de Azure AI que extrae salida estructurada y definida por un esquema a partir de documentos, imágenes, audio y video.
Field schema (esquema de campos)
La lista de campos con nombre, tipo y descripción que debe devolver un analizador.
Extract field (campo extract)
Un campo del esquema cuyo valor aparece en el contenido, como un número de factura.
Generate field (campo generate)
Un campo del esquema cuyo valor produce el modelo a partir del contenido, como un resumen.
Classify field (campo classify)
Un campo del esquema cuyo valor se elige de una lista fija de categorías.
Grounding (fundamentación)
Información de la salida que muestra de qué parte del contenido salió el valor de un campo.
