Dominio 1: Setting up a cloud solution environment (23%)

Consejos para el examen

  • Las políticas de permiso de IAM son aditivas y no se pueden revocar más abajo en el árbol. Si una pregunta dice que un usuario todavía tiene acceso después de que eliminaste un permiso a nivel de proyecto, busca un permiso en una carpeta o en la organización por encima.
  • Si una pregunta dice que el equipo quiere cambiar un ID de proyecto, la respuesta es que no se puede; solo el nombre visible puede cambiar. Un error de 'API no habilitada' se resuelve habilitando la API, no otorgando más roles de IAM.
  • Lee bien el requisito: 'nadie, incluidos los propietarios' apunta a una política de la organización; 'solo este grupo puede' apunta a IAM. La creación de claves de cuentas de servicio, las IPs externas y las regiones permitidas son preguntas clásicas de políticas de la organización.
  • Usuarios existentes de AD más 'sin volver a crearlos' significa Google Cloud Directory Sync (a menudo con SAML SSO). IAM no crea usuarios, y las cuentas de servicio son para cargas de trabajo, no para empleados.
  • Elige el nivel más bajo que cumpla el requisito, otorga a un grupo y usa un rol predefinido antes que un rol básico. Si la pregunta menciona 'todos los proyectos del departamento', la respuesta esperada suele ser un permiso a nivel de carpeta.
  • 'Vincular proyectos, pero no cambiar la cuenta de facturación' es Billing Account User. 'Solo ver costos' es Billing Account Viewer. 'Administrarlo todo' es Billing Account Administrator.
  • Si una pregunta espera que el gasto se detenga automáticamente, un presupuesto por sí solo es incorrecto; necesita notificaciones de Pub/Sub y código. Para analizar costos con SQL, la respuesta es la exportación de facturación a BigQuery, no los registros de auditoría.
  • Conoce la sintaxis exacta: gcloud config set compute/zone ZONE, gcloud config set project ID y gcloud config configurations activate NAME. Las respuestas distractoras a menudo inventan comandos como gcloud compute zones set.
  • 'No se puede instalar software localmente' o 'la forma más rápida de ejecutar gcloud y kubectl' apunta a Cloud Shell. Recuerda que solo persiste el directorio home.
  • Los errores de cuota se resuelven solicitando un aumento para la métrica y la región indicadas (o desplegando en otro lugar). Volver a habilitar APIs, cambiar IAM o mover carpetas no cambia las cuotas.
  • Falla de una zona significa repartir entre zonas de una región; falla de una región significa usar otra región. Para el costo por aplicación, elige labels, no etiquetas de red.

Términos clave

Organization node (nodo de organización)
La raíz de la jerarquía, vinculada a un dominio de Cloud Identity o Google Workspace.
Folder (carpeta)
Una agrupación de proyectos y otras carpetas que te permite aplicar IAM y políticas de la organización a todos ellos.
Project (proyecto)
El contenedor al que pertenece cada recurso, con sus propias APIs, cuotas, política de IAM y vínculo de facturación.
Policy inheritance (herencia de políticas)
Las políticas de IAM y de la organización definidas en un nodo se aplican a cada carpeta, proyecto y recurso que está debajo.
IAM deny policy (política de denegación de IAM)
Una política que bloquea permisos específicos para las principales elegidas y que se evalúa antes que las políticas de permiso.
Organization policy (política de la organización)
Una regla basada en una restricción (constraint) que limita cómo se pueden configurar los recursos, sin importar los roles de IAM.
Project ID (ID del proyecto)
El identificador permanente y único a nivel global que eliges al crear el proyecto y que usas en comandos y APIs.
Project number (número del proyecto)
Un identificador numérico permanente que asigna Google y que se usa en algunos nombres de cuentas de servicio.
Project name (nombre del proyecto)
Una etiqueta visible que se puede cambiar y que no necesita ser única.
Service agent (agente de servicio)
Una cuenta de servicio administrada por Google que un servicio de Google Cloud usa para actuar sobre los recursos de tu proyecto.
Project Creator
El rol de IAM, otorgado en una organización o carpeta, que permite crear proyectos allí.
gcloud services enable
El comando que activa una API, como run.googleapis.com, en el proyecto actual.
Constraint (restricción)
La definición de un límite al comportamiento de un servicio de Google Cloud, como las ubicaciones permitidas.
List constraint (restricción de lista)
Una restricción que permite o deniega un conjunto de valores, como las regiones permitidas.
Boolean constraint (restricción booleana)
Una restricción que se aplica o no se aplica, como deshabilitar la creación de claves de cuentas de servicio.
Organization Policy Administrator
El rol que permite a alguien definir políticas de la organización; se otorga a nivel de organización.
Resource locations constraint (restricción de ubicaciones de recursos)
gcp.resourceLocations, que limita dónde se pueden crear los recursos basados en ubicación.
Domain restricted sharing (uso compartido restringido por dominio)
Una restricción que permite otorgar permisos de IAM solo a identidades de los clientes de Cloud Identity o Workspace indicados.
Cloud Identity
El producto de identidad como servicio de Google para administrar usuarios, grupos y dispositivos de un dominio, disponible en una edición gratuita.
Google Cloud Directory Sync
Una herramienta que sincroniza en un solo sentido usuarios y grupos desde Active Directory o LDAP hacia Cloud Identity o Google Workspace.
SAML single sign-on (inicio de sesión único con SAML)
Federación que permite a los usuarios iniciar sesión en Google con las credenciales de su proveedor de identidad existente.
Google group (grupo de Google)
Una colección de identidades con su propia dirección de correo a la que se le pueden otorgar roles de IAM.
Super administrator (superadministrador)
El administrador más poderoso de Cloud Identity o Workspace, capaz de administrar a todos los usuarios y otorgar cualquier rol; ten pocos y protégelos.
Workload Identity Federation
Una forma de que las cargas de trabajo externas accedan a Google Cloud usando los tokens de su propio proveedor de identidad en lugar de claves de cuentas de servicio.
Principal
Una identidad a la que se le puede otorgar acceso: un usuario, un grupo, una cuenta de servicio, un dominio o un identificador especial.
Role binding (vinculación de rol)
La asociación de un rol con una o más principales en una política de permiso.
Allow policy (política de permiso)
El conjunto de vinculaciones de roles adjuntas a un recurso, también llamado política de IAM.
add-iam-policy-binding
El subcomando de gcloud que agrega una vinculación de miembro y rol a la política de un recurso.
Predefined role (rol predefinido)
Un rol diseñado por Google para un trabajo específico, preferible a los roles básicos amplios.
IAM condition (condición de IAM)
Una expresión adjunta a una vinculación que limita cuándo se aplica, como una hora de vencimiento o un prefijo del nombre del recurso.
Cloud Billing account (cuenta de Cloud Billing)
La cuenta que paga el uso de los proyectos vinculados a ella.
Billing Account User
Un rol que permite vincular proyectos a una cuenta de facturación sin administrarla.
Billing Account Administrator
Un rol que administra la configuración de pagos, los usuarios y los vínculos de una cuenta de facturación.
Billing Account Viewer
Un rol que puede ver los costos y las transacciones de una cuenta de facturación sin cambiar nada.
Billing Account Costs Manager
Un rol que puede administrar presupuestos y ver y exportar información de costos sin administrar los pagos.
Project Billing Manager
Un rol a nivel de proyecto que permite conectar o desconectar la facturación del proyecto.
Budget (presupuesto)
Un monto y un conjunto de reglas de umbral que activan alertas a medida que crece el gasto real o previsto.
Threshold rule (regla de umbral)
Un porcentaje del presupuesto que envía una notificación cuando se cruza.
Forecasted spend (gasto previsto)
La estimación de Google de cuál será el total del mes, sobre la cual los presupuestos pueden alertar.
Billing export (exportación de facturación)
Un flujo continuo de datos detallados de Cloud Billing hacia un conjunto de datos de BigQuery.
Detailed usage cost data (datos detallados de costo de uso)
El tipo de exportación de facturación que agrega detalle a nivel de recurso, como instancias de VM individuales.
Budget Pub/Sub notification (notificación de presupuesto en Pub/Sub)
Un mensaje publicado en un tema con el gasto actual, que se usa para activar respuestas automatizadas.
gcloud init
Un comando interactivo que autoriza una cuenta y prepara una configuración con valores predeterminados.
Named configuration (configuración con nombre)
Un conjunto guardado de propiedades de gcloud, como la cuenta, el proyecto, la región y la zona, entre los que puedes alternar.
Application Default Credentials (credenciales predeterminadas de la aplicación)
Credenciales que las bibliotecas cliente encuentran automáticamente; se definen localmente con gcloud auth application-default login.
gcloud config set
El comando para definir una propiedad, como compute/zone, en la configuración activa.
gcloud auth list
El comando que muestra las cuentas con credenciales y cuál está activa.
gcloud components update
El comando que actualiza la CLI y sus componentes en las instalaciones que no administra un administrador de paquetes.
Cloud Shell
Una terminal gratuita y ya autenticada en el navegador, sobre una VM temporal con herramientas de Google Cloud preinstaladas.
Cloud Shell Editor
Un editor de código basado en el navegador, construido sobre Code OSS, que trabaja con el directorio home de Cloud Shell.
Persistent home directory (directorio home persistente)
El almacenamiento de Cloud Shell que sobrevive entre sesiones, a diferencia del resto de la VM.
Web preview (vista previa web)
Una función de Cloud Shell que abre un servidor web que se ejecuta en la sesión, en el puerto que elijas.
Equivalent code link (enlace Equivalent code)
Una opción de la consola que muestra el comando de gcloud o la solicitud REST de lo que configuraste en un formulario.
Cloud Workstations
Entornos de desarrollo administrados y de pago para trabajos de desarrollo más pesados o de larga duración.
Allocation quota (cuota de asignación)
Un límite sobre cuánto de un recurso puede tener un proyecto, como las CPUs regionales.
Rate quota (cuota de tasa)
Un límite sobre cuántas solicitudes a una API se pueden hacer en un período de tiempo.
System limit (límite del sistema)
Un máximo fijo que no se puede aumentar mediante una solicitud.
Quota increase request (solicitud de aumento de cuota)
Una solicitud hecha desde la página Quotas para aumentar un límite, que a veces se aprueba automáticamente.
RESOURCE_EXHAUSTED
El estado de error, a menudo con HTTP 429, que se devuelve cuando se supera una cuota de tasa.
Quota Administrator
Un rol que incluye el permiso para ver y cambiar cuotas, incluido el envío de solicitudes de aumento.
Region (región)
Un área geográfica independiente, como us-central1, formada por zonas.
Zone (zona)
Un área de despliegue aislada dentro de una región, como us-central1-a.
Label (etiqueta)
Un par clave-valor en un recurso que se usa para organizar, filtrar e informar costos.
Network tag (etiqueta de red)
Una cadena en una VM que se usa para aplicarle reglas de firewall y rutas.
Regional persistent disk (disco persistente regional)
Un disco que se replica de forma síncrona en dos zonas de una región para lograr mayor disponibilidad.
Resource manager tag (etiqueta de Resource Manager)
Un par clave-valor definido de forma centralizada que se asigna a los recursos y se usa en condiciones de IAM y de políticas de la organización.

Dominio 2: Planning and implementing a cloud solution (30%)

Consejos para el examen

  • Las palabras clave deciden: 'kernel', 'control del OS' o 'licencia' significan Compute Engine; 'Kubernetes' o 'Helm' significan GKE; 'contenedor sin estado, escalar a cero, sin infraestructura' significa Cloud Run; 'ejecutar código cuando se sube un archivo' significa Cloud Run functions; 'dividir el tráfico entre versiones de una aplicación web existente' suele significar App Engine.
  • 'Se puede interrumpir' más 'menor costo' significa Spot VMs. 'Necesita una proporción inusual de CPU a memoria' significa un tipo de máquina personalizado. 'Arrancar siempre desde el OS más reciente con parches' significa una familia de imágenes. Las Spot VMs no son adecuadas para bases de datos.
  • Sobrevivir a una falla de zona sin perder escrituras: disco regional. Almacenamiento temporal más rápido y la pérdida de datos es aceptable: local SSD. Almacenamiento en bloques masivo más barato: persistent disk standard. Separar el rendimiento de la capacidad: Hyperdisk.
  • No puedes editar una plantilla: plantilla nueva y luego actualización progresiva. La autorreparación necesita una verificación de estado. Los grupos no administrados no escalan automáticamente. Resistencia ante fallas de zona significa un MIG regional. maxUnavailable 0 mantiene la capacidad durante las actualizaciones.
  • 'No administrar nodos' significa Autopilot. 'El plano de control debe sobrevivir a una caída de zona' significa un clúster regional. 'Distintos tipos de máquina en un clúster' significa grupos de nodos. En los clústeres Standard regionales, --num-nodes es por zona.
  • Solo interno: ClusterIP. Una IP externa para un servicio: LoadBalancer. Enrutamiento por URL hacia varios servicios: Ingress. No olvides get-credentials antes de que kubectl funcione. Identidad y disco estables por pod: StatefulSet. Un pod por nodo: DaemonSet.
  • 'Ejecutar código cuando un archivo llega a un bucket' es una función activada por eventos mediante Eventarc. 'Solo ciertos servicios pueden llamarlo' significa exigir autenticación y otorgar Cloud Run Invoker a esas identidades. 'Se ejecuta hasta terminar según una programación' significa un trabajo de Cloud Run con Cloud Scheduler.
  • Relacional y regional: Cloud SQL. PostgreSQL de alto rendimiento: AlloyDB. Relacional y escala global: Spanner. Series temporales o IoT a escala enorme: Bigtable. Documentos para móvil o web: Firestore. Análisis con SQL: BigQuery. Caché: Memorystore.
  • Relaciona la frecuencia de acceso con la clase: mensual es Nearline, trimestral es Coldline, anual o menos es Archive. Recuerda los mínimos de 30, 90 y 365 días, que todas las clases leen en milisegundos y que la ubicación de un bucket no se puede cambiar después.
  • Un equipo central administra la red de muchos proyectos: Shared VPC. Conectar dos VPCs administradas por separado: peering. El peering no es transitivo y los rangos no pueden superponerse. Ganan los números de prioridad más bajos. Las reglas implícitas deniegan la entrada y permiten la salida.
  • HTTP(S) más global más enrutamiento por URL o CDN: Application Load Balancer externo global. UDP o conservar la IP del cliente: Network Load Balancer de paso. VMs privadas que necesitan salir a internet: Cloud NAT. Rápido de configurar por internet: HA VPN. Privado y de gran ancho de banda: Interconnect.
  • 'Ver una vista previa de los cambios antes de aplicarlos', 'con control de versiones', 'repetible' y 'módulos reutilizables' apuntan a Terraform. 'Terraform administrado con el estado gestionado por ti' apunta a Infrastructure Manager. 'Desplegar rápidamente un producto común de terceros' apunta a Cloud Marketplace. El estado compartido va en un bucket de Cloud Storage con el backend gcs.

Términos clave

Compute Engine
Las máquinas virtuales de infraestructura como servicio (IaaS) de Google Cloud, en las que tú administras el sistema operativo.
GKE
Google Kubernetes Engine, un servicio de Kubernetes administrado para ejecutar contenedores, en modo Autopilot o Standard.
Cloud Run
Una plataforma sin servidor que ejecuta contenedores sin estado y escala automáticamente, incluso a cero.
Cloud Run functions
Funciones activadas por eventos o por HTTP que se despliegan como código fuente; antes se llamaba Cloud Functions.
App Engine
La plataforma como servicio (PaaS) original de Google para aplicaciones web, con entornos estándar y flexible y una aplicación por proyecto.
Machine family (familia de máquinas)
Un grupo de tipos de máquina optimizados para una clase de carga de trabajo, como uso general, optimizada para cómputo, optimizada para memoria u optimizada para aceleradores.
Custom machine type (tipo de máquina personalizado)
Una forma de VM en la que eliges el número de vCPUs y la cantidad de memoria, dentro de la proporción permitida por la familia.
Image family (familia de imágenes)
Un nombre que siempre se resuelve en la imagen más reciente no obsoleta de una serie, como debian-12.
Spot VM
Una VM con descuento que Google puede interrumpir en cualquier momento, con unos 30 segundos de aviso, cuando necesita la capacidad.
Preemptible VM (VM interrumpible)
La forma anterior de VM con descuento e interrumpible, limitada a 24 horas de ejecución.
Persistent Disk
Almacenamiento en bloques duradero y conectado por red para VMs, en los tipos standard, balanced, SSD y extreme.
Hyperdisk
Almacenamiento en bloques por red en el que la capacidad y el rendimiento (IOPS y throughput) se aprovisionan por separado, según el tipo.
Regional persistent disk (persistent disk regional)
Un disco replicado de forma síncrona entre dos zonas de una región que se puede conectar a la fuerza (force-attach) en la zona que sobrevive.
Local SSD
Almacenamiento de alto rendimiento conectado físicamente al host, cuyos datos no persisten cuando la VM se detiene o se elimina.
Snapshot
Una copia de seguridad incremental de un disco en un punto en el tiempo, que se puede usar para crear discos nuevos.
Instance template (plantilla de instancia)
Una definición inmutable de las propiedades de una VM que se usa para crear VMs en un grupo de instancias administrado.
Managed instance group (grupo de instancias administrado)
Un grupo de VMs idénticas creadas a partir de una plantilla que admite escalado automático, autorreparación y actualizaciones progresivas.
Regional MIG (MIG regional)
Un grupo de instancias administrado que distribuye sus VMs en varias zonas de una región para mayor disponibilidad.
Autohealing (autorreparación)
Recrear las VMs que fallan repetidamente una verificación de estado de la aplicación.
Rolling update (actualización progresiva)
Reemplazar gradualmente las VMs de un grupo por otras creadas con una plantilla nueva, según maxSurge y maxUnavailable.
Autopilot
Un modo de GKE en el que Google administra los nodos y la facturación se basa principalmente en las solicitudes de recursos de los pods.
Standard cluster (clúster Standard)
Un modo de GKE en el que tú configuras, administras y pagas los grupos de nodos.
Regional cluster (clúster regional)
Un clúster con réplicas del plano de control y nodos distribuidos en varias zonas de una región.
Node pool (grupo de nodos)
Un conjunto de nodos de un clúster que comparten la misma configuración, como el tipo de máquina.
Taint and toleration (taint y toleration)
Una marca en un nodo que rechaza pods, y un ajuste del pod que le permite programarse en esos nodos.
Deployment
Un objeto de Kubernetes que mantiene en funcionamiento una cantidad fija de réplicas idénticas de un pod y gestiona las actualizaciones progresivas.
Service
Una IP y un nombre DNS estables que balancean el tráfico hacia un conjunto de pods seleccionados por etiquetas.
LoadBalancer Service (Service de tipo LoadBalancer)
Un tipo de Service que aprovisiona un Network Load Balancer de paso (passthrough) de Google Cloud con una IP externa o interna.
Ingress
Un objeto de Kubernetes que enruta el tráfico HTTP(S) por host y ruta; en GKE crea un Application Load Balancer.
kubeconfig
El archivo local que guarda los endpoints y las credenciales de los clústeres que usa kubectl, y que actualiza get-credentials.
Revision (revisión)
Una instantánea inmutable de la imagen y la configuración de un servicio de Cloud Run que se crea en cada despliegue.
Concurrency (concurrencia)
El número máximo de solicitudes que una instancia de Cloud Run atiende al mismo tiempo.
Eventarc
Un servicio que enruta eventos de fuentes de Google Cloud hacia servicios y funciones de Cloud Run.
Pub/Sub
Un servicio de mensajería administrado en el que los publicadores envían mensajes a temas y los suscriptores los reciben mediante suscripciones pull o push.
Cloud Run Invoker
El rol de IAM (roles/run.invoker) que permite a una entidad principal llamar a un servicio de Cloud Run.
Cloud SQL
MySQL, PostgreSQL y SQL Server administrados para cargas de trabajo relacionales regionales.
AlloyDB for PostgreSQL
Una base de datos administrada y compatible con PostgreSQL para cargas transaccionales de alto rendimiento y cargas mixtas con análisis.
Spanner
Una base de datos relacional con escalado horizontal y consistencia fuerte que puede abarcar varias regiones.
Firestore
Una base de datos NoSQL de documentos sin servidor, con listeners en tiempo real y soporte sin conexión para aplicaciones móviles y web.
Bigtable
Una base de datos NoSQL de columnas anchas para cargas masivas de baja latencia basadas en claves, como series temporales.
BigQuery
Un almacén de datos sin servidor para análisis con SQL a muy gran escala.
Storage class (clase de almacenamiento)
El ajuste Standard, Nearline, Coldline o Archive que determina el precio de almacenamiento, el costo de acceso y la duración mínima.
Bucket location (ubicación del bucket)
La región, birregión o multirregión donde se guardan los datos de un bucket, elegida al crearlo y que no se puede cambiar.
Lifecycle rule (regla de ciclo de vida)
Una acción automática, como cambiar de clase o eliminar, que se aplica cuando un objeto cumple ciertas condiciones.
Object Versioning
Un ajuste del bucket que conserva versiones no actuales de los objetos sobrescritos o eliminados.
Retention policy (política de retención)
Un tiempo mínimo que los objetos deben conservarse antes de poder eliminarse o reemplazarse, que se puede bloquear con Bucket Lock.
Custom mode VPC (VPC en modo personalizado)
Una VPC en la que tú creas las subredes y eliges sus rangos, recomendada para producción.
Firewall rule priority (prioridad de regla de firewall)
Un número de 0 a 65 535 en el que se aplica la regla coincidente con el número más bajo.
Implied firewall rules (reglas de firewall implícitas)
Las reglas integradas de menor prioridad de toda VPC, que deniegan toda la entrada y permiten toda la salida.
Shared VPC
Un modelo en el que los proyectos de servicio usan subredes de la VPC de un proyecto host administrado de forma central.
VPC Network Peering
Una conexión privada y no transitiva entre dos redes VPC que intercambia rutas de subred.
Application Load Balancer
Un balanceador de carga proxy de capa 7 para HTTP(S) con enrutamiento basado en URL, disponible como global o regional, externo o interno.
Passthrough Network Load Balancer (Network Load Balancer de paso)
Un balanceador de carga de capa 4 que reenvía los paquetes y conserva las direcciones IP de los clientes.
Cloud NAT
Traducción de direcciones de red administrada que da a los recursos privados acceso saliente a internet, configurada en un Cloud Router.
HA VPN
VPN IPsec de alta disponibilidad hacia Google Cloud que usa dos interfaces y BGP mediante Cloud Router.
Cloud Interconnect
Conectividad privada de gran ancho de banda hacia una VPC, ya sea Dedicated (enlace físico directo) o Partner (a través de un proveedor de servicios).
Infrastructure as code (infraestructura como código)
Administrar la infraestructura mediante archivos de configuración declarativos y versionados en lugar de cambios manuales.
terraform plan
Muestra los cambios que haría Terraform, comparados con el estado, sin aplicarlos.
Terraform state (estado de Terraform)
Un archivo que registra qué recursos reales corresponden a cada bloque de la configuración.
gcs backend (backend gcs)
El backend de Terraform que guarda el estado compartido en un bucket de Cloud Storage, con bloqueo durante las ejecuciones.
Module (módulo)
Un paquete reutilizable de configuración de Terraform, como una VPC estándar o una fábrica de proyectos.
Infrastructure Manager
Un servicio administrado de Google Cloud que ejecuta despliegues de Terraform y guarda su estado.
Cloud Marketplace
Un catálogo de soluciones listas para desplegar de Google y sus socios, algunas facturadas a través de Cloud Billing.

Dominio 3: Ensuring successful operation of a cloud solution (27%)

Consejos para el examen

  • Sin IP externa y sin bastión: reenvío TCP de IAP con una regla de firewall para 35.235.240.0/20 y el rol IAP-secured Tunnel User. Acceso vinculado a IAM y retirado automáticamente: OS Login. Cambiar el tipo de máquina requiere detener la VM. Los discos crecen en ejecución y nunca se reducen.
  • Copia de seguridad de un disco: snapshot. Copias automáticas sin scripts: programación de snapshots. Plantilla para muchas VMs idénticas: imagen personalizada en una familia de imágenes. VM completa con su configuración: machine image. Mover un disco entre regiones: snapshot y luego disco nuevo.
  • Más pods: kubectl scale o HPA. Más nodos: cluster autoscaler o redimensionar el grupo de nodos. Versión defectuosa: kubectl rollout undo. Velocidad de las versiones: canal de versiones. Momento de las actualizaciones: períodos y exclusiones de mantenimiento. No escales automáticamente de forma directa los grupos de instancias subyacentes de GKE.
  • Un lanzamiento gradual en Cloud Run es dividir el tráfico entre revisiones del mismo servicio, a menudo con --no-traffic y una etiqueta primero. Revertir es un cambio de tráfico. La primera solicitud lenta se resuelve con un mínimo de instancias; proteger una base de datos se hace con un máximo de instancias.
  • De otra nube a Cloud Storage, programado y administrado: Storage Transfer Service. Cientos de terabytes por un enlace lento: Transfer Appliance. Hacia BigQuery desde SaaS: BigQuery Data Transfer Service. Sincronizar una carpeta local: gcloud storage rsync.
  • Conmutación automática ante fallo de zona: HA. Descargar lecturas: réplica de lectura. Pérdida de una región: promover una réplica entre regiones. Deshacer un cambio equivocado: recuperación a un momento dado. Estimar el costo en BigQuery: dry run. Limitar el costo: máximo de bytes facturados o cuotas personalizadas. LIMIT no reduce los bytes escaneados.
  • Las subredes crecen, nunca se reducen, y no deben superponerse. Un /24 ofrece 252 direcciones utilizables. Una IP pública que cambia se resuelve reservando o promoviendo una dirección estática. Nombres solo internos: zona DNS privada. Zona pública: actualiza los servidores de nombres en el registrador.
  • Las métricas de memoria y de espacio en disco necesitan el Ops Agent. 'Avisar cuando una métrica cruza un umbral' es una política de alertas. '¿Se puede acceder a mi sitio web desde todo el mundo?' es una verificación de tiempo de actividad. 'Un solo lugar para muchos proyectos' es un metrics scope. 'Presupuesto de errores' apunta a SLO y alertas de tasa de consumo.
  • Contar o graficar algo que aparece en los logs: métrica basada en logs. Enviar logs a otro lugar: sink (y otorga acceso a su identidad de escritura). Todos los proyectos de la organización: sink agregado con include-children. Archivo barato a largo plazo: Cloud Storage. Análisis con SQL: BigQuery. Transmisión a un SIEM: Pub/Sub. Descartar ruido: filtro de exclusión.
  • Quién cambió o eliminó algo: Admin Activity (siempre activo, gratuito). Acciones propias de Google: System Event. Quién leyó datos: Data Access, que debe activarse primero (excepto en BigQuery). Bloqueado por VPC Service Controls: Policy Denied. Ver los registros Data Access requiere Private Logs Viewer.
  • Excepciones agrupadas y '¿este error es nuevo?': Error Reporting. Solicitudes lentas entre servicios: Cloud Trace. Puntos críticos de CPU o memoria a nivel de código: Cloud Profiler.

Dominio 4: Configuring access and security (20%)

Consejos para el examen

  • Prefiere los roles predefinidos; usa roles personalizados solo cuando ningún predefinido encaje; evita los roles básicos. Los roles personalizados no se pueden crear en carpetas y Google no los actualiza automáticamente.
  • Para un solo cambio, usa add- o remove-iam-policy-binding. set-iam-policy lo sobrescribe todo. El acceso temporal es una IAM Condition sobre request.time. Bloquear un acceso heredado es una política de denegación.
  • Las cargas de trabajo deben usar cuentas de servicio dedicadas y adjuntas, no claves ni la cuenta predeterminada con Editor. Un error de permisos al adjuntar una cuenta de servicio significa que el usuario no tiene Service Account User sobre ella.
  • 'Sin crear una clave' más 'actuar como una cuenta de servicio' significa Token Creator y suplantación. Una clave filtrada debe deshabilitarse o eliminarse; borrar el commit no es suficiente.
  • Pods que necesitan su propia identidad de Google: Workload Identity Federation for GKE. CI/CD u otras nubes sin claves: Workload Identity Federation con un pool y un proveedor. Las claves guardadas en secretos son la respuesta incorrecta.
  • Acceso basado en identidad a una aplicación web interna sin VPN: IAP. SSH sin IP externas: reenvío TCP de IAP con acceso en el firewall desde 35.235.240.0/20. Acceso SSH controlado por IAM: OS Login, con Admin Login para sudo.
  • 'Controlar la rotación y poder deshabilitar la clave, pero que Google haga el cifrado' es CMEK. 'Google nunca debe almacenar la clave' es CSEK. Si no se requiere nada, es el cifrado predeterminado.
  • Las contraseñas y las claves de API van en Secret Manager, con Secret Accessor otorgado a la cuenta de servicio de la carga de trabajo sobre el secreto específico. Cloud KMS es para claves de cifrado, no para guardar contraseñas de aplicaciones.
  • Solo IAM, sin ACLs: acceso uniforme a nivel de bucket. Nunca público, ni siquiera por error: aplica la prevención del acceso público (política de la organización para todo). Acceso temporal para alguien sin cuenta: signed URL, máximo 7 días con V4.
  • 'Por qué se le deniega el acceso a este usuario' es Policy Troubleshooter. 'Quién puede acceder a este recurso' es Policy Analyzer. 'Qué roles no se usan' es el IAM recommender. 'El auditor puede ver pero no cambiar' es Security Reviewer.
