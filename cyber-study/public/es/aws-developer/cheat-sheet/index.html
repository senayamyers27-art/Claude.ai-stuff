Dominio 1: Development with AWS Services (32%)

Consejos para el examen

  • Cuando una pregunta dice que un evento debe disparar varios procesos independientes y que un consumidor lento no debe afectar a los demás, busca fan-out de SNS a colas SQS (o EventBridge con varios destinos). Cuando enfatiza un flujo de trabajo visible y ordenado con manejo de errores, elige la orquestación con Step Functions.
  • Si una pregunta menciona errores de limitación como ProvisionedThroughputExceededException o ThrottlingException, la respuesta casi siempre es reintentos con retroceso exponencial (y jitter), no simplemente agregar más reintentos ni aumentar los tiempos de espera.
  • Que distintos consumidores procesen dos veces los mismos mensajes suele significar que el tiempo de visibilidad es menor que el tiempo de procesamiento. Muchas respuestas vacías de ReceiveMessage y un costo alto indican que hay que habilitar el long polling.
  • Larga duración, auditable o esperando a personas apunta a Standard. Tasas de eventos altas con duración corta apunta a Express. Todo lo que deba pausarse hasta que responda un sistema externo apunta a un task token con .waitForTaskToken.
  • Si el código en EC2, ECS o Lambda usa los permisos equivocados, sospecha que hay credenciales fijas en el código o en variables de entorno que ganan sobre el rol en la cadena de credenciales. Ejecuta aws sts get-caller-identity para confirmar quién eres.
  • Necesitas más de 15 minutos: no es Lambda (usa Step Functions, Fargate o Batch). Limitada por CPU y lenta: aumenta la memoria. Una función en una VPC no llega a internet: agrega un NAT gateway o endpoints de VPC.
  • Una DLQ configurada en la función Lambda solo se aplica a las invocaciones asíncronas. Para una fuente de eventos SQS, configura la política de reenvío y la DLQ en la propia cola de origen.
  • Espera una pregunta en la que la solución para funciones lentas o que agotan las conexiones sea mover la creación del cliente o de la conexión fuera del handler. Un 502 de una integración proxy casi siempre significa que la forma de la respuesta o el body de tipo cadena están mal.
  • En las preguntas de RCU/WCU, siempre redondea el tamaño del elemento hacia arriba al siguiente múltiplo de 4 KB (lecturas) o de 1 KB (escrituras) antes de multiplicar, y luego divide entre dos para las lecturas de consistencia eventual o duplica para las transacciones.
  • Las cargas de más de 5 GB deben usar carga multiparte. Recuerda la regla de ciclo de vida que cancela las cargas multiparte incompletas cuando una pregunta plantee por qué los costos de almacenamiento siguen creciendo sin objetos visibles.
  • Queja por datos desactualizados: agrega write-through o acorta el TTL. Caché que se llena de datos que nadie lee: es la rotación del write-through, así que combínalo con TTL. Necesitas replicación, conmutación por error o conjuntos ordenados: Redis OSS o Valkey, no Memcached.

Términos clave

Loose coupling (acoplamiento débil)
Diseñar componentes para que interactúen a través de un intermediario o un contrato estable, de modo que cada uno pueda fallar, escalar y desplegarse de forma independiente.
Fan-out (distribución a múltiples destinos)
Entregar un mensaje publicado a muchos suscriptores en paralelo, por ejemplo un tema de SNS con varias suscripciones de colas SQS.
Choreography (coreografía)
Coordinación en la que cada servicio reacciona a eventos y emite otros nuevos, sin un controlador central.
Orchestration (orquestación)
Coordinación en la que un motor de flujos de trabajo central, como Step Functions, invoca cada paso y administra el estado y los errores.
Stateless service (servicio sin estado)
Un servicio que no guarda estado del cliente entre solicitudes y lo almacena externamente, para que cualquier instancia pueda atender cualquier solicitud.
Event-driven architecture (arquitectura orientada a eventos)
Un diseño en el que los componentes emiten eventos sobre cosas que ocurrieron y otros componentes reaccionan, en lugar de llamarse directamente.
Microservice (microservicio)
Un servicio pequeño que se despliega de forma independiente, es dueño de una capacidad de negocio y de sus propios datos, y se alcanza a través de una API o de eventos.
Exponential backoff (retroceso exponencial)
Una estrategia de reintento en la que la espera entre intentos crece de forma multiplicativa, lo que reduce la presión sobre un servicio en problemas.
Jitter
Variación aleatoria agregada a los retrasos de reintento para que muchos clientes no reintenten en oleadas sincronizadas.
Idempotency (idempotencia)
La propiedad por la que repetir una operación produce el mismo resultado que hacerla una vez, lo que hace seguros los reintentos y las entregas duplicadas.
Poison message (mensaje envenenado)
Un mensaje que falla al procesarse cada vez que se recibe y que se repetiría para siempre sin una cola de mensajes fallidos.
Dead-letter queue (DLQ, cola de mensajes fallidos)
Una cola que recibe los mensajes o eventos que fallaron al procesarse después de un número configurado de intentos, para inspeccionarlos más tarde.
Idempotency key (clave de idempotencia)
Un valor único, como un ID de pedido, enviado con una solicitud para que el receptor pueda detectar e ignorar repeticiones de la misma operación.
Redrive policy (política de reenvío)
La configuración de SQS que indica una cola de mensajes fallidos y el maxReceiveCount a partir del cual los mensajes fallidos se mueven a ella.
Visibility timeout (tiempo de visibilidad)
El período después de recibir un mensaje de SQS durante el cual queda oculto para los demás consumidores; reaparece si no se elimina a tiempo.
Message group ID (ID de grupo de mensajes)
El atributo de las colas FIFO que define un grupo ordenado; los mensajes del mismo grupo se procesan en orden estricto.
Long polling (sondeo largo)
Una llamada a ReceiveMessage que espera hasta 20 segundos a que haya mensajes, lo que reduce las respuestas vacías y el costo.
Event pattern (patrón de eventos)
El filtro JSON de una regla de EventBridge que selecciona qué eventos se envían a los destinos de la regla.
Shard
La unidad de capacidad y de orden en un stream de datos de Kinesis; los registros con la misma clave de partición van al mismo shard.
Subscription filter policy (política de filtro de suscripción)
Una configuración de SNS que entrega a un suscriptor determinado solo los mensajes cuyos atributos o cuerpo coinciden con la política.
EventBridge Scheduler
Una capacidad de EventBridge que invoca destinos según programaciones únicas o recurrentes con expresiones cron o rate, con zonas horarias, reintentos y configuración de DLQ.
Amazon States Language (ASL)
El lenguaje basado en JSON que se usa para definir las máquinas de estados de Step Functions.
Standard workflow (flujo de trabajo Standard)
Un tipo de flujo de trabajo de Step Functions para ejecuciones largas (hasta un año), exactamente una vez y totalmente auditadas.
Express workflow (flujo de trabajo Express)
Un tipo de flujo de trabajo de Step Functions para ejecuciones cortas (hasta cinco minutos) y de gran volumen, registradas en CloudWatch Logs.
Task token
Un token que Step Functions pasa a un proceso externo en el patrón Wait for Callback; el flujo se reanuda cuando se llama a SendTaskSuccess o SendTaskFailure con él.
Retry y Catch
Manejo de errores a nivel de estado en ASL: Retry vuelve a intentar un estado fallido con retroceso, y Catch dirige los errores no resueltos a un estado alternativo.
HeartbeatSeconds
Una configuración de Task que hace fallar la tarea si el trabajador externo no envía un heartbeat (latido) dentro del intervalo, lo que detecta fallas silenciosas.
Default credential provider chain (cadena predeterminada de proveedores de credenciales)
La lista ordenada de lugares donde un SDK o la CLI busca credenciales, que termina con las credenciales del rol del entorno de cómputo.
Paginator (paginador)
Un ayudante del SDK que sigue automáticamente los tokens de continuación para devolver todas las páginas de resultados de una API de listado.
Waiter
Un ayudante del SDK o de la CLI que sondea hasta que un recurso alcanza un estado especificado o se llega a un número máximo de intentos.
SigV4
Signature Version 4, el proceso que firma las solicitudes a la API de AWS con credenciales para que el servicio pueda autenticarlas.
Instance profile (perfil de instancia)
Un contenedor para un rol de IAM que EC2 usa para entregar credenciales temporales del rol al software de la instancia mediante el servicio de metadatos de instancia.
aws sts get-caller-identity
Un comando de la CLI que devuelve la cuenta, el ID de usuario y el ARN de la identidad a la que corresponden las credenciales actuales.
Timeout (tiempo de espera)
El tiempo máximo de ejecución de una invocación de Lambda, configurable de 1 segundo a 15 minutos, con un valor predeterminado de 3 segundos.
Ephemeral storage (almacenamiento efímero, /tmp)
Disco temporal por entorno de una función Lambda, de 512 MB de forma predeterminada y configurable hasta 10,240 MB; no es duradero.
Layer (capa)
Un archivo .zip con versiones que contiene código compartido o dependencias que muchas funciones pueden referenciar; cada función puede incluir hasta cinco capas.
Reserved concurrency (concurrencia reservada)
Un ajuste que garantiza y a la vez limita el número de ejecuciones simultáneas de una función.
Provisioned concurrency (concurrencia aprovisionada)
Un ajuste que mantiene inicializado de antemano un número elegido de entornos de ejecución para evitar arranques en frío.
NAT gateway
Un servicio administrado que permite que los recursos en subredes privadas, incluidas las funciones Lambda conectadas a una VPC, establezcan conexiones salientes a internet.
Synchronous invocation (invocación síncrona)
Quien llama espera la respuesta de la función; los reintentos son responsabilidad de quien llama.
Asynchronous invocation (invocación asíncrona)
Lambda pone el evento en cola, devuelve 202 de inmediato y reintenta las fallas por su cuenta antes de enviarlas a una DLQ o a un destino.
Lambda destination (destino de Lambda)
Un destino (SQS, SNS, Lambda, EventBridge, o S3 para las fallas) que recibe un registro del éxito o la falla de una invocación asíncrona o de stream.
Event source mapping (mapeo de fuente de eventos)
Un recurso de Lambda que sondea una cola o un stream e invoca la función con lotes de registros.
ReportBatchItemFailures
Un ajuste del mapeo de fuente de eventos que permite que la función devuelva solo los registros fallidos para que los exitosos no se reintenten.
Bisect batch on function error (dividir el lote ante un error de la función)
Una opción del mapeo de fuente de eventos de streams que parte en dos un lote fallido y reintenta cada mitad para aislar un registro malo.
Maximum event age (antigüedad máxima del evento)
Un ajuste de la invocación asíncrona que limita cuánto tiempo guarda Lambda un evento en su cola interna, hasta seis horas.
Handler (manejador)
La función que Lambda llama en cada invocación, que recibe el evento y el objeto de contexto.
Init phase (fase de inicialización)
La parte de un arranque en frío en la que Lambda carga el código y ejecuta la inicialización fuera del handler, una vez por entorno de ejecución.
Lambda proxy integration (integración proxy de Lambda)
Una integración de API Gateway que pasa la solicitud HTTP completa a Lambda y espera una respuesta con statusCode, headers y un body de tipo cadena.
Context object (objeto de contexto)
El segundo argumento del handler, que expone el ID de solicitud, el nombre de la función, el límite de memoria y el tiempo de ejecución restante.
Payload format version 2.0 (versión 2.0 del formato de carga útil)
El formato de evento de las HTTP API, que coloca el método en requestContext.http.method y la ruta en rawPath, y omite las cadenas de consulta ausentes.
Cold start (arranque en frío)
La latencia adicional de un entorno de ejecución nuevo, incluida la fase de inicialización, antes de que el handler se ejecute por primera vez.
Partition key (clave de partición)
El atributo clave del que DynamoDB calcula un hash para decidir qué partición guarda un elemento.
Global secondary index (GSI, índice secundario global)
Un índice con su propia clave de partición y de ordenamiento, que puede agregarse en cualquier momento, con capacidad separada y solo lecturas de consistencia eventual.
Local secondary index (LSI, índice secundario local)
Un índice que comparte la clave de partición de la tabla con una clave de ordenamiento alternativa; solo se crea junto con la tabla.
Read capacity unit (RCU, unidad de capacidad de lectura)
Una lectura de consistencia fuerte por segundo, o dos de consistencia eventual, de un elemento de hasta 4 KB.
Write capacity unit (WCU, unidad de capacidad de escritura)
Una escritura por segundo de un elemento de hasta 1 KB.
Condition expression (expresión de condición)
Una regla sobre una escritura, como attribute_not_exists o una verificación de versión, que hace que la escritura falle con ConditionalCheckFailedException si no se cumple.
DynamoDB Accelerator (DAX)
Una caché en memoria compatible con la API de DynamoDB que sirve lecturas de consistencia eventual en microsegundos.
Multipart upload (carga multiparte)
Subir un objeto como partes que se cargan por separado y que S3 ensambla; obligatoria por encima de 5 GB y recomendable para archivos grandes.
Lifecycle rule (regla de ciclo de vida)
Una configuración del bucket que hace la transición de los objetos a otras clases de almacenamiento o los hace vencer después de períodos definidos.
S3 Intelligent-Tiering
Una clase de almacenamiento que mueve automáticamente los objetos entre niveles de acceso según la frecuencia con que se accede a ellos.
Event notification (notificación de eventos)
Una función de S3 que envía eventos a nivel de objeto a Lambda, SQS, SNS o EventBridge, con filtro opcional por prefijo y sufijo.
S3 Transfer Acceleration
Una función del bucket que acelera las cargas a larga distancia enrutándolas a través de las ubicaciones de borde de CloudFront por la red de AWS.
Byte-range fetch (obtención por rango de bytes)
Una solicitud GetObject con un encabezado Range que recupera parte de un objeto, lo que permite descargas paralelas o reanudables.
Lazy loading (cache-aside, carga diferida)
Una estrategia que llena la caché solo cuando hay un fallo de caché, después de leer de la base de datos.
Write-through (escritura simultánea)
Una estrategia que escribe en la caché cada vez que se actualiza la base de datos, lo que mantiene al día los datos en caché.
TTL (time to live, tiempo de vida)
Un tiempo de vencimiento en una clave de caché después del cual se elimina y se vuelve a cargar en la siguiente lectura.
Cache hit ratio (tasa de aciertos de caché)
La proporción de lecturas que se sirven desde la caché; una tasa baja sugiere claves mal elegidas, TTL cortos o una caché demasiado pequeña.
Cache miss (fallo de caché)
Una lectura en la que la clave solicitada no está en la caché, así que la aplicación debe obtenerla de la base de datos.
Eviction policy (política de desalojo)
La regla que usa un motor en memoria para eliminar claves cuando la memoria está llena, como la de menos usado recientemente (LRU).

Dominio 2: Security (26%)

Consejos para el examen

  • Si una pregunta muestra un Allow y un Deny para la misma acción, la respuesta es denegado. Si pregunta cómo debe obtener credenciales una aplicación en EC2, elige un rol de IAM mediante un perfil de instancia, nunca claves de acceso en la instancia. En ECS, los permisos de la aplicación van en el rol de tarea.
  • Los orígenes que empujan (S3, SNS, API Gateway, EventBridge) necesitan permiso en la política basada en recursos de la función. Los orígenes que se sondean (SQS, Kinesis, DynamoDB Streams) necesitan permisos en el rol de ejecución. En KMS, la política de clave se revisa primero.
  • El acceso entre cuentas necesita ambos lados: la política de confianza del rol de destino debe confiar en quien llama, y la política de IAM de quien llama debe permitir sts:AssumeRole sobre el rol. Si falta cualquiera de los dos, recibes AccessDenied. Los proveedores externos apuntan a los ID externos; los sistemas de CI externos apuntan a AssumeRoleWithWebIdentity.
  • Si el escenario necesita registro, inicio de sesión o tokens para una API, elige un grupo de usuarios. Si los usuarios deben acceder directamente desde el dispositivo a servicios de AWS como S3 o DynamoDB, o los invitados necesitan acceso limitado, elige un grupo de identidades.
  • Las claves de API sirven para identificar a los clientes y aplicar planes de uso, no para proteger una API. Si una pregunta necesita validar tokens personalizados o de terceros, elige un autorizador Lambda; para tokens de Cognito sin código, un autorizador de Cognito; para clientes con credenciales de AWS, IAM.
  • Registro de auditoría y control del uso de la clave: SSE-KMS. Limitación o costo de KMS con SSE-KMS: habilita Bucket Keys. Tú administras las claves y S3 nunca debe guardarlas: SSE-C (solo HTTPS). AWS nunca debe ver el texto plano: cifrado del lado del cliente.
  • Cualquier pregunta con datos de más de 4 KB y KMS apunta al cifrado de sobre con GenerateDataKey. Los requisitos entre cuentas o de política de clave personalizada descartan las claves administradas por AWS. ThrottlingException apunta a caché de claves de datos, Bucket Keys, retroceso o un aumento de cuota.
  • CloudFront (y los dominios de API Gateway optimizados para bordes) necesitan certificados de ACM en us-east-1. Para obligar a usar HTTPS en un bucket de S3, deniega en la política de bucket las solicitudes en las que aws:SecureTransport es false. La validación por DNS mantiene automáticas las renovaciones de ACM.
  • La rotación automática es la palabra clave de Secrets Manager. La forma más barata de guardar configuración y algunos valores cifrados, organizados en una jerarquía: Parameter Store con SecureString. En Lambda, lee una vez en la inicialización y guarda en caché.
  • Para el código en AWS, la respuesta correcta es un rol que se obtiene mediante la cadena predeterminada de credenciales, no claves de acceso en ningún lugar. Para datos sensibles en los logs, la respuesta nativa de AWS es una política de protección de datos de CloudWatch Logs, con logs:Unmask controlando quién ve los originales.
  • Acceso temporal a un objeto privado de S3 para alguien sin credenciales de AWS: URL prefirmada. Recuerda que la URL está limitada tanto por su expiración como por la duración y los permisos de las credenciales con que se firmó. Mínimo privilegio a partir del uso real: generación de políticas de Access Analyzer.

Términos clave

Execution role (rol de ejecución)
El rol de IAM que asume una función Lambda para obtener credenciales temporales con las que llamar a otros servicios de AWS, incluida la escritura de sus logs.
Instance profile (perfil de instancia)
Un contenedor que asocia un rol de IAM a una instancia EC2 para que las aplicaciones que corren en ella reciban credenciales temporales a través del servicio de metadatos de instancia.
ECS task role (rol de tarea de ECS)
El rol de IAM cuyos permisos usan los contenedores de la aplicación en una tarea de ECS, distinto del rol de ejecución de tarea.
ECS task execution role (rol de ejecución de tarea de ECS)
El rol de IAM que usa el agente de ECS para descargar imágenes de contenedor de ECR, enviar logs y obtener los secretos referenciados.
Explicit deny (denegación explícita)
Una declaración de política con Effect Deny que anula cualquier Allow para las solicitudes que coinciden.
Implicit deny (denegación implícita)
El resultado predeterminado de cualquier solicitud que ninguna política permite.
Least privilege (mínimo privilegio)
Conceder solo las acciones y los recursos específicos necesarios para realizar una tarea.
Permissions boundary (límite de permisos)
Una política administrada que fija los permisos máximos que una política basada en identidad puede conceder a un usuario o rol.
Resource-based policy (política basada en recursos)
Una política asociada a un recurso que nombra a los principales a los que se permite acceder a él.
Principal
El elemento de una política basada en recursos que identifica la cuenta, el rol, el usuario o el servicio al que se concede o deniega el acceso.
Function policy (política de función)
La política basada en recursos de una función Lambda que autoriza a servicios o cuentas a invocarla.
Bucket policy (política de bucket)
Una política basada en recursos en un bucket de S3 que controla el acceso e impone condiciones a las solicitudes que recibe.
Key policy (política de clave)
La política basada en recursos obligatoria de una clave de KMS; las políticas de IAM solo funcionan si ella lo permite.
Grant (concesión)
Un mecanismo de KMS para delegar el uso de una clave a un principal, a menudo un servicio de AWS, sin cambiar la política de clave.
Confused deputy (suplente confundido)
Una situación en la que se engaña a un servicio de confianza para que actúe en nombre de la parte equivocada, lo que se evita con las condiciones SourceArn y SourceAccount.
Trust policy (política de confianza)
La política basada en recursos de un rol de IAM que especifica qué principales pueden asumirlo.
AssumeRole
La API de STS que devuelve credenciales temporales de un rol a quien llama si es de confianza.
Temporary credentials (credenciales temporales)
Un ID de clave de acceso, una clave de acceso secreta y un token de sesión que expiran después de una duración establecida.
Role session name (nombre de sesión del rol)
Un identificador elegido por quien llama para una sesión de rol asumido, que aparece en CloudTrail y en el ARN del rol asumido.
External ID (ID externo)
Un valor exigido en una condición de la política de confianza que los terceros deben proporcionar al asumir un rol, lo que evita problemas de suplente confundido.
Role chaining (encadenamiento de roles)
Usar las credenciales de un rol asumido para asumir otro rol; las sesiones se limitan a una hora.
AssumeRoleWithWebIdentity
La API de STS que intercambia un token de identidad OIDC por credenciales temporales de AWS.
User pool (grupo de usuarios)
Un directorio de usuarios de Cognito que gestiona el registro y el inicio de sesión y emite tokens JWT de ID, de acceso y de actualización.
Identity pool (grupo de identidades)
Un componente de Cognito que intercambia tokens de proveedores de identidad por credenciales temporales de AWS mediante roles de IAM.
ID token (token de ID)
Un JWT que contiene claims sobre la identidad del usuario autenticado, como email y sub.
Access token (token de acceso)
Un JWT que contiene scopes y grupos, usado para autorizar solicitudes a API.
Refresh token (token de actualización)
Un token de larga duración que se usa para obtener nuevos tokens de ID y de acceso sin volver a autenticarse.
Unauthenticated identity (identidad no autenticada)
Una identidad de invitado en un grupo de identidades que recibe credenciales para un rol de IAM limitado sin iniciar sesión.
Pre token generation trigger (disparador previo a la generación de tokens)
Un disparador de Lambda del grupo de usuarios que puede agregar, modificar o suprimir claims antes de emitir los tokens.
IAM authorization (autorización de IAM)
Autorización de API Gateway que exige solicitudes firmadas con SigV4 y una política de IAM que permita execute-api:Invoke.
SigV4
AWS Signature Version 4, el proceso de firmar solicitudes HTTP con credenciales de AWS para que AWS pueda verificar a quien llama.
Cognito user pool authorizer (autorizador de grupo de usuarios de Cognito)
Un autorizador de API Gateway que valida los JWT emitidos por un grupo de usuarios de Cognito sin código personalizado.
Lambda authorizer (autorizador Lambda)
Una función que recibe un token o parámetros de la solicitud y devuelve una política de IAM que permite o deniega la solicitud.
Authorizer caching (caché del autorizador)
Guardar durante un TTL la política devuelta por un autorizador Lambda, con la fuente de identidad como clave, para no invocarlo en cada solicitud.
Usage plan (plan de uso)
Una configuración de API Gateway que aplica límites de limitación y cuotas a las claves de API asociadas a ella.
API resource policy (política de recursos de la API)
Una política basada en recursos en una API REST que restringe o permite el acceso por cuenta, rango de IP o endpoint de VPC.
SSE-S3
Cifrado del lado del servidor con claves administradas por completo por S3, usando AES-256; el valor predeterminado para los objetos nuevos.
SSE-KMS
Cifrado del lado del servidor con una clave de KMS, que ofrece auditoría en CloudTrail y control mediante la política de clave.
DSSE-KMS
Cifrado de doble capa del lado del servidor con claves de KMS, que aplica dos capas de cifrado para necesidades específicas de cumplimiento.
SSE-C
Cifrado del lado del servidor con una clave proporcionada por el cliente, enviada en cada solicitud HTTPS y que S3 no almacena.
S3 Bucket Key
Una clave a nivel de bucket derivada de KMS que reduce el número de llamadas a KMS, el costo y la limitación en SSE-KMS.
Client-side encryption (cifrado del lado del cliente)
Cifrar los datos en la aplicación antes de subirlos, de modo que el servicio de almacenamiento solo recibe texto cifrado.
AWS Encryption SDK
Una biblioteca del lado del cliente que realiza cifrado de sobre para que los datos se cifren antes de salir de la aplicación.
Customer managed key (clave administrada por el cliente)
Una clave de KMS que creas y controlas, incluida su política de clave, su rotación, su deshabilitación y el acceso entre cuentas.
AWS managed key (clave administrada por AWS)
Una clave de KMS creada por un servicio de AWS para tu cuenta, con una política de clave fija que no puedes cambiar.
AWS owned key (clave propiedad de AWS)

Dominio 3: Deployment (24%)

Consejos para el examen

  • Las dependencias de más de 250 MB descomprimidos apuntan a imágenes de contenedor (hasta 10 GB). Los errores de importación de bibliotecas nativas suelen indicar que el paquete se compiló en un sistema operativo o arquitectura distintos a los de Lambda. Una capa que está adjunta pero cuya biblioteca no se encuentra suele tener la estructura de carpetas equivocada.
  • La línea Transform es la que identifica una plantilla de SAM. Para probar una API en local, el comando es sam local start-api; para un solo evento, sam local invoke. sam deploy --guided escribe samconfig.toml.
  • Comparte valores entre stacks independientes con Export en Outputs más Fn::ImportValue. Previsualiza las actualizaciones riesgosas con un change set. Despliega plantillas con rutas de código locales ejecutando primero cloudformation package. Replacement: True en un change set es tu aviso de que un recurso con estado se va a recrear.
  • Si un primer despliegue del CDK falla porque falta el bucket de staging o el stack de bootstrap, la respuesta es cdk bootstrap. Para ver la plantilla de CloudFormation que producirá el CDK, usa cdk synth.
  • Canary son dos pasos (un porcentaje pequeño y luego todo); linear son muchos pasos iguales. La reversión automática en CodeDeploy la activan las alarmas de CloudWatch o los hooks que fallan. En producción, apunta los disparadores a alias, nunca a $LATEST.
  • Si los cambios no son visibles para los clientes, olvidaste desplegar en la etapa. Si distintas etapas llaman a distintos alias de Lambda desde una sola API, la respuesta son las variables de etapa, más un permiso de Lambda para cada alias.
  • Busca las palabras del requisito: costo mínimo con tiempo de inactividad aceptable significa all at once; mantener la capacidad completa significa rolling with additional batch; la reversión segura más rápida significa immutable; un entorno separado y un cambio por DNS significa blue/green. Un porcentaje del tráfico en vivo hacia instancias nuevas antes del cambio completo significa traffic splitting.
  • El orden de las fases del buildspec es install, pre_build, build, post_build. Los archivos que necesita la siguiente etapa de la canalización deben estar en artifacts. Guarda los secretos en env, en parameter-store o secrets-manager, nunca escritos en el buildspec.
  • Memoriza el orden de EC2: ApplicationStop, DownloadBundle, BeforeInstall, Install, AfterInstall, ApplicationStart, ValidateService. Lambda solo tiene BeforeAllowTraffic y AfterAllowTraffic. Los despliegues en EC2 que nunca empiezan suelen indicar que el agente no está en ejecución. En ECS, las pruebas antes de que lleguen los usuarios reales van en AfterAllowTestTraffic.
  • Cambiar el comportamiento de una aplicación de forma segura sin volver a desplegar código apunta a las feature flags de AppConfig con una estrategia de despliegue y reversión basada en alarmas. Las pruebas que deben verificar permisos de IAM o integraciones reales necesitan una etapa de pruebas desplegada, no mocks.

Dominio 4: Troubleshooting and Optimization (18%)

Consejos para el examen

  • Conoce qué herramienta responde cada pregunta: las métricas te dicen qué y cuándo, los logs (a través de Logs Insights) te dicen por qué, y las trazas te dicen dónde en la cadena de llamadas. Convertir un patrón de log en algo sobre lo que puedas crear una alarma significa un filtro de métricas.
  • Relaciona códigos con causas: 429 es limitación (concurrencia de Lambda o límites de API Gateway), 502 es una respuesta proxy incorrecta o un error no controlado de la función, 504 es el backend superando el tiempo de espera de integración de 29 segundos de API Gateway, y un AccessDenied que nombra el rol asumido es un permiso faltante en el rol de ejecución.
  • Necesitas buscar o filtrar trazas por un valor: anotación. Necesitas guardar detalle extra solo para verlo: metadatos. No hay trazas desde EC2 o ECS: revisa el daemon o el agente en UDP 2000 y los permisos de escritura de X-Ray del rol. No hay trazas desde Lambda: habilita el rastreo activo y otorga PutTraceSegments.
  • Publicar métricas desde Lambda sin llamadas a una API ni latencia adicional apunta al formato de métricas integradas. Necesitas granularidad de menos de un minuto o alarmas de 10 segundos: métricas de alta resolución con StorageResolution 1. Uso de memoria en EC2: el agente de CloudWatch.
  • Una alarma que debe notificar a personas publica en un tema de SNS; si los correos nunca llegan, revisa que la suscripción esté confirmada y, en temas cifrados, la política de la clave de KMS. Para evitar alertas por picos aislados, usa M de N puntos de datos para alarma en lugar de un solo período.
  • Latencia por arranques en frío: concurrencia aprovisionada (o SnapStart en los runtimes compatibles). Proteger un sistema posterior o garantizar capacidad: concurrencia reservada. Función lenta con mucho uso de CPU: aumentar la memoria.
  • IteratorAge en aumento: busca errores que bloquean un shard (corrígelos con división del lote, límites de reintento y respuestas de lote parcial) o muy poco paralelismo (sube el factor de paralelización o agrega shards). Mensajes procesados dos veces desde SQS: tiempo de espera de visibilidad más corto que el tiempo de procesamiento.
  • Limitación mientras la capacidad total consumida es baja significa una partición caliente: corrige la clave de partición (mayor cardinalidad, fragmentación de escrituras) o pon en caché las lecturas calientes. Tráfico impredecible o con picos sin planificación de capacidad apunta al modo bajo demanda.
  • DAX solo acelera las lecturas eventualmente consistentes; las lecturas fuertemente consistentes la evitan. La caché de API Gateway es por etapa, con un TTL predeterminado de 300 segundos y un máximo de 3600; incluye en la clave de caché los parámetros que cambian la respuesta.

La configuración de la alarma que decide si los puntos de datos faltantes cuentan como que superan el umbral, que no lo superan, ignorados o faltantes.
Composite alarm (alarma compuesta)
Una alarma cuyo estado se calcula a partir de una regla que combina los estados de otras alarmas.
SNS topic (tema de SNS)
Un canal de publicación-suscripción que distribuye los mensajes de alarma a suscriptores como correo electrónico, SMS, Lambda, HTTPS o SQS.
Structured logging (logging estructurado)
Escribir las entradas de log como campos consistentes y legibles por máquina, normalmente en JSON.
Correlation ID (ID de correlación)
Un identificador único que se propaga por todos los servicios que manejan una solicitud para poder vincular sus logs.
Memory setting (ajuste de memoria)
El único control de tamaño de cómputo de Lambda; la CPU y el ancho de banda de red se asignan en proporción a la memoria configurada.
Cold start (arranque en frío)
La latencia adicional cuando Lambda crea e inicializa un nuevo entorno de ejecución antes de ejecutar el handler.
Init Duration (duración de inicialización)
El campo de la línea de log REPORT que muestra cuánto tardó la inicialización en una invocación que tuvo un arranque en frío.
Provisioned concurrency (concurrencia aprovisionada)
Entornos de ejecución preinicializados en una versión o alias que eliminan los arranques en frío, facturados mientras están configurados.
Reserved concurrency (concurrencia reservada)
Un ajuste gratuito que garantiza y limita las ejecuciones simultáneas de una función.
Lambda SnapStart
Una característica para los runtimes compatibles que reanuda los nuevos entornos a partir de una instantánea de uno ya inicializado para acortar los arranques en frío.
IteratorAge (antigüedad del iterador)
La métrica que muestra la antigüedad de los registros que se procesan de un stream, lo que indica qué tan atrasado está un consumidor.
Parallelization factor (factor de paralelización)
Un ajuste del mapeo de origen de eventos (de 1 a 10) para lotes simultáneos por shard, que conserva el orden por clave de partición.
Bisect batch on function error (división del lote ante error de la función)
Una opción del mapeo de origen de eventos que divide en dos un lote que falla y reintenta cada mitad para aislar un registro defectuoso.
Enhanced fan-out
Una característica de Kinesis que da a cada consumidor registrado un rendimiento de lectura dedicado por shard.
maxReceiveCount
El número de veces que se puede recibir un mensaje de SQS antes de que la política de redrive lo mueva a la DLQ.
DLQ redrive (reenvío desde la DLQ)
Mover los mensajes de una cola de mensajes fallidos de vuelta a una cola de origen para reprocesarlos después de una corrección.
Partition key (clave de partición)
El atributo al que DynamoDB le aplica un hash para decidir qué partición guarda un elemento; debe tener alta cardinalidad y un acceso parejo.
Hot partition (partición caliente)
Una partición que recibe una parte desproporcionada de las solicitudes y provoca limitación a pesar de que haya capacidad de la tabla sin usar.
Write sharding (fragmentación de escrituras)
Agregar un sufijo aleatorio o calculado a las claves de partición para repartir las escrituras entre más particiones.
On-demand capacity (capacidad bajo demanda)
Un modo de DynamoDB que se factura por solicitud y escala automáticamente sin planificación de capacidad.
Provisioned capacity (capacidad aprovisionada)
Un modo de DynamoDB en el que defines las RCU y WCU, normalmente con escalado automático; más barato para tráfico estable.
Adaptive capacity (capacidad adaptativa)
La reasignación automática de rendimiento de DynamoDB a las particiones más ocupadas y el aislamiento de los elementos consultados con frecuencia.
Burst capacity (capacidad de ráfaga)
Capacidad no utilizada que DynamoDB conserva brevemente para absorber picos cortos de tráfico.
API Gateway stage cache (caché de etapa de API Gateway)
Una caché de API REST por etapa que devuelve respuestas de integración almacenadas durante un TTL de 300 segundos de forma predeterminada y de hasta 3600 segundos.
Cache key (clave de caché)
Los atributos de la solicitud que se usan para decidir si una respuesta en caché corresponde a una nueva solicitud.
Time to live (TTL, tiempo de vida)
Cuánto tiempo se considera fresco un elemento en caché antes de que la caché obtenga una copia nueva.
CloudFront invalidation (invalidación de CloudFront)
Una solicitud que elimina objetos de las cachés perimetrales de CloudFront antes de que venza su TTL.
Amazon ElastiCache
Un almacén de datos administrado en memoria (Redis OSS, Valkey o Memcached) que el código de la aplicación usa como caché de propósito general.
DynamoDB Accelerator (DAX)
Una caché en memoria compatible con la API de DynamoDB que ofrece lecturas eventualmente consistentes en microsegundos.
