CompTIA Cloud+ CV0-004

Modelos de servicio en la nube (IaaS, PaaS, SaaS, FaaS) y el modelo de responsabilidad compartida

Un modelo de servicio en la nube describe cuánta parte de la pila tecnológica ejecuta el proveedor por ti y cuánta sigues ejecutando tú. Imagina la pila como capas: el centro de datos físico, los servidores y la red, la capa de virtualización, el sistema operativo, el entorno de ejecución y el middleware, la aplicación y, por último, los datos y las cuentas de usuario. CompTIA Cloud+ (examen CV0-004) espera que ubiques cualquier servicio en ese espectro con rapidez, porque el modelo decide quién parchea qué, quién asegura qué y a quién le avisan cuando algo se rompe.

La infraestructura como servicio (IaaS) te da máquinas virtuales (VM), redes virtuales y almacenamiento en bloque. El proveedor opera el centro de datos, los hosts físicos y el hipervisor; tú instalas y parcheas el sistema operativo, el entorno de ejecución, tus aplicaciones y tus datos. En la práctica, IaaS se siente como tener servidores sin tener hardware: sigues ejecutando herramientas de actualización como apt upgrade o Windows Update en cada sistema invitado, sigues configurando el firewall del host y sigues eligiendo y manteniendo el software del servidor web. IaaS ofrece el mayor control y el mayor trabajo, y por eso es el destino habitual de las migraciones lift-and-shift (trasladar tal cual) de aplicaciones heredadas.

La plataforma como servicio (PaaS) traslada el sistema operativo y el entorno de ejecución al proveedor. Implementas código o un contenedor en una plataforma de aplicaciones gestionada, o usas una base de datos gestionada, y solo administras la aplicación, su configuración y sus datos. El proveedor parchea el sistema operativo invitado y el entorno de ejecución del lenguaje, a menudo durante una ventana de mantenimiento que puedes elegir. PaaS acelera el desarrollo porque los equipos dejan de mantener servidores, pero limita el control de bajo nivel: por lo general no puedes iniciar sesión en el host subyacente ni instalar cualquier software de sistema.

El software como servicio (SaaS) es una aplicación terminada, como el correo web, un sistema de gestión de relaciones con clientes (CRM) o una suite en línea para compartir archivos. Tú administras los usuarios, los ajustes y los datos que colocas en ella. Nunca ves los servidores, el motor de base de datos ni el código. La función como servicio (FaaS), a menudo llamada cómputo sin servidor (serverless), ejecuta fragmentos cortos de código en respuesta a eventos como la carga de un archivo, un mensaje en una cola o una solicitud HTTP. Tú aportas el código de la función y su configuración, como la memoria y el tiempo de espera, y el proveedor se encarga de los servidores, el escalado y los parches, cobrando por invocación y por tiempo de ejecución. FaaS se ubica entre PaaS y SaaS en cuanto a lo que oculta: sigues siendo dueño del código, pero nunca piensas en un servidor.

El modelo de responsabilidad compartida es el acuerdo que se desprende de esas elecciones. El proveedor siempre es responsable de la seguridad de la nube: los edificios físicos, el hardware, la red global y la capa de virtualización. El cliente siempre es responsable de la seguridad en la nube: sus datos, quién tiene acceso a ellos mediante la gestión de identidades y accesos (IAM) y cómo se configuran los servicios. Las capas intermedias se desplazan según el modelo. En IaaS tú parcheas el sistema operativo invitado; en PaaS lo hace el proveedor; en SaaS sigues decidiendo quién puede iniciar sesión y qué datos se comparten. Los proveedores publican una matriz de responsabilidades para cada servicio, y en una organización real ese documento suele adjuntarse al registro de riesgos y lo consultan los auditores.

Dos puntos hacen tropezar a la gente. Primero, la responsabilidad sobre los datos y las identidades nunca pasa al proveedor, ni siquiera en SaaS. Un bucket de almacenamiento legible públicamente, una carpeta compartida con "cualquier persona que tenga el enlace" o un usuario sin autenticación multifactor (MFA) es una falla del cliente, sin importar cuán gestionado sea el servicio. Segundo, gestionado no significa sin configurar. Una base de datos gestionada todavía requiere que tú elijas la exposición de red, las claves de cifrado, la retención de copias de seguridad y las cuentas de usuario. El proveedor garantiza que el motor funcione y esté parcheado; no decide que tu base de datos deba ser privada ni que las copias de seguridad deban conservarse durante treinta días.

Una forma confiable de responder las preguntas del examen es trabajar en dos pasos. Paso uno: identifica el modelo de servicio a partir de las pistas de la pregunta. Palabras como máquina virtual, sistema operativo invitado o instalar el agente apuntan a IaaS; implementar código, entorno de ejecución gestionado o base de datos gestionada apuntan a PaaS; aplicación por suscripción o ajustes del inquilino (tenant) apuntan a SaaS; disparador por eventos, facturación por invocación o sin servidores apuntan a FaaS. Paso dos: ubica la capa que falló. Si es física, de hardware o del hipervisor, le corresponde al proveedor. Si son datos, identidad, acceso o configuración, le corresponde al cliente. Solo las capas intermedias, el sistema operativo y el entorno de ejecución, exigen que sepas qué modelo está en juego.

Este modelo también da forma a las operaciones más allá de la seguridad. El monitoreo, las copias de seguridad y la respuesta a incidentes siguen las mismas líneas: con IaaS tu equipo instala agentes de monitoreo y programa copias de seguridad del sistema invitado; con PaaS dependes de las métricas de la plataforma y configuras la función de copia de seguridad integrada; con SaaS principalmente revisas los registros de auditoría y exportas datos para su retención. Cuando planificas personal, contratos y acuerdos de nivel de servicio (SLA), el modelo de servicio te dice qué tareas todavía necesitan personas de tu lado.

Términos clave

IaaS
Infraestructura como servicio: el proveedor suministra cómputo, almacenamiento y redes virtuales, y el cliente administra el sistema operativo y todo lo que está por encima.
PaaS
Plataforma como servicio: el proveedor también opera el sistema operativo y el entorno de ejecución, de modo que el cliente implementa y administra solo el código de la aplicación, la configuración y los datos.
SaaS
Software como servicio: una aplicación completa entregada por internet; el cliente administra usuarios, ajustes y datos.
FaaS
Función como servicio: código dirigido por eventos que se ejecuta bajo demanda sin servidores que el cliente deba administrar, facturado por ejecución.
Shared responsibility model (modelo de responsabilidad compartida)
La división de tareas de seguridad y operación entre el proveedor y el cliente, que se desplaza según el modelo de servicio.
Security of the cloud (seguridad de la nube)
La parte fija del proveedor: instalaciones físicas, hardware, red global y capa de virtualización.
Security in the cloud (seguridad en la nube)
La parte fija del cliente: datos, identidades y accesos, y la configuración de los servicios que usa.
Ejemplo real

Una empresa migra su intranet de una VM autogestionada a un servicio de aplicaciones web PaaS. El equipo de operaciones ya no parchea el sistema invitado Windows ni el entorno de ejecución del servidor web, pero todavía configura los certificados TLS, restringe quién puede implementar, almacena de forma segura las cadenas de conexión y respalda la base de datos de la aplicación. Cuando una auditoría posterior señala que la aplicación permite acceso anónimo a una página de administración, el hallazgo le corresponde a la empresa, no al proveedor, porque la configuración de la aplicación siempre es tarea del cliente.

Consejo para el examen: Cuando una pregunta te pida quién es responsable de algo, identifica primero el modelo de servicio. Los datos, las identidades, las políticas de acceso y la configuración siempre quedan del lado del cliente; la seguridad física y el hipervisor siempre quedan del lado del proveedor. Solo las capas del sistema operativo y del entorno de ejecución se mueven entre ambos.

Comprueba lo que sabes

En una implementación IaaS, ¿quién aplica los parches de seguridad al sistema operativo invitado?

El cliente. En IaaS el proveedor se detiene en el hipervisor y los hosts físicos; el sistema operativo invitado y todo lo que está por encima son tarea del cliente.

Un inquilino de una herramienta SaaS para compartir archivos filtra datos porque una carpeta se compartió públicamente. ¿De quién era la responsabilidad?

Del cliente. Los datos y la configuración de acceso siguen siendo responsabilidades del cliente en todos los modelos de servicio, incluido SaaS.

¿Qué modelo cobra por invocación y ejecuta el código solo cuando ocurre un evento?

FaaS (funciones sin servidor).

En PaaS, ¿quién parchea el entorno de ejecución del lenguaje que usa la aplicación?

El proveedor. PaaS traslada el sistema operativo y el entorno de ejecución al proveedor; el cliente administra el código, la configuración y los datos.
