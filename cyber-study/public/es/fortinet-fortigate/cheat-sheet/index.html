Dominio 1: Deployment and system configuration (24%)

Consejos para el examen

  • Perder el acceso a la GUI después de cambiar una interfaz casi siempre se debe a que falta HTTPS en el Administrative Access de esa interfaz, o a un cambio de IP que sacó la interfaz de la subred de tu laptop. Confirma allowaccess antes de desconectarte.
  • Cuando una pregunta pide cómo restringir desde dónde inicia sesión un administrador, la respuesta es trusted hosts, no la MFA ni la política de contraseñas. Los perfiles responden qué puede cambiar, no desde dónde.
  • Nunca instales la imagen más reciente directamente sobre una compilación mucho más antigua. Sigue la ruta de actualización publicada paso a paso y haz primero un respaldo cifrado para poder revertir.
  • Las VDOMs dan tablas de enrutamiento, conjuntos de políticas y administradores separados; las VLANs y las zonas solo segmentan dentro de un mismo contexto de enrutamiento y políticas. Elige VDOMs cuando necesites aislamiento real, no solo subredes separadas.
  • Memoriza ambos órdenes de elección. Override desactivado: puertos monitoreados, uptime, prioridad, número de serie. Override activado: puertos monitoreados, prioridad, uptime, número de serie. Los puertos monitoreados siempre van primero.
  • Session pickup está desactivado de forma predeterminada. Si una pregunta menciona sesiones que se caen durante una conmutación, la solución es activar session pickup, no agregar enlaces de heartbeat ni override.
  • Dos datos del Fabric se repiten en el examen: el root debe tener FortiAnalyzer o registro en la nube, y los equipos downstream se autorizan en el root por número de serie. Una cuenta compartida o una VPN no crean un Fabric.
  • Cuando la pregunta pide la forma más simple de reaccionar al instante ante un evento, elige un automation stitch. Los reportes programados y el reenvío de syslog no son inmediatos y necesitan herramientas adicionales.
  • Los registros en memoria se borran al reiniciar. Para cualquier pregunta sobre conservar el historial de registros, la respuesta es un destino persistente: disco, FortiAnalyzer, FortiGate Cloud o syslog, no un búfer de memoria más grande.
  • Agregar vCPUs más allá de lo que permite la licencia de la VM no aumenta el rendimiento. En la nube, recuerda que el tráfico llega al FortiGate a través de las tablas de rutas de la nube, y que la HA usa mecanismos SDN, no MACs compartidas.
  • av-failopen rige el antivirus por proxy en conserve mode; IPS fail-open rige el motor IPS. No los confundas. Y un rastreo de flujo no imprime nada hasta que ejecutas diagnose debug enable.

Términos clave

Management IP (192.168.1.99) (IP de gestión)
La dirección predeterminada en la interfaz de gestión o interna de un FortiGate de fábrica, a la que se accede por HTTPS para el primer inicio de sesión.
Default admin account (cuenta admin predeterminada)
La cuenta integrada llamada admin con contraseña en blanco; FortiOS obliga a definir una contraseña nueva en el primer inicio de sesión.
Administrative access (acceso administrativo)
La lista, por interfaz, de servicios de gestión (HTTPS, SSH, PING, SNMP y otros) a los que el FortiGate responderá en esa interfaz.
Interface role (rol de interfaz)
Una etiqueta (LAN, WAN, DMZ o Undefined) que ajusta qué campos de configuración se muestran para una interfaz; por sí sola no filtra tráfico.
allowaccess
La palabra clave de la CLI, dentro de una interfaz del sistema, que define qué protocolos de gestión acepta la interfaz; set reemplaza la lista y append agrega a ella.
Admin profile / access profile (perfil de administrador / perfil de acceso)
Permisos None, Read o Read/Write por área funcional que definen lo que un administrador puede hacer; super_admin es el perfil integrado completo y no se puede editar.
Trusted hosts (hosts de confianza)
Una lista, por cuenta, de direcciones o subredes de origen permitidas; una vez definida, se rechazan los inicios de sesión de esa cuenta desde cualquier otra dirección.
MFA / two-factor para administradores (autenticación multifactor)
Un segundo factor de inicio de sesión, como un código de FortiToken, que protege contra contraseñas robadas pero no limita las redes de origen.
Password policy (política de contraseñas)
Reglas de longitud, complejidad de caracteres y caducidad para las contraseñas de administrador, aplicables de forma opcional a las claves precompartidas de IPsec.
Least privilege (mínimo privilegio)
Dar a cada cuenta solo los permisos que necesita, por ejemplo acceso de solo lectura a los registros para una auditora.
Upgrade path (ruta de actualización)
La secuencia ordenada de compilaciones intermedias de FortiOS que Fortinet exige entre dos versiones para que la configuración se convierta correctamente.
Configuration backup (respaldo de la configuración)
Una copia guardada de toda la configuración del FortiGate, opcionalmente cifrada con una contraseña, que se usa para revertir cambios o clonar equipos idénticos.
Encrypted backup (respaldo cifrado)
Un respaldo protegido con una contraseña; solo se puede restaurar en un FortiGate y solo con esa contraseña.
Restore (restauración)
Cargar un archivo de configuración guardado, lo que reemplaza la configuración en ejecución y reinicia el equipo.
Release notes (notas de la versión)
El documento de Fortinet para cada compilación que enumera la ruta de actualización soportada, los problemas resueltos, los problemas conocidos y los cambios de comportamiento.
VDOM (virtual domain, dominio virtual)
Una instancia aislada en un FortiGate con sus propias interfaces, tabla de enrutamiento, políticas, perfiles y administradores.
Root VDOM (VDOM root)
La VDOM predeterminada que siempre existe, no se puede eliminar y, de forma predeterminada, es la VDOM de gestión para el tráfico de todo el equipo, como las actualizaciones de FortiGuard y el registro.
Global vs per-VDOM settings (ajustes globales vs por VDOM)
Los ajustes globales (firmware, HA, nombre de host, administradores globales) se aplican a todo el equipo; los ajustes por VDOM (interfaces, rutas, políticas, perfiles) pertenecen a una sola VDOM.
Inter-VDOM link (enlace entre VDOMs)
Un par virtual de interfaces que conecta dos VDOMs para que el tráfico pueda pasar entre ellas bajo el control de rutas y políticas.
Split-task VDOM mode (modo de VDOM de tareas divididas)
Un modo con exactamente dos VDOMs: root para la gestión y FG-traffic para el tráfico de los usuarios.
FGCP
FortiGate Clustering Protocol, que une FortiGates idénticos en un solo clúster HA con direcciones MAC virtuales compartidas.
Active-passive vs active-active (activo-pasivo vs activo-activo)
Activo-pasivo: solo el primario reenvía tráfico. Activo-activo: el primario además distribuye a los secundarios las sesiones de inspección de perfiles de seguridad.
Heartbeat link (enlace de heartbeat)
Una interfaz dedicada que transporta la salud de HA, la sincronización de configuración y la de sesiones; se usan dos para evitar el split brain.
Monitored interface (interfaz monitoreada)
Un puerto que HA vigila; gana la elección el equipo con más puertos monitoreados conectados, así que la caída de un enlace monitoreado provoca una conmutación.
Override
Un ajuste de HA que coloca la prioridad del dispositivo antes del uptime en la elección, para que un equipo preferido recupere el rol de primario tras recuperarse.
Split brain (cerebro dividido)
Una falla en la que los miembros pierden todo contacto de heartbeat y cada uno actúa como primario al mismo tiempo.
Session pickup (sincronización de sesiones)
Sincronización de sesiones de HA que permite que las sesiones establecidas sobrevivan a una conmutación; desactivada de forma predeterminada por su costo de CPU y de heartbeat; solo TCP a menos que se active la sincronización sin conexión (connectionless).
Configuration sync (sincronización de configuración)
La replicación automática de la configuración del primario a los secundarios para que todos los miembros permanezcan idénticos, salvo algunos ajustes propios de cada equipo, como el nombre de host y la prioridad de HA.
HA checksum
Un hash de las áreas de configuración que se compara entre miembros para confirmar que están sincronizados; una diferencia revela qué área difiere.
get system ha status
Un comando de la CLI que muestra el modo de HA, los miembros, el primario, el uptime de HA, las interfaces monitoreadas y el estado de sincronización.
execute ha manage
Un comando de la CLI que te conecta desde un miembro del clúster a la consola de otro miembro a través del enlace de heartbeat.
Fabric root (root del Fabric)
El FortiGate superior de un Security Fabric, que agrega la topología y los datos; requiere FortiAnalyzer o un servicio de registro en la nube.
Downstream FortiGate (FortiGate downstream)
Un FortiGate que se une al Fabric conectándose a la IP upstream (normalmente la del root) y siendo autorizado por el root.
Fabric authorization (autorización del Fabric)
La aprobación por parte del root de un equipo downstream mediante su número de serie, que completa la unión y bloquea dispositivos desconocidos.
Security Fabric Connection
La opción de acceso administrativo (antes FortiTelemetry) que debe estar activada en la interfaz upstream para que los dispositivos downstream puedan conectarse.
Security Rating (calificación de seguridad)
Una función del Fabric que compara los dispositivos con las buenas prácticas de Fortinet y devuelve una puntuación con hallazgos priorizados y correcciones sugeridas.
Automation stitch
Una regla que combina un trigger con una o más acciones para que el FortiGate responda automáticamente a un evento.
Trigger (disparador)
El evento que inicia un stitch, como un cambio de configuración, una conmutación de HA, una detección de seguridad, una programación o un webhook entrante.
Action (acción)
Lo que hace un stitch cuando se dispara: correo electrónico, webhook saliente, script de CLI o cuarentena, entre otras.
Webhook
Una solicitud HTTP enviada a otro sistema (o recibida de él) para integrarse con herramientas de chat, de tickets o de orquestación.
Quarantine action (acción de cuarentena)
Una acción que aísla un host comprometido, por ejemplo bloqueando su IP en el FortiGate o su MAC en un switch o punto de acceso gestionado.
Traffic log (registro de tráfico)
Un registro de las sesiones que pasan por las políticas de firewall, incluido el ID de la política y el resultado de permitir o denegar.
Event log (registro de eventos)
Un registro de la actividad propia del FortiGate: inicios de sesión y cambios de los administradores, HA, VPN, enrutamiento y salud del sistema.
Security (UTM) log (registro de seguridad)
Un registro de las acciones de los perfiles de seguridad, como eventos de antivirus, filtro web, IPS, control de aplicaciones y filtro DNS.
Log allowed traffic (registrar tráfico permitido)
Un ajuste por política (desactivado, Security Events, All Sessions) que controla qué sesiones aceptadas se registran.
Severity level (nivel de severidad)
La importancia de una entrada de registro, desde emergency, alert y critical hasta warning, notification, information y debug.
FortiGate-VM
FortiOS ejecutándose como máquina virtual en un hipervisor o en una nube pública, licenciado por software.
VM licensing, vCPU-bound (licenciamiento de VM ligado a vCPUs)
Una licencia ligada a un modelo virtual que limita las vCPUs utilizables; las vCPUs adicionales más allá de la licencia no agregan capacidad.
BYOL vs PAYG
Modelos de licenciamiento en la nube: bring your own license usa una licencia que compraste; pay as you go cobra la licencia por hora a través del proveedor de nube.
SDN connector (conector SDN)
Una integración de FortiOS con una plataforma de nube o de virtualización que habilita objetos de dirección dinámicos (etiquetas, grupos) y llamadas a la API para la HA en la nube.
Cloud route table (tabla de rutas de la nube)
La configuración de enrutamiento de la red de la nube que debe apuntar el tráfico a la interfaz del FortiGate como siguiente salto para que se inspeccione.
get system performance status
Un resumen en la CLI de la carga en vivo de CPU, memoria, sesiones y rendimiento, más el uptime.
diagnose sys top
Una lista en vivo de los procesos que más CPU y memoria usan, útil para encontrar procesos descontrolados.
Conserve mode (modo de conservación)
Un estado de protección al que se entra cuando el uso de memoria cruza el umbral rojo, y que detiene las nuevas sesiones de inspección basada en proxy hasta que la memoria baja del umbral verde.
av-failopen
El ajuste global que decide si, durante el conserve mode, el tráfico que necesita antivirus por proxy pasa sin inspeccionar (pass, el predeterminado), se bloquea (off) u omite el AV hasta que un administrador cambie el ajuste (one-shot).
diagnose debug flow
Un rastreo de cómo el FortiGate maneja un paquete, que muestra la búsqueda de ruta, la coincidencia de política, el NAT y cualquier motivo de denegación.
diagnose sniffer packet
Una herramienta de captura de paquetes que muestra el tráfico de una interfaz, similar a tcpdump.

Dominio 2: Firewall policies and authentication (22%)

Consejos para el examen

  • El ID de la política es solo una etiqueta. Cuando una regla específica no surte efecto, mira su posición en la lista, no su número, y revisa si una regla más amplia que está por encima coincide primero.
  • Para un servicio en la nube grande y cambiante, elige la entrada de ISDB. Un solo FQDN pierde muchos extremos y un objeto de geografía es demasiado amplio para identificar un servicio.
  • El ID de política es fijo y no define el orden; la secuencia (posición en la lista) sí. Reordenar cambia la secuencia, no los ID, así que nunca razones la coincidencia a partir del número de ID.
  • One-to-one limita los usuarios simultáneos a la cantidad de direcciones del pool porque no usa traducción de puertos. Para muchos usuarios con pocas IP, elige overload.
  • Central SNAT y el NAT por política son mutuamente excluyentes. Después de habilitar central SNAT, las políticas ya no traducen por sí mismas; debes recrear las traducciones como entradas de la tabla o el tráfico saldrá sin traducir.
  • El destino de la política de entrada es la propia VIP, no la IP interna. Solo una VIP de port forwarding reescribe el puerto; un objeto de servicio solo identifica el tráfico y nunca traduce puertos.
  • Las políticas hacen referencia a grupos de usuarios, no directamente a entradas de servidores LDAP o RADIUS. Para buscar grupos en Active Directory, elige regular bind, ya que anonymous y simple bind no pueden consultar la pertenencia a grupos.
  • Los captive portals solo se activan con HTTP y HTTPS (y en algunos casos FTP y Telnet), y el DNS no puede activarlos. Permite siempre DNS en una política por encima de la política de autenticación, o el inicio de sesión será imposible.
  • Si los miembros de un grupo nuevo de AD nunca coinciden con las políticas, revisa primero el filtro de grupos de FSSO. Probablemente ese grupo no está seleccionado, así que su pertenencia nunca se envía al FortiGate.
  • FortiToken se asigna por cuenta de usuario, no mediante un interruptor en un perfil de administrador ni una regla de contraseñas. Habilitar los dos factores en la cuenta y vincular el token es la respuesta de configuración.

Términos clave

Matching criteria (criterios de coincidencia)
Los campos que FortiGate compara para ubicar una sesión: interfaz de entrada y de salida, origen (dirección, usuario, ISDB), destino, servicio y horario.
Top-down first match (primera coincidencia de arriba hacia abajo)
Las políticas se evalúan en el orden de la lista y se usa la primera que coincide por completo; decide la posición en la lista, no el ID de la política.
Implicit deny, policy 0 (denegación implícita)
La regla final que descarta todo el tráfico que no coincidió con ninguna política, haciendo que el FortiGate deniegue de forma predeterminada; no registra de forma predeterminada.
ISDB (Internet Service Database, base de datos de servicios de internet)
Una base de datos mantenida por FortiGuard con las direcciones y los puertos de servicios de internet, que las políticas pueden usar como origen o destino.
Security profile timing (momento de aplicación de los perfiles de seguridad)
Los perfiles se aplican después de que una política coincide, así que nunca influyen en qué política se selecciona.
Address object (objeto de dirección)
Un host, subred o rango IP con nombre que puede reutilizarse como origen o destino en muchas políticas.
Address group (grupo de direcciones)
Un conjunto con nombre de objetos de dirección; al editarlo se actualizan todas las políticas que hacen referencia a él.
FQDN object (objeto FQDN)
Un objeto de dirección basado en un nombre de dominio que el FortiGate resuelve mediante DNS y mantiene actualizado.
Geography object (objeto de geografía)
Un objeto de dirección que cubre todos los rangos IP asignados a un país, según los datos de geolocalización de FortiGuard.
Internet Service Database (ISDB)
Un catálogo mantenido por FortiGuard de servicios públicos con sus direcciones, protocolos y puertos actuales, que puede usarse como origen o destino de una política.
Log Allowed Traffic
Un ajuste por política con las opciones desactivado, Security Events (solo sesiones sobre las que actuó un perfil) o All Sessions (todas las sesiones aceptadas).
Policy lookup tool (herramienta de búsqueda de políticas)
Una herramienta de la GUI que toma parámetros de una sesión hipotética e indica con qué política coincidirían, usando el orden real de la lista.
Policy ID (ID de política)
Una etiqueta estable asignada al crearla que no cambia cuando la política se mueve; identifica una política en los registros y la CLI, pero no define el orden de coincidencia.
Sequence (secuencia)
La posición de una política en la lista, que es lo que realmente determina el orden de coincidencia de arriba hacia abajo.
Recurring vs one-time schedule (horario recurrente vs de una sola vez)
Los horarios recurrentes se repiten en los días y horas elegidos; los de una sola vez están activos una vez durante una única ventana y luego vencen.
Source NAT (SNAT)
Reescribir la dirección de origen del tráfico saliente para que los hosts privados aparezcan con una dirección pública.
Port address translation, PAT (traducción de direcciones de puerto)
Permitir que muchos hosts compartan una IP pública asignando a cada sesión un puerto de origen único.
Overload IP pool (IP pool overload)
Un pool en el que muchos hosts internos comparten las direcciones públicas del pool usando traducción de puertos.
One-to-one IP pool (IP pool uno a uno)
Un pool que asigna a cada host su propia dirección pública sin traducción de puertos, lo que limita los hosts simultáneos al tamaño del pool.
Fixed port range / port block allocation (rango de puertos fijo / asignación de bloques de puertos)
Tipos de pool que asignan hosts internos a IP externas y a rangos o bloques de puertos predecibles, lo que reduce el volumen de registros y permite el rastreo.
Central SNAT
Un modo en el que las reglas de source NAT viven en una única tabla ordenada en lugar de en las políticas de firewall individuales.
Per-policy NAT (NAT por política)
El modo predeterminado en el que cada política de firewall tiene su propio ajuste de NAT y su elección de traducción.
Central SNAT table order (orden de la tabla de central SNAT)
La evaluación de arriba hacia abajo de las entradas de central SNAT, donde la primera entrada que coincide decide la traducción.
DNAT and Virtual IPs table (tabla de DNAT e IP virtuales)
En el modo central NAT, el lugar donde las VIP se aplican de forma central; las políticas entonces hacen referencia a la dirección interna asignada.
Destination NAT, DNAT (NAT de destino)
Traducir la dirección de destino, y opcionalmente el puerto, del tráfico entrante para que los usuarios externos puedan llegar a un servidor interno.
Virtual IP, VIP (IP virtual)
Un objeto de FortiGate que realiza NAT de destino asignando una IP y un puerto externos a unos internos.
Static NAT VIP (VIP de NAT estático)
Una VIP que asigna toda la dirección externa a la dirección interna para todos los puertos (uno a uno).
Port forwarding VIP (VIP de reenvío de puertos)
Una VIP que asigna un puerto externo específico a un puerto interno específico, reescribiendo tanto la dirección como el puerto.
VIP group (grupo de VIP)
Un conjunto de VIP referenciadas juntas como destino de una sola política de entrada.
Local user (usuario local)
Una cuenta definida directamente en el FortiGate con su propio nombre de usuario y contraseña; sencilla, pero no escala.
LDAP regular bind
Usar el DN y la contraseña de una cuenta de servicio para que el FortiGate pueda buscar en el directorio y leer la pertenencia a grupos, como lo exige Active Directory.
RADIUS
Un protocolo AAA muy usado para la autenticación de usuarios que puede devolver atributos de grupo o rol; usa un secreto compartido con el FortiGate.
TACACS+
Un protocolo AAA común para la administración de dispositivos que separa la autenticación, la autorización y la contabilidad.
User group (grupo de usuarios)
Un objeto de FortiGate que combina usuarios locales y/o un servidor remoto con una coincidencia de grupo opcional, referenciado en el origen de una política para exigir autenticación.
Active authentication / captive portal (autenticación activa / portal cautivo)
Solicitar explícitamente las credenciales del usuario mediante una página de inicio de sesión antes de permitir su tráfico.
Passive authentication (autenticación pasiva)
Identificar a los usuarios sin solicitarles nada, aprendiendo los inicios de sesión de otra fuente, normalmente FSSO.
Idle vs hard timeout (tiempo de espera por inactividad vs absoluto)
El idle timeout cierra la sesión de un usuario tras un período de inactividad; el hard timeout la cierra un tiempo fijo después del inicio de sesión, sin importar la actividad.
DNS-before-login rule (regla de DNS antes del inicio de sesión)
Una política que permite DNS sin autenticación, ubicada por encima de la política con captive portal, para que los navegadores puedan resolver nombres y llegar a la página de inicio de sesión.
Collector agent (agente recolector)
Un servicio de Windows que reúne datos de inicios de sesión y envía al FortiGate las asociaciones de usuario, IP y grupo.
DC agent mode (modo DC agent)
Un agente en cada controlador de dominio que envía los eventos de inicio de sesión al collector en tiempo real.
Polling mode (modo polling o de sondeo)
El collector, o el FortiGate en agentless polling, lee periódicamente y de forma remota la información de inicios de sesión de los DC, sin software en los DC pero con más retraso.
Group filter (filtro de grupos)
La selección de grupos de AD que FSSO informa al FortiGate; los grupos no seleccionados nunca se envían.
diagnose debug authd fsso list
Un comando de la CLI de FortiGate que muestra las entradas de inicio de sesión FSSO actuales: usuario, dirección IP y grupos.
Two-factor authentication, 2FA (autenticación de dos factores)
Exigir una contraseña más una segunda prueba, como un código de token, para que una contraseña robada por sí sola no permita iniciar sesión.
FortiToken
El token de contraseñas de un solo uso de Fortinet, disponible como llavero de hardware o como la aplicación FortiToken Mobile, que proporciona un segundo factor TOTP.
TOTP
Una contraseña de un solo uso basada en el tiempo que cambia en un intervalo corto; es el código que muestra un FortiToken.
Per-user assignment (asignación por usuario)
Habilitar los dos factores en una cuenta individual y vincularle un token específico, en lugar de usar un interruptor global.

Dominio 3: Content inspection (26%)

Consejos para el examen

  • Solo la deep inspection puede analizar la carga útil (antivirus, URL completas, acciones dentro de las aplicaciones). La certificate inspection solo ve la SNI y el certificado. Los clientes deben confiar en la CA del FortiGate, o cada sitio mostrará una advertencia.
  • Son dos decisiones separadas: flow vs proxy (motor) y profile-based vs policy-based (estilo de reglas). En el modo profile-based, el modo de inspección se elige por política, no de forma global ni por interfaz.
  • Exempt corta todas las revisiones restantes; Allow solo supera la etapa del filtro de URL estático y todavía puede ser bloqueada por la categoría de FortiGuard. Usa Exempt para garantizar que una página cargue.
  • La ventaja clave del filtrado DNS para el examen es que bloquea dominios maliciosos en el momento de la consulta, para cualquier protocolo y sin descifrado. No ve las rutas de las URL ni analiza archivos, así que combínalo con filtrado web y antivirus para tener más profundidad, y recuerda que la búsqueda segura basada en DNS evita la necesidad de inspección profunda.
  • El control de aplicaciones identifica las aplicaciones por firma, así que usa categorías y excepciones, no reglas de puertos ni categorías web, para detener cosas como BitTorrent. Las excepciones por aplicación apuntan a una aplicación con nombre; las excepciones por filtro apuntan a un conjunto definido por atributos. Controlar acciones dentro de una aplicación cifrada requiere inspección profunda.
  • El CDR y el bloqueo confiable del archivo completo con mensajes de reemplazo necesitan el modo proxy; el modo de flujo es más rápido pero más limitado. Las firmas detectan malware conocido, y el sandbox es lo que agrega análisis de comportamiento para archivos desconocidos. Para HTTPS, el AV necesita inspección profunda para poder ver el archivo.
  • Ajusta el IPS con filtros de firmas (objetivo, sistema operativo, aplicación, severidad) en lugar de habilitarlo todo, usa exenciones de IP para los falsos positivos entre equipos específicos y habilita el bloqueo de C&C de botnets para contener a los equipos infectados. No confundas IPS fail-open con av-failopen.
  • Las políticas DoS actúan en la interfaz de entrada antes de la búsqueda de políticas de firewall; por eso ellas, y no el control de aplicaciones, el IPS ni los IP pools, son la respuesta para detener temprano una inundación SYN. Establece una línea base del tráfico y empieza en modo de monitoreo antes de definir umbrales de bloqueo.
  • Cuando las firmas parecen desactualizadas o fallan las calificaciones, ejecuta diagnose autoupdate versions para revisar la vigencia de las bases de datos y el derecho de uso, y luego revisa el acceso a FortiGuard y el licenciamiento. Cuando un registro está en silencio, confirma que el perfil esté asociado, que el registro esté activado y que el tráfico realmente se haya inspeccionado.

Términos clave

Certificate inspection (inspección de certificados)
Inspección SSL que lee solo el handshake (SNI y certificado) sin descifrar, lo que permite identificar categorías y aplicaciones, pero no analizar la carga útil.
Deep inspection (inspección profunda)
Inspección SSL completa que descifra, inspecciona y vuelve a cifrar el tráfico usando un certificado refirmado por la CA del FortiGate; necesaria para el antivirus y la inspección detallada.
CA trust distribution (distribución de confianza en la CA)
Enviar a los clientes la CA de firma del FortiGate mediante GPO o MDM para que los certificados refirmados sean de confianza y cesen las advertencias.
Inspection exemption (exención de inspección)
Una regla que omite el descifrado para las categorías o direcciones elegidas, como sitios bancarios o de salud, mientras se aplica deep inspection al resto del tráfico.
Certificate pinning (fijación de certificados)
Una aplicación que acepta solo su propio certificado esperado, por lo que rechaza el refirmado por el FortiGate y requiere una exención.
Flow-based inspection (inspección basada en flujo)
Analizar el tráfico a medida que pasan los paquetes con un búfer mínimo; menor latencia y mayor rendimiento, pero menos funciones que requieren el objeto completo.
Proxy-based inspection (inspección basada en proxy)
Almacenar en búfer el objeto completo antes de analizarlo; admite CDR y mensajes de reemplazo, con un mayor costo de memoria y latencia.
Content disarm and reconstruction, CDR (desarme y reconstrucción de contenido)
Eliminar el contenido activo, como las macros, de los archivos y reenviar una versión limpia; requiere inspección proxy-based.
Profile-based NGFW mode (modo NGFW basado en perfiles)
El estilo predeterminado en el que los perfiles de seguridad se asocian a las políticas de firewall y el modo de inspección se define por política.
Policy-based NGFW mode (modo NGFW basado en políticas)
Un estilo en el que las aplicaciones y categorías de URL se referencian directamente en las políticas de seguridad, con la inspección SSL y el NAT en políticas separadas.
FortiGuard category action (acción por categoría de FortiGuard)
El comportamiento por categoría en un perfil de filtro web: Allow, Monitor, Warning, Authenticate o Block.
Warning action (acción de advertencia)
Muestra una página intermedia que le permite al usuario elegir continuar, a diferencia de Block, que no da ninguna opción.
Static URL filter, Exempt vs Allow (filtro de URL estático)
Una lista de URL que se revisa antes de las categorías; Exempt se salta todas las revisiones restantes, mientras que Allow todavía pasa la URL a la revisión por categoría.
Rating error handling (manejo de errores de calificación)
El ajuste que permite los sitios web cuando no se puede contactar a FortiGuard para calificarlos, en lugar de bloquearlos.
Web filter override (excepción del filtro web)
Una excepción controlada y temporal que permite que un usuario autenticado use un perfil menos restrictivo; un web rating override recategoriza una URL de forma local.
DNS filtering (filtrado DNS)
Calificar el dominio de una consulta DNS y actuar sobre él para que los dominios no deseados se bloqueen en el momento de la consulta, para cualquier protocolo y sin descifrado TLS.
Block at lookup (bloqueo en la consulta)
Impedir la resolución de nombres de un dominio no deseado para que el cliente nunca se conecte a él.
Redirect to block portal (redirigir al portal de bloqueo)
Una acción del filtro DNS que responde la consulta con la dirección de la página de bloqueo del FortiGate para que los usuarios vean una explicación.
Safe search enforcement (imposición de búsqueda segura)
Obligar a los buscadores y a algunos sitios de video a usar su modo apto para toda la familia, de modo que los resultados explícitos se filtren sin importar la configuración del usuario.
Protocol independence (independencia del protocolo)
El filtrado DNS funciona para cualquier aplicación porque actúa sobre la consulta, no sobre cargas útiles descifradas.
Application control sensor (sensor de control de aplicaciones)
Un perfil de acciones por aplicación y por categoría, asociado a una política de firewall, que identifica las aplicaciones mediante firmas de FortiGuard.
Category action (acción por categoría)
La acción aplicada a toda una categoría de aplicaciones, como bloquear Peer-to-Peer, efectiva sin importar el puerto.
Application override (excepción por aplicación)
Una regla por firma que define para una aplicación específica una acción diferente de la de su categoría.
Filter override (excepción por filtro)
Una regla que selecciona aplicaciones por atributos (categoría, popularidad, tecnología, riesgo, fabricante) y aplica una acción a ese conjunto.
In-app control (control dentro de la aplicación)
Actuar sobre comportamientos específicos dentro de una aplicación, como las subidas, lo cual requiere inspección profunda en las aplicaciones cifradas.
Flow vs proxy AV (AV basado en flujo vs en proxy)
Flow escanea a medida que pasan los paquetes con un búfer mínimo (rápido); proxy almacena el archivo completo antes de reenviarlo (más funciones, más costo).
Signature database (base de datos de firmas)
Firmas de malware actualizadas por FortiGuard con las que el FortiGate compara los archivos; detecta amenazas conocidas, pero no las totalmente nuevas.
Sandbox (FortiSandbox / nube)
Un entorno aislado que ejecuta archivos desconocidos para detectar malware por su comportamiento, capturando amenazas de día cero que las firmas no detectan.
Grayware
Software no deseado pero no claramente malicioso, como el adware o el riskware, que un perfil AV puede detectar como una opción separada.
IPS sensor (sensor IPS)
Un perfil de firmas y acciones seleccionadas asociado a una política de firewall para detectar y bloquear ataques.
Signature filter (filtro de firmas)
Una regla que selecciona firmas por objetivo, sistema operativo, aplicación o protocolo y severidad para mantener la inspección enfocada.
Rate-based signature (firma basada en tasa)
Una firma que se activa cuando un evento supera un umbral a lo largo del tiempo, como intentos repetidos de inicio de sesión.
Botnet C&C blocking (bloqueo de C&C de botnets)
Una opción de IPS que usa la base de datos de FortiGuard para bloquear las conexiones salientes hacia servidores de comando y control conocidos.
IP exemption (exención de IP)
Una exclusión de direcciones de origen y destino específicas de una sola firma, usada para corregir un falso positivo de forma puntual.
IPS fail-open
El ajuste que deja pasar el tráfico sin inspeccionar cuando el motor de IPS está sobrecargado (disponibilidad) frente a descartarlo (seguridad).
DoS policy (política DoS)
Una regla evaluada temprano en la entrada de una interfaz que aplica umbrales de anomalías para descartar o registrar tráfico de inundación y escaneo antes de la búsqueda de políticas de firewall.
Anomaly sensor (sensor de anomalías)
Un detector de un patrón específico (inundación SYN, escaneo de puertos, inundación UDP o ICMP, cantidad de sesiones) con un umbral y una acción configurables.
Threshold (umbral)
La tasa o cantidad a partir de la cual una anomalía dispara su acción; se define por encima de los picos normales para evitar falsos positivos.
Early evaluation (evaluación temprana)
Las políticas DoS se ejecutan antes que las políticas de firewall y la mayor parte de la inspección, lo que les permite deshacerse de las inundaciones a bajo costo.
Monitor mode (modo de monitoreo)
Una acción de anomalía que registra cuando se supera el umbral sin bloquear, usada para establecer una línea base del tráfico antes de aplicar el bloqueo.
Security (UTM) log (registro de seguridad)
El registro de las acciones de los perfiles de seguridad (AV, filtro web, control de aplicaciones, IPS, DNS) con origen, destino, firma y acción.
FortiGuard connectivity (conectividad con FortiGuard)
La capacidad del FortiGate de comunicarse con FortiGuard para obtener actualizaciones de firmas y calificaciones, de la que dependen la mayoría de los perfiles de seguridad.
diagnose autoupdate versions
Un comando de la CLI que muestra la versión de cada base de datos de FortiGuard, la hora de su última actualización y el estado del derecho de uso.
Rating error (error de calificación)
Un síntoma del filtro web que aparece cuando no se puede contactar a FortiGuard para categorizar un sitio.
execute update-now
Un comando de la CLI que dispara un intento inmediato de actualización desde FortiGuard.

Dominio 4: Routing (14%)

Consejos para el examen

  • Las rutas de política se evalúan antes que la tabla de enrutamiento, de arriba hacia abajo, y gana la primera coincidencia. Dentro de la tabla, el orden es coincidencia de prefijo más largo, luego distancia, luego prioridad y luego ECMP. La especificidad (longitud del prefijo) siempre gana antes que la distancia.
  • La distancia decide qué rutas están en la tabla (una activa); la prioridad decide la preferencia entre las rutas que ya están en la tabla (todas activas). Usa la distancia para un respaldo en frío y la prioridad para un respaldo en caliente. El ECMP balancea sesiones, por IP de origen salvo que se configure otra cosa.
  • Las rutas de respaldo y las de mayor distancia aparecen solo en la vista de base de datos, no en la tabla de enrutamiento activa. Usa routing-table all para las rutas activas y la palabra clave database para todo lo conocido, donde > marca la ruta seleccionada y * marca la entrada de la tabla de reenvío.
  • Una falla de RPF (camino inverso) en un debug flow casi siempre significa una ruta de regreso faltante o inactiva hacia la subred de origen por la interfaz de entrada, algo común después de crear subredes nuevas o de cambios de enrutamiento asimétrico. Agrega la ruta en lugar de desactivar la comprobación, y recuerda que solo cuentan las rutas activas.
  • El link monitor es lo que detecta un camino muerto y elimina la ruta, ya que de lo contrario una ruta sigue activa mientras su interfaz esté activa; sondea un objetivo más allá del gateway. Las rutas blackhole con una distancia alta evitan que el tráfico se filtre cuando un túnel se cae.
  • Dos trampas de SD-WAN: las políticas deben referenciar la zona, no la interfaz miembro, y debes agregar una ruta predeterminada estática que apunte a la zona, o las reglas de SD-WAN no tendrán tráfico que dirigir. Recuerda que las interfaces deben estar libres de referencias antes de poder convertirse en miembros.
  • Sondea un destino que represente el destino real, no el gateway local, o el SLA no verá la pérdida del lado de internet. Un miembro debe cumplir todos los umbrales de un objetivo. El SLA solo mide; las reglas de SD-WAN actúan según qué miembros cumplen el objetivo.
  • Best quality siempre persigue la mejor métrica aunque el enlace actual esté bien; lowest cost (SLA) solo cambia cuando el enlace barato reprueba el SLA. Ajusta la estrategia a la intención que plantea la pregunta y recuerda que las reglas funcionan por primera coincidencia, de arriba hacia abajo, por encima de la regla implícita.
  • Health-check muestra las mediciones y si se aprueba o reprueba el SLA; service muestra qué miembro eligió cada regla. Revisa primero las mediciones, porque las reglas actúan según el estado de SLA, y luego revisa cómo las usó la regla.

Términos clave

Policy route, PBR (ruta basada en políticas)
Una regla que se evalúa antes de la tabla de enrutamiento y obliga al tráfico coincidente a salir por una interfaz o un gateway especificados, anulando el enrutamiento basado en el destino.
Longest prefix match (coincidencia de prefijo más largo)
La regla de enrutamiento según la cual la ruta más específica (máscara más larga) hacia un destino se prefiere sobre las menos específicas.
Administrative distance (distancia administrativa)
Una medida de confianza en el origen de una ruta; entre rutas con el mismo prefijo, la de menor distancia se instala como activa.
Priority, static (prioridad en rutas estáticas)
Un criterio de desempate entre rutas con el mismo prefijo y la misma distancia; se prefiere el valor más bajo, mientras ambas permanecen en la tabla.
ECMP
Multitrayecto de igual costo (equal-cost multipath): las rutas empatadas en prefijo, distancia y prioridad quedan todas activas y se reparten las sesiones.
Priority (prioridad)
Entre rutas con igual distancia (todas activas), se prefiere para el reenvío el valor de prioridad más bajo, mientras las demás siguen siendo utilizables.
Floating static route (ruta estática flotante)
Una ruta estática de respaldo con una distancia mayor, para que permanezca fuera de la tabla hasta que falle la ruta principal.
ECMP load-balancing method (método de balanceo de carga ECMP)
Cómo se reparten las sesiones entre rutas con igual distancia e igual prioridad: por IP de origen (predeterminado), por IP de origen y destino, ponderado o basado en el uso.
Session affinity (afinidad de sesión)
Mantener todas las sesiones de un cliente en el mismo camino, lo que proporciona el método ECMP predeterminado basado en la IP de origen.
Routing table, RIB (tabla de enrutamiento)
Las rutas activas que se usan actualmente para reenviar tráfico; se muestran con get router info routing-table all.
Routing database (base de datos de enrutamiento)
Todas las rutas candidatas que conoce el FortiGate, activas e inactivas; se muestran con get router info routing-table database.
Active vs inactive route (ruta activa vs inactiva)
Una ruta activa está instalada y reenviando; una ruta inactiva (por ejemplo, un respaldo con mayor distancia) espera en la base de datos.
Standby or backup route (ruta en espera o de respaldo)
Una ruta (a menudo una ruta estática flotante) que permanece en la base de datos hasta que se elimine la ruta activa.
Selected and FIB markers (marcas de seleccionada y de FIB)
En la salida de la base de datos, un > marca la ruta seleccionada y un * marca una ruta instalada en la tabla de reenvío.
Reverse path forwarding, RPF (reenvío por camino inverso)
Una comprobación anti-spoofing que descarta las sesiones nuevas cuyo origen no tiene una ruta de regreso válida por la interfaz por la que llegaron.
Strict RPF (RPF estricto)
Un modo que exige que la mejor ruta de regreso al origen use la misma interfaz por la que llegó el paquete.
Feasible-path / loose RPF (RPF de camino factible o flexible)
El modo predeterminado y más permisivo, que acepta el paquete si existe alguna ruta activa de regreso al origen por la interfaz de entrada, aunque no sea la mejor ruta.
Asymmetric routing (enrutamiento asimétrico)
Una situación en la que el tráfico toma caminos diferentes en cada sentido; un detonante común de descartes por RPF cuando falta la ruta de regreso.
src-check
El ajuste de interfaz que puede desactivar el RPF en una interfaz específica, lo que elimina ahí la protección anti-spoofing.
Link health monitor (monitor de salud del enlace)
Un sondeo activo (ping de forma predeterminada, u otros tipos como TCP echo o HTTP) a través de una interfaz que retira las rutas asociadas cuando el camino falla.
Route withdrawal on failure (retiro de ruta ante falla)
Eliminar una ruta estática de la tabla cuando su monitor de salud detecta un camino muerto, lo que permite que un respaldo tome el control.
Blackhole route (ruta blackhole o agujero negro)
Una ruta que descarta en silencio el tráfico coincidente, normalmente con una distancia alta para que se active solo cuando la ruta real ya no está.
Traffic leak prevention (prevención de fugas de tráfico)
Usar una ruta blackhole para que, cuando un túnel o una ruta se cae, el tráfico sensible se descarte en lugar de seguir la ruta predeterminada hacia afuera.
Probe target (objetivo del sondeo)
La dirección que prueba un link monitor, idealmente más allá del gateway para que se compruebe el camino completo.
SD-WAN member (miembro de SD-WAN)
Una interfaz WAN o un túnel agregado a SD-WAN como camino seleccionable, con ajustes por miembro como el gateway y el costo.
SD-WAN zone (zona de SD-WAN)
Un grupo de miembros que las políticas de firewall y las rutas referencian en lugar de las interfaces individuales; virtual-wan-link es la zona predeterminada.
Zone reference in policy (referencia a la zona en la política)
Después de que una interfaz se convierte en miembro, las políticas seleccionan la zona de SD-WAN, no la interfaz directamente.
Route to the zone (ruta hacia la zona)
Una ruta estática (normalmente predeterminada) que apunta a la zona de SD-WAN, necesaria para que la tabla de enrutamiento entregue el tráfico a SD-WAN.
Performance SLA (SLA de rendimiento)
Una verificación de salud que mide la latencia, el jitter y la pérdida de paquetes de los miembros, y que las reglas de SD-WAN usan para elegir un camino.
Probe / probe server (sondeo / servidor de sondeo)
La prueba periódica (ping, HTTP, DNS, TCP y otras) enviada a través de un miembro hacia un destino alcanzable para medir la calidad de ese miembro.
Latency, jitter, packet loss (latencia, jitter, pérdida de paquetes)
Las tres métricas medidas: retardo de ida y vuelta, variación del retardo entre sondeos y porcentaje de sondeos sin respuesta.
SLA target (objetivo de SLA)
Valores umbral (por ejemplo, latencia, jitter y pérdida máximos) que deciden si un miembro cumple el SLA en ese momento; superar cualquiera de ellos significa reprobarlo.
Dead frente a out of SLA (muerto frente a fuera de SLA)
Muerto significa que fallaron sondeos consecutivos y el miembro se trata como caído; fuera de SLA significa que está vivo pero su calidad no alcanza un objetivo.
Manual rule (regla manual)
Asigna el tráfico coincidente a los miembros especificados en un orden fijo, ignorando las mediciones del SLA.
Best quality (mejor calidad)
Selecciona el miembro con la mejor métrica medida (latencia, jitter, pérdida o ancho de banda), persiguiendo siempre la mejor puntuación.
Lowest cost (SLA) (menor costo)
Selecciona el miembro más barato, según el costo configurado en el miembro, que cumple en ese momento el objetivo de SLA, y solo lo abandona cuando reprueba el SLA.
Maximize bandwidth (SLA) (maximizar ancho de banda)
Reparte las sesiones entre todos los miembros que cumplen en ese momento el objetivo de SLA para aumentar el rendimiento total.
Implicit rule (regla implícita)
La regla general al final de la lista de reglas de SD-WAN para el tráfico que no coincide con ninguna regla explícita; usa un método de balanceo de carga por defecto, como Source IP.
diagnose sys sdwan health-check
Muestra, por miembro, el estado, la latencia, el jitter y la pérdida de paquetes de cada performance SLA, y si cada miembro cumple cada objetivo de SLA.
diagnose sys sdwan service
Muestra cada regla de SD-WAN, su estrategia y sus miembros en el orden de preferencia actual, incluido qué miembro está seleccionado y por qué otros bajaron de posición.
SLA state / SLA map (estado de SLA / mapa de SLA)
Si un miembro cumple en ese momento sus objetivos de SLA, mostrado en la salida como un mapa de los objetivos que aprueba; las reglas lo usan para decidir la elegibilidad.
Measurement-then-decision flow (flujo de medición y luego decisión)
Resolver problemas revisando primero health-check (los datos) y luego service (cómo las reglas usaron los datos).

Dominio 5: VPN (14%)

Consejos para el examen

  • Fase 1 activa pero fase 2 caída casi siempre significa discrepancias en las propuestas de la fase 2, en PFS o el grupo DH, o en los selectores. Y cuando un par está detrás de NAT, recuerda UDP 4500 (NAT-T), no solo UDP 500.
  • Prefiere las VPN basadas en rutas (interface mode): la interfaz de túnel permite que la usen las rutas, las políticas, SD-WAN y ADVPN. La fortaleza del cifrado es la misma que en el modo basado en políticas, así que la razón es la flexibilidad, no una criptografía más fuerte.
  • El lado con la dirección desconocida o dinámica debe iniciar; el lado estático lo acepta como par dial-up. Dos pares dial-up nunca pueden conectarse porque ninguno tiene una dirección a la cual llamar.
  • Que un túnel aparezca activo no es suficiente. Todavía necesitas una ruta para la subred remota a través de la interfaz de túnel y políticas en ambas direcciones, y las políticas del túnel normalmente no deben aplicar SNAT. Agrega una ruta blackhole de mayor distancia para que el tráfico nunca se filtre cuando el túnel se cae.
  • La conmutación por error de una VPN redundante necesita las dos partes: distancias o prioridades de ruta distintas para definir el principal y el respaldo, y DPD (o el monitoreo de túneles) para detectar un túnel muerto y retirar su ruta. Con DPD deshabilitado, la conmutación por error no funciona.
  • Hub and spoke necesita n menos 1 túneles; la malla completa necesita n(n-1)/2. ADVPN mantiene la poca configuración de hub and spoke y a la vez da caminos directos entre spokes bajo demanda, así que escala sin el mantenimiento de una malla.
  • Usa la lista de gateways para la fase 1, la lista de túneles para la fase 2 y los contadores de paquetes, y el debug de IKE para ver por qué falla la negociación. Filtra el debug por el par y recuerda que no se imprime nada hasta que ejecutas diagnose debug enable.
  • En compilaciones posteriores de 7.6, el tunnel mode de SSL VPN se eliminó y el web mode pasó a llamarse agentless VPN; IPsec dial-up con FortiClient es el método de acceso remoto completo. Confirma si tu versión del examen cubre el acceso remoto y recuerda UDP 4500 para los clientes detrás de NAT.

Términos clave

IKEv1 vs IKEv2
Versiones de IKE para negociar IPsec; IKEv2 es más nueva, usa menos mensajes, integra soporte para NAT-T y EAP, y en general se prefiere. Ambos pares deben usar la misma versión.
Phase 1 vs phase 2 (fase 1 vs fase 2)
La fase 1 construye la SA de IKE autenticada (canal seguro); la fase 2 construye la SA de IPsec que cifra los datos de los usuarios con ESP.
Proposal (propuesta)
El conjunto ofrecido de algoritmos de cifrado e integridad; los pares deben compartir al menos una combinación en cada fase.
DH group / PFS (grupo DH / PFS)
El grupo DH define la fortaleza del intercambio de claves; PFS ejecuta un nuevo intercambio DH para cada clave de fase 2, de modo que el compromiso de una clave no expone a las demás.
Selectors (selectores)
Las subredes locales y remotas que lleva una SA de fase 2; la local de cada lado debe coincidir con la remota del otro lado.
UDP 500 / 4500 (NAT-T)
IKE usa UDP 500; cuando se detecta NAT, NAT traversal traslada IKE y el ESP encapsulado a UDP 4500.
Route-based (interface-mode) VPN (VPN basada en rutas)
Una VPN IPsec que crea una interfaz de túnel virtual que pueden usar las rutas, las políticas de firewall, SD-WAN y ADVPN.
Policy-based VPN (VPN basada en políticas)
Una VPN IPsec vinculada a una política de firewall con la acción IPsec en lugar de a una interfaz; más sencilla para un solo túnel, pero no escalable.
Tunnel interface (interfaz de túnel)
La interfaz virtual que produce una VPN basada en rutas, a través de la cual enrutas el tráfico y a la que aplicas políticas.
Feature visibility (visibilidad de funciones)
La configuración de FortiOS que muestra u oculta funciones en la GUI; el IPsec basado en políticas debe habilitarse allí antes de que aparezca la acción IPsec en las políticas.
Scalability and flexibility (escalabilidad y flexibilidad)
Las VPN basadas en rutas admiten rutas de respaldo, enrutamiento dinámico, SD-WAN y ADVPN; las VPN basadas en políticas no.
Static peer (par estático)
Un par IPsec con una IP pública fija y conocida; cada lado configura la dirección específica del gateway del otro y cualquiera de los dos puede iniciar.
Dial-up (dynamic) peer (par dial-up o dinámico)
Una fase 1 con el tipo de gateway remoto dial-up user que acepta túneles entrantes de quienes llaman con direcciones desconocidas de antemano.
Initiator vs responder (iniciador vs respondedor)
El par con la dirección desconocida o dinámica debe iniciar; el par con la dirección estática acepta (responde) como servidor dial-up.
Dynamic DNS remote gateway (gateway remoto de DNS dinámico)
Una fase 1 que resuelve un nombre de host para encontrar a un par cuya dirección cambia, lo que permite que ambos lados inicien mientras el nombre se mantenga actualizado.
Peer ID / authentication (ID de par / autenticación)
Identificadores y credenciales (clave precompartida o certificado) que permiten a un servidor dial-up asociar a quienes llaman con la fase 1 correcta y autorizarlos.
Route via tunnel interface (ruta a través de la interfaz de túnel)
Una ruta estática cuyo destino es la subred remota y cuyo dispositivo es la interfaz de túnel IPsec, que dirige el tráfico hacia el túnel.
Blackhole route (ruta blackhole o de agujero negro)
Una ruta de mayor distancia para la subred remota que descarta el tráfico cuando desaparece la ruta del túnel, lo que evita filtraciones hacia internet.
Bidirectional policies (políticas bidireccionales)
Políticas de firewall de la LAN al túnel y del túnel a la LAN, para que cualquiera de los sitios pueda iniciar conexiones (las respuestas se permiten por estado).
No SNAT for tunnel traffic (sin SNAT para el tráfico del túnel)
Las políticas del túnel normalmente no aplican source NAT, para que ambas LAN vean las direcciones reales de la otra.
Up but no traffic (activo pero sin tráfico)
El síntoma cuando un túnel negocia correctamente pero faltan la ruta o las políticas, así que ningún dato lo atraviesa.
Redundant tunnels (túneles redundantes)
Dos o más túneles basados en rutas por caminos distintos para que la VPN sobreviva a la falla de un solo enlace o túnel.
Route distance/priority for failover (distancia o prioridad de rutas para la conmutación por error)
Una distancia menor hace que la ruta de un túnel esté activa y la otra en espera; la misma distancia con prioridades distintas mantiene ambas en la tabla con una preferida.
Dead peer detection, DPD (detección de pares inactivos)
Mensajes periódicos de actividad que detectan un par que no responde, dan de baja el túnel y permiten que su ruta se retire.
Tunnel monitoring (monitoreo de túneles)
El monitoreo del enlace a través de un túnel, o una fase 1 que monitorea a otra, que detecta un camino roto y provoca cambios de rutas o de túneles para la conmutación por error.
Black hole (agujero negro)
Un túnel que falló pero sigue apareciendo activo, así que su ruta sigue activa y el tráfico que se envía a él se pierde.
Hub and spoke (concentrador y radios)
Cada spoke crea un túnel solo hacia un hub central (n menos 1 túneles); el tráfico entre spokes pasa por el hub.
Full mesh (malla completa)
Cada sitio tiene un túnel directo hacia cada uno de los demás (n por (n menos 1) dividido entre 2 túneles); caminos más cortos, pero muchos túneles.
Partial mesh (malla parcial)
Túneles directos solo entre pares de sitios seleccionados, y el resto a través del hub, lo que equilibra la eficiencia y la cantidad de túneles.
ADVPN (Auto-Discovery VPN, VPN de descubrimiento automático)
Un diseño hub and spoke en el que el hub hace que los spokes construyan bajo demanda túneles directos de atajo, lo que da caminos como los de una malla sin túneles de malla completa manuales.
Short-cut tunnel (túnel de atajo)
Un túnel dinámico entre spokes que ADVPN crea cuando fluye tráfico entre ellos y que se elimina cuando queda inactivo.
diagnose vpn ike gateway list
Muestra los gateways de fase 1 (IKE): estado, direcciones y puertos local y remoto, versión negociada, propuesta y grupo DH, y estado de NAT-T.
diagnose vpn tunnel list
Muestra las SA de fase 2 (IPsec), los selectores, las propuestas, los tiempos de vida y los contadores de paquetes cifrados y descifrados.
diagnose debug application ike -1
Registro detallado y en tiempo real de la negociación IKE que revela la razón exacta por la que un túnel no logra establecerse.
IKE log filter (filtro de registro de IKE)
Un filtro, como la dirección del par remoto, que se aplica antes de depurar para que solo se muestre la negociación relevante.
Debug enable/disable (habilitar y deshabilitar el debug)
diagnose debug enable es necesario para que se imprima la salida del debug; diagnose debug disable lo desactiva después.
FortiClient dial-up IPsec (IPsec dial-up con FortiClient)
VPN de acceso remoto en la que FortiClient inicia un túnel IPsec hacia una fase 1 dial-up de un FortiGate, que autentica al usuario y asigna la configuración mediante mode-config.
Mode-config
El mecanismo de IKE que asigna una dirección IP, servidores DNS y rutas opcionales de split tunnel a un cliente remoto cuando se levanta el túnel.
EAP / XAUTH
Métodos de autenticación de usuarios que se agregan sobre IPsec: EAP con IKEv2 y XAUTH con IKEv1, verificados contra usuarios locales, de LDAP o de RADIUS.
SSL VPN tunnel mode removal (eliminación del tunnel mode de SSL VPN)
En compilaciones posteriores de FortiOS 7.6 se eliminó la SSL VPN de túnel completo, y IPsec (FortiClient) quedó como el camino soportado para el acceso remoto completo.
Agentless VPN (VPN sin agente)
El web mode de SSL VPN con su nuevo nombre: acceso sin cliente, basado en navegador, a recursos web y de aplicaciones internos específicos a través de un portal.
Split tunneling (túnel dividido)
Enviar por la VPN solo el tráfico hacia las redes internas, mientras el resto del tráfico va directamente a internet.
