Fortinet NSE 4 - FortiOS 7.6 Administrator NSE4_FGT_AD-7.6

Configuración inicial: IP de gestión predeterminada 192.168.1.99, cuenta admin, cambio obligatorio de contraseña, roles de interfaz y acceso (HTTPS, SSH, ping)

Todos los FortiGate que sacas de la caja parten del mismo estado conocido, y el examen NSE 4 espera que lo conozcas de memoria. Un FortiGate físico viene con la dirección 192.168.1.99 en su interfaz de gestión. Según el modelo, ese puerto puede estar rotulado como MGMT, o pueden ser los puertos del switch interno o port1 en las unidades de escritorio más pequeñas. La máscara de subred predeterminada es /24, así que el equipo tiene 192.168.1.99 en la red 192.168.1.0/24, y muchos modelos pequeños también ejecutan un servidor de protocolo de configuración dinámica de host (DHCP) en ese segmento interno.

Para la primera conexión, conectas una laptop a esa interfaz con un cable y le das una dirección en la misma subred, por ejemplo 192.168.1.50 con máscara 255.255.255.0, a menos que la laptop ya haya recibido una por DHCP. Luego abres un navegador web y vas a 192.168.1.99 por protocolo seguro de transferencia de hipertexto (HTTPS). HTTPS es el protocolo predeterminado de la interfaz gráfica de usuario (GUI), y una solicitud HTTP simple se redirige a HTTPS. Espera una advertencia de certificado en esa primera visita, porque el equipo presenta un certificado autofirmado; esa advertencia es normal en un equipo de fábrica y no indica ninguna falla.

La cuenta de administrador predeterminada se llama admin y tiene una contraseña en blanco (vacía). FortiOS no te deja mantenerla así: la primera vez que inicias sesión, el equipo te obliga a definir una contraseña nueva antes de permitirte hacer cualquier otra cosa. Este cambio obligatorio cierra el agujero más evidente de un dispositivo nuevo. En un FortiGate no existe una cuenta root ni un inicio de sesión con el número de serie, y por eso ambos son distractores favoritos en el examen. Registrar el equipo en FortiCloud es útil para el soporte y el licenciamiento, pero es opcional para la gestión local y no es necesario solo para iniciar sesión.

Una vez dentro, las interfaces tienen un rol que describe su lugar en la red. Los roles integrados son LAN, WAN y DMZ (zona desmilitarizada), además de Undefined. El rol es sobre todo una comodidad que muestra u oculta los campos que tienen sentido para ese tipo de puerto. Una interfaz WAN, por ejemplo, muestra ajustes como el ancho de banda estimado, mientras que una interfaz LAN facilita activar un servidor DHCP y crear un objeto de dirección para la subred. El rol por sí solo no cambia cómo se filtra el tráfico. Las políticas de firewall siguen decidiendo qué pasa, así que un puerto etiquetado como WAN no queda protegido automáticamente y un puerto etiquetado como LAN no es de confianza automáticamente.

Cada interfaz también tiene un ajuste de Administrative Access (acceso administrativo) que enumera a qué servicios de gestión responderá el propio FortiGate en esa interfaz. HTTPS abre la GUI, Secure Shell (SSH) abre de forma remota la interfaz de línea de comandos (CLI) y PING hace que la interfaz responda a las solicitudes de eco del protocolo de mensajes de control de internet (ICMP). Otras opciones incluyen HTTP, el protocolo simple de administración de red (SNMP), FMG-Access para FortiManager y Security Fabric Connection, que antes se llamaba FortiTelemetry. Estos ajustes controlan el tráfico dirigido al FortiGate, no el tráfico que pasa a través de él.

El acceso administrativo es una causa frecuente de bloqueos. Si quitas HTTPS de la interfaz por la que estás administrando, la GUI deja de responder en el momento en que haces clic en Apply. Lo mismo ocurre si cambias la IP de la interfaz y olvidas que tu laptop sigue en la subred anterior. Cuando eso pasa, recuperas el acceso por otra interfaz que todavía permita la gestión, por SSH si sigue permitido, o por el puerto de consola físico. En una interfaz WAN expuesta a internet, la buena práctica es permitir poco o nada, y apoyarse en trusted hosts y en una red privada virtual (VPN) para la gestión remota en lugar de exponer la GUI a todo el mundo.

En un laboratorio configurarás una IP estática en una interfaz desde la GUI, en Network e Interfaces, o con la CLI. El equivalente en la CLI es corto, y conocer tanto la ruta en la GUI como la palabra clave allowaccess te ayuda a responder preguntas planteadas de cualquiera de las dos formas:

config system interface
    edit port1
        set ip 10.0.0.1/24
        set allowaccess ping https ssh
    next
end

Observa que set allowaccess reemplaza toda la lista en lugar de agregar elementos. Si escribes set allowaccess ping en la interfaz que usas para HTTPS, acabas de quitar HTTPS y SSH. Para agregar un solo servicio a una lista existente, FortiOS ofrece append allowaccess, y show system interface port1 te permite confirmar el resultado antes de desconectarte. Convierte ese hábito, revisar la lista antes y después, en parte de cada cambio de interfaz.

Términos clave

Management IP (192.168.1.99) (IP de gestión)
La dirección predeterminada en la interfaz de gestión o interna de un FortiGate de fábrica, a la que se accede por HTTPS para el primer inicio de sesión.
Default admin account (cuenta admin predeterminada)
La cuenta integrada llamada admin con contraseña en blanco; FortiOS obliga a definir una contraseña nueva en el primer inicio de sesión.
Administrative access (acceso administrativo)
La lista, por interfaz, de servicios de gestión (HTTPS, SSH, PING, SNMP y otros) a los que el FortiGate responderá en esa interfaz.
Interface role (rol de interfaz)
Una etiqueta (LAN, WAN, DMZ o Undefined) que ajusta qué campos de configuración se muestran para una interfaz; por sí sola no filtra tráfico.
allowaccess
La palabra clave de la CLI, dentro de una interfaz del sistema, que define qué protocolos de gestión acepta la interfaz; set reemplaza la lista y append agrega a ella.
Ejemplo real

Un técnico conecta una laptop al puerto MGMT de un FortiGate nuevo, configura la laptop con 192.168.1.50/24, navega por HTTPS a 192.168.1.99, acepta la advertencia del certificado autofirmado, inicia sesión como admin con contraseña en blanco y de inmediato el equipo lo obliga a crear una contraseña nueva de administrador.

Consejo para el examen: Perder el acceso a la GUI después de cambiar una interfaz casi siempre se debe a que falta HTTPS en el Administrative Access de esa interfaz, o a un cambio de IP que sacó la interfaz de la subred de tu laptop. Confirma allowaccess antes de desconectarte.

Comprueba lo que sabes

¿Qué dirección y qué credenciales usas para el primer inicio de sesión en un FortiGate físico con configuración de fábrica?

Navega por HTTPS a 192.168.1.99 e inicia sesión como admin con contraseña en blanco; FortiOS luego te obliga a definir una contraseña nueva.

Quitaste HTTPS de la interfaz por la que administras y perdiste la GUI. ¿Qué ajuste lo causó?

La lista de Administrative Access (allowaccess) de la interfaz ya no incluye HTTPS, así que el FortiGate deja de responder a las solicitudes de la GUI en esa interfaz.

¿El rol WAN de una interfaz bloquea tráfico por sí solo?

No. El rol solo ajusta los campos que se muestran; las políticas de firewall deciden qué tráfico pasa.

¿Qué opción de acceso administrativo permite que otros dispositivos Fortinet se conecten a esta interfaz para unirse al Security Fabric?

Security Fabric Connection, que antes se llamaba FortiTelemetry.
