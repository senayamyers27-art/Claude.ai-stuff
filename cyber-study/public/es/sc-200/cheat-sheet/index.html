Dominio 1: Manage a security operations environment (41%)

Consejos para el examen

  • Para silenciar una alerta que se sabe benigna sin perder protección, elige el ajuste de alertas con un alcance reducido. Para limitar qué dispositivos puede ver un analista, elige un grupo de dispositivos con acceso para un grupo de Entra, no un rol de Entra para todo el inquilino. Cuando coinciden dos grupos de dispositivos, gana el de mayor rango.
  • Espera preguntas sobre el orden del despliegue de ASR (audit antes que block) y sobre la dependencia entre los indicadores personalizados de IP o URL y la protección de red. La protección contra alteraciones es la respuesta siempre que alguien con derechos de administrador intenta desactivar Defender. La detección de dispositivos encuentra dispositivos, pero nunca los incorpora.
  • Si una opción dice que el CSPM fundamental generará alertas de amenazas, es incorrecta. Las alertas de amenazas necesitan un plan Defender de cargas de trabajo; el análisis de rutas de ataque necesita el plan de pago Defender CSPM. Los planes se activan por suscripción, cuenta de AWS o proyecto de GCP.
  • Conoce la lista de servidores para los sensores de MDI: todos los controladores de dominio más AD FS, AD CS y Entra Connect. En MDO, la revisión en el momento del clic significa Safe Links; la detonación en sandbox significa Safe Attachments. Las predefinidas ganan a las personalizadas.
  • Responder frente a Contributor es una pregunta favorita: solo administrar incidentes significa Responder; editar reglas, watchlists o workbooks significa Contributor. Automation Contributor se concede a Sentinel, no a un usuario. Divide los espacios de trabajo solo por una razón real, como la residencia de datos.
  • Cuando un escenario dice «conservar registros detallados durante años a bajo costo, pero seguir detectando sobre agregados», la respuesta combina un nivel de bajo costo con una regla de resumen. Las reglas de análisis estándar necesitan los datos en el nivel de análisis.
  • Asocia formatos con tablas: eventos de Windows a SecurityEvent, Syslog a Syslog, CEF a CommonSecurityLog y datos personalizados de la API a una tabla _CL. El filtrado y la transformación ocurren en la DCR.
  • Expresiones como «en aproximadamente un minuto» apuntan a NRT. «Ataque de múltiples etapas entre productos» apunta a Fusion (o a la correlación de Defender XDR en el portal unificado). «Demasiados incidentes para el mismo usuario» apunta a la agrupación de alertas. Mantén el lookback al menos tan largo como la frecuencia.
  • Si una pregunta dice que la regla no se puede guardar, busca columnas obligatorias faltantes. Si pregunta cómo ver qué técnicas de ATT&CK no tienen detecciones, elige la vista de cobertura de MITRE ATT&CK o las recomendaciones de cobertura de SOC optimization.
  • Elige una regla de automatización para los cambios dentro de Sentinel (responsable, estado, severidad, etiquetas, tareas). Elige un playbook cuando el escenario mencione un sistema externo, una API de enriquecimiento, correo, Teams o tickets. A menudo, la regla de automatización es la que ejecuta el playbook.

Términos clave

Alert tuning rule (regla de ajuste de alertas)
Una regla, antes llamada regla de supresión, que oculta o resuelve automáticamente las alertas que cumplen condiciones elegidas sin cambiar la protección ni la recopilación de datos.
Unified RBAC (control de acceso basado en roles unificado)
El modelo de control de acceso basado en roles de Defender XDR, en el que los roles personalizados combinan grupos de permisos y se asignan por fuente de datos.
Device group (grupo de dispositivos)
Un conjunto de dispositivos con rango, definido por reglas de coincidencia, que controla el acceso, el nivel de automatización y el alcance de otras configuraciones.
Device group rank (rango del grupo de dispositivos)
El orden que decide a qué grupo se une un dispositivo cuando coincide con varios; gana la coincidencia de mayor rango.
Incident notification rule (regla de notificación de incidentes)
Una configuración que envía correos a destinatarios elegidos cuando se crean o actualizan incidentes que cumplen filtros como la severidad, el origen o el grupo de dispositivos.
Automation level (nivel de automatización)
La configuración de cada grupo de dispositivos que decide si la investigación automatizada corrige por sí sola o espera aprobación.
Ungrouped devices (dispositivos sin agrupar)
El grupo predeterminado que contiene cualquier dispositivo que no cumple las reglas de un grupo de dispositivos definido.
Onboarding package (paquete de incorporación)
El script o la configuración que se descarga del portal de Defender y que conecta un dispositivo a tu inquilino mediante el método de implementación elegido.
Detection test (prueba de detección)
Un comando inofensivo que ofrece la página de incorporación y que genera una alerta de prueba para demostrar que un dispositivo está reportando.
Tamper protection (protección contra alteraciones)
Una configuración que impide cambios locales a la configuración de seguridad de Defender, incluso por administradores o malware con derechos de administrador.
ASR rule modes (modos de las reglas ASR)
Audit solo registra, Warn bloquea pero permite que el usuario lo omita, y Block aplica la regla.
Indicator (indicador)
Una entrada personalizada de permitir, auditar, advertir o bloquear para un hash de archivo, una dirección IP, una URL, un dominio o un certificado.
Network protection (protección de red)
Un filtro a nivel de todo el sistema operativo que bloquea conexiones a dominios e IP maliciosos y aplica indicadores personalizados de IP y URL fuera de Edge.
Device discovery (detección de dispositivos)
La función que usa dispositivos incorporados para encontrar dispositivos no administrados en la red, en modo básico (pasivo) o estándar (activo).
Foundational CSPM (CSPM fundamental)
El nivel gratuito de Defender for Cloud que ofrece secure score, recomendaciones e inventario de recursos.
Defender CSPM
El plan de postura de pago que agrega análisis de rutas de ataque, cloud security explorer, análisis sin agente y gobernanza.
Cloud workload protection (protección de cargas de trabajo en la nube)
Los planes Defender de pago (Servers, Storage, Databases y otros) que detectan amenazas y generan alertas de seguridad.
Secure score (puntuación de seguridad)
Una medida de postura basada en cuántas recomendaciones de seguridad has atendido; no es un recuento de alertas.
Multicloud connector (conector multinube)
La conexión de Defender for Cloud a una cuenta de AWS o a un proyecto de GCP, creada con una plantilla de CloudFormation o un script de GCP.
Azure Arc
El servicio que proyecta servidores que no son de Azure dentro de Azure para que se les puedan aplicar extensiones y planes Defender.
Defender for Endpoint integration (integración con Defender for Endpoint)
La función de Defender for Servers que implementa y licencia el sensor de Defender for Endpoint en los servidores protegidos.
Defender for Identity sensor (sensor de Defender for Identity)
Software instalado en controladores de dominio y en servidores AD FS, AD CS y Entra Connect que recopila tráfico y eventos de identidad para la detección.
Directory Service account (cuenta de Directory Service)
La cuenta, idealmente una gMSA, que Defender for Identity usa para consultar Active Directory.
Group managed service account, gMSA (cuenta de servicio administrada de grupo)
Una cuenta de AD cuya contraseña administran y rotan automáticamente los controladores de dominio, adecuada para servicios.
Safe Links
Una función de MDO que revisa las URL cuando se hace clic en ellas en el correo, Teams y las aplicaciones de Office.
Safe Attachments
Una función de MDO que detona los adjuntos en un sandbox para encontrar malware desconocido antes o durante la entrega.
Dynamic Delivery (entrega dinámica)
Una acción de Safe Attachments que entrega el cuerpo del correo de inmediato y agrega el adjunto después del análisis en sandbox.
Preset security policies (directivas de seguridad predefinidas)
Paquetes de directivas Standard y Strict mantenidos por Microsoft que tienen prioridad sobre las directivas personalizadas.
Log Analytics workspace (espacio de trabajo de Log Analytics)
El almacén de datos de Azure Monitor sobre el que se habilita Sentinel y donde viven todas sus tablas.
Microsoft Sentinel Reader
El rol que permite ver datos, incidentes y contenido sin cambiar nada.
Microsoft Sentinel Responder
El rol que permite ver datos y administrar incidentes, pero no crear ni editar contenido.
Microsoft Sentinel Contributor
El rol que agrega la creación y edición de contenido como reglas de análisis, workbooks y watchlists.
Microsoft Sentinel Automation Contributor
Un rol que se otorga al servicio de Sentinel en un grupo de recursos para que las reglas de automatización puedan ejecutar playbooks ahí.
Unified security operations platform (plataforma unificada de operaciones de seguridad)
Sentinel y Defender XDR trabajando juntos en el portal de Microsoft Defender con una sola cola de incidentes.
Primary workspace (espacio de trabajo principal)
El espacio de trabajo de Sentinel designado en el portal de Defender cuyas alertas se correlacionan con los datos de Defender XDR.
Analytics tier (nivel de análisis)
El nivel de almacenamiento interactivo y de mayor costo que admite reglas de análisis, workbooks y consultas de búsqueda rápidas.
Sentinel data lake tier (nivel de data lake de Sentinel)
Almacenamiento a largo plazo de bajo costo para datos de alto volumen, consultado con KQL jobs, consultas de exploración o notebooks.
Table plan (plan de tabla)
La configuración de cada tabla (Analytics, Basic o Auxiliary) que equilibra el costo de ingesta frente a las funciones de consulta.
Summary rule (regla de resumen)
Una consulta KQL programada que agrega datos detallados y escribe los resultados en una tabla del nivel de análisis.
SOC optimization
Una página de recomendaciones sobre el valor de los datos, la cobertura de detección y fuentes de datos basadas en organizaciones similares.
Ingestion-time transformation (transformación en el momento de la ingesta)
Una instrucción KQL en una DCR que filtra o transforma los datos antes de almacenarlos, lo que reduce el costo.
KQL job
Una consulta que se ejecuta sobre datos del nivel de data lake, a menudo para recuperar datos antiguos para una investigación.
Content hub
El catálogo de soluciones de Sentinel que empaqueta conectores, reglas, workbooks, parsers y playbooks.
Azure Monitor Agent (AMA)
El agente actual para Windows y Linux que recopila datos según las reglas de recopilación de datos.
Data collection rule, DCR (regla de recopilación de datos)
Una configuración que define las fuentes, una transformación opcional en el momento de la ingesta y la tabla de destino.
Common Event Format, CEF (formato común de eventos)
Un formato de registro estructurado de clave-valor transportado sobre Syslog que llega a la tabla CommonSecurityLog.
Linux log forwarder (reenviador de registros Linux)
Una máquina Linux que ejecuta un demonio de Syslog y AMA, recibe registros de los dispositivos y los envía al espacio de trabajo.
Logs Ingestion API
Una API para enviar datos personalizados a una tabla del espacio de trabajo mediante una DCR.
Monitoring Metrics Publisher
El rol que la identidad de una aplicación necesita en la DCR para enviar datos mediante la Logs Ingestion API.
Scheduled rule (regla programada)
Una regla de análisis basada en KQL que se ejecuta con una frecuencia fija sobre un lookback fijo y alerta cuando se alcanza un umbral.
NRT rule (regla casi en tiempo real)
Una regla near-real-time que se ejecuta aproximadamente cada minuto para detecciones urgentes, con límites de consulta más estrictos.
Microsoft security rule (regla de seguridad de Microsoft)
Una regla que crea incidentes de Sentinel a partir de alertas generadas por otros productos de seguridad de Microsoft.
Anomaly rule (regla de anomalías)
Una regla integrada de aprendizaje automático cuyos parámetros, pero no su lógica, se pueden ajustar en un duplicado.
Fusion
La correlación por aprendizaje automático de Sentinel que combina alertas y anomalías en incidentes de ataques de múltiples etapas.
Entity mapping (mapeo de entidades)
Mapear columnas de la consulta a tipos de entidad como Account, Host e IP para que las alertas lleven evidencia estructurada.
Custom details (detalles personalizados)
Campos del evento que se muestran directamente en una alerta para que los analistas vean los valores clave sin volver a ejecutar la consulta.
Alert grouping (agrupación de alertas)
Configuraciones que deciden qué alertas se combinan en un solo incidente y durante cuánto tiempo.
Custom detection rule (regla de detección personalizada)
Una consulta programada de advanced hunting en Defender XDR que crea alertas y puede desencadenar acciones de respuesta automatizadas.
Required columns (columnas obligatorias)
Columnas identificadoras, como Timestamp, DeviceId y ReportId, que una consulta de detección personalizada debe devolver.
Impacted entity (entidad afectada)
La columna de dispositivo, usuario o buzón que la regla marca como afectada y sobre la que dirige las acciones.
MITRE ATT&CK
Un marco público de tácticas y técnicas de adversarios que se usa para etiquetar detecciones y medir la cobertura.
Tactic (táctica)
En MITRE ATT&CK, el objetivo del adversario en una etapa del ataque, como el acceso a credenciales o la persistencia.
Technique (técnica)
En MITRE ATT&CK, el método usado para lograr una táctica, identificado con un ID como T1003.
Simulated coverage (cobertura simulada)
Una vista de la página MITRE ATT&CK de Sentinel que muestra la cobertura que ganarías al habilitar las plantillas de reglas disponibles.
Automation rule (regla de automatización)
Una regla integrada de Sentinel que actúa sobre incidentes o alertas cuando se crean o actualizan, incluida la ejecución de playbooks.
Playbook
Un flujo de trabajo de Azure Logic Apps desencadenado por un incidente, una alerta o una entidad de Sentinel para enriquecimiento o respuesta.
Incident task (tarea de incidente)
Un elemento de lista de verificación dentro de un incidente que estandariza y registra los pasos de la investigación.
Watchlist (lista de seguimiento)
Una lista de referencia, consultada con _GetWatchlist(), que se usa para enriquecer o filtrar reglas y búsquedas.
Workbook (libro de trabajo)
Un panel interactivo basado en KQL para visualización e informes.
UEBA
User and entity behavior analytics (análisis del comportamiento de usuarios y entidades), que establece líneas base de la actividad normal y destaca anomalías en las páginas de entidad.
STIX/TAXII
Un formato estándar (STIX) y un protocolo de transporte (TAXII) para compartir indicadores de inteligencia de amenazas.

Dominio 2: Respond to security incidents (37%)

Consejos para el examen

  • Una prueba de penetración autorizada o un ejercicio de red team es informational expected activity con la determinación security testing (benign positive en Sentinel), no un falso positivo. Falso positivo significa que la lógica de detección o los datos estaban mal.
  • Aislamiento frente a restrict app execution es un par clásico: propagación activa o comando y control significa aislar; si el usuario debe seguir trabajando y la herramienta no está firmada, significa restrict app execution. Un bloqueo en todo el tenant es un indicador de archivo, no la cuarentena en un dispositivo.
  • Si la remediación 'no ocurrió', revisa la pestaña Pending: probablemente el nivel de automatización del grupo de dispositivos requería aprobación. La interrupción de ataques es automática y de alta confianza; no espera aprobación.
  • Threat Explorer es de Plan 2; Real-time detections es de Plan 1. La remediación que tomas desde Threat Explorer aparece en el Action center. Soft delete es recuperable; hard delete no lo es.
  • KRBTGT se restablece dos veces porque AD acepta tickets firmados con la contraseña actual o con la anterior. DCSync se reconoce por solicitudes de replicación que provienen de una máquina que no es un controlador de dominio.
  • Restablecer la contraseña más revocar las sesiones es la respuesta correcta habitual ante el robo de tokens. Confirm compromised sube el riesgo a alto y entrena al modelo; dismiss solo borra el riesgo.
  • Restablecer una contraseña no elimina una concesión OAuth maliciosa. La respuesta es revocar el consentimiento o prohibir la aplicación, y luego restringir el consentimiento de los usuarios.
  • Las preguntas sobre 'quién hizo qué y cuándo' en Microsoft 365 apuntan a una búsqueda en Purview Audit. 'Qué correos leyó el atacante' apunta al evento de auditoría MailItemsAccessed.
  • Ejecutar una Logic App sobre una alerta ahora: Trigger automated response en la pestaña Take action. Ejecutarla automáticamente cada vez: automatización de flujos de trabajo. Detener las alertas esperadas: regla de supresión.
  • Si faltan entidades en el gráfico de investigación, la corrección es la asignación de entidades en la regla de análisis. Para una prueba autorizada, cierra como benign positive; false positive significa que la regla o los datos estaban mal.
  • Relaciona la necesidad con la función: 'explica este comando ofuscado' es análisis de scripts, 'qué debo hacer ahora' es respuesta guiada, 'informa al siguiente turno' es el resumen o el informe del incidente.

Términos clave

Incident (incidente)
Un grupo de alertas correlacionadas y evidencia que representa un ataque o una actividad relacionada.
Alert correlation (correlación de alertas)
Agrupación automática de alertas en incidentes con base en entidades compartidas y en el tiempo.
Attack story (historia del ataque)
La vista del incidente que muestra la línea de tiempo de las alertas, un gráfico del incidente y los detalles de las alertas.
Merge incidents (combinar incidentes)
Unir incidentes que representan el mismo ataque para que sus alertas queden en un solo incidente.
Classification (clasificación)
El veredicto de resolución: true positive, informational expected activity o false positive.
Determination (determinación)
La razón detallada bajo una clasificación, como phishing, security testing o not malicious.
Link alert to another incident (vincular la alerta a otro incidente)
Mover una sola alerta a un incidente existente o nuevo cuando la correlación la colocó en el equivocado.
Isolate device (aislar el dispositivo)
Desconecta un dispositivo de la red, excepto la conexión con el servicio de Defender.
Restrict app execution (restringir la ejecución de aplicaciones)
Permite que solo se ejecute código firmado por Microsoft en un dispositivo mientras sigue conectado.
Investigation package (paquete de investigación)
Un zip de datos forenses (procesos, conexiones, autoruns, registros) recopilado de forma remota desde un dispositivo.
Live response (respuesta en vivo)
Una sesión de shell remota en un dispositivo para recopilar archivos y ejecutar scripts aprobados.
Stop and quarantine file (detener y poner en cuarentena el archivo)
Una acción que termina los procesos de un archivo y lo pone en cuarentena en los dispositivos donde se vio.
Device timeline (línea de tiempo del dispositivo)
Una vista cronológica de los eventos de procesos, red, archivos, inicios de sesión y registro de un dispositivo, con las alertas marcadas.
File indicator (indicador de archivo)
Una regla para todo el tenant o para un grupo de dispositivos sobre un hash de archivo, con una acción como block execution o block and remediate.
Action center (centro de acciones)
La página del portal de Defender que lista las acciones de remediación pendientes y completadas de todo Defender XDR.
Automated investigation and response, AIR (investigación y respuesta automatizadas)
La investigación automática de alertas de Defender, que produce veredictos y acciones de remediación propuestas.
Automation level (nivel de automatización)
Una configuración del grupo de dispositivos que decide si la remediación se ejecuta automáticamente o espera aprobación.
Automatic attack disruption (interrupción automática de ataques)
Contención automática y de alta confianza de dispositivos y usuarios comprometidos durante un ataque activo.
Contain device (contener el dispositivo)
Una acción de interrupción de ataques que impide que los demás dispositivos incorporados se comuniquen con un dispositivo comprometido.
Contain user (contener el usuario)
Una acción de interrupción de ataques que impide que una cuenta comprometida se use para moverse lateralmente.
Pending tab (pestaña Pending)
La lista del Action center con las acciones de remediación que esperan aprobación.
History tab (pestaña History)
La lista del Action center con las acciones completadas, fallidas, rechazadas o deshechas, con quién las aprobó y cuándo.
Threat Explorer (explorador de amenazas)
Una herramienta de MDO Plan 2 para buscar, analizar y remediar correo en todo el tenant.
Real-time detections (detecciones en tiempo real)
La herramienta de búsqueda de correo más sencilla de MDO Plan 1, con menos acciones de remediación que Threat Explorer.
Soft delete (eliminación temporal)
Sacar un mensaje del buzón y llevarlo a Recoverable Items, donde todavía puede restaurarse.
Submissions (envíos)
La página del portal de Defender para los mensajes reportados por usuarios y los envíos de administradores de correos, archivos y URL a Microsoft.
Zero-hour auto purge, ZAP (purga automática de hora cero)
Eliminación automática de mensajes ya entregados que más tarde se consideran maliciosos.
Tenant Allow/Block List (lista de permitidos y bloqueados del tenant)
Una lista para todo el tenant con entradas de permiso y de bloqueo para remitentes, URL y archivos.
Network Message ID (identificador de mensaje de red)
Un identificador único de un mensaje de correo, que se usa para seguirlo en Threat Explorer, las alertas y la búsqueda avanzada.
DCSync
Un ataque que se hace pasar por un controlador de dominio para solicitar datos de contraseñas mediante la replicación del directorio.
KRBTGT account (cuenta KRBTGT)
La cuenta de AD cuya clave firma cada ticket de concesión de tickets de Kerberos del dominio.
Golden Ticket (ticket dorado)
Un TGT de Kerberos falsificado creado con el hash robado de KRBTGT, que otorga acceso como cualquier usuario.
Pass-the-hash (pase del hash)
Autenticarse con un hash NTLM robado en lugar de la contraseña.
Lateral movement path (ruta de movimiento lateral)
Una cadena de sesiones y derechos de administrador que le permite a un atacante pasar de una cuenta de poco valor a una sensible.
LAPS
Local Administrator Password Solution, que da a cada dispositivo una contraseña de administrador local única y rotada.
Pass-the-ticket (pase del ticket)
Reutilizar un ticket de Kerberos robado para autenticarse como un usuario sin la contraseña.
Sign-in risk (riesgo de inicio de sesión)
La probabilidad de que un inicio de sesión específico no lo haya realizado el usuario legítimo.
User risk (riesgo de usuario)
La probabilidad de que la propia cuenta esté comprometida, por ejemplo por credenciales filtradas.
Confirm user compromised (confirmar usuario comprometido)
Una acción del analista que establece el riesgo de usuario en alto, activa las directivas y retroalimenta al modelo de riesgo.
Revoke sessions (revocar sesiones)
Invalidar los tokens de actualización y las cookies de sesión de un usuario para que todas las sesiones deban autenticarse de nuevo.
MFA fatigue (fatiga de MFA)
Un ataque que inunda a un usuario con solicitudes de aprobación push con la esperanza de que apruebe una.
Number matching (coincidencia de números)
Una configuración de las notificaciones push de MFA que exige escribir un número mostrado, lo que frustra las aprobaciones a ciegas en los ataques de fatiga de MFA.
Report suspicious activity (reportar actividad sospechosa)
Una opción que permite a un usuario reportar una solicitud de MFA inesperada, lo que lo marca como de riesgo alto en ID Protection.
Cloud access security broker, CASB (agente de seguridad de acceso a la nube)
Un servicio que da visibilidad y control sobre el uso de aplicaciones en la nube; Defender for Cloud Apps es el de Microsoft.
Impossible travel (viaje imposible)
Una alerta de anomalía por inicios de sesión desde ubicaciones lejanas en un tiempo que hace imposible el viaje físico.
OAuth app consent (consentimiento de aplicación OAuth)
El permiso que un usuario o administrador otorga a una aplicación para acceder a datos en su nombre.
Consent phishing (phishing de consentimiento)
Engañar a los usuarios para que otorguen permisos OAuth a una aplicación maliciosa, lo que evade los controles de contraseña.
Ban app (prohibir la aplicación)
Una acción de Defender for Cloud Apps que revoca los permisos de una aplicación OAuth y bloquea nuevos consentimientos.
Admin consent workflow (flujo de trabajo de consentimiento del administrador)
Una función de Entra ID que permite a los usuarios solicitar la aprobación de un administrador para aplicaciones a las que no pueden dar su consentimiento.
Anomaly detection policy (directiva de detección de anomalías)
Una directiva integrada de Defender for Cloud Apps que aprende el comportamiento normal de los usuarios y alerta sobre desviaciones como el viaje imposible o la descarga masiva.
Data loss prevention, DLP (prevención de pérdida de datos)
Directivas de Purview que detectan y controlan el uso compartido de información sensible en servicios y endpoints.
Insider risk management (gestión de riesgos internos)
Capacidad de Purview que detecta actividad riesgosa de los usuarios, como el robo de datos por parte de empleados que se van.
Pseudonymization (seudonimización)
Mostrar un alias en lugar del nombre real de un usuario en las alertas de riesgo interno hasta que se autoriza revelar la identidad.
Unified audit log (registro de auditoría unificado)
El registro de Purview Audit de las actividades de usuarios y administradores en los servicios de Microsoft 365.
Audit (Premium)
El nivel de Purview Audit que agrega retención más larga, directivas de retención personalizadas y eventos adicionales de alto valor.
MailItemsAccessed
Un evento de auditoría de buzones, ahora disponible tanto en Audit (Standard) como en Premium, que muestra a qué elementos del buzón se accedió.
Security alert (alerta de seguridad)
Una detección de Defender for Cloud de una amenaza contra una carga de trabajo protegida, generada por un plan de Defender de pago.
Take action tab (pestaña Take action)
La pestaña de la alerta con secciones para inspeccionar el contexto, mitigar, prevenir que se repita, desencadenar automatización y suprimir alertas similares.
Workflow automation (automatización de flujos de trabajo)

Suppression rule (regla de supresión)

Continuous export (exportación continua)

Dismiss (descartar)

Sample alerts (alertas de ejemplo)

Investigation graph (gráfico de investigación)

Entity page (página de entidad)
Una página que muestra las alertas de una entidad, la línea de tiempo de su actividad, las entidades relacionadas y la información de UEBA.
Investigation priority (prioridad de investigación)

Playbook Operator

Benign positive (positivo benigno)
Una clasificación de Sentinel para actividad que se detectó correctamente pero era esperada, como una prueba aprobada.
Incident task (tarea del incidente)
Un elemento de la lista de verificación de un incidente, agregado manualmente o por automatización, que sigue los pasos de la investigación.
UEBA
User and entity behavior analytics (análisis del comportamiento de usuarios y entidades), que crea una línea base de usuarios y entidades frente a su propio historial y sus pares para resaltar la actividad inusual.
Security Copilot
El asistente de IA generativa de Microsoft para operaciones de seguridad, integrado en el portal de Defender.
Incident summary (resumen del incidente)

Guided response (respuesta guiada)
Las acciones recomendadas por Copilot de triaje, contención, investigación y remediación para un incidente.
Script analysis (análisis de scripts)
Una función de Copilot que decodifica y explica scripts y líneas de comandos sospechosos encontrados en la evidencia.
Incident report (informe del incidente)
Un documento generado por Copilot con la línea de tiempo, los hallazgos y las acciones tomadas en un incidente.
Security compute unit, SCU (unidad de cómputo de seguridad)
La unidad de capacidad que una organización aprovisiona para ejecutar Security Copilot.
Role-based access control, RBAC (control de acceso basado en roles)
Permisos asignados por rol; Copilot solo puede usar los datos a los que el usuario que inició sesión tiene permiso de acceder.

Dominio 3: Perform threat hunting (22%)

Consejos para el examen

  • Conoce la diferencia entre project (conserva solo las columnas indicadas) y extend (agrega columnas y conserva todas), y entre take (muestra sin ordenar) y top (ordenado y limitado). Recuerda Timestamp en las tablas de Defender y TimeGenerated en las tablas de Sentinel.
  • Al examen le gusta preguntar qué tipo de join encuentra registros sin coincidencia (leftanti) y por qué se prefiere has en lugar de contains (rendimiento con términos completos). Recuerda que el tipo de join predeterminado es innerunique.
  • Relaciona la redacción de la pregunta con las tablas: proceso y línea de comandos significa DeviceProcessEvents; conexión o IP remota significa DeviceNetworkEvents; inicios de sesión Kerberos o NTLM locales significa IdentityLogonEvents; reglas de buzón en Exchange Online normalmente significa CloudAppEvents.
  • Si un escenario dice que la regla no se puede guardar o que las alertas no tienen entidades, a la consulta le faltan columnas obligatorias o de entidad. El KQL generado es un punto de partida que el analista debe validar.
  • Guardar evidencia de una búsqueda: marcador (bookmark). Vigilar nuevas coincidencias sin escribir una regla: livestream. Python, aprendizaje automático o enriquecimiento complejo: notebook con MSTICPy.
  • Busca estas pistas: 'encontrar registros que coincidan con X del año pasado' significa trabajo de búsqueda; 'investigar todo lo de esa semana con KQL completo' significa restauración; 'consultar el data lake según un horario y enviar los resultados al nivel de análisis' significa KQL job.
  • Una sola consulta para muchos proveedores con el mismo tipo de evento significa ASIM. Usa los parsers de filtrado _Im_ con parámetros para obtener rendimiento; los parsers _ASim_ no aceptan parámetros.
  • TAXII es el transporte y STIX el formato. Informes escritos sobre actores con el estado de exposición y mitigación en tu inquilino significa threat analytics; comparar indicadores con los registros significa reglas de análisis TI map.
  • Cuando una pregunta plantea a qué podría llegar un atacante desde una identidad o un dispositivo comprometido, la respuesta es el radio de impacto o una vista de rutas de ataque; cuando pregunta qué eventos cumplen una condición, es una consulta KQL.

Términos clave

where
Un operador que conserva solo las filas que cumplen una condición.
project
Un operador que conserva, ordena y opcionalmente renombra solo las columnas indicadas.
extend
Un operador que agrega columnas calculadas y conserva las existentes.
summarize
Un operador que agrupa filas y calcula agregados como count() o dcount().
bin()
Una función que redondea valores, normalmente marcas de tiempo, en intervalos de tamaño fijo para agrupar.
ago()
Una función que devuelve un momento relativo a ahora, como ago(1d) para hace un día.
render
Un operador que dibuja los resultados de la consulta como un gráfico, por ejemplo un timechart.
take
Un operador que devuelve un conjunto arbitrario y sin ordenar de filas, útil para previsualizar una tabla.
top
Un operador que ordena por una columna y devuelve las primeras N filas en un solo paso.
has vs. contains
has coincide rápidamente con términos completos indexados; contains coincide con cualquier subcadena y es más lento.
has_any
Un operador que comprueba si una columna de texto contiene algún término de una lista.
let
Una instrucción que le da nombre a un valor, una lista o una consulta para reutilizarlos más adelante en la consulta.
leftanti join
Un join que devuelve las filas del lado izquierdo que no tienen coincidencia en el derecho.
union
Un operador que apila filas de varias tablas en un solo resultado.
mv-expand
Un operador que convierte cada elemento de un arreglo en su propia fila.
make-series
Un operador que construye series temporales regulares para analizarlas con funciones como series_decompose_anomalies().
innerunique
El tipo de join predeterminado, que elimina las claves duplicadas del lado izquierdo antes de emparejar.
parse_json()
Una función que convierte una cadena JSON en un objeto dinámico cuyas propiedades puedes referenciar.
DeviceProcessEvents
La tabla de eventos de creación de procesos, que incluye líneas de comandos y detalles del proceso padre.
DeviceNetworkEvents
La tabla de conexiones de red de los dispositivos, con IP remota, puerto, URL y proceso iniciador.
NetworkMessageId
El identificador de correo que vincula EmailEvents con EmailUrlInfo, EmailAttachmentInfo y tablas relacionadas.
IdentityLogonEvents
Eventos de autenticación de Defender for Identity (AD local) y de Microsoft Entra ID.
CloudAppEvents
Actividad de aplicaciones en la nube como Exchange Online y SharePoint, con los detalles en RawEventData.
AlertEvidence
Una fila por cada entidad adjunta a una alerta, unida a AlertInfo por AlertId.
AlertInfo
Una fila por alerta de los productos de Defender, con título, gravedad, categoría y origen; unida a AlertEvidence por AlertId.
ActionType
Una columna presente en la mayoría de las tablas de búsqueda avanzada que describe el tipo de evento que registra cada fila.
Hypothesis-driven hunting (hunting basado en hipótesis)
Hunting que parte de una idea específica sobre el comportamiento del atacante y la pone a prueba con consultas.
Detection-ready query (consulta lista para detección)
Una consulta que devuelve eventos específicos con las columnas identificadoras y de entidad obligatorias y un nivel de ruido aceptable.
arg_max()
Una agregación que devuelve la fila con el valor máximo de una columna, conservando las demás columnas.
Noise testing (prueba de ruido)
Ejecutar una detección candidata sobre todo su período de revisión para medir con qué frecuencia se dispararía antes de guardarla.
Natural-language to KQL (de lenguaje natural a KQL)
La capacidad de Security Copilot de generar una consulta KQL a partir de una solicitud en lenguaje sencillo.
Detection rules page (página de reglas de detección)
La página del portal de Defender donde se listan, editan, ejecutan y supervisan las detecciones personalizadas.
Custom detection rule (regla de detección personalizada)
Una regla de Defender XDR creada a partir de una consulta de búsqueda avanzada que se ejecuta según un horario y genera alertas, opcionalmente con acciones automáticas.
Threat hunting (búsqueda de amenazas)
Buscar de forma proactiva a los atacantes que evadieron las detecciones existentes, normalmente a partir de una hipótesis.
Hunting query (consulta de hunting)
Una consulta KQL guardada para la búsqueda proactiva, a menudo mapeada a MITRE ATT&CK, que no crea alertas.
Hunt
Un objeto de Sentinel que organiza un proyecto de búsqueda con una hipótesis, consultas, estado y hallazgos.
Bookmark (marcador)
Resultados de consulta guardados con notas, etiquetas y entidades que pueden agregarse a un incidente o crear uno.
Livestream
Una sesión que ejecuta una consulta de hunting de forma continua sobre datos nuevos y te notifica las coincidencias.
MSTICPy
Una biblioteca de Python de código abierto para investigaciones de seguridad en notebooks, con consultas de datos, enriquecimiento y visualización.
HuntingBookmark
La tabla del área de trabajo donde Sentinel guarda los marcadores, para que puedan consultarse con KQL.
Long-term retention (retención a largo plazo)
Almacenamiento de bajo costo de datos más allá de la retención interactiva, que las reglas de análisis no pueden usar directamente.
Search job (trabajo de búsqueda)
Una búsqueda asíncrona en datos a largo plazo cuyos registros coincidentes se escriben en una tabla _SRCH.
Restore (restauración)
Traer de vuelta un rango de tiempo de datos a largo plazo al nivel de análisis, en una tabla _RST, para consultarlos por completo.
KQL job
Una consulta KQL única o programada sobre el data lake de Sentinel que escribe los resultados en una tabla del nivel de análisis.
Data lake exploration (exploración del data lake)
Consulta interactiva con KQL de los datos guardados en el nivel de data lake de Sentinel.
Results table (tabla de resultados)
La tabla del nivel de análisis creada por un trabajo de búsqueda, una restauración o un KQL job, que se puede consultar con KQL normal.
Analytics tier (nivel de análisis)
El nivel interactivo donde el KQL completo, las reglas de análisis, los libros de trabajo y el hunting se ejecutan sobre datos recientes.
ASIM
El Advanced Security Information Model, que normaliza eventos de distintas fuentes en esquemas comunes.
ASIM schema (esquema de ASIM)
Un conjunto estándar de nombres de columnas y valores para un tipo de evento, como sesión de red o DNS.
Source-specific parser (parser específico de la fuente)
Una función de ASIM que normaliza los datos de un producto en un esquema.
Unifying parser (parser unificador)
Una función de ASIM que combina todos los parsers específicos de la fuente de un esquema en un solo resultado normalizado.
Filtering parser (parser de filtrado)
Un parser _Im_ que acepta parámetros como filtros de tiempo y de IP para mejorar el rendimiento.
Query-time normalization (normalización en el momento de la consulta)
Convertir los datos de un proveedor a un esquema común cuando se ejecuta la consulta, y no cuando se ingieren los datos.
_ASim_ parser (parser _ASim_)
Un parser unificador sin parámetros que devuelve todos los datos normalizados de un esquema, útil para explorar.
Ingestion-time normalization (normalización en el momento de la ingesta)
Convertir los datos a un esquema de ASIM a medida que se ingieren y guardarlos en tablas normalizadas, cambiando flexibilidad por rendimiento en las consultas.
Indicator of compromise, IoC (indicador de compromiso)
Un observable como una IP, un dominio, una URL o un hash asociado con actividad maliciosa.
STIX
Structured Threat Information Expression, un formato estándar para describir la inteligencia de amenazas.
TAXII
Trusted Automated Exchange of Intelligence Information, un protocolo para compartir datos STIX entre servidores y clientes.
TI map rule (regla TI map)
Una regla de análisis de coincidencia de inteligencia de amenazas que genera alertas cuando los indicadores aparecen en los registros.
Threat analytics
Informes del portal de Defender sobre amenazas activas que muestran incidentes relacionados, activos afectados y el estado de las mitigaciones.
Exposure and mitigations (exposición y mitigaciones)
La sección de threat analytics que muestra si tus dispositivos tienen los parches y las configuraciones que defienden contra una amenaza.
Finished intelligence (inteligencia elaborada)
Análisis escrito sobre actores de amenazas, campañas y técnicas que orienta las prioridades y las defensas.
Threat intelligence platform, TIP (plataforma de inteligencia de amenazas)
Un sistema que recopila y administra indicadores y puede enviarlos a Sentinel a través de la API de carga.
Graph (grafo)
Un modelo de datos de nodos (entidades) y aristas (relaciones) que se usa para analizar conexiones.
Node and edge (nodo y arista)
Un nodo es una entidad, como un usuario o un dispositivo; una arista es una relación entre dos nodos, como miembro de.
Sentinel graph
Un modelo de relaciones de identidades, dispositivos, recursos y actividad construido sobre el data lake de Sentinel y los datos de seguridad de Microsoft.
Hunting graph
Una exploración visual e interactiva de las relaciones entre entidades durante una búsqueda en el portal de Defender.
Blast radius (radio de impacto)
El conjunto de activos a los que un atacante podría llegar desde un usuario o dispositivo comprometido, mostrado como rutas hacia objetivos críticos.
Attack path (ruta de ataque)
Una cadena de relaciones y debilidades que podría llevar a un atacante desde un punto de entrada hasta un activo crítico.
Critical asset (activo crítico)
Un recurso marcado como muy importante, como un controlador de dominio o un almacén de claves, que las vistas de radio de impacto y de rutas de ataque resaltan como objetivo.
