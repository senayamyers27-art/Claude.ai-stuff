Lógica y estructura de Python: palabras clave, instrucciones, indentación y comentarios

Un programa de Python es una secuencia de instrucciones (statements) que el intérprete ejecuta de arriba hacia abajo. Normalmente cada instrucción ocupa su propia línea, y el final de la línea termina la instrucción; no hay punto y coma al final como en otros lenguajes. Puedes poner varias instrucciones cortas en una línea separadas por punto y coma, y puedes continuar una instrucción larga en varias líneas dentro de paréntesis, corchetes o llaves, o con una barra invertida al final de una línea, pero el estilo simple de una instrucción por línea es el que debes escribir y el que el examen suele mostrar. Por ejemplo, una suma larga escrita entre paréntesis puede continuar en la línea siguiente, porque Python sigue leyendo hasta que se cierra el paréntesis. Recuerda también que las instrucciones se ejecutan estrictamente en orden: una línea no puede usar un nombre que solo se asigna más abajo en el archivo.

Las palabras clave son palabras reservadas con un significado fijo en el lenguaje, como if, else, elif, while, for, in, def, return, pass, break, continue, import, global, try, except, and, or, not, is, None, True y False. No puedes usar una palabra clave como nombre de variable o de función: for = 3 es un error de sintaxis. Las palabras clave distinguen mayúsculas de minúsculas: True es una palabra clave, pero true es un nombre común y corriente, y normalmente no está definido. Puedes ver la lista completa con import keyword seguido de print(keyword.kwlist). Cada palabra clave tiene una función que conocerás en lecciones posteriores: if, elif y else eligen entre caminos, while y for repiten, def y return construyen funciones, y try y except manejan errores. El resaltado de sintaxis de IDLE y de la mayoría de los editores muestra las palabras clave en un color distinto, lo que sirve como comprobación visual rápida de que no usaste una por accidente como nombre.

La indentación es parte de la sintaxis de Python, no solo una cuestión de estilo. Una instrucción compuesta como if, while, for, def o try termina su línea de encabezado con dos puntos, y las líneas que le pertenecen (su bloque, también llamado suite) deben tener más indentación que el encabezado. El bloque termina cuando la indentación vuelve al nivel anterior. Todas las líneas de un bloque deben usar exactamente la misma indentación. PEP 8 (Python Enhancement Proposal 8, la guía de estilo oficial) recomienda cuatro espacios por nivel. Mezclar tabulaciones y espacios de forma inconsistente provoca TabError, y un nivel incorrecto provoca IndentationError; ambos son tipos de SyntaxError. La indentación reemplaza las llaves que lenguajes como C o Java usan para marcar bloques, así que en Python el aspecto visual y la estructura del programa nunca pueden contradecirse. Los bloques pueden anidarse: un for dentro de un if recibe un segundo nivel de indentación, ocho espacios en el estilo de PEP 8, y cada nivel se cierra cuando el código vuelve hacia el margen izquierdo.

x = 7
if x > 5:
    print("big")      # dentro del bloque if
    print("still in") # mismo bloque, misma indentación
print("always runs")  # de vuelta en el nivel exterior
# salida: big / still in / always runs

Los comentarios empiezan con # y llegan hasta el final de la línea. El intérprete los ignora por completo, así que son para los lectores humanos: explica por qué el código hace algo, no qué hace cada línea obvia. Un # dentro de un literal de cadena es solo un carácter, no un comentario. Python no tiene una sintaxis especial para comentarios de varias líneas; pones # en cada línea o, por convención, usas una cadena entre comillas triples, que en realidad es un literal de cadena que se evalúa y se descarta. Cuando una cadena entre comillas triples es la primera instrucción de una función o de un módulo, se convierte en su docstring, una pieza de documentación integrada. Los buenos comentarios explican la intención, como # retry once because the sensor sometimes misses a reading, mientras que los que solo repiten el código, como # add 1 to x, estorban. Poner # delante de una línea también es una forma rápida de desactivarla durante las pruebas, un hábito llamado comentar la línea.

Veamos un ejemplo práctico. Un estudiante escribe un bucle que debe imprimir un total acumulado. El encabezado for n in range(3): va seguido de dos líneas, la primera con cuatro espacios de indentación y la segunda con tres. Python se niega a ejecutar el archivo e informa IndentationError: unindent does not match any outer indentation level. Después de corregirlo, el estudiante mueve print(total) de vuelta al margen izquierdo; ahora se ejecuta una vez después del bucle en lugar de tres veces dentro de él. Ambas versiones contienen exactamente las mismas palabras, pero la indentación por sí sola cambia si el programa se ejecuta y lo que imprime.

Errores comunes: olvidar los dos puntos al final de un encabezado, lo que es un SyntaxError; indentar una línea que no tiene encabezado encima, lo que da IndentationError: unexpected indent; terminar un encabezado con dos puntos y no indentar nada debajo, lo que da IndentationError: expected an indented block (la razón por la que existe la palabra clave pass); escribir true o none en minúsculas; y creer que un comentario puede servir como cuerpo de un bloque. No puede, porque los comentarios se descartan antes de revisar la gramática.

Las preguntas del examen en esta área suelen mostrar un fragmento corto y preguntar si se ejecuta, qué imprime o qué error aparece. Pistas: "palabra reservada" o "no puede usarse como nombre" significa palabra clave; "pertenece al bloque" significa nivel de indentación; "ignorado por el intérprete" significa comentario; "unexpected indent" y "expected an indented block" nombran los dos errores de indentación clásicos. Cuando la indentación de una línea es la única diferencia entre las opciones de respuesta, revisa las columnas con cuidado, porque eso es exactamente lo que se está evaluando.

Términos clave

Statement (instrucción)
Una sola orden que el intérprete ejecuta, normalmente una por línea.
Keyword (palabra clave)
Una palabra reservada con significado fijo, como if, for o def, que no puede usarse como identificador.
Block (bloque, suite)
El grupo de instrucciones indentadas que pertenece a una línea de encabezado que termina en dos puntos.
Comment (comentario)
Texto desde # hasta el final de la línea, que el intérprete ignora.
IndentationError
La subclase de SyntaxError que se lanza cuando la indentación falta, es inesperada o es inconsistente.
Docstring (cadena de documentación)
Un literal de cadena colocado en primer lugar en un módulo o una función, que se conserva como su documentación.
Ejemplo real

Un estudiante escribe un bucle cuya segunda línea del cuerpo tiene tres espacios de indentación en lugar de cuatro. Python informa un IndentationError (unindent does not match any outer indentation level) antes de ejecutar nada. Al indentar ambas líneas con cuatro espacios, el programa se ejecuta, y al mover el print final de vuelta al margen, se ejecuta una vez después del bucle en lugar de en cada pasada.

Consejo para el examen: True, False y None son palabras clave con mayúscula inicial; true en minúsculas es solo un nombre no definido. Un # entre comillas no es un comentario, y un comentario solo nunca puede ser el cuerpo de un bloque.

Comprueba lo que sabes

¿Qué ocurre si escribes if x > 3: y la línea siguiente no está indentada?

Python lanza IndentationError: expected an indented block, porque el encabezado de una instrucción compuesta debe ir seguido de un bloque indentado.

¿Puedes llamar pass a una variable?

No. pass es una palabra clave, así que pass = 1 es un SyntaxError.

¿Qué muestra print("a # b")?

a # b. El # forma parte del literal de cadena, no es el inicio de un comentario.

¿Cuántos espacios por nivel de indentación recomienda PEP 8, y es obligatorio?

Cuatro espacios. El intérprete solo exige consistencia dentro de un bloque; los cuatro espacios son una convención de estilo.
