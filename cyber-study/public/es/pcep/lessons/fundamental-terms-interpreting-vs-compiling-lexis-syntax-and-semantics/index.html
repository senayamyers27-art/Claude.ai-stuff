PCEP – Certified Entry-Level Python Programmer PCEP-30-02

Términos fundamentales: interpretar vs. compilar, léxico, sintaxis y semántica, código fuente y el intérprete de Python

El procesador de una computadora solo entiende código máquina: largas secuencias de instrucciones binarias propias de ese procesador. Las personas no lo escriben directamente. En su lugar, escribes código fuente en un lenguaje de programación de alto nivel como Python, y un programa lo traduce a algo que la máquina puede ejecutar. El examen PCEP (Certified Entry-Level Python Programmer) espera que conozcas el vocabulario de cómo ocurre esa traducción y de las reglas que impone cualquier lenguaje, porque estas palabras aparecen en las preguntas mucho antes de que escribas una línea de código.

Hay dos estrategias clásicas de traducción. La compilación traduce todo el programa por adelantado a un archivo ejecutable separado de código máquina, que luego puede ejecutarse muchas veces sin el compilador. La interpretación lee el código fuente y lo ejecuta instrucción por instrucción cada vez que el programa corre, así que el intérprete siempre debe estar presente. Los programas compilados suelen ejecutarse más rápido y pueden distribuirse sin su código fuente; los interpretados son más rápidos de probar y más fáciles de llevar de una plataforma a otra, porque el mismo código fuente corre en cualquier lugar donde exista un intérprete. Python se considera un lenguaje interpretado: ejecutas python3 script.py y el intérprete lo ejecuta. Internamente, CPython primero convierte el código fuente en bytecode para su propia máquina virtual, pero para el examen, Python es interpretado. La consecuencia práctica es que un programa compilado queda atado a un tipo de procesador y de sistema operativo, mientras que un script de Python puede copiarse a Windows, macOS o Linux y ejecutarse sin cambios, siempre que haya un intérprete instalado allí. El precio es que cada usuario necesita ese intérprete y cada ejecución paga un pequeño costo de traducción.

Todo lenguaje, humano o de computadora, tiene capas de reglas. Un alfabeto es el conjunto de símbolos que puedes usar. El léxico es el vocabulario: el conjunto de palabras y símbolos válidos, como palabras clave, operadores, nombres y literales. La sintaxis es la gramática: las reglas sobre cómo pueden combinarse esas palabras en instrucciones válidas. La semántica es el significado: si una instrucción bien formada realmente tiene sentido. Por ejemplo, print("hi" es un error de sintaxis porque falta un paréntesis, mientras que print(10 / 0) es gramaticalmente correcta, pero falla al ejecutarse porque dividir entre cero no tiene significado. Piensa en las capas como una escalera: el texto solo puede usar símbolos permitidos, esos símbolos deben formar palabras permitidas, las palabras deben ordenarse según la gramática, y solo entonces alguien puede preguntarse si el resultado significa algo. Un problema en un peldaño inferior te detiene antes de que se revisen siquiera los peldaños superiores.

El intérprete encuentra los problemas en momentos distintos, y el examen evalúa esa diferencia. Antes de ejecutar nada, Python lee (analiza) todo el archivo; un error de sintaxis en cualquier parte detiene el programa antes de que se ejecute siquiera la primera línea, y el mensaje muestra la línea con un acento circunflejo (^) bajo el problema. Los errores en tiempo de ejecución, llamados excepciones, aparecen solo cuando realmente se llega a la línea defectuosa, así que las líneas anteriores ya pueden haber producido salida. Los errores de lógica son los más difíciles: el programa se ejecuta sin quejarse pero da una respuesta incorrecta, y ninguna herramienta te los señalará. Puedes distinguir los dos primeros por lo que ves en pantalla. Un mensaje de error de sintaxis indica el archivo y la línea, repite la línea problemática con un ^ debajo y termina con una línea como SyntaxError: invalid syntax (las versiones más recientes suelen mostrar una explicación más específica). Un error en tiempo de ejecución muestra un traceback que empieza con Traceback (most recent call last): y termina con el nombre de la excepción y un mensaje, por ejemplo ZeroDivisionError: division by zero.

CPython es la implementación de referencia de Python, escrita en lenguaje C, y es la que descargas del sitio oficial de Python. Puedes usarla de dos modos. El modo interactivo, también llamado REPL (read-eval-print loop, bucle de lectura, evaluación e impresión), muestra el indicador >>> y evalúa cada línea de inmediato, lo que es ideal para experimentar. El modo script ejecuta un archivo .py guardado de principio a fin. Los archivos fuente son texto plano, así que sirve cualquier editor, e IDLE (Integrated Development and Learning Environment), que viene con Python, te ofrece tanto un editor como un shell. En el REPL ni siquiera necesitas print() para ver un valor: al escribir 2 + 3 en el indicador >>> aparece 5, lo que lo convierte en un lugar práctico para probar una idea. Un script, en cambio, no muestra nada a menos que lo imprimas.

# guarda como demo.py y ejecuta: python3 demo.py
print("start")        # se ejecuta primero
print(len("abc"))     # 3
print(10 / 0)         # ZeroDivisionError aquí, en tiempo de ejecución
print("never shown")

Veamos un ejemplo práctico. Guardas un archivo con tres llamadas a print(), pero a la tercera le falta el paréntesis de cierre. Al ejecutarlo, no se imprime nada: el intérprete informa un SyntaxError antes de ejecutar cualquier cosa, porque primero analiza todo el archivo. Corriges el paréntesis, pero ahora la segunda línea es print(1 / 0). Esta vez la primera línea se imprime y luego un ZeroDivisionError detiene el programa, así que la tercera línea nunca se ejecuta. Por último corriges eso, pero escribiste area = width + height cuando querías una multiplicación; todo se ejecuta e imprime un número, pero es incorrecto. Eso es un error de lógica.

Errores comunes: pensar que Python es compilado porque crea archivos de bytecode .pyc; suponer que un error de sintaxis en la línea 10 deja que se ejecuten primero las líneas 1 a 9 (no es así); y confundir léxico con sintaxis. Un nombre mal escrito, como prnt, es léxicamente válido (es un nombre permitido), se analiza sin problema y solo falla en tiempo de ejecución con NameError. Las preguntas del examen usan palabras clave: "traducido una vez a un ejecutable" significa compilador; "ejecutado línea por línea cada vez" significa intérprete; "vocabulario" significa léxico; "gramática" o "estructura" significa sintaxis; "significado" significa semántica; "detectado antes de la ejecución" significa error de sintaxis.

Términos clave

Source code (código fuente)
El texto del programa, legible por humanos, que escribes; en Python se guarda en un archivo .py de texto plano.
Compiler (compilador)
Un programa que traduce todo el código fuente a código máquina por adelantado y produce un ejecutable separado.
Interpreter (intérprete)
Un programa que lee y ejecuta el código fuente cada vez que este se ejecuta; CPython es el intérprete de referencia de Python.
Lexis (léxico)
El vocabulario de un lenguaje: las palabras y símbolos válidos que reconoce.
Syntax (sintaxis)
Las reglas gramaticales para combinar los elementos léxicos en instrucciones válidas.
Semantics (semántica)
Las reglas que deciden si una instrucción bien formada tiene sentido y qué significa.
REPL
El bucle interactivo de lectura, evaluación e impresión, indicado por el símbolo >>>, que ejecuta cada línea a medida que la escribes.
Ejemplo real

Guardas un archivo con tres llamadas a print(), pero a la tercera le falta el paréntesis de cierre. Al ejecutarlo no se imprime nada: el intérprete informa un SyntaxError antes de ejecutar cualquier cosa. Corriges eso, pero haces que la segunda línea sea print(1 / 0), y ahora la primera línea se imprime y luego un ZeroDivisionError detiene el programa antes de la tercera línea.

Consejo para el examen: Las preguntas del examen suelen pedir qué tipo de error produce un fragmento. Los paréntesis faltantes, la mala indentación o las palabras clave fuera de lugar son errores de sintaxis detectados antes de ejecutar nada; el código válido que hace algo imposible es un error en tiempo de ejecución, que solo aparece cuando se llega a esa línea.

Comprueba lo que sabes

¿Cuál es la diferencia práctica clave entre compilar e interpretar?

Un compilador traduce todo el programa una vez a un ejecutable que corre sin el compilador; un intérprete traduce y ejecuta el código fuente cada vez, así que el intérprete debe estar presente.

¿print("a" + 5) es un error de sintaxis o un error en tiempo de ejecución?

Un error en tiempo de ejecución (TypeError). La línea es gramaticalmente válida, pero sumar una cadena y un entero no tiene significado, así que solo falla al ejecutarse.

¿Qué se viola al escribir prnt en lugar de print: el léxico, la sintaxis o la semántica?

Ni el léxico ni la sintaxis: prnt es un nombre válido y la línea se analiza bien. Falla en tiempo de ejecución con NameError porque el nombre no está definido, lo cual es un problema semántico.

Un archivo tiene un error de sintaxis en su última línea. ¿Cuántas líneas anteriores se ejecutan?

Ninguna. Python analiza todo el archivo antes de ejecutarlo, así que el SyntaxError se informa antes de que se ejecute cualquier línea.
