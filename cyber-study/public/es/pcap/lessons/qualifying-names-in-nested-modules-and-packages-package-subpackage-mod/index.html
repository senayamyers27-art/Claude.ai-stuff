PCAP – Certified Associate Python Programmer PCAP-31-03

Calificar nombres en módulos y paquetes anidados (package.subpackage.module.name)

Cuando un proyecto supera unos pocos archivos, los módulos se agrupan en paquetes. Un paquete es un directorio de módulos, y un paquete puede contener subpaquetes, que son simplemente paquetes dentro de paquetes. Para llegar a un objeto en lo profundo de ese árbol usas una ruta con puntos que refleja la estructura de directorios. Para un archivo extra/good/best/sigma.py que define una función funS(), el nombre totalmente calificado es extra.good.best.sigma.funS. Cada punto baja un nivel: paquete, subpaquete, sub-subpaquete, módulo y, por último, el objeto definido dentro del módulo.

Cuánto de esa ruta debes escribir depende por completo de cómo importaste. Con import extra.good.best.sigma, Python enlaza solo el nombre de nivel superior extra en tu namespace (espacio de nombres). No enlaza sigma, best ni good como nombres separados. Eso significa que siempre debes escribir la ruta completa: extra.good.best.sigma.funS(). Por eso exactamente Marcus vio un NameError para rules. Sorprende a mucha gente, pero es coherente: la instrucción import garantiza que cada paquete a lo largo de la ruta se carga y se adjunta como atributo de su padre, de modo que la cadena de búsquedas de atributos funciona cuando empiezas desde extra.

El alias es la primera forma de acortar la ruta. import extra.good.best.sigma as sig enlaza el nombre sig directamente al módulo sigma, así que llamas sig.funS(). En esta forma el nombre extra no se enlaza; el alias reemplaza toda la ruta por un solo nombre. Suele ser la opción más legible cuando un módulo está en lo profundo de un árbol y llamas a varias de sus funciones.

La forma from te permite detenerte en el nivel que quieras. from extra.good.best import sigma enlaza sigma, así que escribes sigma.funS(). from extra.good.best.sigma import funS enlaza la función misma, así que escribes funS() sin ningún prefijo. En cada caso, solo el nombre que va después de import se agrega a tu namespace; los nombres a la izquierda de import en una instrucción from no se enlazan.

Hay una regla estructural que al examen le encanta evaluar. En la forma simple import a.b.c, cada componente, incluido el último, debe ser un paquete o un módulo. Nunca puede ser una función, una clase ni una variable. import extra.good.best.sigma.funS falla con ModuleNotFoundError, porque Python intenta encontrar un módulo o paquete llamado funS dentro de sigma, y sigma es un módulo, no un paquete. Si quieres la función sola, debes usar from extra.good.best.sigma import funS.

@@EN@@

Para que todo esto funcione, el directorio de nivel superior, aquí extra, debe poder encontrarse. Tiene que estar dentro de una de las carpetas listadas en sys.path, como la carpeta que contiene tu script principal. No agregas las carpetas internas good ni best a sys.path; Python recorre el árbol hacia abajo por sí mismo usando el nombre con puntos. Tradicionalmente cada directorio contiene un archivo __init__.py que lo marca como paquete regular, y ese archivo se ejecuta cuando el paquete se importa por primera vez, así que importar extra.good.best.sigma ejecuta los archivos __init__.py de extra, extra.good y extra.good.best, en ese orden, antes de ejecutar sigma.py.

También conviene saber qué ocurre cuando importas menos de lo que usas. Supón que un script ejecuta solo import extra.good y más adelante escribe extra.good.best.sigma.funS(). Importar un paquete no importa automáticamente todos los subpaquetes y módulos que contiene, así que, a menos que otra cosa, como el propio __init__.py del paquete o una importación anterior en otra parte del programa, ya haya cargado best y sigma, la búsqueda de atributos falla con AttributeError. La regla segura es importar el módulo más profundo que necesitas, con la forma que prefieras, en lugar de confiar en que un paquete padre traiga a sus hijos. Observa también que una importación simple exitosa de una ruta profunda sigue enlazando solo el nombre superior, así que escribir la ruta completa no es opcional; es el precio de esa forma.

Un hábito útil al leer código del examen es dibujar primero el árbol de directorios y luego comprobar que cada nombre con puntos coincide exactamente con él, incluida la ortografía y el nivel que contiene la función. Después, fíjate qué forma de import se usó y, por lo tanto, qué único nombre se enlazó. Muchas respuestas incorrectas usan una ruta que se salta un nivel, intercambia dos nombres de carpeta, pone el nombre de la función donde debería ir un módulo, o usa un nombre corto como sigma después de un import que enlazó solo extra.

Términos clave

Package (paquete)
Un directorio de módulos (y posiblemente subpaquetes) que Python puede importar por nombre.
Subpackage (subpaquete)
Un paquete anidado dentro de otro, al que se llega con un punto, como extra.good.
Fully qualified name (nombre totalmente calificado)
La ruta completa con puntos desde el paquete superior hasta un objeto, como extra.good.best.sigma.funS.
ModuleNotFoundError
La excepción que se genera cuando un import nombra un módulo o paquete que Python no puede encontrar, incluso cuando la última parte de un import simple es una función.
Ejemplo real

El código de un equipo está en company/reports/pdf/render.py. Un script nuevo que escribe import company.reports.pdf.render debe llamar a company.reports.pdf.render.build(); cambiar a from company.reports.pdf import render le permite llamar a render.build() en su lugar.

Consejo para el examen: Con import a.b.c simple debes usar el prefijo completo a.b.c, y el último componente debe ser un módulo, no una función ni una clase. Las preguntas suelen ofrecer import a.b.func como respuesta incorrecta tentadora.

Comprueba lo que sabes

Después de import extra.good.best.sigma, ¿qué nombre se agrega a tu namespace?

Solo extra; llegas a la función mediante la ruta completa extra.good.best.sigma.funS().

¿Qué debe cumplirse en sys.path para que import extra.good.best.sigma funcione?

El directorio que contiene la carpeta de nivel superior extra debe estar en sys.path; las carpetas internas no necesitan estar listadas.

¿Qué import te permite llamar a funS() sin ningún prefijo?

from extra.good.best.sigma import funS, porque enlaza directamente el nombre de la función.
