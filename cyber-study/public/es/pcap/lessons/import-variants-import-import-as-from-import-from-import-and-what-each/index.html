PCAP – Certified Associate Python Programmer PCAP-31-03

Variantes de import: import, import as, from … import, from … import * y qué agrega cada una al namespace

Un módulo es simplemente un archivo de código Python, e importarlo te permite reutilizar las funciones, clases y valores que define. Al examen PCAP (Certified Associate Python Programmer, examen PCAP-31-03) le importa menos que sepas importar y más qué nombres exactamente quedan disponibles después. Cada módulo y cada script tiene su propio namespace (espacio de nombres): una tabla que asocia nombres con objetos. Cada forma de import agrega entradas distintas al namespace que importa, y muchas preguntas del examen en realidad preguntan algo sencillo disfrazado: ¿existe este nombre concreto en este momento concreto?

Empieza por la forma simple. import math agrega exactamente un nombre, math, que hace referencia al objeto módulo. Todo lo que está dentro del módulo debe calificarse con ese prefijo: math.pi, math.sqrt(2). Escribir sqrt(2) solo genera NameError, porque sqrt nunca se colocó en tu namespace; vive dentro del objeto módulo, no a su lado. Esta forma es la más clara para quien lee, ya que cada llamada muestra de dónde viene la función.

La forma con alias cambia solo la etiqueta. import math as m carga el mismo módulo pero lo enlaza al nombre m, y ese es el único nombre que agrega. El nombre math no está definido, así que math.pi falla con NameError mientras que m.pi funciona. Esto es justo lo que rompió el script de Priya en la escena inicial. Los alias son prácticos para nombres de módulo largos y son comunes en el ecosistema en general, por ejemplo import numpy as np, pero la regla del examen es estricta: después de import X as Y, solo existe Y.

La forma from funciona al revés. from math import sqrt, pi copia referencias a sqrt y pi directamente en tu namespace, de modo que llamas sqrt(2) sin prefijo, pero el nombre math no está definido en absoluto. También puedes poner alias a nombres individuales: from math import sqrt as root enlaza solo root. Como estos nombres llegan directamente a tu namespace, pueden chocar con los tuyos. Si después escribes pi = 3, reemplazaste el valor importado. Si defines tu propia sqrt y luego importas una, gana la importación porque ocurrió después. La regla siempre es la misma: gana el último enlace de un nombre, y Python no avisa cuando un enlace reemplaza a otro.

La forma con asterisco importa en bloque. from math import * copia todos los nombres públicos del módulo en tu namespace. Qué nombres cuentan como públicos sigue dos reglas que el examen espera que conozcas. Si el módulo define una lista de cadenas llamada __all__, solo se importan los nombres de esa lista. Si no existe __all__, se importa cada nombre de nivel superior que no empiece con guion bajo, así que una función auxiliar llamada _cache se queda atrás. Las importaciones con asterisco se desaconsejan en código real porque ocultan de dónde viene un nombre y pueden sobrescribir tus nombres sin aviso, pero aun así necesitas predecir exactamente qué traen.

@@EN@@

Sigue ese ejemplo nombre por nombre. La primera línea enlaza solo m, así que m.floor funciona y el math.pi comentado fallaría. La línea from enlaza pi directamente, y la asignación pi = 3 vuelve a enlazar ese mismo nombre a un nuevo entero. El módulo en sí no cambia: m.pi sigue siendo 3.141592653589793, porque solo cambiaste a qué objeto apunta tu propia etiqueta.

Dos datos más completan este tema. Primero, el código de un módulo se ejecuta solo en su primera importación dentro de un proceso. Python guarda los módulos cargados en un diccionario llamado sys.modules, y las importaciones posteriores del mismo módulo, en cualquier forma, reutilizan ese objeto módulo ya cargado en lugar de ejecutar el archivo de nuevo. Segundo, toda forma de import ejecuta el archivo completo del módulo la primera vez, incluso from mod import one_name. Python no puede darte una función sin ejecutar el archivo que la crea, así que cualquier llamada a print en el nivel superior de ese módulo aparecerá aunque hayas pedido un solo nombre.

Cuando encuentres una pregunta de import en el examen, ve despacio y anota, línea por línea, qué nombres agrega cada instrucción. Luego compara cada línea posterior con esa lista. Opciones que parecen perfectamente razonables a menudo fallan con NameError porque usan el nombre del módulo después de un import con alias o de un import from, y opciones que parecen incorrectas pueden funcionar porque un import from puso el nombre suelto justo donde se necesitaba.

Términos clave

Namespace (espacio de nombres)
Una asociación de nombres con objetos; cada módulo, llamada a función y clase tiene el suyo.
Alias
Un nombre alternativo dado con as, por ejemplo import math as m, que enlaza solo m.
__all__
Una lista de cadenas en un módulo que indica qué debe importar from module import *.
Qualified name (nombre calificado)
Un nombre escrito con el prefijo de su módulo, como math.sqrt.
sys.modules
El diccionario de módulos ya cargados en este proceso; las importaciones posteriores reutilizan sus entradas.
Ejemplo real

Un script de datos empieza con from statistics import mean y más adelante define su propia función llamada mean para manejar valores faltantes. Como el def aparece después del import, todas las llamadas posteriores usan la versión local, y la importación original queda ocultada sin ningún aviso.

Consejo para el examen: Pregúntate qué nombres agrega cada línea. import m as x define solo x, nunca m; from m import f define solo f, nunca m. Muchas opciones de respuesta que parecen correctas fallan con NameError justamente por esto.

Comprueba lo que sabes

Después de import random as r, ¿funciona print(random.random())?

No. Solo está definido el alias r, así que random genera NameError; debes escribir r.random().

¿Qué nombres omite from mod import * cuando mod no tiene __all__?

Los nombres que empiezan con guion bajo, como _helper; todos los demás nombres de nivel superior se importan.

Si un módulo se importa dos veces en el mismo programa, ¿cuántas veces se ejecuta su código de nivel superior?

Una vez. La segunda importación encuentra el módulo ya en sys.modules y lo reutiliza.
