Dominio 1: Understand and use essential tools (12%)

Consejos para el examen

  • Es el shell, no el comando, quien expande los globs, las variables y ~. Si un resultado te sorprende, pon echo delante del comando para ver exactamente qué argumentos recibirá el programa.
  • El orden importa: > file 2>&1 captura ambos flujos en el archivo, pero 2>&1 > file deja los errores en la terminal. Recuerda también que un solo > sobrescribe; usa >> cuando la tarea diga agregar.
  • En una regex, * no significa 'cualquier cosa' como en un comodín del shell; significa 'cero o más del carácter anterior'. La regex para 'cualquier cosa' es .* y los patrones van entre comillas simples.
  • su pide la contraseña del usuario de DESTINO; sudo pide TU contraseña. Y usa siempre el guion (su -) cuando necesites el entorno completo del otro usuario.
  • Haz coincidir la letra con la extensión: z = .gz, j = .bz2, J = .xz. Deja la f al final del grupo de opciones para que el nombre del archivo vaya justo después.
  • Si vim parece ignorar lo que escribes o hace cosas raras, estás en el modo equivocado: presiona Esc y luego usa :wq para guardar o :q! para abandonar los cambios.
  • Sabe qué conserva cada comando: mv dentro de un sistema de archivos conserva todo (incluido el contexto de SELinux anterior), cp sin -a toma un nuevo propietario y atributos predeterminados, y cp -a los conserva.
  • Enlaces duros: mismo inodo, solo en el mismo sistema de archivos, sin directorios, sobreviven al borrado del otro nombre. Symlinks: archivo aparte que contiene una ruta, pueden cruzar sistemas de archivos y apuntar a directorios, se rompen si el destino se mueve.
  • Borrar un archivo depende del permiso de escritura sobre el DIRECTORIO, no sobre el archivo. Y recuerda que la clase del propietario se revisa primero: un propietario con menos derechos que el grupo no hereda los derechos del grupo.
  • Si man -k devuelve 'nothing appropriate', el índice todavía no se ha creado: ejecuta mandb como root y busca de nuevo. Usa el número de sección (man 5 ...) cuando necesites un formato de archivo en lugar de un comando.

Términos clave

Shell
El programa (Bash en RHEL) que lee tus líneas de comandos, las expande e inicia los programas solicitados.
Opción
Una palabra que empieza con - o -- y cambia el comportamiento de un comando, como -l o --all.
Argumento
Una palabra después de las opciones sobre la que actúa el comando, normalmente un nombre de archivo o directorio.
Glob (comodín)
Un patrón con comodines como *.conf o file?.txt que el shell expande en los nombres de archivo que coinciden.
Tab completion (autocompletado con Tab)
Presionar Tab para que Bash termine un nombre de comando o de ruta, lo que reduce los errores de tipeo.
Expansión
La reescritura que hace el shell de una línea de comandos (globs, ~, variables, sustitución de comandos) antes de que el programa se ejecute.
stdin, stdout, stderr
Los descriptores de archivo 0, 1 y 2: la entrada estándar, la salida normal y la salida de errores de todo proceso.
> y >>
Redirigen stdout a un archivo, sobrescribiéndolo (>) o agregando al final (>>).
2>&1
Redirige stderr adonde apunta stdout en ese momento; colócalo después de la redirección de stdout.
Pipe (tubería, |)
Conecta el stdout de un comando con el stdin del comando siguiente.
tee
Copia su entrada tanto a la pantalla (stdout) como a archivos; -a agrega al final.
/dev/null
Un archivo especial que descarta todo lo que se escribe en él; se usa para desechar la salida no deseada.
Regular expression (expresión regular)
Un lenguaje de patrones para describir texto, que usan grep, sed, vim y muchas otras herramientas.
Ancla
^ coincide con el comienzo de una línea y $ con el final; coinciden con posiciones, no con caracteres.
Character class (clase de caracteres)
Una expresión entre corchetes como [a-z] que coincide con un carácter del conjunto indicado; [^...] la niega.
-v
Opción de grep que muestra las líneas que NO coinciden con el patrón.
-E
Opción de grep que activa las expresiones regulares extendidas, con lo que + ? | {} y () pasan a ser especiales.
-r
Opción de grep que busca de forma recursiva en todos los archivos bajo un directorio y antepone los nombres de archivo a los resultados.
SSH
Secure Shell: un protocolo cifrado y un cliente (ssh) para iniciar sesión y ejecutar comandos en sistemas remotos.
su -
Cambia de usuario con un shell de inicio de sesión completo y el entorno de ese usuario; pide la contraseña del usuario de destino.
sudo -i
Inicia un shell de inicio de sesión de root después de autenticarte con tu propia contraseña, según lo permita la política de sudoers.
wheel group (grupo wheel)
El grupo cuyos miembros pueden ejecutar cualquier comando con sudo según la política de sudoers predeterminada de RHEL.
multi-user.target
El target de systemd para un sistema en modo texto con red y servicios, pero sin inicio de sesión gráfico.
authorized_keys
Archivo en ~/.ssh del servidor que lista las claves públicas autorizadas para iniciar sesión en esa cuenta.
Archive (archivo empaquetado)
Un solo archivo que agrupa muchos archivos y directorios junto con sus metadatos; se crea con tar.
-c / -x / -t
Acciones de tar: crear un archivo, extraerlo o listarlo (tabla de contenido) sin extraer.
-f
Opción de tar que nombra el archivo; el nombre del archivo debe ir inmediatamente después.
-z / -j / -J
Usan compresión gzip, bzip2 o xz, respectivamente.
-C
Opción de tar que cambia a un directorio antes de extraer (o de archivar).
file
Comando que identifica el formato real de un archivo inspeccionando su contenido, como bzip2 o XZ compressed data.
Normal mode (modo normal)
El modo predeterminado de vim, en el que las teclas son comandos para moverse, borrar, copiar y pegar.
Insert mode (modo de inserción)
Modo de vim al que se entra con i, a u o, en el que las teclas escritas se convierten en texto; Esc sale de él.
:wq / :q!
Comandos de vim para guardar y salir, o para salir descartando los cambios no guardados.
visudo
Edita de forma segura el archivo sudoers: lo bloquea y revisa la sintaxis antes de guardar.
Swap file (archivo de intercambio)
Un archivo de recuperación .swp que vim mantiene mientras editas; uno sobrante indica una edición simultánea o que se colgó.
nano
Un editor de terminal sin modos cuyos atajos con la tecla Ctrl se listan en la parte inferior de la pantalla.
mkdir -p
Crea un directorio y cualquier directorio padre que falte; no da error si ya existe.
cp -a
Copia de archivo: recursiva, conserva permisos, propietario, marcas de tiempo, enlaces y atributos extendidos como los contextos de SELinux.
mv
Mueve o cambia el nombre de archivos; dentro de un mismo sistema de archivos conserva sin cambios los metadatos del archivo.
rm -r
Elimina de forma recursiva un directorio y todo su contenido.
rmdir
Elimina un directorio solo si está vacío.
Absolute path (ruta absoluta)
Una ruta que empieza en el directorio raíz /, independiente del directorio actual.
Inode (inodo)
La estructura en disco que guarda los metadatos de un archivo y la ubicación de sus datos, identificada por un número único dentro de su sistema de archivos.
Hard link (enlace duro)
Una entrada de directorio adicional que apunta al mismo inodo; se crea con ln.
Symbolic link (enlace simbólico)
Un archivo especial que contiene una ruta a otro archivo o directorio; se crea con ln -s.
Link count (contador de enlaces)
El número de enlaces duros (nombres) que hacen referencia a un inodo, que se muestra en la segunda columna de ls -l.
Dangling link (enlace colgante)
Un enlace simbólico cuyo destino ya no existe.
readlink -f
Muestra la ruta totalmente resuelta a la que apunta finalmente un enlace simbólico.
ugo
Las tres clases de permisos: user (usuario propietario), group (grupo) y others (otros); a significa las tres.
Octal mode (modo octal)
Permisos numéricos en los que r=4, w=2 y x=1 se suman por clase, por ejemplo 755 o 640.
Symbolic mode (modo simbólico)
Notación de chmod como u+x, g-w u o=r que cambia permisos específicos.
Ejecución en un directorio
Permiso para entrar en el directorio y acceder a los elementos que contiene.
chown
Cambia el usuario propietario de un archivo y, opcionalmente, su grupo (user:group).
umask
Una máscara de bits de permiso que se quitan de los archivos y directorios nuevos al crearlos.
man page (página man)
Una página de manual que se ve con man, organizada en secciones estándar como SYNOPSIS, OPTIONS y EXAMPLES.
Man section (sección del manual)
Una categoría numerada de páginas man: 1 comandos de usuario, 5 formatos de archivo, 7 descripciones generales, 8 comandos de administración.
man -k
Busca una palabra clave en los nombres y descripciones de las páginas man; equivale a apropos.
mandb
Crea o actualiza la base de datos de índice en la que busca man -k.
info
Visor de documentos GNU info, manuales con formato de libro y nodos enlazados.
/usr/share/doc
Directorio que contiene la documentación adicional y los archivos de configuración de ejemplo de los paquetes instalados.

Dominio 2: Manage software (7%)

Consejos para el examen

  • baseurl debe apuntar al directorio que contiene repodata/. En RHEL, BaseOS y AppStream son repositorios separados, así que normalmente necesitas dos secciones, cada una con su propio ID único.
  • config-manager --add-repo no configura una clave GPG. Revisa el archivo generado y añade tú gpgcheck o gpgkey, ejecuta dnf clean all y después confirma con dnf repolist y una instalación de prueba.
  • Para paquetes locales, prefiere dnf install ./file.rpm en lugar de rpm -i file.rpm: dnf resuelve las dependencias desde los repositorios y registra el cambio en dnf history, así que puedes deshacerlo más tarde.
  • Cuando una tarea nombra un comando y no un paquete, recurre a dnf provides command (pon entre comillas los globs como '*/bin/name'). Usa dnf search cuando solo sabes qué hace el software, y dnf info para confirmar antes de instalar.
  • Asocia las letras con su inicial inglesa: a = all (todos), i = info, l = list (lista de archivos), c = config (configuración), d = docs (documentación), f = file (qué paquete es dueño de este archivo), p = package (consultar un archivo de paquete en lugar de la base de datos).
  • Pon entre comillas los nombres de grupo con espacios o usa sus IDs, lee primero dnf group info y recuerda que los paquetes opcionales no se instalan a menos que añadas --with-optional.
  • Comprueba si la tarea quiere un remote para todo el sistema (ejecutado como root, lo predeterminado) o uno por usuario (--user). El nombre del remote debe coincidir exactamente con la tarea, y flatpak remote-ls demuestra que el remote funciona.
  • Usa el ID de aplicación (nombre en DNS inverso) con los comandos de flatpak, y verifica las tareas de Flatpak con flatpak list y flatpak run; rpm y dnf no saben nada de las apps Flatpak.

Términos clave

Repository (repositorio)
Una colección de paquetes RPM más metadatos (repodata) desde la que dnf puede descargar.
Repository ID (ID de repositorio)
El nombre único entre corchetes que inicia una sección de un archivo .repo.
baseurl
La URL del directorio que contiene el repodata del repositorio; puede usar esquemas web, FTP o file.
enabled
Ajuste que hace que dnf use el repositorio (1) o lo ignore (0).
gpgcheck
Ajuste que hace que dnf verifique las firmas de los paquetes (1) u omita la verificación (0).
gpgkey
Ubicación de la clave pública usada para verificar las firmas de los paquetes cuando gpgcheck=1.
dnf config-manager
Comando de un plugin de dnf (del paquete dnf-plugins-core) para añadir repositorios y habilitarlos o deshabilitarlos de forma persistente.
--add-repo
Crea un archivo .repo en /etc/yum.repos.d a partir de la URL de un repositorio, o descarga un archivo .repo ya preparado.
dnf repolist
Lista los repositorios habilitados; añade all para incluir los deshabilitados y -v para ver detalles como el baseurl y el número de paquetes.
dnf clean all
Elimina los metadatos y paquetes de repositorios en caché para que dnf obtenga datos nuevos.
dnf makecache
Descarga y guarda en caché los metadatos de los repositorios de inmediato.
--enablerepo / --disablerepo
Opciones que habilitan o deshabilitan un repositorio solo para un comando dnf, sin cambiar los archivos.
gpgcheck / gpgkey
Ajustes del repositorio que activan o desactivan la comprobación de firmas e indican la clave usada para verificar los paquetes.
dnf install
Instala paquetes y sus dependencias desde los repositorios habilitados o desde archivos RPM locales.
dnf remove
Desinstala paquetes junto con los paquetes que dependen de ellos.
dnf update
Actualiza los paquetes instalados a las versiones más nuevas disponibles; también se llama dnf upgrade.
dnf reinstall
Reinstala la versión actual de un paquete, restaurando los archivos del paquete.
dnf history undo
Revierte los cambios hechos por una transacción de dnf registrada concreta.
dnf history rollback
Deshace todas las transacciones posteriores al ID indicado, volviendo a ese punto.
installonly_limit
Ajuste de dnf.conf que limita cuántas versiones se conservan de los paquetes de solo instalación, como los kernels.
dnf search
Busca palabras clave en los nombres y resúmenes de los paquetes (o, con --all, también en las descripciones y URL).
dnf provides
Encuentra qué paquete contiene un archivo, comando o glob de ruta dado; también se llama whatprovides.
dnf info
Muestra detalles de un paquete, como versión, repositorio, tamaño, licencia y descripción.
dnf list
Lista los paquetes instalados y disponibles que coinciden con un patrón de nombre.
@System
Etiqueta que dnf usa para indicar que un paquete está instalado localmente y no disponible desde un repositorio.
rpm -qf
Consulta la base de datos local de RPM para saber qué paquete instalado es dueño de un archivo.
RPM database (base de datos RPM)
La base de datos local que registra cada paquete instalado y sus archivos, consultada con rpm -q.
rpm -qa
Lista todos los paquetes instalados; acepta un glob entre comillas para acotar la lista.
rpm -ql / -qc / -qd
Lista todos los archivos, solo los archivos de configuración o solo los archivos de documentación instalados por un paquete.
rpm -qi
Muestra información detallada sobre un paquete instalado, incluidas la fecha de instalación y la firma.
rpm -qp
Consulta un archivo de paquete RPM en lugar de la base de datos de instalados.
rpm -V
Verifica los archivos instalados contra la base de datos e informa de cambios de tamaño, suma de comprobación, modo y más.
Package group (grupo de paquetes)
Un conjunto con nombre de paquetes relacionados, definido en los metadatos del repositorio, que se puede instalar en un solo paso.
Environment group (grupo de entorno)
Un conjunto mayor de grupos que representa un tipo completo de sistema, como Server with GUI.
Mandatory / default / optional (obligatorio / predeterminado / opcional)
Clases de paquetes dentro de un grupo; dnf instala los obligatorios y los predeterminados a menos que se indique --with-optional.
dnf group info
Muestra los paquetes que contiene un grupo, ordenados por clase.
@group syntax (sintaxis @grupo)
Forma abreviada para grupos en dnf install, como dnf install @groupid; @^ indica un grupo de entorno.
Hidden group (grupo oculto)
Un grupo que dnf group list no muestra por defecto, normalmente una pieza para construir entornos; se muestra con dnf group list hidden.
Flatpak
Un sistema para distribuir aplicaciones aisladas en un sandbox que incluyen sus propios runtimes, independiente de los paquetes RPM.
Remote (repositorio remoto)
Un repositorio Flatpak con nombre desde el que se instalan aplicaciones y runtimes.
Runtime (entorno de ejecución)
Un conjunto compartido de bibliotecas y servicios sobre el que se ejecutan las aplicaciones Flatpak.
.flatpakrepo file (archivo .flatpakrepo)
Un descriptor que contiene la URL, el título y la clave GPG de un remote, usado con flatpak remote-add.
System vs user installation (instalación de sistema vs. de usuario)
Los remotes y apps de sistema se comparten entre todos los usuarios (/var/lib/flatpak); los de --user viven en el directorio personal del usuario (~/.local/share/flatpak).
flatpak remote-ls
Lista las aplicaciones y runtimes que ofrece un remote; una prueba rápida de que el remote funciona.
Application ID (ID de aplicación)
Un identificador en estilo DNS inverso para una app Flatpak, como org.example.Editor.
Ref (referencia)
Una referencia Flatpak completa que combina tipo, ID, arquitectura y rama, p. ej. app/ID/x86_64/stable.
flatpak install
Instala una aplicación y el runtime que necesita desde un remote.
flatpak list
Muestra las aplicaciones y runtimes instalados; --app o --runtime filtran la lista.
flatpak run
Inicia una aplicación Flatpak instalada en su sandbox.
flatpak update
Actualiza las aplicaciones y runtimes instalados desde sus remotes, de forma independiente de dnf.
flatpak uninstall --unused
Elimina los runtimes y extensiones que ya no necesita ninguna aplicación instalada.

Dominio 3: Create simple shell scripts (7%)

Consejos para el examen

  • Ejecutar un script por su nombre necesita las tres cosas: un shebang correcto en la línea 1, permiso de ejecución y una ubicación en el PATH. Si no, debes usar ./script o bash script.
  • Usa -eq/-gt/-lt para números y = / != para cadenas, mantén los espacios dentro de los corchetes y pon entre comillas cada variable en una prueba.
  • $? se sobrescribe con cada comando, incluidos echo y [ ]; guárdalo enseguida en una variable (rc=$?) si lo necesitas más tarde, y termina los scripts con un código de salida explícito.
  • Recorre archivos con un glob (for f in /dir/*), no con $(ls), y lee archivos línea por línea con while read -r ... done < file en lugar de for line in $(cat file), que divide en cada espacio.
  • Usa "$@" (con comillas) para recorrer o pasar todos los argumentos; $@ o $* sin comillas dividen los argumentos que contienen espacios. Comprueba $# primero, imprime el uso en stderr y sal con un código distinto de cero cuando falte la entrada.
  • $( ) captura solo stdout y elimina los saltos de línea finales. Construye primero la tubería en el prompt y luego envuélvela. Ponle comillas ("$(cmd)") a menos que quieras a propósito que la salida se divida en palabras separadas.
  • Sin espacios alrededor de = en las asignaciones, comillas dobles alrededor de cada $variable y comillas simples cuando quieras que el texto se tome literalmente. '$HOME' imprime $HOME; "$HOME" imprime /root cuando se ejecuta como root.
  • case usa patrones glob del shell, no expresiones regulares, se detiene en la primera coincidencia y necesita ;; después de cada cláusula y esac al final. Pon comillas a la palabra evaluada y deja la cláusula *) que lo atrapa todo al final.

Términos clave

Shebang
La primera línea #! que nombra el intérprete, p. ej. #!/bin/bash, usada cuando se ejecuta el archivo.
Execute permission (permiso de ejecución)
El permiso x que permite ejecutar un archivo como programa; se establece con chmod +x o chmod 755.
PATH
Variable de entorno que lista los directorios en los que el shell busca comandos, en orden.
/usr/local/bin
Directorio convencional de todo el sistema, incluido en el PATH, para scripts y programas creados localmente.
source
Ejecuta un script en el shell actual en lugar de en un proceso hijo; también se escribe con un punto.
bash -x
Ejecuta un script imprimiendo cada comando a medida que se ejecuta, para depurar.
test / [ ]
Comando que evalúa una condición y devuelve el código de salida 0 (verdadero) o 1 (falso); los espacios alrededor de los corchetes son obligatorios.
-f / -d / -e
Pruebas de archivo regular, de directorio o de cualquier ruta existente.
-r / -w / -x / -s
Prueban si el usuario actual puede leer, escribir o ejecutar un archivo, o si el archivo existe y no está vacío.
-z / -n
Prueban si una cadena está vacía o no.
-eq / -gt / -lt
Operadores de comparación numérica: igual, mayor que, menor que (también -ne, -ge, -le).
= / !=
Pruebas de igualdad y desigualdad de cadenas dentro de [ ].
elif
Condición adicional que solo se revisa si el if o elif anterior fue falso.
Exit status (código de salida)
Un número de 0 a 255 que devuelve todo comando; 0 significa éxito y un valor distinto de cero, fallo.
$?
Variable especial que contiene el código de salida del último comando que terminó.
&&
Ejecuta el siguiente comando solo si el anterior tuvo éxito (código de salida 0).
||
Ejecuta el siguiente comando solo si el anterior falló (código de salida distinto de cero).
exit
Comando interno que termina un script inmediatamente con un código de salida dado.
$#
Variable especial que contiene el número de argumentos pasados a un script.
>&2
Redirige la salida de un comando a la salida de error estándar; se usa para los mensajes de error.
for loop (bucle for)
Repite un bloque una vez por cada palabra de una lista, asignando la palabra a una variable.
while loop (bucle while)
Repite un bloque mientras su comando de condición devuelva el código de salida 0.
read
Comando interno que lee una línea de entrada en variables; devuelve un valor distinto de cero al final de la entrada.
seq
Comando que imprime una secuencia de números, p. ej. seq 1 10 o seq 0 5 20.
IFS
Internal Field Separator (separador interno de campos): los caracteres que read y la división de palabras usan para dividir el texto.
continue / break
Saltan a la siguiente iteración del bucle o salen del bucle por completo.
Glob
Un patrón de nombres de archivo, como /etc/*.conf, que el shell expande en los nombres que coinciden.
Positional parameters (parámetros posicionales)
Los argumentos pasados a un script, disponibles como $1, $2, etc.; ${10} y los siguientes necesitan llaves.
$0
El nombre del script tal como se invocó, incluida cualquier ruta escrita.
"$@"
Todos los argumentos como palabras separadas y correctamente entrecomilladas; la forma correcta para bucles y para pasar los argumentos a otro comando.
"$*"
Todos los argumentos unidos en una sola palabra separada por espacios; útil para imprimirlos.
shift
Descarta $1 y renumera hacia abajo los argumentos restantes, reduciendo $# en uno.
${1:-default}
Expansión de parámetros que usa $1 si está definido y no vacío, o el valor predeterminado en caso contrario.
Command substitution (sustitución de comandos)
$(command): ejecuta el comando y se reemplaza a sí misma con la salida estándar del comando, sin los saltos de línea finales.
Backticks (comillas invertidas)
La forma antigua command de la sustitución de comandos; equivalente pero más difícil de leer y de anidar.
Subshell
Una copia hija del shell en la que se ejecuta el comando sustituido; las variables que define no vuelven al padre.
cut
Extrae campos o rangos de caracteres de cada línea, por ejemplo cut -d: -f1 /etc/passwd.
awk '{print $N}'
Imprime el campo N, separado por espacios en blanco, de cada línea.
tr
Traduce o elimina caracteres; por ejemplo, tr -d ' %' elimina los espacios y los signos de porcentaje.
Variable assignment (asignación de variables)
name=value sin espacios alrededor de =; después se referencia como $name o ${name}.
export
Marca una variable para incluirla en el entorno de los procesos hijos.
read -p
Lee una línea de entrada en variables después de mostrar un mensaje; -s oculta la entrada y -t fija un tiempo límite.
Double quotes (comillas dobles)
Permiten la expansión de $ y la sustitución de comandos, pero impiden la división en palabras y los comodines.
Single quotes (comillas simples)
Impiden toda expansión; el texto se toma de forma literal.
$(( ))
Expansión aritmética que evalúa expresiones enteras, como $((n + 1)).
case ... esac
Sentencia que compara un valor con patrones y ejecuta la primera cláusula que coincide.
;;
Termina una cláusula de case; la ejecución continúa después de esac, sin pasar a la cláusula siguiente.
Pattern alternatives (patrones alternativos)
Varios patrones en una cláusula separados por |, como start|up).
*) default clause (cláusula predeterminada)

Dominio 4: Operate running systems (12%)

Consejos para el examen

  • systemctl set-default cambia lo que ocurre en el PRÓXIMO arranque; systemctl isolate cambia el target AHORA. El examen evalúa el sistema después de un reinicio, así que reinicia tú mismo, revisa y deja tiempo para corregir.
  • El modo de rescate monta todos los sistemas de archivos; el de emergencia monta solo la raíz, en solo lectura. Si fstab está dañado, el de rescate falla, así que usa el de emergencia y recuerda volver a montar / en lectura y escritura antes de editar.
  • Recuerda el orden: remount,rw /sysroot, chroot /sysroot, passwd, touch /.autorelabel, exit, exit. Si omites el autorelabel, /etc/shadow queda mal etiquetado y los inicios de sesión fallan con SELinux.
  • Prueba SIGTERM (15, la predeterminada) antes que SIGKILL (9). SIGKILL no se puede capturar, así que el proceso no tiene oportunidad de limpiar. Usa el signo menos en --sort=-%cpu para ver primero los más altos, y revisa antes lo que hará pkill con pgrep -l.
  • Número nice más alto = prioridad más baja. Cualquiera puede subir un valor (ser más amable); solo root puede bajarlo o fijar un valor negativo. Verifícalo con ps -o pid,ni,comm -p PID.
  • El perfil lo aplica el servicio tuned, así que asegúrate de que esté habilitado y en ejecución (systemctl enable --now tuned). No adivines el perfil recomendado: pregúntaselo a tuned-adm recommend, aplícalo y luego comprueba tuned-adm active.
  • journalctl -p err muestra err Y todo lo más grave (crit, alert, emerg). Los problemas de autenticación van a /var/log/secure, no a /var/log/messages. Combina los filtros: -u, -p, -b y --since funcionan juntos.
  • Storage=auto solo conserva el journal si existe /var/log/journal; Storage=persistent lo crea. En ambos casos, reinicia systemd-journald y confírmalo con journalctl --list-boots después de reiniciar el sistema.
  • Una tarea que dice que el servicio debe estar en ejecución y ser persistente necesita tanto start como enable: systemctl enable --now. Luego compruébalo con systemctl is-enabled, is-active y ss -tlnp.
  • En rsync, una barra final en el origen significa 'el contenido de este directorio'; sin ella, se copia el directorio en sí dentro del destino. scp usa -P para el puerto, mientras que ssh usa -p.

Dominio 5: Configure local storage (12%)

Consejos para el examen

  • Ejecuta lsblk antes de tocar cualquier disco para asegurarte de tener el nombre de dispositivo correcto, y usa blkid (o lsblk -f) para obtener el UUID para /etc/fstab. Las particiones NVMe incluyen una p: nvme0n1p1.
  • fdisk y gdisk no cambian nada hasta que pulsas w; parted aplica cada comando de inmediato. Crear una nueva etiqueta (g, o, mklabel) en un disco con datos borra sus particiones.
  • Construye LVM de abajo hacia arriba (partición, pvcreate, vgcreate, lvcreate, mkfs, montaje) y desmantélalo de arriba hacia abajo. pvremove falla mientras un PV todavía pertenezca a un grupo de volúmenes.
  • Busca en la tarea un tamaño de extensión: vgcreate -s debe fijarse al crear el VG. Después, un LV de -l 50 en un VG con extensiones de 16 MiB tiene 800 MiB, no 200 MiB.
  • La -L mayúscula es un tamaño con unidades; la -l minúscula es un número de extensiones (o un porcentaje). Multiplica las extensiones por el PE Size del VG para conocer el tamaño real.
  • Ejecuta siempre mount -a (e idealmente findmnt --verify) después de editar /etc/fstab. Un error de escritura que detectas ahora se corrige en dos segundos; el mismo error al arrancar te deja en modo de emergencia.
  • Nunca vuelvas a crear una tabla de particiones ni ejecutes pvcreate/mkfs sobre algo que contiene datos. Agrega líneas a fstab con >> (o edítalo) y prueba con mount -a y swapon -a antes de reiniciar.
  • La persistencia es lo que comprueban los evaluadores. Un área de swap activada solo con swapon desaparece al reiniciar, así que la tarea no se aprueba a menos que exista la línea en /etc/fstab y swapon -a la active sin errores.

Dominio 6: Create and configure file systems (10%)

Consejos para el examen

  • Usa exactamente el tipo solicitado. Un evaluador que busca ext4 dará por fallido un volumen XFS aunque se monte y funcione, así que confirma con lsblk -f o blkid antes de seguir.
  • Nunca reinicies después de editar /etc/fstab sin ejecutar mount -a y findmnt --verify. Un error de escritura puede dejar el sistema del examen en modo de emergencia y costarte tiempo en todas las demás tareas.
  • Las preguntas del examen suelen pedir qué significan el quinto y el sexto campo. Dump es heredado y se pone en 0; el orden de fsck es 1 para la raíz, 2 para los demás y 0 para XFS, swap y montajes de red.
  • Incluye _netdev en los montajes de red de /etc/fstab. Documenta que el montaje necesita la red, mantiene correcto el orden de arranque y de apagado, y es la opción que buscan las respuestas del examen.
  • No crees los subdirectorios bajo una base de autofs ni añadas líneas de fstab para ellos. Que ls del directorio base salga vacío es lo esperado; prueba accediendo a la ruta completa.
  • El fallo más común es ampliar el LV pero no el sistema de archivos. Usa lvextend -r siempre, y revisa df -h, no solo lvs, antes de seguir.
  • Al reducir, el orden lo es todo: primero el sistema de archivos y luego el volumen lógico. Al ampliar es al revés: primero el volumen y luego el sistema de archivos. La opción -r se encarga de ambos órdenes por ti.
  • Linux aplica solo la primera clase que coincide: propietario, luego grupo, luego other. Y el acceso necesita x en cada directorio padre, algo que namei -l revela con un solo comando.

Dominio 7: Deploy, configure and maintain systems (10%)

Consejos para el examen

  • Ten claro qué formato de cron necesita campo de usuario: los crontabs personales nunca, los archivos /etc/crontab y /etc/cron.d siempre. Y recuerda habilitar la unidad .timer, no la .service, en los timers de systemd.
  • Enabled y active son independientes. Las respuestas del examen que solo inician un servicio, o que solo lo habilitan, están ambas incompletas; enable --now cubre las dos cosas.
  • set-default cambia solo el siguiente arranque; isolate cambia solo el estado actual. Una tarea que dice que el sistema debe arrancar en una consola de texto necesita set-default.
  • En la salida de chronyc sources, el asterisco después del acento circunflejo marca la fuente con la que realmente estás sincronizado. Si no hay asterisco, la configuración todavía no funciona, así que revisa el reinicio, la resolución de nombres y la alcanzabilidad antes de seguir.
  • Un archivo .repo debe terminar en .repo, y cada sección necesita un ID único entre corchetes y un baseurl. Un error tipográfico ahí hace fallar todas las tareas de instalación posteriores, así que confirma con dnf repolist de inmediato.
  • Si dnf repolist está vacío en una instalación nueva de RHEL, probablemente el sistema no está registrado. Es el registro, y no un archivo .repo que te falte escribir, lo que proporciona los repositorios de la CDN.
  • Los ajustes del menú, como el timeout, necesitan /etc/default/grub más grub2-mkconfig -o /boot/grub2/grub.cfg. Los argumentos por kernel son más fáciles con grubby, que actualiza las entradas existentes de inmediato.

Dominio 8: Manage basic networking (8%)

Consejos para el examen

  • nmcli con mod guarda el perfil pero no lo aplica. Síguelo siempre con nmcli con up (y ten en cuenta que puede cortar una sesión SSH si cambia la dirección), y luego verifica con ip addr e ip route.
  • Los keyfiles editados a mano necesitan modo 600, propietario root y una recarga. Si una pregunta menciona archivos ifcfg en RHEL 10, la respuesta es que los keyfiles de /etc/NetworkManager/system-connections los reemplazaron.
  • Si después de reiniciar vuelven los ajustes equivocados, busca otro perfil con autoconnect en el mismo dispositivo. Elimínalo, pon su autoconnect en no o sube la prioridad del que quieres, y luego reinicia una vez para demostrarlo.
  • No arregles el DNS en RHEL editando /etc/resolv.conf directamente; NetworkManager lo reescribe. Establece ipv4.dns en la conexión y vuelve a activarla, y luego prueba con getent hosts.
  • getent hosts muestra lo que resolverán las aplicaciones; dig y host se saltan /etc/hosts. Elige la herramienta que corresponde a la pregunta y comprueba siempre dirección, ruta, alcance y resolución, en ese orden.
  • Para los servicios de red, comprueba tres cosas antes de dar una tarea por terminada: el servicio está habilitado, la conexión tiene autoconnect y la regla del firewall es permanente. Luego reinicia y prueba desde otro host.
  • Un cambio con --permanent sin --reload todavía no hace nada; un cambio sin --permanent desaparece tras la siguiente recarga o reinicio. El evaluador del examen reinicia, así que el patrón seguro es permanent más reload, seguido de firewall-cmd --list-all para verificar.
  • nmtui guarda el perfil pero puede no aplicarlo; desactiva y reactiva la conexión después, exactamente como ejecutarías nmcli con up después de nmcli con mod. Luego confirma que Automatically connect está marcado.

Dominio 9: Manage users and groups (8%)

Consejos para el examen

  • usermod -G sin -a reemplaza todos los grupos suplementarios. Cuando una tarea diga añadir un usuario a un grupo, usa usermod -aG grupo usuario, y verifica cada propiedad pedida con id y getent passwd.
  • Sin shell interactivo en el examen significa -s /sbin/nologin. Bloquea los inicios de sesión con shell, pero no la autenticación en sí, así que combínalo con el bloqueo cuando una cuenta deba quedar completamente deshabilitada.
  • chage -d 0 obliga a cambiar la contraseña en el próximo inicio de sesión; chage -E 0 o una fecha pasada hace caducar toda la cuenta. Confundirlos deja al usuario fuera o no hace nada útil, así que lee chage -l después de cada cambio.
  • login.defs y /etc/default/useradd solo cambian las cuentas creadas después. Si los usuarios existentes deben cumplir la política, ejecuta chage también sobre ellos, y comprueba tanto una cuenta nueva como una antigua con chage -l.
  • Tanto usermod -aG como gpasswd -a añaden un grupo sin quitar los demás. La trampa es usermod -G sin -a, que borra los grupos suplementarios existentes del usuario. Cuando una tarea fija el GID, usa siempre groupadd -g.
  • El grupo primario de un usuario lo define el campo GID de /etc/passwd, no aparece listado en /etc/group. Usa id para ver todas las membresías a la vez, y getent en lugar de grep para que se incluyan las cuentas de red.
  • Usa siempre visudo; un error de sintaxis en un archivo sudoers puede quitarle a todos el acceso a sudo. Además, un archivo drop-in cuyo nombre contiene un punto se ignora en silencio. Cuando una tarea solo dice derechos de administración completos, añadir el usuario a wheel es la respuesta correcta más rápida.
  • usermod -L y passwd -l solo bloquean los inicios de sesión con contraseña; chage -E 0 bloquea todos los métodos de inicio de sesión, incluidas las claves SSH. Elige según lo que la tarea diga que se debe impedir, y recuerda chage -E -1 para deshacer la caducidad.

Dominio 10: Manage security (14%)

Consejos para el examen

  • Las vinculaciones de origen tienen prioridad sobre las zonas de interfaz. Compara firewall-cmd --list-all con firewall-cmd --permanent --list-all para asegurarte de que tus reglas en tiempo de ejecución y las guardadas coinciden antes de terminar.
  • Resta la umask a 666 para los archivos y a 777 para los directorios. Con umask 027, los archivos quedan en 640 y los directorios en 750. Verifica un cambio persistente en un nuevo shell de inicio de sesión, no en el que usaste para editar.
  • La mayoría de los fallos con claves son de permisos: ~/.ssh debe ser 700, authorized_keys 600, y ni el grupo ni el resto del mundo deben poder escribir en el directorio personal. Revisa journalctl -u sshd en el servidor para ver la razón.
  • setenforce cambia solo el modo en ejecución; /etc/selinux/config establece el modo al arrancar. Un cambio persistente necesita el archivo, y los evaluadores revisan después de un reinicio.
  • mv conserva el contexto anterior de un archivo, mientras que cp crea un archivo nuevo con el contexto del directorio. Un archivo movido con el tipo equivocado es una trampa clásica del examen.
  • semanage fcontext solo registra la regla; no cambia ningún archivo. Síguelo siempre de restorecon -Rv sobre la ruta, y prefiere esta pareja a chcon para que el cambio persista.
  • Un servicio movido a un puerto no estándar necesita tres cosas: su propia configuración, una etiqueta de puerto de SELinux y una regla de firewall. Si el puerto ya tiene otro tipo, usa -m en lugar de -a.
  • setsebool sin -P se pierde al reiniciar. Cuando una tarea pide un cambio persistente, compruébalo después con semanage boolean -l -C, que lista solo los booleanos cambiados localmente.
  • Lee el tcontext de la denegación: un tipo de archivo equivocado significa restorecon o semanage fcontext, name_bind significa semanage port y un comportamiento opcional significa un booleano. Nunca dejes SELinux en permissive como solución.

Un archivo del sistema con valores predeterminados de las cuentas; su ajuste UMASK se usa para los directorios personales nuevos y al iniciar sesión mediante PAM.
/etc/profile.d/
Un directorio de scripts del shell que se ejecutan al iniciar sesión para todos los usuarios; un lugar limpio para ajustes de todo el sitio como la umask.
Key pair (par de claves)
Una clave privada guardada en el cliente y una clave pública correspondiente colocada en los servidores para la autenticación.
ssh-keygen
Genera un nuevo par de claves SSH; -t elige el tipo de clave, como ed25519 o rsa.
authorized_keys
El archivo ~/.ssh/authorized_keys de un servidor que lista las claves públicas autorizadas para iniciar sesión como ese usuario.
ssh-copy-id
Copia una clave pública al archivo authorized_keys de un usuario remoto con los permisos correctos.
PasswordAuthentication
Un ajuste de sshd; con no rechaza las contraseñas escritas, de modo que solo funcionan las claves u otros métodos.
PermitRootLogin
Un ajuste de sshd que controla los inicios de sesión de root: yes, no o prohibit-password (solo con clave).
SELinux
Security-Enhanced Linux, un control de acceso obligatorio del kernel basado en etiquetas y una política.
Enforcing mode (modo enforcing)
SELinux aplica la política, denegando y registrando el acceso prohibido.
Permissive mode (modo permissive)
SELinux registra las violaciones de la política pero las permite; se usa para resolver problemas.
setenforce
Cambia entre enforcing (1) y permissive (0) en tiempo de ejecución hasta el siguiente arranque; no puede habilitar ni deshabilitar SELinux.
/etc/selinux/config
El archivo que establece el modo de SELinux y el tipo de política que se usan al arrancar.
/.autorelabel
Un archivo vacío que indica al sistema que reetiquete todos los archivos en el siguiente arranque.
Security context (contexto de seguridad)
Una etiqueta de SELinux de la forma user:role:type:level asociada a archivos, procesos, puertos y sesiones.
Type (tipo)
El campo del contexto que termina en _t y que usa la política targeted para decidir el acceso.
Type enforcement (aplicación de tipos)
Reglas de la política de SELinux que permiten a un tipo de proceso un acceso concreto a tipos de objeto.
unconfined_t
El tipo de las sesiones de inicio de sesión de los usuarios normales, que la política targeted no restringe.
httpd_sys_content_t
El tipo de archivo que el proceso del servidor web Apache (httpd_t) puede leer como contenido web.
matchpathcon
Imprime la etiqueta que la política espera para una ruta dada, para compararla con ls -Z.
restorecon
Restablece las etiquetas de SELinux de los archivos a los valores definidos en la política; -R actúa recursivamente, -v informa de los cambios y -n muestra una vista previa.
semanage fcontext
Añade (-a), modifica (-m), borra (-d) o lista (-l) las reglas de la política que asocian patrones de ruta con tipos de archivo.
chcon
Cambia directamente la etiqueta de un archivo; el cambio se pierde con restorecon o un reetiquetado.
(/.*)?
El sufijo de expresión regular que, en las reglas de fcontext, coincide con un directorio y todo lo que hay debajo.
default_t
El tipo que reciben las rutas sin una regla específica, como los directorios nuevos de nivel superior; la mayoría de los servicios confinados no pueden leerlo.
policycoreutils-python-utils
El paquete que proporciona el comando semanage.
Port type (tipo de puerto)
Una etiqueta de SELinux en un puerto de red, como http_port_t o ssh_port_t, que controla qué tipos de proceso pueden usarlo.
name_bind
El permiso que necesita un proceso para escuchar en un puerto; sus denegaciones indican que falta una etiqueta de puerto.
semanage port -a
Añade un número de puerto y un protocolo a un tipo de puerto de SELinux.
semanage port -m
Modifica un puerto que ya está definido con otro tipo.
semanage port -l -C
Lista solo las asociaciones de puertos añadidas o cambiadas localmente.
http_cache_port_t
El tipo de puerto que incluye el 8080 por defecto, y por eso añadir el 8080 a http_port_t necesita -m.
SELinux boolean (booleano de SELinux)
Un interruptor de la política que activa o desactiva un conjunto opcional de permisos sin escribir una política nueva.
getsebool -a
Lista todos los booleanos y sus valores actuales.
setsebool -P
Establece un booleano y hace que el cambio persista tras los reinicios.
semanage boolean -l
Lista los booleanos con su valor actual, su valor predeterminado y su descripción.
semanage boolean -l -C
Lista solo los booleanos cuyo valor persistente se ha cambiado localmente.
httpd_enable_homedirs
Un booleano que permite al servidor web Apache leer contenido de los directorios personales de los usuarios.
AVC denial (denegación AVC)
Un registro del log de auditoría de un acceso bloqueado por SELinux, que nombra el permiso, el contexto de origen, el contexto de destino y la clase.
auditd
El demonio de auditoría que escribe las denegaciones de SELinux y otros eventos en /var/log/audit/audit.log.
ausearch
Busca en el log de auditoría por tipo de mensaje, hora y comando; -m AVC selecciona las denegaciones de SELinux y -i hace legible la salida.
sealert
Una herramienta de setroubleshoot que explica las denegaciones en lenguaje sencillo y sugiere soluciones.
scontext y tcontext
El contexto de origen del proceso que intenta el acceso y el contexto de destino del archivo, puerto u otro objeto.
dontaudit rule (regla dontaudit)
Una regla de la política que deniega un acceso sin registrarlo, así que no aparece ningún AVC.
