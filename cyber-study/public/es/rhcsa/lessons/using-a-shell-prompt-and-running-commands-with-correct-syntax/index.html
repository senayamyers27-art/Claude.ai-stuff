Red Hat Certified System Administrator EX200 (RHEL 10)

Usar el prompt del shell y ejecutar comandos con la sintaxis correcta

Casi todo en el examen RHCSA (Red Hat Certified System Administrator, administrador de sistemas certificado por Red Hat) ocurre en un prompt del shell. El shell de Red Hat Enterprise Linux (RHEL) es Bash, el Bourne Again SHell. Lee la línea que escribes, la divide en palabras, expande los caracteres especiales y luego ejecuta un programa. Saber exactamente cómo lo hace es lo que distingue un comando que funciona de uno que hace lo incorrecto en silencio en un sistema de examen real, donde no hay forma de deshacer y el evaluador solo revisa el resultado final.

Empieza por leer el prompt, porque te dice quién eres y dónde estás. Un prompt típico de RHEL se ve así: [student@servera ~]$: el nombre de usuario, el nombre corto del host, el directorio actual (~ significa tu directorio personal) y un carácter final que es $ para un usuario normal y # para root. El examen te da más de una máquina y más de una cuenta, así que antes de cambiar algo, mira el prompt. Una tarea hecha a la perfección en el host equivocado no suma puntos, y un comando ejecutado como root por accidente puede causar mucho más daño que el mismo comando ejecutado como usuario normal.

Después, aprende la estructura de una línea de comandos: el nombre del comando, luego las opciones y luego los argumentos. Las opciones cambian el comportamiento del comando y normalmente empiezan con un guion. Las opciones cortas son de una sola letra y se pueden agrupar, así que ls -l -a -h es lo mismo que ls -lah. Las opciones largas empiezan con dos guiones y se escriben completas, como ls --all; son más fáciles de leer en scripts. Los argumentos son aquello sobre lo que actúa el comando, normalmente nombres de archivo o directorios. Los espacios separan las palabras, por eso un nombre de archivo que contiene un espacio debe ir entre comillas ('my file') o con el espacio escapado con una barra invertida (my\ file). Si no, el shell le pasa al comando dos argumentos separados, y puede actuar sobre dos archivos que no existen o, peor aún, sobre dos que sí existen.

ls -lah /etc/ssh          # comando, opciones agrupadas, un argumento
cp --verbose a.txt b.txt   # opción larga, dos argumentos
command1 ; command2        # ejecutar uno después del otro
sleep 300 &                # ejecutar en segundo plano

El shell también controla cómo se ejecutan los comandos en conjunto. Un punto y coma ejecuta los comandos uno tras otro, sin importar si tienen éxito. Un ampersand al final de la línea, como en sleep 300 &, inicia el comando en segundo plano y te devuelve el prompt de inmediato, mostrando un número de trabajo y un identificador de proceso (PID). Estos pequeños símbolos forman parte de la sintaxis, así que un & o un ; suelto dentro de un argumento sin comillas cambia el significado de toda la línea.

La idea más importante de esta lección es la expansión: el shell reescribe tu línea antes de que el programa la vea. Los globs como *.conf se convierten en la lista de nombres de archivo que coinciden, ~ se convierte en tu directorio personal, $HOME en el valor de una variable y $(date) en la salida de un comando. Como lo hace el shell, rm *.log y rm a.log b.log son idénticos desde el punto de vista de rm; el programa nunca sabe que se escribió un comodín. Por eso también un glob que no coincide con nada puede comportarse de forma extraña, ya que Bash pasa el texto literal *.log al comando cuando ningún archivo coincide. Usa echo delante de un comando arriesgado (echo rm *.log) para ver exactamente qué producirá la expansión, luego quita echo y ejecútalo de verdad.

Bash también ahorra esfuerzo y evita errores de tipeo. La tecla Tab completa nombres de comandos y de archivos, y al presionarla dos veces muestra todas las opciones, que es la forma más rápida de escribir correctamente rutas largas como /etc/systemd/system/. La flecha hacia arriba y history recuperan comandos anteriores, Ctrl+R los busca mientras escribes y Ctrl+C interrumpe un comando en ejecución. Cuando no estés seguro de qué es realmente una palabra, type te dice si es un comando integrado (built-in), un alias o un programa en disco, y which muestra la ruta de un programa encontrado mediante tu variable PATH, la lista de directorios donde Bash busca comandos.

Por último, recuerda que Linux distingue entre mayúsculas y minúsculas. File.txt y file.txt son archivos distintos, y -R y -r pueden ser opciones diferentes según el comando (en ls, -R es recursivo mientras que -r invierte el orden). Cuando un comando falle, lee el mensaje de error con atención en lugar de volver a escribir a ciegas. Mensajes como No such file or directory, command not found o invalid option -- 'q' nombran la palabra exacta que el shell o el programa no pudo entender, y casi siempre ahí está la solución.

Términos clave

Shell
El programa (Bash en RHEL) que lee tus líneas de comandos, las expande e inicia los programas solicitados.
Opción
Una palabra que empieza con - o -- y cambia el comportamiento de un comando, como -l o --all.
Argumento
Una palabra después de las opciones sobre la que actúa el comando, normalmente un nombre de archivo o directorio.
Glob (comodín)
Un patrón con comodines como *.conf o file?.txt que el shell expande en los nombres de archivo que coinciden.
Tab completion (autocompletado con Tab)
Presionar Tab para que Bash termine un nombre de comando o de ruta, lo que reduce los errores de tipeo.
Expansión
La reescritura que hace el shell de una línea de comandos (globs, ~, variables, sustitución de comandos) antes de que el programa se ejecute.
Ejemplo real

Una tarea del examen te pide listar todos los archivos de /etc/ssh, incluidos los ocultos, con tamaños legibles para humanos. Revisas el prompt para confirmar que estás en servera, escribes ls -lah /etc/ssh y usas Tab para completar la ruta, de modo que un error de tipeo no te lleve al directorio equivocado.

Consejo para el examen: Es el shell, no el comando, quien expande los globs, las variables y ~. Si un resultado te sorprende, pon echo delante del comando para ver exactamente qué argumentos recibirá el programa.

Comprueba lo que sabes

¿Qué indica normalmente el # al final de un prompt?

Que tienes la sesión iniciada como root; el prompt de un usuario normal termina en $.

¿Son diferentes ls -la y ls -l -a?

No. Las opciones cortas se pueden agrupar detrás de un solo guion, así que ambos dan un listado largo que incluye los archivos ocultos.

¿Cómo le pasas a un comando un archivo llamado my report.txt?

Ponlo entre comillas ('my report.txt') o escapa el espacio (my\ report.txt) para que el shell lo trate como un solo argumento.

¿Qué comando te dice si ls es un alias, un comando integrado o un programa en disco?

type ls, que informa cómo interpretará Bash esa palabra.
