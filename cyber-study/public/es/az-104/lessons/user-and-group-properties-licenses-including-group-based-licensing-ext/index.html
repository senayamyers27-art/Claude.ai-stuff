Propiedades de usuarios y grupos, licencias (incluida la asignación de licencias basada en grupos), usuarios externos (invitados B2B) y restablecimiento de contraseña de autoservicio

Un objeto de usuario en Microsoft Entra ID contiene mucho más que un nombre y una contraseña. Propiedades como el puesto, el departamento, el jefe, la ubicación de la oficina, el ID de empleado y la ubicación de uso las usan las reglas de grupos dinámicos, la lista global de direcciones y las licencias. Las editas en la página Propiedades del usuario en el portal, de forma masiva con Microsoft Graph PowerShell (Update-MgUser -UserId ana@contoso.com -Department "Finance") o, en el caso de los usuarios sincronizados, en Active Directory Domain Services (AD DS) local, porque el directorio local es la fuente de autoridad. Vale la pena mantener estos atributos exactos, porque un valor de departamento incorrecto puede sacar silenciosamente a alguien de un grupo dinámico y quitarle el acceso y las licencias que ese grupo concede.

Los grupos también tienen propiedades: nombre, descripción, propietarios, tipo de pertenencia y si al grupo se le pueden asignar roles de Microsoft Entra. Los propietarios pueden administrar la pertenencia sin ser administradores, lo que permite que un líder de equipo mantenga su propio grupo de proyecto. La opción de grupo asignable a roles es la que debes vigilar: solo puedes elegirla al crear el grupo y no se puede activar después. Si más adelante necesitas que un grupo tenga un rol de Entra, creas un grupo nuevo con esa opción habilitada.

Luego vienen las licencias. Productos como Microsoft 365 o Microsoft Entra ID P1 y P2 se licencian por usuario. Antes de poder asignar una licencia, el usuario debe tener configurada una ubicación de uso, una propiedad de país de dos letras, porque algunos servicios no están disponibles en todos los países; sin ella la asignación falla, sin importar cuántas licencias libres tenga el inquilino. Puedes asignar una licencia directamente en la página Licencias del usuario, pero a gran escala la asignación directa se vuelve difícil de controlar y fácil de olvidar cuando las personas se van, así que se siguen pagando licencias de personas que ya no están.

La asignación de licencias basada en grupos resuelve eso. Asignas la licencia a un grupo y cada miembro la recibe, con la opción de desactivar planes de servicio individuales dentro del producto, por ejemplo deshabilitar una aplicación para un departamento. Cuando un usuario se une al grupo obtiene la licencia; cuando sale, se le quita. Combínalo con un grupo dinámico y las licencias siguen automáticamente los datos de Recursos Humanos (RR. HH.). La asignación de licencias basada en grupos necesita Entra ID P1 o un producto que lo incluya. Si la asignación falla, por ejemplo porque no hay suficientes licencias, falta una ubicación de uso o dos planes de servicio entran en conflicto, la página Licencias del grupo muestra a esos usuarios en estado de error para que puedas corregirlos y volver a procesar. Un usuario puede tener la misma licencia de forma directa y a través de un grupo; al quitar la asignación directa queda la heredada, lo que es una forma segura de migrar de licencias directas a licencias basadas en grupos.

El siguiente tema es la colaboración externa, que usa Microsoft Entra B2B (de empresa a empresa). Invitas a un socio por su dirección de correo electrónico (Usuarios > Nuevo usuario > Invitar usuario externo, o New-MgInvitation) y se crea en tu inquilino un objeto de usuario invitado con el tipo de usuario Guest. El socio inicia sesión con su propia identidad de su organización de origen, una cuenta Microsoft o un código de acceso de un solo uso enviado por correo electrónico, así que nunca almacenas ni restableces su contraseña. Después de que canjea la invitación, puedes poner a los invitados en grupos y darles roles del control de acceso basado en roles (RBAC) como a cualquier otro usuario. La configuración de colaboración externa controla quién puede invitar a invitados (por ejemplo, solo los administradores y los usuarios con el rol Guest Inviter), cuánto de tu directorio pueden ver los invitados y qué dominios asociados se permiten o se bloquean. La configuración de acceso entre inquilinos agrega un control más fino sobre la colaboración entrante y saliente con organizaciones específicas.

El restablecimiento de contraseña de autoservicio (SSPR) ataca el problema de la mesa de ayuda. En Microsoft Entra ID > Restablecimiento de contraseña lo habilitas para Ninguno, Seleccionado (un grupo) o Todos los usuarios, eliges qué métodos de autenticación se permiten (como la aplicación Microsoft Authenticator, el teléfono móvil, el correo electrónico o las preguntas de seguridad) y estableces cuántos métodos se requieren para restablecer: uno o dos. Los usuarios deben registrar métodos antes de poder usar SSPR, y puedes exigir el registro al iniciar sesión con una reconfirmación periódica, para que se les pida configurar métodos antes del día en que olviden su contraseña. Las cuentas de administrador siempre usan una directiva integrada más estricta que requiere dos métodos y nunca permite preguntas de seguridad, independientemente de tu configuración.

Los entornos híbridos agregan un requisito más. Para los usuarios sincronizados desde el entorno local, se necesita la escritura diferida de contraseñas (password writeback) mediante Microsoft Entra Connect o Cloud Sync, para que la nueva contraseña se escriba de vuelta en AD DS. Sin ella, el restablecimiento falla o deja sin cambios la contraseña local, y el usuario termina con una contraseña en la nube que no abre su estación de trabajo ni sus recursos compartidos de archivos.

Veamos un ejemplo práctico. Una firma de ingeniería crea un grupo de usuario dinámico para user.department -eq "Engineering" y le asigna la licencia de Microsoft 365, desactivando un plan de servicio que el equipo no usa. Se crea una ingeniera nueva con el departamento Engineering pero sin ubicación de uso, y el grupo la muestra en estado de error. Estableces la ubicación de uso en Canadá, vuelves a procesar el grupo y llega la licencia. Un contratista de una firma asociada es invitado como invitado B2B, canjea la invitación con la cuenta de su propia empresa y se agrega a un grupo de seguridad del proyecto que tiene Contributor en un grupo de recursos. SSPR se habilita para el grupo Engineering con dos métodos requeridos, y la escritura diferida de contraseñas se activa porque los ingenieros se sincronizan desde el entorno local.

Entre los errores comunes están suponer que las licencias libres garantizan la asignación cuando la ubicación de uso está vacía; pensar que los invitados tienen contraseña en tu inquilino; elegir 'Seleccionado' para SSPR y esperar agregar varios grupos (acepta un solo grupo, así que anida grupos o usa Todos); olvidar que la escritura diferida es necesaria para los usuarios sincronizados; y creer que la opción de grupo asignable a roles se puede activar después. La redacción del examen los delata. 'La asignación de licencias falla pero hay licencias disponibles' apunta a la ubicación de uso. 'Asignar licencias automáticamente cuando los usuarios se unen a un departamento' apunta a licencias basadas en grupos con un grupo dinámico. 'Socio externo, con sus propias credenciales' apunta a una invitación de invitado B2B. 'Los usuarios restablecen su propia contraseña y el cambio debe llegar al entorno local' apunta a SSPR más escritura diferida de contraseñas. 'Minimizar las llamadas a la mesa de ayuda' casi siempre es SSPR.

Términos clave

Usage location (ubicación de uso)
La propiedad de país de un usuario que debe estar configurada antes de poder asignarle una licencia.
Group-based licensing (licencias basadas en grupos)
Asignar una licencia a un grupo para que todos los miembros la hereden y la pierdan al salir del grupo.
Service plan (plan de servicio)
Un componente individual de un producto con licencia que se puede desactivar durante la asignación.
B2B guest user (usuario invitado B2B)
Una identidad externa invitada a tu inquilino con el tipo de usuario Guest, que inicia sesión con credenciales de su propia organización o cuenta.
External collaboration settings (configuración de colaboración externa)
Opciones del inquilino que controlan quién puede invitar a invitados, qué pueden ver los invitados y qué dominios se permiten.
Self-service password reset (SSPR, restablecimiento de contraseña de autoservicio)
Una función que permite a los usuarios registrados restablecer su propia contraseña con métodos de autenticación verificados.
Password writeback (escritura diferida de contraseñas)
Una función de sincronización que escribe en Active Directory local las contraseñas restablecidas en la nube.
Guest Inviter role (rol de invitador de invitados)
Un rol de Entra que permite a quienes no son administradores invitar a usuarios externos cuando la configuración de colaboración externa restringe las invitaciones.
Ejemplo real

Una firma de ingeniería agrega un grupo dinámico para todos los usuarios del departamento Engineering y le asigna la licencia de Microsoft 365. La licencia de una ingeniera nueva falla hasta que el administrador establece su ubicación de uso en Canadá y vuelve a procesar el grupo. Un contratista de una firma asociada es invitado como invitado B2B, se agrega a un grupo de proyecto e inicia sesión con la cuenta de su propia empresa, mientras que los ingenieros restablecen sus contraseñas olvidadas mediante SSPR con escritura diferida hacia AD DS local.

Consejo para el examen: Si una asignación de licencia falla, revisa primero la ubicación de uso. En SSPR, las opciones de alcance son Ninguno, Seleccionado (un solo grupo) y Todos, los administradores siempre necesitan dos métodos y los usuarios sincronizados necesitan escritura diferida de contraseñas.

Comprueba lo que sabes

La asignación de una licencia a un usuario nuevo falla con un error. El inquilino tiene licencias libres. ¿Cuál es la causa más probable?

La ubicación de uso del usuario no está configurada; es obligatoria antes de poder asignar una licencia.

¿Cómo se autentica un invitado B2B en tu inquilino?

Con su propia identidad de su organización de origen, una cuenta Microsoft o un código de acceso de un solo uso; tu inquilino no almacena su contraseña.

Habilitas SSPR para usuarios sincronizados, pero las contraseñas restablecidas no funcionan en el entorno local. ¿Qué falta?

La escritura diferida de contraseñas mediante Microsoft Entra Connect o Cloud Sync, que escribe la nueva contraseña de vuelta en Active Directory.

Quieres que cada usuario del departamento de Ventas reciba una licencia automáticamente. ¿Qué configuras?

Licencias basadas en grupos sobre un grupo de usuario dinámico cuya regla coincida con el departamento de Ventas, lo que requiere Entra ID P1.

¿Qué directiva de autenticación se aplica cuando un administrador usa SSPR?

Una directiva integrada más estricta que siempre requiere dos métodos y nunca permite preguntas de seguridad, independientemente de la configuración del inquilino.
