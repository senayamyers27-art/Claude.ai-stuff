CompTIA Data+ DA0-002

Datos estructurados, semiestructurados y no estructurados, con ejemplos de cada uno

Todo proyecto de datos empieza con una pregunta sencilla: ¿qué forma tienen estos datos? La respuesta decide dónde puedes almacenarlos, qué herramientas pueden leerlos y cuánto trabajo cuesta prepararlos antes del análisis. CompTIA Data+ agrupa los datos en tres formas: estructurados, semiestructurados y no estructurados. Clasificar bien una fuente desde el principio te evita elegir el almacenamiento equivocado, la herramienta equivocada o un plazo poco realista.

Los datos estructurados siguen un esquema fijo, es decir, una definición de los campos y tipos que debe cumplir cada registro. Todos los registros tienen los mismos campos, cada campo tiene un tipo definido y los datos encajan de forma natural en filas y columnas. Una tabla de pedidos en una base de datos relacional, con las columnas OrderID, CustomerID, OrderDate y Amount, es el ejemplo clásico. Las hojas de cálculo organizadas como tablas limpias también son estructuradas, siempre que cada fila siga la misma disposición de columnas. Como la forma se conoce de antemano, puedes consultar los datos estructurados directamente con el lenguaje de consulta estructurado (SQL), y son los más fáciles de filtrar, agregar, combinar y graficar. Si abres una fuente estructurada en un cliente SQL, ves nombres de columnas, tipos de datos como INTEGER o DATE y filas que se alinean todas.

Los datos semiestructurados llevan sus propias etiquetas, pero no obligan a que todos los registros tengan la misma forma. JSON (JavaScript Object Notation) y el lenguaje de marcado extensible (XML) son los ejemplos habituales: cada valor está junto a una clave o dentro de una etiqueta que dice qué es, pero un registro puede tener campos que a otro le faltan, y los valores pueden estar anidados, como un pedido que contiene una lista de artículos. Un ticket en JSON podría verse así: {"id": 4412, "priority": "high", "tags": ["billing", "refund"]}, mientras que el siguiente ticket no tiene la clave tags en absoluto. Los archivos de registro con pares clave=valor, los encabezados de correo electrónico y muchas respuestas de interfaces de programación de aplicaciones (API) también son semiestructurados. A este tipo de datos se le suele llamar autodescriptivo, porque las etiquetas viajan con los valores.

Trabajar con datos semiestructurados normalmente implica analizarlos (parsing) o aplanarlos en tablas antes del análisis. Aplanar convierte las listas anidadas en filas o columnas adicionales, de modo que un pedido con tres artículos puede convertirse en tres filas que repiten el ID del pedido. Las claves que faltan se convierten en valores nulos, y tienes que decidir cómo manejarlos. Las bases de datos modernas pueden almacenar y consultar columnas JSON, y herramientas como pandas en Python pueden leer JSON directamente, pero el analista todavía tiene que decidir cómo se asignan los campos anidados y opcionales a columnas.

Los datos no estructurados no tienen un modelo de datos que una consulta pueda usar. Aquí entran el texto libre de correos, mensajes de chat y documentos, los PDF, las imágenes, el audio y el video. La mayor parte de los datos del mundo no son estructurados, y a menudo contienen información valiosa, como la razón por la que un cliente está descontento, el daño visible en una foto de un seguro o el tono de una llamada grabada. El reto es que no puedes escribir WHERE reason = 'price' contra un párrafo de texto. Necesitas un procesamiento adicional para convertirlo en campos analizables.

Ese procesamiento adicional se llama a veces extracción de características. Algunos ejemplos son el procesamiento de lenguaje natural (NLP) para puntuar el sentimiento o clasificar temas, el reconocimiento óptico de caracteres (OCR) para extraer texto de formularios escaneados, la conversión de voz a texto para transcribir llamadas y las etiquetas que una persona o un modelo asigna a las imágenes. El resultado de cada paso es una nueva columna estructurada, como sentiment_score o complaint_topic, que se puede combinar con otras tablas y contar. Como estos pasos pueden cometer errores, un analista cuidadoso revisa una muestra de los valores extraídos antes de confiar en ellos para un reporte.

Presta atención a los casos mixtos, porque las fuentes reales rara vez encajan perfectamente en una sola categoría. Un correo electrónico es semiestructurado en sus encabezados (From, To, Date, Subject) y no estructurado en su cuerpo. Un archivo de valores separados por comas (CSV) es estructurado si todas las filas tienen las mismas columnas, aunque sea solo un archivo de texto. Una tabla de base de datos puede contener una columna no estructurada, como un campo de comentarios en texto libre, junto a columnas con tipos bien definidos. Un almacén de documentos puede contener documentos JSON que son semiestructurados aunque vivan dentro de una base de datos. El contenedor no decide la clasificación; lo que la decide es la presencia o ausencia de un modelo consistente.

Cuando una pregunta del examen te pida clasificar datos, aplica tres pruebas en orden. Primero, ¿hay un esquema consistente que describa todos los registros, de modo que los datos encajen en filas y columnas con tipos definidos? Entonces son estructurados. Segundo, si no, ¿los datos son autodescriptivos, con claves o etiquetas, quizá anidados o con campos opcionales? Entonces son semiestructurados. Tercero, si no hay ningún modelo, como en fotos, grabaciones o texto libre, son no estructurados. Luego piensa en la consecuencia: los datos estructurados están listos para consultarse, los semiestructurados necesitan análisis o aplanamiento, y los no estructurados necesitan extracción antes de poder analizarse.

Términos clave

Structured data (datos estructurados)
Datos que siguen un esquema fijo de campos y tipos, como las filas de una tabla relacional.
Semi-structured data (datos semiestructurados)
Datos autodescriptivos con claves o etiquetas pero con una forma flexible, como JSON o XML.
Unstructured data (datos no estructurados)
Datos sin un modelo predefinido que las consultas puedan usar, como texto libre, imágenes, audio y video.
Schema (esquema)
La definición de los campos, tipos y relaciones que se espera que sigan los datos.
Flattening (aplanamiento)
Convertir registros semiestructurados anidados en filas y columnas para poder analizarlos como una tabla.
Feature extraction (extracción de características)
Obtener campos estructurados, como el sentimiento o el tema, a partir de contenido no estructurado como texto o imágenes.
Ejemplo real

Un equipo de soporte quiere saber por qué cancelan los clientes. Los datos de las cuentas y las fechas de cancelación están en una tabla estructurada del sistema de gestión de relaciones con clientes (CRM), los metadatos de los tickets llegan como JSON desde la API de la mesa de ayuda y las razones reales están en transcripciones de chat en texto libre. La analista aplana el JSON en una tabla de tickets, la combina con los datos del CRM por ID de cliente y luego usa un paso de clasificación de texto para etiquetar cada transcripción con una razón, convirtiendo el texto no estructurado en una columna que se puede contar. Revisa a mano 100 transcripciones etiquetadas antes de publicar el gráfico.

Consejo para el examen: JSON y XML son los ejemplos típicos de datos semiestructurados. Si una pregunta menciona campos anidados, claves opcionales o etiquetas, elige semiestructurados; si menciona fotos, grabaciones o texto libre, elige no estructurados; si menciona una disposición de tabla fija, elige estructurados.

Comprueba lo que sabes

Una API web devuelve registros en los que algunos objetos contienen una clave opcional 'discount' y una lista anidada de artículos. ¿Cómo se clasifican estos datos?

Semiestructurados. Son autodescriptivos gracias a las claves, pero no todos los registros comparten un único esquema fijo.

¿Por qué los datos no estructurados suelen necesitar procesamiento adicional antes del análisis?

No tienen campos que las consultas puedan filtrar o agregar, así que primero debes extraer características como el sentimiento, palabras clave o el texto de las imágenes.

Un correo electrónico tiene los encabezados From, To y Date y un cuerpo en texto libre. ¿Cómo clasificarías sus partes?

Los encabezados son semiestructurados (campos etiquetados) y el cuerpo es texto libre no estructurado.
