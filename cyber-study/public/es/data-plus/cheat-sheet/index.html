Dominio 1: Data concepts and environments (18%)

Consejos para el examen

  • JSON y XML son los ejemplos típicos de datos semiestructurados. Si una pregunta menciona campos anidados, claves opcionales o etiquetas, elige semiestructurados; si menciona fotos, grabaciones o texto libre, elige no estructurados; si menciona una disposición de tabla fija, elige estructurados.
  • Si una pregunta pide qué columna vincula dos tablas, la respuesta es la clave foránea en la tabla del lado 'muchos'. Si pregunta qué elimina los datos del cliente repetidos en cada fila de pedido, la respuesta es la normalización. Si pregunta cómo modelar una relación de muchos a muchos, la respuesta es una tabla de unión.
  • Relaciona la palabra clave con el tipo: registros JSON flexibles significa documentos; búsqueda solo por ID significa clave-valor; escrituras masivas de series de tiempo significa familias de columnas; relaciones y saltos significa grafos.
  • Los números con los que nunca haces cálculos (códigos postales, teléfonos, ID) deben ser texto. Para el dinero, elige decimal en lugar de float. Para las fechas, conviértelas a un tipo de fecha real y prefiere ISO 8601.
  • Columnar más comprimido más analítica significa Parquet. Datos anidados de una API significa JSON. Etiquetas y validación con esquema en intercambios empresariales sugieren XML. Intercambio tabular simple, universal y sin tipos significa CSV.
  • Schema on write significa data warehouse; schema on read significa data lake. Transacciones significa OLTP; análisis significa OLAP. Un solo departamento significa data mart. Una sola plataforma para BI y ciencia de datos sobre archivos abiertos significa lakehouse.
  • Las medidas van en los hechos; las descripciones van en las dimensiones. Conservar el historial significa SCD Type 2; sobrescribir significa Type 1; un valor anterior en una columna significa Type 3. Dimensiones divididas en subtablas significa copo de nieve.
  • Código reproducible más narrativa significa notebook; dashboards interactivos para usuarios de negocio significa plataforma de BI; capacidad elástica de pago por uso significa nube; control directo y total del hardware propio significa on-premises.
  • Consultar y agregar datos donde viven apunta a SQL; la automatización y el machine learning apuntan a Python; el análisis estadístico intensivo y los gráficos estadísticos apuntan a R. Espera tener que leer fragmentos cortos de código y decir qué hacen.
  • La automatización de interfaz de usuario basada en reglas es RPA, no machine learning. Predecir una etiqueta conocida es aprendizaje supervisado; encontrar grupos sin etiquetas es no supervisado. Convertir texto en campos que se pueden contar es NLP. El resultado de un LLM siempre debe validarse.

Términos clave

Structured data (datos estructurados)
Datos que siguen un esquema fijo de campos y tipos, como las filas de una tabla relacional.
Semi-structured data (datos semiestructurados)
Datos autodescriptivos con claves o etiquetas pero con una forma flexible, como JSON o XML.
Unstructured data (datos no estructurados)
Datos sin un modelo predefinido que las consultas puedan usar, como texto libre, imágenes, audio y video.
Schema (esquema)
La definición de los campos, tipos y relaciones que se espera que sigan los datos.
Flattening (aplanamiento)
Convertir registros semiestructurados anidados en filas y columnas para poder analizarlos como una tabla.
Feature extraction (extracción de características)
Obtener campos estructurados, como el sentimiento o el tema, a partir de contenido no estructurado como texto o imágenes.
Primary key (clave primaria)
Una columna o conjunto de columnas cuyos valores identifican de forma única cada fila y nunca son nulos.
Foreign key (clave foránea)
Una columna que hace referencia a la clave primaria de otra tabla, vinculando las tablas y haciendo cumplir la integridad referencial.
Composite key (clave compuesta)
Una clave primaria formada por dos o más columnas que son únicas solo en combinación.
Surrogate key (clave sustituta)
Un identificador generado por el sistema, como un entero autoincremental, sin significado de negocio.
Normalization (normalización)
Organizar las tablas en formas normales (1NF, 2NF, 3NF) para que cada hecho se almacene una sola vez, reduciendo la redundancia y las anomalías de actualización.
Junction table (tabla de unión)
Una tabla que contiene pares de claves foráneas y resuelve una relación de muchos a muchos.
Referential integrity (integridad referencial)
La regla de que cada valor de clave foránea debe coincidir con un valor de clave primaria existente en la tabla referenciada.
Document store (almacén de documentos)
Una base de datos NoSQL que almacena documentos independientes, a menudo anidados y parecidos a JSON, con campos flexibles.
Key-value store (almacén clave-valor)
Una base de datos NoSQL que guarda y recupera valores mediante una clave única, optimizada para búsquedas rápidas.
Column-family store (almacén de familias de columnas)
Una base de datos NoSQL distribuida cuyas filas contienen conjuntos variables de columnas agrupadas en familias, adecuada para cargas de escritura intensas.
Graph database (base de datos de grafos)
Una base de datos que almacena nodos y relaciones como datos de primera clase, optimizada para recorrer conexiones.
Columnar storage (almacenamiento columnar)
Una disposición de almacenamiento, usada por los almacenes de datos analíticos y por Parquet, que guarda juntos los valores de cada columna para acelerar las agregaciones; no es lo mismo que un almacén de familias de columnas.
Eventual consistency (consistencia eventual)
Un modelo en el que las réplicas de los datos pueden diferir brevemente después de una escritura, pero con el tiempo convergen al mismo valor.
String (cadena)
Un tipo de dato de texto que guarda caracteres; se usa para nombres y para identificadores de aspecto numérico, como los códigos postales.
Integer (entero)
Un tipo numérico para números enteros, como conteos y cantidades.
Decimal (numeric)
Un tipo numérico exacto con precisión y escala fijas, adecuado para montos de dinero.
Floating point (punto flotante)
Un tipo numérico aproximado guardado en binario que puede introducir pequeños errores de redondeo.
Boolean (booleano)
Un tipo que contiene verdadero o falso, usado a menudo para indicadores como is_active.
Casting (conversión de tipos)
Convertir explícitamente un valor de un tipo de dato a otro, por ejemplo de texto a fecha.
ISO 8601
Un formato internacional de fecha y hora, como YYYY-MM-DD, que se ordena correctamente y evita la ambigüedad entre día y mes.
Flat file (archivo plano)
Un archivo simple que contiene registros sin relaciones ni índices de base de datos, normalmente un registro por línea.
CSV
Comma-separated values (valores separados por comas): un archivo plano de texto con un registro por línea y campos delimitados por comas.
JSON
JavaScript Object Notation: un formato de texto de pares clave-valor y arreglos que admite anidamiento; común en las API.
XML
Extensible Markup Language (lenguaje de marcado extensible): un formato de texto autodescriptivo basado en etiquetas que se puede validar contra un esquema (XSD).
Parquet
Un formato de archivo binario, columnar y comprimido, que guarda los tipos de datos y está hecho para consultas analíticas.
Delimiter (delimitador)
El carácter que separa los campos en un archivo plano, como una coma, una tabulación o una barra vertical (pipe).
Character encoding (codificación de caracteres)
El esquema que asigna caracteres a bytes, como UTF-8; si no coincide, los caracteres acentuados o especiales se vuelven ilegibles.
OLTP
Online transaction processing (procesamiento de transacciones en línea): sistemas optimizados para muchas lecturas y escrituras pequeñas y rápidas que hacen funcionar el negocio.
OLAP
Online analytical processing (procesamiento analítico en línea): sistemas optimizados para consultas analíticas complejas, principalmente de lectura, sobre datos históricos.
Data warehouse (almacén de datos)
Un repositorio central de datos históricos integrados, limpios y estructurados, modelados para reportes (schema on write).
Data mart
Un subconjunto temático de datos al estilo data warehouse para un equipo o función.
Data lake (lago de datos)
Un repositorio de datos sin procesar en formatos nativos donde la estructura se aplica al leerlos (schema on read).
Data lakehouse
Una arquitectura que agrega funciones de data warehouse, como esquemas, transacciones y SQL rápido, a datos en formatos abiertos sobre el almacenamiento de un data lake.
Data swamp (pantano de datos)
Un data lake mal gobernado cuyo contenido no está documentado, no es confiable o es difícil de encontrar.
Fact table (tabla de hechos)
Una tabla de medidas numéricas de eventos de negocio con una granularidad definida, con claves foráneas a las dimensiones.
Grain (granularidad)
El nivel de detalle que representa una fila de la tabla de hechos, como una línea de un recibo.
Dimension table (tabla de dimensiones)
Una tabla de atributos descriptivos (como producto, cliente o fecha) que se usan para filtrar y agrupar los hechos.
Star schema (esquema en estrella)
Un diseño con una tabla de hechos central unida directamente a tablas de dimensiones desnormalizadas.
Snowflake schema (esquema en copo de nieve)
Un esquema en estrella cuyas dimensiones están normalizadas en subtablas relacionadas.
Galaxy schema (esquema de galaxia)
Un diseño con varias tablas de hechos que comparten dimensiones comunes; también se llama constelación de hechos (fact constellation).
Slowly changing dimension, SCD (dimensión de cambio lento)
Un método para manejar cambios en los atributos de las dimensiones; el Type 1 sobrescribe, el Type 2 agrega una fila nueva para conservar el historial y el Type 3 agrega una columna con el valor anterior.
On-premises (local)
Infraestructura que la organización posee y opera en sus propias instalaciones.
Cloud (nube)
Cómputo y almacenamiento alquilados bajo demanda a un proveedor, a menudo como servicios administrados que se cobran por uso.
Hybrid environment (entorno híbrido)
Una combinación de recursos on-premises y en la nube, como sistemas de transacciones locales que alimentan un almacén de datos en la nube.
Data residency (residencia de datos)
El requisito o la preocupación sobre la ubicación geográfica en la que se almacenan y procesan los datos.
Notebook
Un documento interactivo que combina código ejecutable, resultados y texto narrativo, como Jupyter.
BI platform (plataforma de BI)
Software que se conecta a los datos, los modela y publica dashboards y reportes interactivos.
IDE
Integrated development environment (entorno de desarrollo integrado): software para escribir, ejecutar y depurar código o consultas.
SQL
Structured Query Language (lenguaje de consulta estructurado): un lenguaje declarativo para consultar y administrar datos en bases de datos relacionales.
Declarative language (lenguaje declarativo)
Un lenguaje en el que indicas el resultado que quieres en lugar de los pasos para producirlo.
pandas
Una biblioteca de Python para trabajar con datos tabulares en DataFrames.
DataFrame
Una tabla bidimensional de filas y columnas con nombre que se usa en pandas y en R.
R
Un lenguaje de programación y entorno diseñado para computación estadística y gráficos.
SQL dialect (dialecto de SQL)
La variante de SQL de un proveedor de bases de datos, que comparte las instrucciones principales pero difiere en algunas funciones y en la sintaxis.
Machine learning, ML (aprendizaje automático)
Algoritmos que aprenden patrones a partir de los datos para hacer predicciones, en lugar de seguir reglas escritas a mano.
Supervised learning (aprendizaje supervisado)
Machine learning entrenado con ejemplos etiquetados para predecir una etiqueta (clasificación) o un valor (regresión) en datos nuevos.
Unsupervised learning (aprendizaje no supervisado)
Machine learning sobre datos sin etiquetas que encuentra estructura, como grupos de clientes parecidos.
Overfitting (sobreajuste)
Cuando un modelo aprende los datos de entrenamiento con demasiado detalle, incluido el ruido, y funciona mal con datos nuevos.
Large language model, LLM (modelo de lenguaje grande)
Un modelo fundacional entrenado con grandes cantidades de texto que genera e interpreta lenguaje.
Hallucination (alucinación)
Un resultado seguro pero incorrecto o inventado de un modelo de IA generativa.
Natural language processing, NLP (procesamiento de lenguaje natural)
Técnicas que permiten a las computadoras analizar y generar lenguaje humano, como el análisis de sentimiento.
Robotic process automation, RPA (automatización robótica de procesos)
Bots de software que repiten tareas de interfaz de usuario basadas en reglas, como la captura de datos, sin aprender.

Dominio 2: Data acquisition and preparation (22%)

Consejos para el examen

  • Si existe una API, casi siempre es la respuesta preferida frente al scraping. En encuestas, busca el método de muestreo que garantiza que todos los subgrupos estén representados: el estratificado. El muestreo por conveniencia es la opción sesgada clásica.
  • Transformar antes de cargar es ETL; transformar dentro del warehouse después de cargar es ELT. Necesidades del orden de segundos significan streaming. Solo filas modificadas significa incremental. Si en una pregunta aparece un dashboard desactualizado, revisa primero la última ejecución del pipeline.
  • Una condición sobre una sola fila significa WHERE; una condición sobre un total, un conteo o un promedio significa HAVING. Las comparaciones con NULL necesitan IS NULL, nunca = NULL. Si tienes dudas, recorre la consulta en orden de procesamiento.
  • 'Incluir registros aunque no tengan coincidencia' significa un outer join (normalmente LEFT). 'Apilar archivos con las mismas columnas' significa UNION o append. Si un join aumenta el número de filas de forma inesperada, sospecha de claves duplicadas.
  • Conoce la solución que corresponde a cada problema: deduplicar los duplicados, estandarizar los formatos inconsistentes, validar los valores inválidos, investigar los valores atípicos antes de eliminarlos, e imputar o marcar los valores faltantes.
  • Para datos numéricos sesgados, como ingresos o precios de viviendas, la imputación por la mediana es mejor que por la media. Reemplazar los espacios en blanco con cero casi siempre es incorrecto, salvo que cero sea el valor real. Marca siempre lo que imputaste.
  • Dividir un campo en varios significa parsing; unir varios en uno significa concatenación; crear una nueva columna calculada significa una variable derivada; asignar etiquetas nuevas a valores antiguos significa recodificación.
  • Rango de 0 a 1 significa normalización min-max; media 0 y desviación estándar 1 significa estandarización. Grupos del mismo tamaño significan binning por cuantiles. No promedies promedios; agrega a partir de los totales subyacentes.
  • De columnas a filas es despivotar (unpivot); de filas a columnas es pivotar (pivot). Las herramientas de BI y las bases de datos generalmente quieren el formato largo. Si los totales se ven demasiado bajos, busca un filtro olvidado.
  • Indexa las columnas por las que filtras y haces joins, filtra lo antes posible y nombra solo las columnas que necesitas. Filtrar después de que los datos llegan a la herramienta de BI es la respuesta lenta. Revisa el plan de ejecución para confirmarlo.

Términos clave

Database extract (extracción de base de datos)
Una obtención de datos mediante una consulta directamente de la base de datos de un sistema de origen, a menudo programada y a menudo ejecutada contra una réplica de lectura.
API
Una interfaz de programación de aplicaciones: una forma documentada de que los programas soliciten datos a un sistema, a menudo por HTTPS y devolviendo JSON.
Pagination (paginación)
Dividir un resultado grande de una API en páginas que deben solicitarse una tras otra hasta obtener todos los registros.
Rate limit (límite de solicitudes)
Un tope sobre cuántas solicitudes a la API puede hacer un cliente en una ventana de tiempo determinada.
Web scraping
Extraer datos descargando e interpretando páginas web; se usa cuando no hay una API disponible y los términos del sitio lo permiten.
Stratified sampling (muestreo estratificado)
Dividir una población en grupos y muestrear al azar dentro de cada grupo para que todos los grupos estén representados.
Sampling bias (sesgo de muestreo)
Error sistemático que ocurre cuando una muestra no representa a la población que debería describir.
ETL
Extract, transform, load (extraer, transformar, cargar): los datos se transforman en una capa separada antes de cargarlos en el destino.
ELT
Extract, load, transform (extraer, cargar, transformar): los datos sin procesar se cargan primero y se transforman dentro del sistema de destino con su propio cómputo.
Batch processing (procesamiento por lotes)
Mover y procesar datos en bloques programados, como ejecuciones nocturnas o cada hora.
Streaming processing (procesamiento en streaming)
Procesar cada evento de forma continua en cuanto llega, con resultados disponibles en segundos.
Full load (carga completa)
Reemplazar toda la tabla de destino con una copia nueva del origen en cada ejecución.
Incremental load (carga incremental)
Una carga que procesa solo los registros nuevos o modificados desde la ejecución anterior.
Change data capture, CDC (captura de datos de cambios)
Una técnica que identifica y entrega los cambios realizados en una base de datos de origen, a menudo a partir de su registro de transacciones, incluidas las eliminaciones.
WHERE
Una cláusula que filtra filas individuales antes de agrupar.
GROUP BY
Una cláusula que combina en grupos las filas con los mismos valores para agregarlas.
HAVING
Una cláusula que filtra grupos después de la agregación, lo que permite condiciones sobre funciones de agregación.
Aggregate function (función de agregación)
Una función como COUNT, SUM, AVG, MIN o MAX que resume muchas filas en un solo valor.
NULL
Un marcador que indica que un valor es desconocido o falta; se comprueba con IS NULL, nunca con un signo de igual.
Alias
Un nombre temporal que se da a una columna o tabla con AS, como SUM(amount) AS revenue.
Inner join
Devuelve solo las filas con claves coincidentes en ambas tablas.
Left join
Devuelve todas las filas de la tabla izquierda más las coincidencias de la derecha, con NULL donde no hay coincidencia.
Full outer join
Devuelve todas las filas de ambas tablas, con NULL donde cualquiera de los dos lados no tiene coincidencia; es útil para conciliar.
UNION ALL
Apila las filas de dos conjuntos de resultados con las mismas columnas y conserva los duplicados; UNION los elimina.
Fan-out
Duplicación de filas causada por unir con una tabla que tiene valores de clave repetidos, lo que infla los totales.
Anti-join
Un patrón, a menudo un left join filtrado por NULL en el lado derecho, que encuentra las filas sin coincidencia en otra tabla.
Duplicate record (registro duplicado)
Un registro que representa la misma entidad o el mismo evento que otro registro del conjunto de datos.
Placeholder value (valor de marcador)
Un sustituto como 0, -1, N/A o 9999 usado para indicar desconocido, que puede confundirse con datos reales.
Invalid value (valor inválido)
Un valor que rompe las reglas de un campo en cuanto a tipo, rango, formato o valores permitidos.
Outlier (valor atípico)
Un valor que se encuentra lejos de la mayoría de los demás; puede ser un error o un extremo real.
Data profiling (perfilado de datos)
Resumir los conteos, los valores distintos, los rangos y los espacios en blanco de cada columna para descubrir problemas de calidad.
Redundancy (redundancia)
Guardar los mismos datos en varios lugares, lo que crea el riesgo de inconsistencias entre las copias.
Listwise deletion (eliminación por lista)
Eliminar todos los registros que tengan un valor faltante en cualquier campo que use el análisis.
Pairwise deletion (eliminación por pares)
Usar todos los valores disponibles para cada cálculo por separado, de modo que distintas estadísticas pueden usar filas diferentes.
Imputation (imputación)
Reemplazar los valores faltantes con valores estimados, como la media, la mediana, la moda o la predicción de un modelo.
Missing completely at random (faltante completamente al azar)
Cuando la probabilidad de que falte un valor no está relacionada con ningún dato, de modo que los datos restantes siguen siendo representativos.
Imputation flag (indicador de imputación)
Una columna indicadora que marca qué valores se rellenaron en lugar de haberse observado.
Sensitivity check (prueba de sensibilidad)
Volver a ejecutar un análisis con distintas decisiones sobre los datos faltantes para confirmar que la conclusión no depende de ellas.
Parsing (análisis sintáctico)
Extraer partes significativas de una cadena o un documento estructurado, como dividir un nombre por una coma.
Concatenation (concatenación)
Unir dos o más valores en una sola cadena.
Type conversion (conversión de tipos)
Cambiar el tipo de dato de un campo, como de texto a fecha o de número a texto, a menudo con CAST o CONVERT.
Recoding (recodificación)
Asignar a los valores existentes valores nuevos, estandarizados o agrupados.
Mapping table (tabla de mapeo)
Una tabla de búsqueda que enumera los valores originales y los valores estandarizados en los que deben convertirse.
Derived variable (variable derivada)
Un campo nuevo calculado a partir de campos existentes, como el margen de ganancia o los días hasta el envío.
Min-max normalization (normalización min-max)
Reescalar los valores a un rango fijo, normalmente de 0 a 1, con (x − min) ÷ (max − min).
Standardization (estandarización)
Convertir los valores en z-scores, (x − media) ÷ desviación estándar, lo que da una media de 0 y una desviación estándar de 1.
Z-score
El número de desviaciones estándar a las que un valor se encuentra por encima o por debajo de la media.
Binning (agrupación en intervalos)
Agrupar valores continuos en rangos o categorías, con límites de igual ancho o de igual frecuencia.
Aggregation (agregación)
Resumir filas detalladas en totales o estadísticas de un nivel superior, como por mes y por región.
Weighted average (promedio ponderado)
Un promedio en el que cada valor cuenta en proporción a su peso, como su número de transacciones.
Wide format (formato ancho)
Una organización con una fila por sujeto y las mediciones repetidas repartidas en columnas.
Long (tidy) format (formato largo u ordenado)
Una organización con una fila por observación, que usa columnas de atributo y de valor.
Pivot (pivotar)
Reorganizar datos largos en anchos, convirtiendo valores de fila en encabezados de columna con celdas agregadas.
Unpivot / melt (despivotar)
Reorganizar datos anchos en largos, convirtiendo los encabezados de columna en valores de una nueva columna de atributo.
Transpose (transponer)
Intercambiar todas las filas y columnas de una tabla sin agregar ni crear pares de atributo y valor.
Filter (filtro)
Una condición que conserva solo las filas que coinciden en un conjunto de datos, una consulta o un reporte.
Index (índice)
Una estructura de datos que acelera la búsqueda de filas por los valores de una columna, a costa de almacenamiento y escrituras más lentas.
Full table scan (recorrido completo de la tabla)
Leer todas las filas de una tabla para evaluar una consulta, normalmente porque no existe un índice utilizable.
Execution plan (plan de ejecución)
La descripción que hace la base de datos de cómo ejecutará una consulta, incluidos los recorridos, los joins y el uso de índices, que a menudo se muestra con EXPLAIN.
Temporary table (tabla temporal)
Una tabla que guarda un resultado intermedio durante la sesión actual para que los pasos posteriores puedan reutilizarlo.
Common table expression, CTE (expresión de tabla común)
Una subconsulta con nombre definida con WITH que hace que las consultas complejas sean más fáciles de leer.
Partition pruning (poda de particiones)
Omitir particiones completas de una tabla cuando la consulta filtra por la columna de partición.

Dominio 3: Data analysis (24%)

Consejos para el examen

  • Datos sesgados o con valores atípicos: elige la mediana. Datos categóricos: la moda. La media sigue a la cola: con sesgo a la derecha, la media es mayor que la mediana; con sesgo a la izquierda, la media es menor que la mediana.
  • Memoriza los límites de valores atípicos del IQR: Q1 − 1.5 × IQR y Q3 + 1.5 × IQR. La desviación estándar de muestra divide entre n − 1; la de población divide entre N. Combina la media con la desviación estándar, y la mediana con el IQR.
  • Domina de memoria la regla 68-95-99.7 y z = (x − media) ÷ SD. Usa las reglas de valores atípicos con z-score solo para datos aproximadamente normales; usa la regla del IQR para datos sesgados. Un histograma con dos picos sugiere dos poblaciones que deben analizarse por separado.
  • El cambio porcentual siempre divide entre el valor anterior. Distingue los puntos porcentuales del porcentaje. Compara grupos de distintos tamaños con razones o tasas, no con totales sin procesar, e indica siempre la base.
  • p < alpha significa rechazar la hipótesis nula; en caso contrario, no se rechaza, y nunca se 'acepta' ni se 'demuestra'. Muestras más grandes dan intervalos de confianza más estrechos. Acompaña siempre el p-value con el tamaño del efecto.
  • Falso positivo es Tipo I (alpha); falso negativo es Tipo II (beta). Las muestras más grandes aumentan la potencia (menos errores Tipo II) con el mismo alpha; la tasa de error Tipo I la fija alpha, no el tamaño de muestra.
  • r está entre −1 y 1, y el signo indica la dirección. En el examen, la correlación nunca es prueba de causalidad. Sustituye los números en la ecuación de regresión con cuidado: multiplica la pendiente por x y luego suma la intersección. En la regresión simple, R² = r².
  • Relaciona la palabra de la pregunta: qué pasó es descriptivo, por qué es diagnóstico, qué pasará es predictivo, qué deberíamos hacer es prescriptivo. El perfilado abierto de datos nuevos es exploratorio. Usa la comparación año contra año para datos estacionales.
  • Un KPI necesita una definición medible y una meta. El porcentaje de variación divide entre el plan. Que sea favorable o desfavorable depende de la medida. Conoce la diferencia entre indicadores adelantados y rezagados con un ejemplo de cada uno.
  • GROUP BY reduce las filas; las funciones de ventana conservan cada fila. Los totales acumulados, las clasificaciones y las comparaciones con el periodo anterior apuntan a funciones de ventana. Lo pequeño y puntual va en una hoja de cálculo; lo grande o recurrente, en SQL; la estadística compleja y la automatización, en Python o R.
  • Si un total es exactamente el doble o sospechosamente alto después de un join, sospecha de una multiplicación de filas por claves duplicadas. Si desaparecieron registros, sospecha de un inner join o de un filtro olvidado. La conciliación necesita una fuente independiente.

Términos clave

Mean (media)
La suma de los valores dividida entre su cantidad; usa todos los valores y es sensible a los valores atípicos.
Median (mediana)
El valor central de los datos ordenados, o el promedio de los dos valores centrales si la cantidad es par; robusta frente a valores atípicos y sesgo.
Mode (moda)
El valor más frecuente; la única medida de tendencia central que funciona con datos categóricos.
Weighted mean (media ponderada)
Un promedio en el que algunos valores cuentan más que otros, como precios ponderados por unidades vendidas.
Right skew (sesgo a la derecha)
Una distribución con una cola larga de valores altos, donde la media suele ser mayor que la mediana.
Left skew (sesgo a la izquierda)
Una distribución con una cola larga de valores bajos, donde la media suele ser menor que la mediana.
Range (rango)
El máximo menos el mínimo; sencillo, pero determinado por completo por los dos valores más extremos.
Variance (varianza)
El promedio de las desviaciones al cuadrado respecto de la media, en unidades al cuadrado.
Standard deviation (desviación estándar)
La raíz cuadrada de la varianza; la distancia típica de los valores respecto de la media, en las propias unidades de los datos.
Interquartile range, IQR (rango intercuartílico)
Q3 menos Q1: la dispersión del 50% central de los datos, robusta frente a valores atípicos.
Percentile (percentil)
El valor por debajo del cual cae un porcentaje indicado de las observaciones.
Coefficient of variation (coeficiente de variación)
La desviación estándar dividida entre la media; se usa para comparar la variabilidad entre escalas distintas.
Normal distribution (distribución normal)
Una distribución simétrica en forma de campana en la que la media, la mediana y la moda son iguales, descrita por completo por su media y su desviación estándar.
Empirical rule (regla empírica)
En una distribución normal, alrededor del 68%, el 95% y el 99.7% de los valores caen dentro de 1, 2 y 3 desviaciones estándar de la media.
Z-score (puntuación estándar)
El número de desviaciones estándar a las que un valor está de la media: (x − media) ÷ SD.
Central limit theorem (teorema del límite central)
El principio según el cual los promedios de muestras grandes tienden a distribuirse de forma aproximadamente normal aunque los datos de base no lo hagan.
Skewness (asimetría)
El grado de falta de simetría de una distribución; positiva si hay una cola larga a la derecha, negativa si la cola larga está a la izquierda.
Bimodal distribution (distribución bimodal)
Una distribución con dos picos, que a menudo indica dos grupos mezclados.
Frequency distribution (distribución de frecuencias)
Una tabla o un gráfico que muestra con qué frecuencia aparece cada valor o categoría.
Relative frequency (frecuencia relativa)
El conteo de una categoría dividido entre el conteo total, expresado como proporción o porcentaje.
Cumulative frequency (frecuencia acumulada)
El total acumulado de los conteos hasta un valor dado, incluido este.
Percent change (cambio porcentual)
(nuevo − anterior) ÷ anterior × 100: el cambio relativo respecto del valor anterior.
Percentage point (punto porcentual)
La diferencia aritmética entre dos porcentajes; por ejemplo, pasar del 4% al 5% es 1 punto.
Ratio (razón)
Una comparación entre dos cantidades, como agentes por cada 1000 clientes; una tasa es una razón a lo largo del tiempo o de una exposición.
Population vs sample (población vs. muestra)
El grupo completo de interés frente al subconjunto que realmente se mide para estimarlo.
Parameter vs statistic (parámetro vs. estadístico)
Un valor real de la población, normalmente desconocido, frente al valor calculado a partir de una muestra para estimarlo.
Confidence interval (intervalo de confianza)
Un rango, calculado a partir de una muestra, que probablemente contiene el valor real de la población con un nivel de confianza indicado.
Margin of error (margen de error)
La mitad del ancho de un intervalo de confianza; la cifra de más o menos alrededor de una estimación.
Null hypothesis (hipótesis nula)
La afirmación por defecto de que no hay efecto ni diferencia, contra la cual una prueba busca evidencia.
p-value
La probabilidad de obtener resultados al menos tan extremos como los observados, suponiendo que la hipótesis nula es verdadera.
Type I error (error Tipo I)
Un falso positivo: rechazar una hipótesis nula que en realidad es verdadera; su probabilidad es alpha.
Type II error (error Tipo II)
Un falso negativo: no rechazar una hipótesis nula que en realidad es falsa; su probabilidad es beta.
Statistical power (potencia estadística)
La probabilidad (1 − beta) de que una prueba detecte un efecto que realmente existe.
Power analysis (análisis de potencia)
Un cálculo que se hace antes de un estudio para estimar el tamaño de muestra necesario para detectar el efecto más pequeño que importa.
Practical significance (significancia práctica)
Si un efecto es lo bastante grande como para importar en el mundo real, independientemente de su p-value.
Multiple comparisons problem (problema de las comparaciones múltiples)
El aumento de falsos positivos que ocurre cuando se ejecutan muchas pruebas, cada una con su propia probabilidad de error Tipo I.
Correlation coefficient, r (coeficiente de correlación)
Un valor de −1 a +1 que mide la fuerza y la dirección de una relación lineal.
Confounding variable (variable de confusión)
Una tercera variable que influye en las dos variables estudiadas y crea una asociación engañosa.
Reverse causation (causalidad inversa)
Cuando el supuesto efecto en realidad causa la supuesta causa.
Slope (pendiente)
En la regresión, el cambio promedio de y por cada aumento de una unidad en x.
Residual (residuo)
La diferencia entre un valor real y el valor que predice la línea de regresión.
R-squared (coeficiente de determinación)
La proporción de la variación de la variable dependiente que explica el modelo; es igual a r al cuadrado en la regresión lineal simple.
Exploratory data analysis, EDA (análisis exploratorio de datos)
Investigación inicial y abierta de los datos para entender su estructura, calidad y patrones.
Descriptive analysis (análisis descriptivo)
Análisis que resume lo que pasó, usando conteos, totales, promedios y gráficos.
Diagnostic analysis (análisis diagnóstico)
Análisis que explica por qué ocurrió un resultado, a menudo profundizando y segmentando.
Predictive analysis (análisis predictivo)
Análisis que usa datos históricos para pronosticar resultados o probabilidades futuros.
Prescriptive analysis (análisis prescriptivo)
Análisis que recomienda la mejor acción, a menudo usando optimización o simulación.
Trend analysis (análisis de tendencias)
Análisis de cómo cambia una medida con el tiempo, incluidas la dirección, la estacionalidad y los ciclos.
Cohort analysis (análisis de cohortes)
Seguimiento a lo largo del tiempo de grupos que comparten un punto de partida, como el mes de registro.
Metric (métrica)
Cualquier medida cuantitativa de actividad o desempeño.
KPI
Un indicador clave de desempeño: una métrica vinculada a un objetivo estratégico, con una meta definida.
Leading indicator (indicador adelantado)
Una medida que cambia antes que un resultado y ayuda a predecirlo.
Lagging indicator (indicador rezagado)
Una medida que refleja resultados que ya ocurrieron.
Vanity metric (métrica de vanidad)
Un número que se ve impresionante pero que no orienta decisiones ni refleja valor real.
Benchmark (punto de referencia)
Un valor de comparación, como el resultado del año pasado o un promedio de la industria.
Variance to plan (variación respecto al plan)
La diferencia entre los resultados reales y la meta o el presupuesto, a menudo expresada también como porcentaje del plan.
COUNTIF / COUNTIFS
Funciones de hoja de cálculo que cuentan las celdas que cumplen una condición, o varias condiciones.
XLOOKUP
Una función de hoja de cálculo que busca una clave en un rango y devuelve el valor correspondiente de otro rango.
GROUP BY
Una cláusula de SQL que reduce las filas a un resultado por grupo para las funciones de agregado.
Window function (función de ventana)
Una función de SQL que calcula sobre un conjunto de filas relacionadas usando OVER, sin reducirlas a grupos.
PARTITION BY
La parte de la definición de una ventana que reinicia el cálculo para cada grupo, como cada región.
LAG
Una función de ventana que devuelve un valor de una fila anterior; se usa para comparaciones entre periodos.
pandas
Una biblioteca de Python para trabajar con tablas de datos, que incluye agrupar, unir, cambiar la forma de los datos y hacer cálculos móviles.
Sanity check (comprobación de sensatez)
Una prueba rápida de si un resultado es plausible, como comparar su magnitud con lo esperado o confirmar que las partes suman el todo.
Reconciliation (conciliación)
Comparar los resultados con una fuente independiente de confianza, como el libro mayor, para confirmar que coinciden.
Control total (total de control)
Una suma o un conteo conocidos que se usan para verificar que los datos se procesaron de forma completa y correcta en cada etapa.
Join fan-out (multiplicación de filas por join)
La duplicación de filas que ocurre cuando una clave de join no es única en uno de los lados, lo que infla sumas y conteos.
Integer division (división entera)
La división de números enteros que descarta el residuo, como 7 / 2 que devuelve 3 en algunos dialectos de SQL.

Dominio 4: Visualization and reporting (20%)

Consejos para el examen

  • Tendencia en el tiempo significa línea; comparación entre categorías significa barras; relación significa dispersión; distribución significa histograma o diagrama de caja; parte de un todo con pocas categorías significa circular o barra apilada al 100%; puente de inicio a fin significa cascada; búsqueda de valores exactos significa tabla.
  • Ajusta el tipo de dashboard al público: estratégico para ejecutivos, táctico para gerentes, operativo para el personal que trabaja en tiempo real. Pon los KPI clave arriba a la izquierda, muestra los filtros activos y usa seguridad a nivel de fila en lugar de copias.
  • Las barras empiezan en cero. No codifiques el significado solo con el color. Una paleta divergente sirve para por encima y por debajo de la meta; una secuencial, para de bajo a alto. Los títulos expresan la conclusión.
  • Un registro formal que no debe cambiar significa estático. La supervisión continua con interacción significa dinámico. Una pregunta puntual significa ad hoc. Una solicitud repetida debe volverse recurrente o de autoservicio. Líderes que leen una sola página significa resumen ejecutivo.
  • Empieza con la conclusión para los ejecutivos, adapta el detalle al público, haz que las recomendaciones sean concretas y siempre indica las limitaciones. Los hallazgos correlacionales deben presentarse como asociaciones, no como causas probadas.
  • El detalle que respalda pero satura va en un apéndice. Qué tan actuales son los datos corresponde a la fecha de actualización o de corte. Cómo se obtuvieron los números corresponde a la metodología. De dónde vinieron los datos corresponde a las fuentes de datos. Los límites de uso corresponden a los avisos.
  • Las necesidades operativas de reacción inmediata significan tiempo real; el historial formal de cierre de mes significa instantánea. Si un reporte programado muestra datos viejos, revisa si la actualización se ejecutó después de la carga previa y si falló. Envía enlaces, no adjuntos.
  • Las copias contradictorias apuntan al control de versiones con números, fechas y un registro de cambios, además de una única ubicación autorizada. Las fuentes, colores y formatos consistentes apuntan a una guía de estilo. Que cada reporte empiece cumpliendo las reglas apunta a una plantilla.
  • Datos viejos significa revisar el historial de actualización, las credenciales y las cargas previas. Un filtro que no afecta a un visual significa revisar las relaciones y las conexiones del segmentador. Totales duplicados significa sospechar de claves duplicadas o joins de muchos a muchos. Páginas lentas significa agregar, quitar columnas y reducir visuales.

Términos clave

Histogram (histograma)
Un gráfico de la distribución de una variable numérica, con barras adyacentes que muestran los conteos en cada rango de valores (bin).
Box plot (diagrama de caja)
Un gráfico que resume una distribución con su mediana, cuartiles, bigotes y valores atípicos.
Choropleth map (mapa de coropletas)
Un mapa que sombrea áreas geográficas según el valor de una medida.
Scatter plot (diagrama de dispersión)
Un gráfico que representa dos variables numéricas una frente a la otra, con un punto por registro.
Waterfall chart (gráfico de cascada)
Un gráfico que muestra cómo un valor inicial cambia hasta un valor final mediante una serie de pasos positivos y negativos.
Heat map (mapa de calor)
Una cuadrícula en la que la intensidad del color representa el valor en cada combinación de dos dimensiones.
KPI card (tarjeta de KPI)
Un visual de dashboard que muestra una sola medida clave, normalmente con una comparación con la meta o con un periodo anterior y un indicador de tendencia.
Drill-down
Navegar desde datos resumidos hacia niveles más detallados de una jerarquía dentro de un visual.
Drill-through
Saltar desde un punto de datos seleccionado a una página de detalle separada, filtrada para ese elemento.
Slicer / filter (segmentador o filtro)
Un control interactivo que limita los datos que se muestran en los visuales de un dashboard.
Row-level security (seguridad a nivel de fila)
Reglas que restringen qué filas de datos puede ver cada usuario, según quién sea.
Wireframe
Un bosquejo sencillo de la distribución de un dashboard que se usa para acordar el contenido antes de construirlo.
Sequential palette (paleta secuencial)
Tonos de un mismo color de claro a oscuro, que se usan para valores ordenados de bajo a alto.
Diverging palette (paleta divergente)
Dos tonos contrastantes alrededor de un punto medio neutro, que se usan para valores por encima y por debajo de una referencia.
Truncated axis (eje truncado)
Un eje de valores que no empieza en cero, lo que exagera las diferencias en los gráficos de barras.
Chart junk
Elementos visuales como efectos 3D y líneas de cuadrícula pesadas que no agregan información y distraen de los datos.
Informative title (título informativo)
Un título de gráfico que expresa la conclusión principal en lugar de solo nombrar los datos que se muestran.
Alternative text (texto alternativo)
Una breve descripción en texto de un visual que los lectores de pantalla anuncian a los usuarios que no pueden verlo.
Static report (reporte estático)
Un reporte fijo, como un PDF, que captura los datos en un momento dado y no cambia.
Dynamic report (reporte dinámico)
Un reporte conectado a los datos que se actualiza y permite interacción, como filtrar y hacer drill-down.
Ad hoc report (reporte ad hoc)
Un reporte puntual creado para responder una pregunta específica.
Recurring report (reporte recurrente)
Un reporte que se produce con un calendario regular y un formato constante para poder comparar periodos.
Self-service reporting (reportes de autoservicio)
Permitir que los usuarios de negocio construyan sus propios reportes a partir de fuentes de datos gobernadas y confiables.
Executive summary (resumen ejecutivo)
Una breve sección inicial que expone los hallazgos clave, su importancia y la acción recomendada para los lectores de la alta dirección.
Data storytelling (contar historias con datos)
Presentar los hallazgos de datos como una narrativa estructurada de contexto, hallazgo y recomendación.
Limitation (limitación)
Una debilidad o restricción conocida de un análisis, como datos faltantes o una muestra pequeña.
Assumption (supuesto)
Una condición que se da por cierta en un análisis, como precios estables, y que los lectores deben conocer.
Actionable insight (hallazgo accionable)
Un hallazgo lo bastante específico como para que una parte interesada pueda decidir o actuar a partir de él.
Bottom line up front (la conclusión primero)
Un enfoque de comunicación que expone la conclusión o recomendación principal al inicio, antes del detalle de apoyo.
Methodology (metodología)
La descripción de cómo se realizó el análisis, incluida la preparación de los datos y los cálculos.
Data as-of date (fecha de corte de los datos)
El momento que reflejan los datos del reporte, que se muestra para que los lectores sepan qué tan actuales son.
Disclaimer (aviso)
Una nota que limita cómo debe interpretarse o usarse el reporte, como 'cifras preliminares, no auditadas'.
Appendix (apéndice)
Una sección al final de un reporte que contiene detalle de apoyo, como tablas completas y definiciones.
Data dictionary (diccionario de datos)
Una referencia que describe cada campo, su significado, su tipo y sus valores permitidos.
Confidentiality label (etiqueta de confidencialidad)
Una marca como 'Interno' o 'Confidencial' que indica a los lectores cómo se puede compartir el reporte.
Scheduled refresh (actualización programada)
Una actualización automatizada de los datos importados de un reporte en horarios establecidos.
Live / direct connection (conexión en vivo o directa)
Una conexión de reporte que consulta el origen cada vez que los usuarios interactúan, de modo que los datos siempre están actualizados.
Incremental refresh (actualización incremental)
Una actualización que vuelve a cargar solo los datos recientes o modificados en lugar del conjunto de datos completo.
Snapshot (instantánea)
Una copia almacenada de los valores de los datos en un momento dado, que se usa para reportar la historia tal como era.
Subscription (suscripción)
Una entrega programada de un reporte o un enlace a los usuarios, a menudo por correo electrónico.
Data-driven alert (alerta basada en datos)
Una notificación que se envía automáticamente cuando una medida cruza un umbral definido.
Version control (control de versiones)
Registrar y gestionar los cambios de archivos o reportes a lo largo del tiempo, con la posibilidad de comparar y restaurar versiones.
Change log (registro de cambios)
Un registro de qué cambió en cada versión, cuándo, por qué y quién lo hizo.
Style guide (guía de estilo)
Un conjunto documentado de reglas sobre fuentes, colores, formatos, terminología y convenciones de gráficos.
Template (plantilla)
Una distribución y un tema predefinidos a partir de los cuales empiezan los reportes nuevos para garantizar la consistencia.
Authoritative copy (copia autorizada)
La única versión oficial y publicada de un reporte que todos deben usar.
Theme (tema)
La paleta, las fuentes y la configuración visual guardadas en una herramienta de BI que se aplican automáticamente a los visuales nuevos.
Stale data (datos desactualizados)
Datos de un reporte que son más viejos de lo esperado debido a una actualización o un pipeline fallidos o mal sincronizados.
Data model relationship (relación del modelo de datos)
Un vínculo entre tablas de un modelo de BI que permite que los filtros y los cálculos fluyan entre ellas.
Cross-filter direction (dirección de filtrado cruzado)
El sentido en que una relación pasa los filtros entre tablas: único o en ambos sentidos.
Cardinality (cardinalidad)
El número de valores distintos de una columna, o la naturaleza uno a uno, uno a muchos o muchos a muchos de una relación.
Pre-aggregation (preagregación)
Resumir de antemano los datos detallados al nivel que necesitan los visuales, para acelerar las consultas.

Dominio 5: Data governance (16%)

Consejos para el examen

  • Decide y rinde cuentas significa propietario. Define y mantiene la calidad significa steward. Implementa controles técnicos como copias de seguridad, permisos y cifrado significa custodio. Usa los datos conforme a la política significa consumidor.
  • De dónde vinieron los datos y qué los transformó significa linaje. Qué significa una columna significa diccionario de datos. Un inventario de conjuntos de datos en el que se puede buscar significa catálogo de datos. Definiciones de negocio acordadas significan glosario.
  • Falta significa completitud; formato incorrecto o valor imposible significa validez; desacuerdo entre sistemas o dentro de un registro significa consistencia; duplicados significan unicidad; desactualizado significa oportunidad; no coincide con la realidad significa exactitud.
  • El perfilado descubre cómo se ven los datos; las reglas de validación hacen cumplir cómo deberían verse; las métricas lo miden; el monitoreo ejecuta las reglas de forma continua con alertas. Corrige en el origen cuando puedas.
  • El mismo cliente o producto con diferencias entre sistemas apunta a la gestión de datos maestros. Una versión oficial que todos usan es la fuente única de verdad. Qué fuente prevalece en cada campo lo deciden las reglas de supervivencia.
  • Datos de salud vinculados a una persona y en poder de un proveedor o una aseguradora significan PHI (HIPAA). Números de tarjeta significan PCI DSS. Eliminar solo los nombres puede dejar cuasi-identificadores que vuelven a identificar a las personas. Los datos combinados toman su clasificación más sensible.
  • Datos personales de la UE significan GDPR; datos de salud de EE. UU. en poder de proveedores, planes y sus socios comerciales significan HIPAA; datos de tarjetas significan PCI DSS (un estándar, no una ley). Las leyes sobre la ubicación de los datos significan soberanía o residencia. Una retención legal prevalece sobre el calendario de retención.
  • Reversible con una clave significa seudonimización; irreversible significa anonimización. Valores ficticios realistas para pruebas significa enmascaramiento estático; ocultar valores en el momento de la consulta significa enmascaramiento dinámico. Ver solo las filas de tu región significa seguridad a nivel de fila. El cifrado es tan fuerte como su gestión de claves.
  • Los datos conservados más allá de su periodo de retención, sobre todo las copias sueltas, son una falla de la etapa de eliminación. Recolectar más de lo necesario es una falla de la etapa de recolección. Archiva lo que debe conservarse; elimina todas las copias de lo que no es necesario conservar.

Términos clave

Data owner (propietario de los datos)
El líder de negocio que rinde cuentas y decide la clasificación, el acceso y el uso de un dominio de datos, y aprueba políticas como la de retención.
Data steward (administrador de datos)
El rol del lado del negocio que gestiona día a día las definiciones, las reglas de calidad y el uso adecuado de los datos, y resuelve definiciones contradictorias.
Data custodian (custodio de los datos)
El rol técnico, como un DBA o un ingeniero de datos, que almacena, protege, respalda y mantiene los datos según las decisiones del propietario.
Data consumer (consumidor de datos)
Cualquier persona que usa los datos para su trabajo y debe seguir las políticas sobre su uso adecuado.
Data governance council (consejo de gobernanza de datos)
Un grupo interdepartamental que establece la política de datos y resuelve las disputas entre dominios.
RACI chart (matriz RACI)
Una matriz que muestra quién es responsable, quién rinde cuentas, a quién se consulta y a quién se informa en cada actividad.
Metadata (metadatos)
Datos que describen otros datos, como su estructura, significado, propietario e historial de procesamiento.
Technical metadata (metadatos técnicos)
Metadatos sobre la estructura, como nombres de tablas y columnas, tipos de datos, claves y formatos de archivo.
Business metadata (metadatos de negocio)
Metadatos sobre el significado, como definiciones, reglas de cálculo, propietarios y sensibilidad.
Operational metadata (metadatos operativos)
Metadatos sobre el procesamiento, como horas de carga, cantidad de filas y el éxito o la falla de los trabajos.
Data dictionary (diccionario de datos)
Documentación del nombre, la definición, el tipo, el formato, los valores permitidos, la admisión de nulos y el origen de cada campo.
Business glossary (glosario de negocio)
Definiciones acordadas de términos y métricas de negocio que se aplican en todos los sistemas.
Data catalog (catálogo de datos)
Un inventario de activos de datos y sus metadatos, en el que se puede buscar, que ayuda a los usuarios a encontrar y entender los datos.
Data lineage (linaje de datos)
Un registro de dónde provienen los datos y de cada transformación por la que pasaron hasta llegar a su destino.
Accuracy (exactitud)
El grado en que los datos reflejan correctamente la entidad o el evento del mundo real que describen.
Completeness (completitud)
El grado en que los valores de datos requeridos están presentes.
Consistency (consistencia)
El grado en que los datos coinciden entre sistemas y dentro de un conjunto de datos, incluidos los formatos consistentes.
Validity (validez)
El grado en que los valores cumplen las reglas de tipo, formato, rango y valores permitidos.
Timeliness (oportunidad)
El grado en que los datos están actualizados y disponibles cuando se necesitan para su uso.
Uniqueness (unicidad)
El grado en que cada entidad o evento del mundo real se registra una sola vez.
Data quality scorecard (scorecard de calidad de datos)
Un reporte que sigue las métricas de calidad de cada dimensión frente a metas acordadas.
Data profiling (perfilado de datos)
Analizar la estructura y el contenido de un conjunto de datos, como los nulos, los valores distintos, los rangos y los patrones, para entender su calidad.
Validation rule (regla de validación)
Una verificación de que los datos cumplen una expectativa, como un tipo, un rango, un formato o un valor permitido.
Cross-field check (verificación entre campos)
Una regla de validación que prueba la lógica entre columnas, como que la fecha de envío no sea anterior a la fecha del pedido.
Referential integrity check (verificación de integridad referencial)
Una prueba de que cada valor de clave foránea coincide con un registro existente en la tabla relacionada.
Quarantine table (tabla de cuarentena)
Un área de retención para los registros que fallaron la validación, de modo que puedan revisarse sin llegar a los reportes.
Reconciliation (conciliación)
Comparar totales o conteos entre un destino y su origen para confirmar que nada se perdió ni se duplicó.
Master data (datos maestros)
Datos centrales y compartidos sobre entidades clave del negocio, como clientes, productos, proveedores y ubicaciones.
Transactional data (datos transaccionales)
Datos que registran eventos del negocio, como pedidos y pagos, y que hacen referencia a los datos maestros.
Master data management, MDM (gestión de datos maestros)
Los procesos, la gobernanza y las herramientas que crean y mantienen una versión única, consistente y oficial de los datos maestros.
Golden record (registro dorado)
El registro único, confiable y consolidado de una entidad que produce la MDM.
Survivorship rules (reglas de supervivencia)
Reglas que deciden qué valor de qué fuente se conserva en cada atributo cuando se fusionan registros coincidentes.
Fuzzy matching (coincidencia difusa)
Hacer coincidir registros mediante puntuaciones de similitud en lugar de igualdad exacta, para detectar variaciones de escritura o de formato.
Single source of truth (fuente única de verdad)
El principio de que cada elemento de datos tiene una fuente oficial que todos usan.
PII
Personally identifiable information (información de identificación personal): datos que pueden identificar a un individuo específico, directamente o en combinación con otros.
Direct identifier (identificador directo)
Un atributo, como un nombre o un número de identificación nacional, que identifica a una persona por sí solo.
Quasi-identifier (cuasi-identificador)
Un atributo, como la fecha de nacimiento o el código postal, que puede identificar a una persona al combinarse con otros.
PHI
Protected health information (información de salud protegida): información de salud identificable individualmente en poder de entidades cubiertas por HIPAA y de sus socios comerciales.
Primary account number, PAN (número de cuenta principal)
El número principal de una tarjeta de pago, que PCI DSS exige proteger cuando se almacena.
Sensitive authentication data (datos de autenticación sensibles)
Los datos completos de la banda o del chip, los códigos de verificación de la tarjeta y los PIN, que no deben almacenarse después de la autorización.
Data classification (clasificación de datos)
Asignar a los datos un nivel de sensibilidad (como público, interno, confidencial o restringido) que determina su manejo.
GDPR
El reglamento de la UE que regula el tratamiento de datos personales de personas en la UE, incluidos los derechos de los titulares de los datos y principios como la minimización.
Data minimization (minimización de datos)
El principio de recopilar y conservar solo los datos personales necesarios para un fin declarado.
Lawful basis (base legal)
La justificación legal que exige el GDPR para tratar datos personales, como el consentimiento, un contrato o los intereses legítimos.
HIPAA
La ley de EE. UU. que protege la información de salud identificable individualmente en poder de las entidades cubiertas y sus socios comerciales.
Minimum necessary standard (estándar del mínimo necesario)
El requisito de HIPAA de usar o divulgar solo la PHI necesaria para una tarea.
PCI DSS
Un estándar de seguridad de la industria, que se hace cumplir por contrato, para las organizaciones que almacenan, procesan o transmiten datos del titular de la tarjeta.
Data sovereignty (soberanía de datos)
El principio de que los datos están sujetos a las leyes del país en el que se encuentran.
Retention schedule (calendario de retención)
Una política que enumera cuánto tiempo se conserva cada tipo de registro, su base y cómo se elimina.
Legal hold (retención legal)
La obligación de preservar los datos relevantes para un litigio o una investigación, que suspende la eliminación normal.
Least privilege (mínimo privilegio)
Otorgar a los usuarios y sistemas solo el acceso mínimo necesario para hacer su trabajo.
Role-based access control, RBAC (control de acceso basado en roles)
Asignar permisos a roles y dar acceso a los usuarios asignándoles roles.
Row-level security (seguridad a nivel de fila)
Restringir qué filas puede ver un usuario, por ejemplo solo los registros de su propia región.
Data masking (enmascaramiento de datos)
Ocultar los valores sensibles con sustitutos realistas o valores parciales, manteniendo los datos utilizables.
Dynamic masking (enmascaramiento dinámico)
Enmascarar los valores en el momento de la consulta para los usuarios no autorizados, mientras los datos almacenados permanecen sin cambios.
Pseudonymization (seudonimización)
Reemplazar los identificadores por valores artificiales que pueden volver a vincularse usando una clave guardada por separado.
Anonymization (anonimización)
Eliminar de forma irreversible de los datos la capacidad de identificar a las personas.
Encryption at rest (cifrado en reposo)
Cifrar los datos almacenados para que sean ilegibles sin la clave si se accede al almacenamiento.
Hashing
Una función unidireccional que produce un valor de longitud fija, usada para verificaciones de integridad y comparaciones, sin clave de descifrado.
Data life cycle (ciclo de vida de los datos)
Las etapas por las que pasan los datos: recolección, almacenamiento, uso, intercambio, archivado y destrucción.
Data sharing agreement (acuerdo de intercambio de datos)
Un contrato que define cómo la parte receptora puede usar, debe proteger y debe eliminar los datos compartidos.
Archiving (archivado)
Trasladar los datos inactivos que deben conservarse a un almacenamiento de largo plazo, de menor costo y con acceso restringido.
Secure disposal (eliminación segura)
Destruir permanentemente los datos al final de su periodo de retención para que no puedan recuperarse.
Cryptographic erasure (borrado criptográfico)
Hacer irrecuperables los datos cifrados destruyendo sus claves de cifrado.
Degaussing (desmagnetización)
Borrar medios magnéticos exponiéndolos a un campo magnético fuerte.
Certificate of destruction (certificado de destrucción)
Un documento que confirma que ciertos datos o medios se destruyeron de forma segura.
