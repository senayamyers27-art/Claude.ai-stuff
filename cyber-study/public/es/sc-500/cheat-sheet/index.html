Dominio 1: Manage identity, access, and governance (24%)

Consejos para el examen

  • Si la pregunta trata de usuarios, grupos, aplicaciones o configuración del tenant, la respuesta es un rol de Entra; si trata de suscripciones o recursos, es un rol de Azure RBAC. Solo Owner, User Access Administrator y Role Based Access Control Administrator (entre los integrados) pueden asignar roles de Azure; Contributor no puede.
  • Las preguntas suelen evaluar que NotActions no es una denegación y que leer datos en una cuenta de almacenamiento necesita un rol con DataActions, no Contributor. Atento también a un rol que no se puede asignar porque el ámbito de destino está fuera de sus AssignableScopes.
  • Elegible es 'puede activarlo', activo es 'lo tiene ahora'. Si una pregunta plantea cómo quitar el acceso de administrador permanente y conservar la capacidad de hacer tareas de administración, la respuesta es convertir las asignaciones activas permanentes en elegibles en PIM.
  • Recuerda la lógica de evaluación: se aplican todas las directivas que coinciden, el bloqueo siempre gana y las exclusiones prevalecen sobre las inclusiones. Si un escenario advierte sobre dejar a todos sin acceso, la respuesta suele incluir el modo solo informe, What If y las exclusiones de cuentas de emergencia.
  • Si la pregunta pide protección contra el phishing o la fatiga de MFA, 'exigir MFA' no basta; elige la fuerza de autenticación resistente al phishing con FIDO2/passkeys, Windows Hello for Business o la autenticación basada en certificados. SMS y voz nunca son resistentes al phishing.
  • Si varios recursos deben compartir una identidad, o la identidad debe sobrevivir a la eliminación del recurso, elige asignada por el usuario. Si el escenario dice 'sin credenciales almacenadas en el código ni en la configuración', la respuesta es una identidad administrada más un rol de RBAC en el destino.
  • Los permisos de aplicación necesitan consentimiento de administrador, sin excepción. Cuando la pregunta es '¿dónde restrinjo quién puede iniciar sesión en esta aplicación o se la asigno a usuarios?', la respuesta es Enterprise applications (la entidad de servicio), no App registrations.
  • Contributor en un almacén no concede acceso a los secretos en el modelo RBAC, pero en el modelo de directivas de acceso un Contributor puede agregarse una directiva. Si los datos deben protegerse contra la eliminación permanente, la respuesta es la protección contra purga, no solo la eliminación temporal.
  • Deny lo detiene, Audit lo informa, Modify y DeployIfNotExists lo corrigen, y los recursos existentes necesitan una tarea de corrección más una identidad administrada. Para una excepción temporal y documentada, elige una exención con fecha de vencimiento.
  • Los bloqueos prevalecen sobre RBAC para todos, incluidos los Owner, pero solo para las operaciones de administración, no para los datos. Si una pregunta dice que los usuarios todavía pueden eliminar blobs a pesar de un bloqueo, ese es el comportamiento esperado.
  • El riesgo de inicio de sesión corresponde a 'exigir MFA'; el riesgo de usuario corresponde a 'exigir cambio de contraseña'. Credenciales filtradas es una detección de riesgo de usuario, mientras que IP anónima y viaje atípico son detecciones de riesgo de inicio de sesión.

Términos clave

Microsoft Entra role (rol de Microsoft Entra)
Rol de directorio que otorga permisos sobre objetos de identidad y la configuración del tenant, como User Administrator o Security Administrator.
Azure RBAC role (rol de Azure RBAC)
Definición de rol que otorga permisos sobre recursos de Azure mediante Azure Resource Manager, como Owner, Contributor o Reader.
Scope (ámbito)
Nivel en el que se aplica una asignación de rol: grupo de administración, suscripción, grupo de recursos o recurso; los niveles inferiores la heredan.
User Access Administrator
Rol de Azure RBAC que puede administrar asignaciones de roles, pero no los recursos en sí.
Role assignment (asignación de rol)
Combinación de una entidad de seguridad, una definición de rol y un ámbito que otorga acceso.
Least privilege (mínimo privilegio)
Otorgar solo los permisos necesarios, en el ámbito más reducido y durante el menor tiempo posible.
Actions
Operaciones del plano de control que permite el rol, como crear o reiniciar una VM.
NotActions
Operaciones que se quitan del comodín de Actions solo para este rol; no es una denegación si otro rol las otorga.
DataActions
Operaciones del plano de datos que permite el rol, como leer blobs o secretos de Key Vault.
NotDataActions
Operaciones del plano de datos que se quitan de un comodín de DataActions solo para este rol.
AssignableScopes (ámbitos asignables)
Los grupos de administración, suscripciones o grupos de recursos donde se puede asignar un rol personalizado.
Eligible assignment (asignación elegible)
Asignación de PIM que permite a un usuario activar un rol cuando lo necesita; no otorga permisos hasta que se activa.
Active assignment (asignación activa)
Asignación de rol cuyos permisos están vigentes en este momento, de forma permanente o por un tiempo establecido.
Activation (activación)
Paso justo a tiempo en el que un usuario elegible activa un rol, sujeto a la configuración de MFA, justificación, ticket o aprobación.
Role settings (configuración del rol)
Configuración de PIM por rol, como la duración máxima de la activación y los requisitos de MFA o contexto de autenticación, justificación, ticket y aprobación.
Access review (revisión de acceso)
Comprobación programada en la que los revisores confirman o quitan el acceso continuo de los usuarios a un rol, grupo o aplicación.
Conditional Access policy (directiva de Conditional Access)
Regla si-entonces de Entra ID que evalúa señales del inicio de sesión y aplica controles de concesión o de sesión.
Workload identity (identidad de carga de trabajo)
Entidad de servicio u otra identidad no humana a la que se puede dirigir Conditional Access con licencias de Workload Identities Premium.
Grant control (control de concesión)
Parte de una directiva que bloquea el acceso o lo concede solo si se cumplen requisitos como MFA o un dispositivo compatible.
Session control (control de sesión)
Control que limita la sesión después de conceder el acceso, como la frecuencia de inicio de sesión o las restricciones aplicadas por la aplicación.
Named location (ubicación con nombre)
Conjunto de intervalos IP o países que se usa como condición; las ubicaciones basadas en IP se pueden marcar como de confianza.
Report-only mode (modo solo informe)
Estado de una directiva que registra lo que ocurriría sin aplicar la directiva.
Authentication methods policy (directiva de métodos de autenticación)
Directiva de Entra ID que habilita o deshabilita cada método de inicio de sesión para todos los usuarios o para grupos seleccionados.
Phishing-resistant MFA (MFA resistente al phishing)
Métodos vinculados criptográficamente al sitio legítimo, como las llaves FIDO2, las passkeys, Windows Hello for Business y la autenticación basada en certificados.
Passkey
Credencial FIDO2 almacenada en una clave de seguridad o un dispositivo que inicia sesión con una clave privada desbloqueada por PIN o biometría.
Authentication strength (fuerza de autenticación)
Control de concesión de Conditional Access que exige combinaciones específicas de métodos, como la fuerza integrada Phishing-resistant MFA.
Temporary Access Pass
Código de acceso con límite de tiempo que se usa para registrar o recuperar métodos fuertes sin contraseña.
Number matching (coincidencia de números)
Función de Authenticator en la que el usuario escribe un número que aparece en la pantalla de inicio de sesión, lo que reduce las aprobaciones accidentales.
Managed identity (identidad administrada)
Identidad de Entra para un recurso de Azure cuyas credenciales Azure administra y rota automáticamente.
System-assigned identity (identidad asignada por el sistema)
Identidad administrada creada en un recurso y ligada a su ciclo de vida.
User-assigned identity (identidad asignada por el usuario)
Recurso de identidad administrada independiente que se puede asociar a muchos recursos y persiste por su cuenta.
IMDS
Azure Instance Metadata Service, en 169.254.169.254, que las VM usan para solicitar tokens de identidad administrada.
DefaultAzureCredential
Clase de la biblioteca Azure Identity que prueba varios orígenes de credenciales, incluida la identidad administrada, para obtener tokens sin secretos en el código.
Application object (objeto de aplicación)
Definición global de la aplicación en su tenant de origen, que se administra en App registrations.
Service principal (entidad de servicio)
Instancia local de una aplicación en un tenant, que se administra en Enterprise applications y recibe consentimiento y asignaciones.
Delegated permission (permiso delegado)
Permiso que una aplicación usa en nombre de un usuario que inició sesión, limitado por el propio acceso de ese usuario.
Application permission (permiso de aplicación)
Permiso solo de aplicación que se usa sin un usuario con sesión iniciada; siempre necesita consentimiento de administrador.
Admin consent workflow (flujo de trabajo de consentimiento de administrador)
Proceso que permite a los usuarios pedir la aprobación de un administrador para aplicaciones a las que no pueden dar su consentimiento.
Illicit consent grant (concesión de consentimiento ilícita)
Ataque que engaña a un usuario para que conceda a una aplicación maliciosa permisos sobre sus datos.
Access policy model (modelo de directivas de acceso)
Autorización heredada del plano de datos de Key Vault que concede conjuntos de permisos para todo el almacén a cada entidad de seguridad.
Key Vault RBAC
Autorización del plano de datos con roles de Azure como Key Vault Secrets User, que se puede limitar a un solo secreto.
Soft delete (eliminación temporal)
Mantiene recuperables los almacenes y objetos eliminados durante un período de retención de 7 a 90 días.
Purge protection (protección contra purga)
Impide la eliminación permanente hasta que pase el período de retención; no se puede deshabilitar una vez habilitada.
Key rotation policy (directiva de rotación de claves)
Programación que crea automáticamente nuevas versiones de una clave y puede avisar antes del vencimiento.
Defender for Key Vault
Plan de Microsoft Defender for Cloud que alerta sobre accesos inusuales o sospechosos a los almacenes de claves.
Policy definition (definición de directiva)
Regla en JSON con una condición y un efecto que describe las configuraciones de recursos permitidas.
Initiative (iniciativa)
Grupo de definiciones de directiva que se asignan y se informan juntas, también llamado conjunto de directivas (policy set).
DeployIfNotExists
Efecto que implementa un recurso o una configuración relacionada que falta mediante una plantilla.
Modify
Efecto que agrega, cambia o quita propiedades o etiquetas de un recurso durante la creación o actualización.
Remediation task (tarea de corrección)
Trabajo que aplica Modify o DeployIfNotExists a recursos que ya existían antes de la asignación.
Exemption (exención)
Registro que excluye un recurso o ámbito de una asignación, con categoría Waiver o Mitigated y, opcionalmente, con límite de tiempo.
CanNotDelete lock (bloqueo CanNotDelete)
Bloqueo que permite lecturas y actualizaciones, pero impide eliminar el recurso y sus elementos secundarios.
ReadOnly lock (bloqueo ReadOnly)
Bloqueo que impide tanto las actualizaciones como la eliminación y solo permite operaciones de lectura.
Management group (grupo de administración)
Contenedor por encima de las suscripciones cuyas asignaciones de RBAC y de directivas heredan todas las suscripciones que tiene debajo.
Root management group (grupo de administración raíz)
El único grupo de administración de nivel superior de cada tenant, que contiene a todos los demás.
Azure landing zone (zona de aterrizaje de Azure)
Arquitectura de referencia de Microsoft que organiza grupos de administración y suscripciones con salvaguardas integradas.
Sign-in risk (riesgo de inicio de sesión)
Probabilidad de que una solicitud de autenticación concreta no la haya hecho el usuario legítimo.
User risk (riesgo de usuario)
Probabilidad de que una identidad esté comprometida, por ejemplo porque se filtraron sus credenciales.
Risk-based Conditional Access (Conditional Access basado en riesgo)
Directivas que exigen MFA o un cambio de contraseña seguro según el nivel de riesgo de inicio de sesión o de usuario.
Auto-apply results (aplicación automática de resultados)
Opción de una revisión de acceso que quita automáticamente el acceso a los usuarios rechazados cuando termina la revisión.

Dominio 2: Secure storage, databases, and networking (28%)

Consejos para el examen

  • Owner o Contributor por sí solos no dan acceso a los datos con Entra, pero sí permiten enumerar las claves, lo que da acceso completo a los datos. La respuesta más segura para el almacenamiento casi siempre es Entra ID con un rol de datos y Shared Key deshabilitada.
  • SAS más segura: user delegation. Revocar una SAS de servicio sin rotar claves: directiva de acceso almacenada. Revocar una SAS ad hoc firmada con clave: regenerar la clave que la firmó. La account SAS y la user delegation SAS no pueden usar directivas de acceso almacenadas, y cada contenedor admite hasta cinco directivas.
  • El cifrado de infraestructura solo puede habilitarse al crear la cuenta. Una directiva de retención basada en tiempo bloqueada no puede acortarse ni quitarse, solo ampliarse. CMK necesita eliminación temporal y protección de purga en el almacén y una identidad administrada con permisos para obtener, envolver y desenvolver. Conservación sin fecha de fin significa retención legal.
  • Los intervalos de IP privadas no pueden añadirse al firewall de IP de Storage; usa reglas de VNet o private endpoints. Si un servicio de Microsoft como Azure Backup falla después de cerrar el firewall, la solución es la excepción de servicios de confianza o una regla de instancia de recurso. Los resultados del análisis de malware quedan como etiquetas de índice del blob.
  • Ocultar datos a los DBA: Always Encrypted. Ocultar datos en los resultados a usuarios con pocos privilegios: enmascaramiento dinámico de datos. Proteger discos y copias de seguridad: TDE. Controlar tú la clave: TDE con CMK. Eliminar los inicios de sesión con contraseña: autenticación solo con Entra. Reglas que viajan con una base de datos replicada geográficamente: reglas de firewall a nivel de base de datos.
  • Gana el número de prioridad más bajo y la evaluación se detiene en la primera coincidencia. Las reglas predeterminadas permiten todo el tráfico de VNet a VNet, así que la microsegmentación dentro de una VNet necesita reglas de denegación explícitas con números de prioridad inferiores a 65 000. Entrada: subred y luego NIC; salida: NIC y luego subred.
  • El orden es: reglas de administrador de seguridad y luego NSG. Un Deny en la capa de administración no puede anularse; Allow sigue dejando que los NSG denieguen; Always Allow omite por completo los NSG. Elige AVNM cuando una pregunta pida imponer de forma central reglas que los equipos locales no puedan saltarse, y grupos de red dinámicos cuando las VNet nuevas deban quedar cubiertas automáticamente.
  • Acceso local, una IP privada, alcance por recurso y protección contra la exfiltración apuntan a private endpoints. Acceso gratuito, sencillo y a nivel de subred conservando la IP pública apunta a service endpoints. Si un private endpoint 'no funciona', sospecha primero del DNS: la zona, el registro A y el vínculo con la VNet.
  • Inspección TLS, IDPS y filtrado de URL completo significan Premium. Un firewall sin una UDR 0.0.0.0/0 en las subredes radiales no inspecciona nada. El orden de las reglas es DNAT, red, aplicación. La tunelización forzada requiere AzureFirewallManagementSubnet. Línea base central más añadidos locales: directivas de firewall principal y secundarias.
  • Global, perímetro, varias regiones: WAF en Front Door. Regional, en una VNet: WAF en Application Gateway. Inundaciones de capa 3/4: DDoS Protection. Las reglas personalizadas se procesan antes que las administradas, y el modo Detection nunca bloquea. La limitación de velocidad está en las reglas personalizadas.
  • Una sede completa hacia Azure: sitio a sitio. Laptops individuales: punto a sitio (con autenticación de Entra para MFA y acceso condicional, solo con OpenVPN). Inspección central del tráfico de Virtual WAN: hub protegido con intención de enrutamiento. Acceso por aplicación sin VPN a nivel de red: Entra Private Access. Las puertas de enlace VPN van en GatewaySubnet.
  • ¿Se permite un paquete concreto y qué regla lo decidió? IP flow verify. ¿Qué reglas están vigentes en una NIC? Reglas de seguridad efectivas. ¿Hacia dónde va el tráfico? Next hop. ¿Qué tráfico circuló en el pasado? Registros de flujo con análisis de tráfico. Prefiere los registros de flujo de VNet a los registros de flujo de NSG.

Términos clave

Data-plane RBAC (RBAC del plano de datos)
Roles de Azure, como Storage Blob Data Reader, que autorizan el acceso a los datos dentro de una cuenta de almacenamiento.
Account access key (clave de acceso de la cuenta)
Una de las dos claves que otorgan acceso completo a todos los datos de una cuenta de almacenamiento mediante la autorización con Shared Key.
allowSharedKeyAccess
Propiedad de la cuenta de almacenamiento que, cuando es false, rechaza las solicitudes autorizadas con claves de cuenta o con SAS firmadas con claves.
Key expiration policy (directiva de vencimiento de claves)
Opción de la cuenta de almacenamiento que señala las claves de cuenta que no se rotaron dentro de un número determinado de días.
User delegation SAS (SAS de delegación de usuario)
Firma de acceso compartido firmada con credenciales de Entra en lugar de una clave de cuenta, por lo que sigue funcionando cuando Shared Key está deshabilitada.
Shared access signature (SAS) (firma de acceso compartido)
Un token firmado en la cadena de consulta de una URL que concede acceso acotado y con tiempo limitado a recursos de almacenamiento.
Service SAS (SAS de servicio)
Una SAS firmada con una clave de cuenta que concede acceso a recursos de un único servicio de almacenamiento.
Account SAS (SAS de cuenta)
Una SAS firmada con clave que puede abarcar varios servicios y operaciones de nivel de servicio.
Stored access policy (directiva de acceso almacenada)
Una directiva con nombre en un contenedor, cola, tabla o recurso compartido a la que pueden hacer referencia los tokens de SAS de servicio, lo que permite cambiarlos o revocarlos de forma centralizada.
SAS expiration policy (directiva de caducidad de SAS)
Una configuración de la cuenta que define una validez máxima recomendada para las SAS y registra los tokens que la superan.
Azure Storage encryption (cifrado de Azure Storage)
Cifrado AES de 256 bits en reposo, siempre activado, para todos los datos de Azure Storage.
Customer-managed key (clave administrada por el cliente)
Una clave en Key Vault o Managed HSM que envuelve las claves de cifrado de datos de la cuenta de almacenamiento bajo tu control.
Envelope encryption (cifrado de sobre)
Cifrar los datos con una clave de datos y luego cifrar esa clave de datos con una clave de cifrado de claves independiente.
Infrastructure encryption (cifrado de infraestructura)
Una segunda capa de cifrado independiente que solo se habilita al crear la cuenta de almacenamiento.
Time-based retention policy (directiva de retención basada en tiempo)
Una directiva de inmutabilidad que impide eliminar y modificar blobs durante un intervalo definido; una vez bloqueada, solo puede ampliarse.
Legal hold (retención legal)
Una configuración de inmutabilidad que conserva los datos indefinidamente hasta que se quita la etiqueta de retención.
Storage firewall (firewall de Storage)
Reglas de red que restringen qué subredes, intervalos de IP públicas o private endpoints pueden llegar a una cuenta de almacenamiento.
Trusted services exception (excepción de servicios de confianza)
Una configuración del firewall que permite que los servicios de Azure de la lista, como Azure Backup, omitan las reglas de red.
Resource instance rule (regla de instancia de recurso)
Una regla de firewall que permite que una instancia de recurso de Azure específica, identificada por su identidad administrada, acceda a la cuenta.
Activity monitoring (supervisión de actividad)
Análisis de las operaciones que hace Defender for Storage para alertar sobre patrones de acceso sospechosos.
Malware scanning (análisis de malware)
Una función de Defender for Storage que analiza los blobs cargados en busca de malware y etiqueta o alerta según los resultados.
Sensitive data threat detection (detección de amenazas a datos confidenciales)
Priorización de Defender for Storage que usa los tipos de información confidencial de Purview para señalar amenazas a cuentas que contienen datos confidenciales.
Microsoft Entra-only authentication (autenticación solo con Microsoft Entra)
Una configuración del servidor que deshabilita la autenticación SQL para que solo las identidades de Entra puedan iniciar sesión.
TDE
Transparent data encryption (cifrado de datos transparente), que cifra en reposo los archivos de base de datos, los registros y las copias de seguridad.
TDE protector (protector de TDE)
La clave, administrada por el servicio o por el cliente en Key Vault, que protege las claves de cifrado de las bases de datos de un servidor.
Always Encrypted
Cifrado de columnas del lado del cliente que mantiene el texto sin cifrar oculto al motor de base de datos y a sus administradores.
Dynamic data masking (enmascaramiento dinámico de datos)
Una directiva que ofusca los valores de columna en los resultados de las consultas para usuarios sin el permiso UNMASK.
Database-level firewall rule (regla de firewall a nivel de base de datos)
Una regla de IP almacenada en una base de datos que se aplica solo a esa base de datos.
Network security group (grupo de seguridad de red)
Un conjunto con estado de reglas de permitir y denegar que se aplica a subredes o NIC.
Rule priority (prioridad de regla)
Un número de 100 a 4096; los números más bajos se procesan primero y gana la primera coincidencia.
Default rules (reglas predeterminadas)
Reglas que no se pueden eliminar, con prioridades de 65 000 a 65 500, que permiten el tráfico de la VNet y del equilibrador de carga, permiten la salida a internet y deniegan todo lo demás.
Service tag (etiqueta de servicio)
Una etiqueta mantenida por Microsoft que representa los prefijos IP de un servicio o categoría de Azure, como Storage o Internet.
Application security group (grupo de seguridad de aplicaciones)
Una agrupación lógica de NIC que se usa como origen o destino en reglas de NSG en lugar de direcciones IP.
Azure Virtual Network Manager
Un servicio central que agrupa redes virtuales y les implementa configuraciones de conectividad y seguridad a escala.
Network group (grupo de red)
Un conjunto estático o dinámico (basado en directivas) de redes virtuales al que se dirigen las configuraciones de AVNM.
Security admin rule (regla de administrador de seguridad)
Una regla administrada de forma central que se evalúa antes que los NSG, con acciones Allow, Deny o Always Allow.
Always Allow
Una acción de administrador de seguridad que permite el tráfico y omite para él la evaluación de los NSG.
Deployment (implementación)
El paso que confirma una configuración de AVNM en las regiones seleccionadas; nada cambia hasta que se confirma.
Service endpoint (punto de conexión de servicio)
Una configuración de subred que enruta el tráfico hacia un servicio de Azure por la red troncal y permite que el firewall del servicio admita esa subred; el servicio conserva su IP pública.
Service endpoint policy (directiva de service endpoint)
Una directiva que limita a qué cuentas de almacenamiento concretas puede llegar una subred con service endpoint.
Private endpoint (punto de conexión privado)
Una NIC con una IP privada en tu subred asignada a un recurso específico mediante Private Link.
Private Link service
Tu propio servicio detrás de un Standard Load Balancer, expuesto a los consumidores mediante private endpoints.
Private DNS zone (zona DNS privada)
Una zona de Azure DNS, como privatelink.blob.core.windows.net, que resuelve los nombres de servicio a las IP de los private endpoints para las VNet vinculadas.
Azure DNS Private Resolver
Un servicio administrado que permite que el DNS local reenvíe consultas a las zonas DNS privadas de Azure.
DNAT rule (regla DNAT)
Una regla de Azure Firewall que traduce el tráfico de entrada en la IP pública del firewall a una dirección y un puerto privados.
Application rule (regla de aplicación)
Una regla de Azure Firewall que permite o deniega el tráfico saliente por FQDN o etiqueta FQDN.
TLS inspection (inspección TLS)
Una función Premium que descifra y vuelve a cifrar el tráfico HTTPS usando un certificado de CA intermedia desde Key Vault.
IDPS
Detección y prevención de intrusiones basada en firmas en Azure Firewall Premium.
Firewall policy (directiva de firewall)
Un recurso que contiene las reglas y la configuración del firewall, reutilizable entre firewalls y con herencia primaria-secundaria.
User-defined route (ruta definida por el usuario)
Una ruta personalizada, como 0.0.0.0/0 hacia la IP privada del firewall, que invalida las rutas del sistema de Azure.
Web application firewall (firewall de aplicaciones web)
Un filtro de capa 7 que inspecciona las solicitudes HTTP en busca de ataques como inyección SQL y cross-site scripting.
Managed rule set (conjunto de reglas administrado)
Reglas de WAF mantenidas por Microsoft basadas en el OWASP Core Rule Set o en el Microsoft Default Rule Set.
Custom rule (regla personalizada)
Una regla de WAF definida por el usuario, evaluada antes que las reglas administradas, que coincide con condiciones como IP, geografía o velocidad.
Detection mode (modo de detección)
Un modo de WAF que registra las coincidencias de reglas sin bloquear las solicitudes.
Anomaly scoring (puntuación de anomalías)
Un método de WAF en el que las reglas que coinciden suman a una puntuación y las solicitudes solo se bloquean por encima de un umbral.
DDoS Network Protection
El nivel de pago de Azure DDoS que agrega ajuste adaptativo, telemetría, respuesta rápida y protección de costos para los recursos de una VNet.
Site-to-site VPN (VPN de sitio a sitio)
Un túnel IPsec/IKE que conecta el dispositivo VPN de una red local con una puerta de enlace VPN de Azure.

Un objeto de Azure que representa la IP pública y los prefijos de direcciones del dispositivo VPN local.

Una VPN desde dispositivos cliente individuales hacia una red virtual de Azure usando OpenVPN, IKEv2 o SSTP.

Un hub de Virtual WAN con Azure Firewall administrado por Firewall Manager, con routing intent para inspeccionar el tráfico.
ZTNA

IP flow verify
Una herramienta de Network Watcher que comprueba si un paquete específico se permite o se deniega hacia o desde una VM y nombra la regla que decide.

Traffic analytics (análisis de tráfico)
Una función que agrega y enriquece los registros de flujo en Log Analytics para paneles, consultas e información sobre amenazas.

Dominio 3: Secure compute (24%)

Consejos para el examen

  • Conoce la pareja: Prompt Shields es la capa de prevención dentro de la ruta de la solicitud (filtrado de contenido); Defender for AI services es la capa de detección que genera alertas de seguridad. Los prompts de los usuarios traen jailbreaks; los documentos traen inyecciones indirectas. La postura de los recursos de IA viene de Defender CSPM.
  • Copilot nunca concede acceso nuevo; expone los permisos excesivos que ya existen. Cuando una pregunta plantea cómo encontrar contenido sobrecompartido antes de implementar Copilot, elige las evaluaciones de riesgo de datos de DSPM for AI. Cuando plantea cómo impedir que se peguen datos confidenciales en sitios de IA para consumidores, elige la directiva DLP que ofrece DSPM for AI.
  • La autenticación de APIM al modelo usa la identidad administrada de APIM más un rol de RBAC, lo que te permite deshabilitar las claves de API del modelo. La protección contra el uso excesivo es la directiva de límite de tokens (429 al excederlo); la visibilidad del uso es la directiva de métricas de tokens más Application Insights y Log Analytics.
  • La respuesta a '¿cómo gobernamos a los agentes de IA?' refleja la gobernanza de identidades de carga de trabajo: una identidad única por agente, un propietario responsable, permisos de mínimo privilegio, directivas de Conditional Access y de riesgo, y revisiones de acceso. Evita las respuestas que comparten las credenciales de un humano con un agente.
  • Cubrir el disco temporal y la caché sin un agente dentro del invitado significa cifrado en el host. El control de las claves por parte del cliente para los discos administrados significa un conjunto de cifrado de disco. BitLocker o DM-Crypt dentro del invitado significa Azure Disk Encryption, que es la opción heredada.
  • Componentes de arranque firmados: Secure Boot. Claves y mediciones: vTPM. Detectar una cadena de arranque manipulada: supervisión de la integridad del arranque mediante Guest Attestation y Defender for Cloud. Trusted launch requiere VM Gen2; cifrar la memoria en uso corresponde a las VM confidenciales, no a trusted launch.
  • Sin IP públicas en las VM y RDP/SSH desde el navegador por el puerto 443: Azure Bastion en AzureBastionSubnet. Puertos cerrados hasta una solicitud aprobada y con tiempo limitado: JIT, que necesita Defender for Servers Plan 2.
  • JIT, la supervisión de la integridad de archivos y el análisis sin agente son funciones de Plan 2. Los servidores que no son de Azure necesitan Azure Arc antes de que Defender for Servers, Policy o Update Manager puedan administrarlos. El escáner de vulnerabilidades integrado es Microsoft Defender Vulnerability Management.
  • Las directivas de red necesitan un motor de directivas de red habilitado en el clúster, que normalmente se elige al crearlo. Deshabilitar las cuentas locales es lo que obliga a que todo el acceso pase por Entra. La aplicación de Gatekeeper en el clúster es Azure Policy para AKS; la detección de amenazas y el análisis de imágenes es Defender for Containers.
  • El acceso en tiempo de ejecución con mínimo privilegio es AcrPull; las canalizaciones necesitan AcrPush. Los private endpoints y las reglas de firewall requieren la SKU Premium. El análisis de CVE de las imágenes proviene de Defender for Containers, no de ACR por sí solo.
  • Las referencias de Key Vault necesitan una identidad administrada con acceso de lectura a los secretos, y los almacenes con restricciones de red necesitan la integración con VNet. El filtrado de entrada se hace con restricciones de acceso o private endpoints; el alcance de salida hacia una VNet es la integración con VNet. Proteger una aplicación sin cambios en el código apunta a Easy Auth.

El permiso de administración de derechos que Copilot necesita para usar, en nombre de un usuario, el contenido de un elemento cifrado y etiquetado.

El conjunto de capacidades de Azure API Management para gobernar y proteger el acceso a los endpoints de modelos de IA.

Una directiva de APIM que comprueba el token de Microsoft Entra de un llamador antes de reenviar la solicitud.

Capacidades de Entra que dan a los agentes de IA sus propias identidades de directorio para inventario, control de acceso y protección.

Una identidad de directorio que representa a un agente de IA específico, distinta de los usuarios y de los service principals de aplicaciones comunes.

Una plantilla a partir de la cual se crean identidades de agente, que define la configuración y los permisos compartidos.

Permisos que un agente usa en nombre de un usuario que inició sesión, limitados tanto por los permisos concedidos como por el propio acceso del usuario.

Azure Arc-enabled server (servidor habilitado para Azure Arc)

Azure Update Manager

Agentless scanning (análisis sin agente)

Uso de asignaciones de roles de Azure, en el ámbito del clúster o del espacio de nombres, para autorizar acciones de la API de Kubernetes.

Dominio 4: Manage and monitor security posture (24%)

Consejos para el examen

  • El nivel gratuito da recomendaciones, puntuación de seguridad y cumplimiento con el MCSB; el análisis de rutas de ataque, el cloud security explorer, las reglas de gobernanza y el análisis sin agente requieren Defender CSPM. Todos los puntos de un control solo se obtienen cuando cada recurso afectado está en buen estado.
  • Cadenas de extremo a extremo automáticas y priorizadas: análisis de rutas de ataque. Tu propia pregunta puntual sobre el grafo: cloud security explorer. Análisis basado en instantáneas sin agentes: análisis sin agente. Responsables y fechas límite: reglas de gobernanza. Todas requieren Defender CSPM, no la CSPM básica.
  • MCSB es el estándar predeterminado e impulsa la puntuación de seguridad. Los demás estándares regulatorios se agregan en Environment settings y generalmente requieren Defender CSPM. En Azure, los estándares se implementan como iniciativas de Azure Policy. Un control se aprueba solo cuando todas sus evaluaciones están en buen estado, falla cuando cualquiera falla y es manual cuando no existe ninguna. Un panel en verde no es una certificación.
  • Los planes se habilitan por suscripción en la página Defender plans; habilítalos a nivel de suscripción para cubrir los recursos futuros. Relaciona cada amenaza con su plan. Usa reglas de supresión para las alertas benignas conocidas, manteniéndolas acotadas y con vencimiento; la automatización de flujos de trabajo para responder; las notificaciones por correo para avisar a las personas; y las alertas de ejemplo para probar. Las alertas también aparecen como incidentes en el portal de Defender.
  • La incorporación de AWS usa una plantilla de CloudFormation; la de GCP usa un script de Cloud Shell o Terraform; ambas evitan las claves de larga duración mediante federación. La protección completa de servidores en otras nubes depende de Azure Arc. Las reacciones automáticas a alertas, recomendaciones o cambios de cumplimiento de Defender for Cloud son automatización de flujos de trabajo con Logic Apps, y el usuario que la configura necesita derechos sobre la Logic App.
  • Por defecto, usa una sola área de trabajo, salvo que la residencia de datos, los límites de inquilino o la facturación obliguen a usar más. AMA más DCR es el método de recopilación; el agente heredado está retirado. CEF va a CommonSecurityLog a través de un reenviador Linux; los eventos de seguridad de Windows van a SecurityEvent; Syslog va a Syslog. Las transformaciones de DCR filtran los datos antes de la ingesta y son tu principal palanca de costo.
  • Detección más rápida para una condición sencilla: NRT. Correlación compleja o umbrales: programada, con un lookback un poco más largo que la programación. Convertir las alertas de otros productos de Microsoft en incidentes: reglas de seguridad de Microsoft, pero deshabilítalas cuando la integración de incidentes de Defender XDR esté activa para evitar duplicados. Las anomalías van a la tabla Anomalies. Sin asignación de entidades, la automatización y los gráficos de investigación no tienen sobre qué actuar.
  • Acciones sencillas de clasificación (asignar, etiquetar, cerrar, fijar la gravedad, agregar tareas) sin código: reglas de automatización. Acciones que involucran sistemas externos o aprobaciones: playbooks, normalmente iniciados por una regla de automatización, con el rol Automation Contributor concedido a Sentinel. Paneles: workbooks. Búsquedas proactivas: hunting, con marcadores. Listas de búsqueda: watchlists mediante _GetWatchlist. IoC: inteligencia de amenazas.
  • Las reglas de detección y en tiempo real necesitan datos del nivel Analytics. Los datos de gran volumen y poco consultados corresponden a un nivel de menor costo, como el data lake o los registros auxiliares o básicos, con resúmenes promovidos a Analytics. La retención a largo plazo dura hasta 12 años y requiere un trabajo de búsqueda o una restauración para consultarla. Las tablas personalizadas terminan en _CL. En KQL, filtra primero por tiempo.
  • Copilot no elude los permisos: un usuario solo ve los datos a los que ya tiene acceso. La capacidad son las SCU, compartidas por el uso independiente y el integrado, con excedente opcional. Los propietarios administran los plugins y la configuración; los colaboradores lo usan; los Global Administrator y Security Administrator de Entra son propietarios de forma predeterminada. Los prompts reutilizables de varios pasos son promptbooks. Los agentes actúan con su propia identidad y necesitan gobernanza.
  • Determinar qué correos leyó un atacante depende de MailItemsAccessed (originalmente solo de Premium, ahora también en Audit Standard); los eventos de consultas de búsqueda siguen siendo de Premium. La retención más larga y las directivas de retención personalizadas son funciones de Premium. Buscar requiere un rol Audit Logs; Search-UnifiedAuditLog es el cmdlet de PowerShell; llevar los datos de auditoría a Sentinel usa el conector de Microsoft 365 (tabla OfficeActivity).

La vista de Defender for Cloud que asigna las evaluaciones automatizadas a los controles de los estándares seleccionados y muestra el estado aprobado, fallido o manual.

Un conjunto definido por el usuario de recomendaciones integradas o personalizadas, agrupado como estándar para su seguimiento.

Un control sin evaluación automatizada que requiere certificación humana y evidencia.
Cloud workload protection (protección de cargas de trabajo en la nube)
Detección de amenazas en tiempo de ejecución para tipos de recursos específicos, proporcionada mediante los planes de Defender for Cloud.
Defender plan (plan de Defender)
Un plan de protección de pago, como Defender for Servers o Defender for Key Vault, que se habilita por suscripción en la página Defender plans.
Security alert (alerta de seguridad)
Una detección de actividad sospechosa con gravedad, evidencia, tácticas de MITRE ATT&CK, recursos afectados e indicaciones de respuesta.

Una regla que descarta automáticamente las alertas que cumplen condiciones definidas, usada para actividad benigna conocida e idealmente con fecha de vencimiento.

Alertas de prueba generadas a petición para validar las notificaciones y la automatización sin un ataque real.

Un grupo de alertas correlacionadas que, en conjunto, describen un mismo ataque.
Multicloud connector (conector multinube)
Un recurso de Defender for Cloud en Azure que incorpora una cuenta u organización de AWS, o un proyecto u organización de GCP, para la evaluación de la postura y la protección.

La plantilla de despliegue de AWS generada por Defender for Cloud para crear los roles de IAM y la confianza OIDC que necesita el conector.
Workload identity federation (federación de identidades de carga de trabajo)
Una confianza que permite que una nube acepte tokens de corta duración de otra, evitando las claves de larga duración; la usa el conector de GCP.

Instalación, impulsada por el conector, del agente de Azure Arc en las VM de AWS o GCP para que Defender for Servers pueda protegerlas por completo.
Log Analytics workspace (área de trabajo de Log Analytics)
El almacén de datos subyacente de Microsoft Sentinel, que se consulta con KQL.
Azure Monitor Agent (AMA)
El agente actual para recopilar registros de máquinas Windows y Linux, configurado mediante reglas de recopilación de datos; reemplaza al agente heredado retirado.

Microsoft security rule (regla de seguridad de Microsoft)
Una regla que crea incidentes de Sentinel a partir de alertas generadas por otros productos de seguridad de Microsoft; se deshabilita cuando se usa la sincronización de incidentes de Defender XDR.
Anomaly rule (regla de anomalías)
Una regla integrada de aprendizaje automático que registra las desviaciones respecto de las líneas base en la tabla Anomalies.
Entity mapping (asignación de entidades)
Vincular columnas de la consulta a tipos de entidad como Account, Host e IP para que los incidentes puedan investigarse, agruparse y automatizarse.
Lookback period (período de lookback)
Cuánto tiempo hacia atrás consulta los datos cada ejecución de una regla programada.
Automation rule (regla de automatización)
Una regla de Sentinel sin código que se ejecuta ante eventos de incidentes o alertas para asignar, etiquetar, cambiar el estado o la gravedad, agregar tareas, cerrar incidentes o ejecutar playbooks.
Playbook
Un flujo de trabajo de Logic Apps desencadenado por Sentinel para realizar acciones de respuesta y enriquecimiento de varios pasos en distintos sistemas.
Workbook
Un panel interactivo basado en KQL para visualizar los datos de Sentinel y elaborar informes.
Hunting query (consulta de hunting)
Una consulta KQL que se ejecuta de forma proactiva para buscar amenazas no detectadas por las reglas de análisis; sus resultados se pueden guardar como marcadores.
Watchlist
Una tabla de búsqueda, normalmente cargada desde un CSV, que se referencia en las consultas con _GetWatchlist.
Indicator of compromise (IoC, indicador de compromiso)
Un elemento observable, como una dirección IP, un dominio, una URL o un hash de archivo, asociado con actividad maliciosa y usado en la coincidencia de inteligencia de amenazas.
Analytics tier (nivel Analytics)
El nivel de registros con todas las funciones, que admite todo KQL, las reglas de análisis y las consultas rápidas, con el costo de ingesta más alto.
Basic and Auxiliary logs (registros básicos y auxiliares)
Planes de tabla de Log Analytics de menor costo, con ingesta más barata, funciones de consulta limitadas y cobros por consulta.
Sentinel data lake
Un nivel de lago de bajo costo para datos de seguridad a largo plazo, consultado de forma asíncrona y usado para alimentar Analytics con resultados resumidos.
Long-term retention (retención a largo plazo)
Retención de bajo costo de hasta 12 años, a la que se accede mediante trabajos de búsqueda o restauración.
Custom table (tabla personalizada)
Una tabla para datos no estándar, con el sufijo _CL, creada mediante la Logs Ingestion API con una DCR o mediante los registros personalizados de AMA.
summarize
Un operador de KQL que agrega filas, como contar eventos por usuario.
Security Compute Unit (SCU)
La unidad de capacidad aprovisionada que determina cuánto procesamiento puede realizar Security Copilot.
Copilot owner (propietario de Copilot)
El rol de Security Copilot que administra la configuración, los plugins, la capacidad y el uso compartido de datos.
Copilot contributor (colaborador de Copilot)
El rol de Security Copilot que puede crear sesiones y usar las funciones, dentro de los permisos del usuario en cada producto.
Plugin
Un conector que proporciona a Security Copilot datos y habilidades de un producto de Microsoft o de terceros.
Promptbook
Una secuencia guardada y reutilizable de prompts para una tarea de seguridad común, que puede recibir entradas.
Embedded experience (experiencia integrada)
Funciones de Security Copilot que aparecen dentro de productos como Defender XDR, Entra, Intune o Purview.
Unified audit log (registro de auditoría unificado)
El registro central de Microsoft 365 de las actividades de usuarios y administradores en los distintos servicios, que se consulta mediante Purview Audit.
Audit (Standard)
El nivel de auditoría predeterminado, con un período de retención estándar, búsqueda en el portal y el cmdlet Search-UnifiedAuditLog.
Audit (Premium)
El nivel avanzado que agrega retención más larga, directivas de retención personalizadas, mayor ancho de banda de API y eventos de información inteligente como SearchQueryInitiatedExchange.
MailItemsAccessed
Un evento de auditoría que registra el acceso a elementos del buzón, usado para delimitar el alcance de un compromiso de correo; originalmente solo de Premium, ahora también se registra en Audit (Standard).
Audit log retention policy (directiva de retención de registros de auditoría)
Una directiva de Premium que define cuánto tiempo se conservan registros de auditoría específicos.
OfficeActivity
La tabla de Microsoft Sentinel que el conector de Microsoft 365 llena con la actividad de Exchange, SharePoint y Teams.
