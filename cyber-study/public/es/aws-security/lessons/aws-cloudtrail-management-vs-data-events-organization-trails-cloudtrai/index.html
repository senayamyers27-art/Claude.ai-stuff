AWS Certified Security – Specialty SCS-C03

AWS CloudTrail: management events vs data events, organization trails, CloudTrail Lake y validación de integridad de los archivos de log

AWS CloudTrail registra la actividad de la interfaz de programación de aplicaciones (API) en tu cuenta: quién hizo una llamada, desde qué dirección de protocolo de internet (IP), con qué credenciales, cuándo y si tuvo éxito. Casi cada clic en la consola, cada comando de la interfaz de línea de comandos (CLI) y cada llamada desde un kit de desarrollo de software (SDK) se convierte en un evento de CloudTrail. Un evento es un registro en JavaScript Object Notation (JSON) con campos como eventTime, eventSource, eventName, userIdentity, sourceIPAddress, requestParameters y, si falla, errorCode. Eso convierte a CloudTrail en el primer lugar donde buscas durante una investigación y en la base de la mayoría de los requisitos de auditoría.

Los eventos son de distintos tipos, y el examen espera que los conozcas. Los management events son operaciones del plano de control, como CreateUser, PutBucketPolicy o RunInstances. Los trails los registran de forma predeterminada, y puedes elegir incluir eventos de lectura, de escritura o ambos. Los data events son operaciones de gran volumen a nivel de recurso, como GetObject y DeleteObject de Amazon Simple Storage Service (S3), Invoke de AWS Lambda o las acciones sobre elementos de Amazon DynamoDB. Están desactivados de forma predeterminada y tienen un costo adicional, así que los activas de forma selectiva, por ejemplo, solo para los buckets que guardan datos sensibles, usando advanced event selectors que pueden filtrar por tipo de recurso, Amazon Resource Name (ARN) o nombre de evento. Los Insights events señalan tasas inusuales de llamadas a la API o de errores en comparación con una línea base aprendida, lo que ayuda a detectar cosas como una ráfaga repentina de llamadas DeleteObject.

Event history es el punto de partida gratuito. En la consola muestra los últimos 90 días de management events de cada región, con filtros sencillos como nombre de usuario o nombre de evento. Es útil para una revisión rápida, pero no incluye data events, funciona por región y no se puede conservar por más tiempo. Para cualquier cosa más allá de eso necesitas un trail o CloudTrail Lake. Por eso precisamente sale mal la escena con la auditora: los borrados de objetos son data events, así que Event history nunca los mostrará.

Un trail entrega archivos de log a un bucket de S3, normalmente cada pocos minutos, y también puede enviar eventos a Amazon CloudWatch Logs para generar alertas con metric filters. Puedes cifrar los archivos de log con cifrado del lado del servidor usando claves de AWS Key Management Service (SSE-KMS), lo que agrega una segunda verificación de permisos, porque quien los lee necesita kms:Decrypt. Un trail multirregión captura la actividad en todas las regiones, incluidas las que normalmente no usas, lo cual importa porque a los atacantes les gustan las regiones tranquilas.

Un organization trail se crea en la cuenta de administración de AWS Organizations o en una cuenta de administrador delegado y registra todas las cuentas miembro, incluidas las que se creen después. Las cuentas miembro pueden ver el trail, pero no pueden cambiarlo ni eliminarlo, y no pueden detener el registro. Combinado con una cuenta de archivo de logs cuyo bucket solo pueden leer unos pocos roles de seguridad, esto te da un registro único y resistente a manipulaciones para toda la organización. Cuando una pregunta pide un solo trail que ningún administrador de una cuenta miembro pueda desactivar, la respuesta es un organization trail.

El cifrado mantiene la confidencialidad de los logs, pero no demuestra que no se hayan alterado. Ese es el trabajo de la validación de integridad de los archivos de log. Con ella activada, CloudTrail entrega cada hora un digest file que contiene hashes SHA-256 de los archivos de log entregados en esa hora, y cada digest está firmado por CloudTrail y encadenado al digest anterior. Ejecutar aws cloudtrail validate-logs verifica la cadena e informa si algún archivo de log se modificó, se eliminó o se falsificó después de la entrega. Agrega versionado de S3, MFA delete o S3 Object Lock en el bucket, además de una bucket policy estricta, y tendrás tanto prevención como prueba.

CloudTrail Lake es un data lake administrado para eventos. Creas un event data store, eliges qué eventos guarda (management events, data events e incluso eventos de fuera de AWS) y por cuánto tiempo los conserva, y lo consultas con lenguaje de consulta estructurado (SQL) en todas las cuentas y regiones de una organización. Una consulta que seleccione eventName, userIdentity.arn y sourceIPAddress donde eventName = 'DeleteObject' para un bucket responde una pregunta de investigación en minutos, sin tener que construir tus propias tablas y particiones de Amazon Athena.

Para el examen, ten claros los puntos de decisión. La actividad de S3 a nivel de objeto necesita data events. La retención prolongada necesita un trail o Lake, no Event history. La evidencia contra manipulaciones necesita la validación de integridad de los archivos de log, mientras que la confidencialidad necesita SSE-KMS. Un solo trail que nadie en las cuentas miembro pueda desactivar es un organization trail. Y las consultas SQL ad hoc sobre meses de actividad sin construir un pipeline apuntan a CloudTrail Lake.

Términos clave

Management event
Una llamada a la API del plano de control, como crear un usuario o cambiar una bucket policy, que los trails registran de forma predeterminada.
Data event
Una operación de gran volumen sobre un recurso, como leer un objeto de S3 o invocar una función Lambda, que solo se registra si se activa.
Insights event
Un evento de CloudTrail que señala tasas inusuales de llamadas a la API o de errores en comparación con una línea base.
Organization trail
Un trail creado desde la cuenta de administración o de administrador delegado que registra todas las cuentas miembro y que estas no pueden cambiar.
Digest file
Un archivo firmado que se genera cada hora con los hashes de los archivos de log entregados, usado para validar la integridad de los logs.
CloudTrail Lake
Un event data store administrado que conserva los eventos de CloudTrail durante el periodo de retención elegido y permite consultarlos con SQL.
Ejemplo real

Después de que alguien vacía un bucket de exportaciones de clientes, el equipo no encuentra nada en Event history porque los borrados de objetos son data events. Activan los data events de S3 para los buckets sensibles en el organization trail, habilitan la validación de integridad de los archivos de log y crean un event data store de CloudTrail Lake. La siguiente vez, una consulta en Lake muestra el rol, la dirección IP y la hora exactos de cada llamada DeleteObject, y validate-logs les permite demostrarle a la auditora que ningún archivo de log cambió.

Consejo para el examen: Fíjate en la palabra 'objeto' en una pregunta: las lecturas, escrituras y borrados de objetos de S3 son data events. Recuerda también que cifrar los archivos de log protege la confidencialidad, mientras que la validación de integridad demuestra que no cambiaron.

Comprueba lo que sabes

¿Cuánto tiempo conserva eventos Event history y de qué tipo?

90 días de management events por región, de forma gratuita.

¿Puede el administrador de una cuenta miembro eliminar un organization trail?

No. Las cuentas miembro pueden verlo, pero solo la cuenta de administración o la de administrador delegado pueden cambiarlo o eliminarlo.

¿Qué comando verifica si los archivos de log de CloudTrail cambiaron después de la entrega?

aws cloudtrail validate-logs, que usa los digest files firmados que se generan cada hora cuando la validación de integridad de los archivos de log está activada.
