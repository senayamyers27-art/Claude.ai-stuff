Hoja de repaso de Security Specialty SCS-C03

Cada consejo para el examen y término clave de las lecciones gratuitas de Security Specialty, por dominio. Usa la opción Imprimir de tu navegador para guardarla como PDF.

Dominio 1: Detection (16%)

Consejos para el examen

  • Cuando una pregunta pide detectar que una aplicación está caída o lenta, piensa en alarmas de CloudWatch y health checks; cuando pregunta quién hizo algo, piensa en CloudTrail. No elijas un servicio de detección de amenazas para un problema puro de disponibilidad, y busca la composite alarm cuando el enunciado se queja de avisos ruidosos.
  • Fíjate en la palabra 'objeto' en una pregunta: las lecturas, escrituras y borrados de objetos de S3 son data events. Recuerda también que cifrar los archivos de log protege la confidencialidad, mientras que la validación de integridad demuestra que no cambiaron.
  • Si una respuesta dice que debes habilitar VPC Flow Logs o el registro DNS antes de que GuardDuty pueda usarlos, es incorrecta. Recuerda también que GuardDuty detecta y reporta; no bloquea el tráfico por sí solo, y la cobertura en toda la organización significa administrador delegado más auto-enable en todas las regiones.
  • Si una pregunta dice que los controles de Security Hub no muestran datos, revisa si AWS Config está grabando los tipos de recursos relevantes. Muchas verificaciones de controles dependen de Config. Para 'una sola vista de todas las regiones', busca la agregación entre regiones más un administrador delegado.
  • Los flow logs muestran REJECT para el tráfico bloqueado por un security group o una network ACL, pero no cuál lo bloqueó, y nunca muestran nombres DNS ni el contenido de los paquetes. Elige el log que realmente contiene los datos sobre los que pregunta el enunciado.
  • Relaciona el periodo de tiempo y el formato con la herramienta: logs operativos recientes en CloudWatch, Logs Insights; archivos a largo plazo en S3, Athena; data lake normalizado de varias fuentes, Security Lake; dashboards con búsqueda de texto completo, OpenSearch.
  • Para 'alertar cuando X ocurre una vez, casi en tiempo real', elige una regla de EventBridge; para 'alertar cuando X ocurre más de N veces', elige un metric filter con alarma. Una consulta programada casi nunca es la respuesta más rápida.
  • Cuando los logs se detienen justo después de un cambio, el cambio casi siempre es la causa: una edición de la bucket policy, una nueva clave de KMS o una nueva SCP o RCP. Busca la respuesta que restablece el acceso del service principal de la forma más acotada.

Términos clave

CloudWatch metric (métrica de CloudWatch)
Un conjunto de datos numéricos ordenados en el tiempo, como el uso de CPU o el número de errores, publicado por los servicios de AWS o por tu aplicación.
CloudWatch alarm (alarma de CloudWatch)
Una regla que vigila una métrica o una expresión de metric math contra un umbral durante varios periodos y cambia al estado ALARM, lo que puede activar notificaciones o acciones.
Composite alarm (alarma compuesta)
Una alarma cuyo estado depende de una combinación lógica de otras alarmas, que se usa para reducir las alertas ruidosas.
Health check de Route 53
Una sonda desde ubicaciones de AWS que prueba si un endpoint responde, o que sigue una alarma de CloudWatch, y que puede impulsar el failover de DNS.
Requisito de monitoreo
Una declaración escrita de lo que se debe observar en una carga de trabajo, de dónde vienen los datos y a quién se alerta.
Fatiga de alertas
La tendencia a ignorar las alertas después de recibir demasiadas que eran falsas o poco importantes.
Management event
Una llamada a la API del plano de control, como crear un usuario o cambiar una bucket policy, que los trails registran de forma predeterminada.
Data event
Una operación de gran volumen sobre un recurso, como leer un objeto de S3 o invocar una función Lambda, que solo se registra si se activa.
Insights event
Un evento de CloudTrail que señala tasas inusuales de llamadas a la API o de errores en comparación con una línea base.
Organization trail
Un trail creado desde la cuenta de administración o de administrador delegado que registra todas las cuentas miembro y que estas no pueden cambiar.
Digest file
Un archivo firmado que se genera cada hora con los hashes de los archivos de log entregados, usado para validar la integridad de los logs.
CloudTrail Lake
Un event data store administrado que conserva los eventos de CloudTrail durante el periodo de retención elegido y permite consultarlos con SQL.
Fuentes de datos fundamentales
Los management events de CloudTrail, los VPC Flow Logs y los logs de consultas DNS de Route 53 Resolver que GuardDuty analiza desde sus propios flujos independientes.
Protection plan (plan de protección)
Una función opcional de GuardDuty que agrega una fuente de datos o una capacidad de análisis, como S3 Protection, EKS Protection o Runtime Monitoring.
Finding type (tipo de hallazgo)
Un nombre estructurado con la forma ThreatPurpose:ResourceType/ThreatFamily.Mechanism!Artifact que describe lo que detectó GuardDuty.
Suppression rule (regla de supresión)
Un filtro que archiva automáticamente los hallazgos que cumplen ciertos criterios, usado para actividad benigna conocida.
Administrador delegado
Una cuenta miembro a la que la cuenta de administración le da permiso para gestionar un servicio en toda la organización.
Attack sequence finding (hallazgo de secuencia de ataque)
Un hallazgo de GuardDuty que correlaciona varias señales relacionadas en la descripción de un ataque de varias etapas.
ASFF
AWS Security Finding Format, el formato JSON que Security Hub usa para los hallazgos de todas las fuentes.
Security standard (estándar de seguridad)
Un conjunto de controles, como CIS o AWS Foundational Security Best Practices, que Security Hub verifica contra tus recursos.
Central configuration (configuración central)
Una función de Security Hub que permite al administrador delegado aplicar configuration policies de estándares y controles en toda la organización, en OU o en cuentas.
Cross-Region aggregation (agregación entre regiones)
Un ajuste que trae los hallazgos de las regiones vinculadas a una sola región de agregación.
Custom action (acción personalizada)
Una acción de Security Hub que un analista elige para los hallazgos seleccionados y que los envía a EventBridge para una respuesta.
Automation rule (regla de automatización)
Una regla que actualiza o suprime automáticamente los hallazgos que cumplen ciertos criterios cuando Security Hub los recibe.
VPC Flow Logs
Registros de metadatos del tráfico IP en interfaces de red, subredes o VPC, incluido ACCEPT o REJECT, sin el contenido de los paquetes.
Resolver query logging (registro de consultas del Resolver)
Una función que registra las consultas DNS que hacen los recursos de una VPC al Route 53 Resolver, incluidos el nombre y la respuesta.
Server access logs de S3
Logs de las solicitudes hechas a un bucket de S3, entregados con el mejor esfuerzo posible a otro bucket.
Access logs de ELB
Registros por solicitud de un balanceador de carga, entregados a S3, que incluyen la IP del cliente, la línea de la solicitud, los códigos de estado y los detalles de TLS.
Traffic Mirroring
Una función de VPC que copia los paquetes de red reales de una interfaz a un destino de monitoreo.
Logs de AWS WAF
Registros de las solicitudes web inspeccionadas por AWS WAF, incluida la regla que coincidió y la acción tomada.
Cuenta de archivo de logs (log archive account)
Una cuenta dedicada cuyos buckets de S3 bien restringidos guardan los logs de todas las cuentas y que solo pueden leer unos pocos roles de seguridad.
CloudWatch Logs Insights
Un lenguaje de consulta y una consola para buscar y agregar datos en CloudWatch Logs.
Subscription filter (filtro de suscripción)
Un ajuste de CloudWatch Logs que transmite los eventos de log que coinciden a Lambda, Kinesis, Firehose o un destino entre cuentas.
Amazon Athena
Un motor SQL serverless que consulta los datos donde están en S3 y cobra según los datos analizados.
OCSF
Open Cybersecurity Schema Framework, un esquema abierto y neutral respecto a proveedores para eventos de seguridad.
Amazon Security Lake
Un servicio que recopila los datos de seguridad y los normaliza a OCSF en un data lake de S3 que pertenece al cliente.
Event bus
Un canal de EventBridge que recibe eventos; cada cuenta tiene un bus predeterminado y se pueden crear buses personalizados o entre cuentas.
Event pattern (patrón de eventos)
Un filtro JSON en una regla de EventBridge que selecciona qué eventos activan sus destinos.
Metric filter (filtro de métricas)
Un patrón de CloudWatch Logs que convierte los eventos de log que coinciden en una métrica de CloudWatch.
Tema de SNS (SNS topic)
Un canal de publicación y suscripción que distribuye notificaciones a suscriptores como correo electrónico, SMS, HTTPS o Lambda.
Topic policy (política del tema)
Una resource policy en un tema de SNS que controla quién puede publicar en él o suscribirse.
Event bus entre cuentas (cross-account event bus)
Un bus de EventBridge en otra cuenta que recibe eventos, usado para centralizar los eventos de seguridad.
Service principal (entidad principal de servicio)
Un identificador como cloudtrail.amazonaws.com que representa a un servicio de AWS en las políticas.
get-trail-status
Una llamada a la API de CloudTrail que muestra si un trail está registrando y los errores de entrega recientes.
aws:SourceArn
Una condition key que vincula el permiso de un service principal a un recurso específico, como un trail.
aws:SourceAccount
Una condition key que limita el permiso de un service principal a las solicitudes hechas en nombre de cuentas específicas.
Encryption context (contexto de cifrado)
Datos adicionales de clave y valor vinculados a una operación de KMS, que se usan en las políticas y se registran en CloudTrail.
Confused deputy (suplente confundido)
Un problema en el que se engaña a un servicio de confianza para que actúe en nombre de otra parte; se previene con condiciones de ARN de origen y cuenta de origen.

Dominio 2: Incident Response (14%)

Consejos para el examen

  • Cuando una pregunta pide hacer una respuesta consistente y repetible, prefiere un runbook automatizado (Systems Manager Automation, Step Functions o Lambda) activado por un evento antes que una lista de verificación manual. Si el escenario necesita una decisión humana, busca un paso de aprobación en lugar de renunciar a la automatización.
  • Busca pistas de 'antes de un incidente': las respuestas correctas crean de antemano roles, claves, cuentas y runbooks. Una respuesta que otorga acceso amplio solo después de que empieza el incidente, o que comparte credenciales de manera informal, es una trampa.
  • Primero desactiva, después elimina. Para los roles, la respuesta es revocar las sesiones, no eliminar el rol, lo que rompería las cargas de trabajo sanas. Después de la contención, la siguiente mejor respuesta suele ser una búsqueda de persistencia en CloudTrail.
  • Cualquier respuesta que detenga o termine la instancia antes de capturar la memoria pierde evidencia. Si la sesión de un atacante sobrevive a un cambio de security group, la explicación es el rastreo de conexiones, y una network ACL lo resuelve.
  • Detective sirve para la investigación visual y las relaciones a lo largo del tiempo; CloudTrail Lake y Athena sirven para consultas exactas; GuardDuty genera la alerta. Fíjate en el verbo de la pregunta: investigar y visualizar, consultar o detectar.
  • Acción única y rápida: Lambda. Varios pasos con reintentos o aprobaciones: Step Functions. Corregir una configuración no conforme: remediación de Config con un documento de Automation. Cambiar o suprimir hallazgos: automation rules de Security Hub. Respuesta disparada por un analista: custom action.
  • Los snapshots cifrados con la clave de EBS predeterminada administrada por AWS no se pueden compartir con otra cuenta. Para compartir evidencia, la respuesta incluye una clave administrada por el cliente que la cuenta forense pueda usar, o volver a cifrar la copia. Para «nadie, ni siquiera el usuario raíz, puede eliminarla», elige Object Lock en modo compliance.
  • Las respuestas de recuperación restauran desde backups limpios y reconstruyen desde imágenes confiables; las que limpian y reutilizan el sistema comprometido son trampas. Para backups que ni siquiera los administradores pueden eliminar, busca Vault Lock en modo compliance, idealmente en una cuenta separada.

Términos clave

Plan de respuesta a incidentes (incident response plan)
Un documento escrito que define roles, niveles de severidad, comunicación y fases para manejar los incidentes de seguridad.
Playbook
Un plan para manejar un tipo de incidente, incluidos su detección, sus puntos de decisión y sus runbooks.
Runbook
Un procedimiento paso a paso, idealmente automatizado, para realizar una tarea de respuesta.
Systems Manager Automation
Un servicio que ejecuta documentos de runbook con pasos que llaman a API de AWS y a scripts, iniciados de forma manual o por eventos.
OpsCenter
Una capacidad de Systems Manager que da seguimiento a los problemas operativos como OpsItems con sus recursos y runbooks relacionados.
Post-incident review (revisión posterior al incidente)
Una reunión sin búsqueda de culpables, después de un incidente, para registrar lo que pasó y actualizar los planes, las detecciones y los runbooks.
Acceso break-glass
Credenciales de emergencia, muy protegidas y monitoreadas, que solo se usan cuando fallan las vías de acceso normales.
Incident response role (rol de respuesta a incidentes)
Un rol de IAM creado de antemano en cada cuenta que quienes responden asumen para investigar o contener un incidente.
Cuenta forense (forensics account)
Una cuenta de AWS aislada que se usa para guardar evidencia y hacer análisis lejos de producción.
S3 Object Lock
Una función de S3 que impide que los objetos se eliminen o se sobrescriban durante un periodo de retención, usada para evidencia y logs.
Game day
Un evento de práctica que simula un incidente para poner a prueba a las personas, los procesos y las herramientas.
Tabletop exercise (ejercicio de mesa)
Un recorrido en forma de discusión por un escenario de incidente para poner a prueba los roles y las decisiones.
Desactivar access key (deactivate access key)
Poner una access key de IAM en Inactive para que deje de funcionar, pero siga existiendo para la investigación.
Revoke active sessions (revocar sesiones activas)
Una acción sobre un rol de IAM que niega todas las solicitudes de las sesiones emitidas antes de un momento elegido.
aws:TokenIssueTime
Una condition key que contiene el momento en que se emitieron las credenciales temporales.
IMDSv2
Instance Metadata Service Version 2, que exige un token de sesión y protege las credenciales de la instancia contra los ataques comunes de falsificación de solicitudes.
Persistencia
Los cambios que hace un atacante para conservar el acceso, como crear usuarios, claves o roles nuevos.
Prefijo del ID de la access key
AKIA para las claves de largo plazo de usuarios de IAM y ASIA para las credenciales temporales de STS, lo que ayuda a identificar el tipo de credencial.
Isolation security group (security group de aislamiento)
Security group sin reglas, o solo con reglas forenses mínimas, que se usa para desconectar de la red una instancia comprometida.
Tracked connection (conexión rastreada)
Flujo que un security group stateful recuerda y que sigue abierto incluso después de quitar las reglas que lo permitían.
Captura de memoria
Obtener una copia de la RAM de un sistema en ejecución para preservar evidencia volátil, como procesos y conexiones de red.
Termination protection (protección contra terminación)
Ajuste de EC2 que impide terminar una instancia mediante la API o la consola hasta que se desactive.
Standby state (estado Standby)
Estado de Auto Scaling que saca una instancia de servicio y del reemplazo por verificaciones de estado sin terminarla.
Cuenta forense
Cuenta de AWS dedicada y estrictamente controlada donde la evidencia se guarda y se analiza lejos del entorno comprometido.
Behavior graph (grafo de comportamiento)
Modelo de Detective que vincula entidades y su actividad, construido automáticamente a partir de logs y hallazgos.
Finding group
Agrupación de Detective de hallazgos y entidades relacionados que probablemente pertenecen a un mismo evento de seguridad.
Event data store
Almacén de eventos de CloudTrail Lake que se puede consultar con SQL y conservar durante un período de retención configurable.
Organization event data store (event data store de organización)
Event data store de CloudTrail Lake que reúne los eventos de todas las cuentas de una organización de AWS.
Dimensionamiento
Determinar el alcance de un incidente: cuentas, recursos, datos y período afectados.
Blast radius (radio de impacto)
Todo lo que una identidad o un recurso comprometido podría afectar según sus permisos y su alcance de red.
EventBridge rule (regla de EventBridge)
Regla con un patrón de eventos que coincide con eventos, como hallazgos de seguridad, y los envía a destinos como Lambda o Step Functions.
Step Functions
Servicio de flujos de trabajo que coordina varios pasos con reintentos, ramas, esperas y aprobaciones, útil para respuestas de varios pasos.
Automatic remediation (remediación automática)
Función de AWS Config que ejecuta un documento de Systems Manager Automation cuando una regla encuentra un recurso no conforme.
Security Hub automation rule
Regla sin código que actualiza los hallazgos que coinciden, por ejemplo cambiando la severidad o estableciendo el estado de flujo de trabajo en SUPPRESSED.
Custom action
Función de Security Hub que envía a EventBridge los hallazgos que selecciona un analista.
Paso de aprobación humana
Pausa en un flujo automatizado que espera a que una persona confirme una acción riesgosa.
Chain of custody (cadena de custodia)
Registro de quién recopiló, transfirió, guardó y accedió a cada pieza de evidencia, y cuándo.
Compliance mode (modo compliance)
Modo de S3 Object Lock en el que ningún usuario, incluido el usuario raíz, puede eliminar una versión de objeto ni acortar su retención hasta que expire.
Governance mode (modo governance)
Modo de S3 Object Lock que pueden anular los usuarios con el permiso s3:BypassGovernanceRetention.
Legal hold
Ajuste de S3 Object Lock que impide eliminar una versión de objeto hasta que se quite el bloqueo, sin fecha fija de fin.
Hash
Huella de longitud fija de un archivo, como SHA-256, que se usa para demostrar que no ha cambiado.
WORM
Write once, read many (escritura única, lectura múltiple): almacenamiento que no se puede modificar ni eliminar después de escribirse.
AWS Backup
Servicio que gestiona de forma central los planes de backup y los puntos de recuperación entre servicios y cuentas de AWS.
Backup Vault Lock
Ajuste que impone una retención de escritura única sobre una bóveda de backup e impide eliminar puntos de recuperación; en modo compliance no se puede quitar una vez que termina el período de gracia.
Logically air-gapped vault (bóveda con aislamiento lógico)
Tipo de bóveda de AWS Backup que mantiene los puntos de recuperación aislados y bloqueados, y que se puede compartir para la recuperación.
Causa raíz
La debilidad de fondo que permitió un incidente, a diferencia de sus síntomas.
Revisión posterior al incidente
Reunión sin culpas después de un incidente para documentar la línea de tiempo, las causas y las mejoras.

Dominio 3: Infrastructure Security (18%)

Consejos para el examen

  • La inyección SQL, el XSS, los bots maliciosos y las inundaciones HTTP apuntan a AWS WAF; los DDoS grandes en la capa de red apuntan a Shield; el tráfico que no es HTTP apunta a security groups, network ACLs o Network Firewall. Las reglas nuevas van primero en Count.
  • La protección de costos, el equipo de respuesta y los informes avanzados solo vienen con Shield Advanced. Si una pregunta dice «sin costo adicional» para la protección básica contra DDoS, la respuesta es Shield Standard. Firewall Manager necesita Organizations, una cuenta de administrador y AWS Config.
  • Un solo archivo, o clientes sin soporte de cookies: signed URLs. Muchos archivos: signed cookies. Los diseños nuevos usan OAC en lugar de OAI, sobre todo con SSE-KMS. Los certificados de dominios personalizados para CloudFront van en ACM en us-east-1.
  • Necesitas denegar una IP específica: network ACL. Necesitas hacer referencia a otra capa: security group. Necesitas filtrado por dominio o IPS sobre el tráfico: Network Firewall. Necesitas bloquear búsquedas DNS: DNS Firewall.
  • S3 o DynamoDB sin costo por hora: gateway endpoint. Otros servicios: interface endpoint. Restringir a qué buckets se puede llegar desde la VPC: endpoint policy. Restringir desde qué red se puede llegar a un bucket: bucket policy con aws:SourceVpce.
  • Direct Connect es privado, pero no está cifrado. Cifrar sobre él significa MACsec (capa 2) o VPN sobre Direct Connect (IPsec, capa 3). «Sin una VPN» más «identidad y postura del dispositivo» significa Verified Access.
  • Sin puertos abiertos, sin claves, sesiones auditadas: Session Manager. Proteger las credenciales del rol de la instancia contra SSRF: exigir IMDSv2. Parches programados con informes de cumplimiento: Patch Manager. Punto de partida conocido y confiable: Image Builder.
  • Inspector encuentra vulnerabilidades; no las corrige. Combínalo con Patch Manager, la reconstrucción de imágenes o cambios de código. No lo confundas con GuardDuty (amenazas) ni con Macie (datos sensibles).
  • Una ruta, por qué está bloqueada: Reachability Analyzer. Todas las rutas no deseadas en la red: Network Access Analyzer. Contenido real de los paquetes: Traffic Mirroring. Metadatos de flujos aceptados y rechazados: flow logs.

Términos clave

Web ACL
Conjunto de reglas de AWS WAF y una acción predeterminada asociado a un recurso web protegido.
Managed rule group
Conjunto de reglas de WAF mantenido por AWS o por un vendedor del Marketplace, como el core rule set.
Rate-based rule
Regla de WAF que bloquea o desafía a los orígenes cuya cantidad de solicitudes supera un límite en una ventana de tiempo.
Count action (acción Count)
Acción de WAF que registra las coincidencias sin bloquear, usada para probar reglas de forma segura.
WCU
Web ACL capacity unit (unidad de capacidad de web ACL): la medida de cuánta capacidad de procesamiento consumen las reglas en una web ACL.
Label (etiqueta)
Marca que WAF agrega a una solicitud cuando una regla coincide, y que las reglas posteriores pueden usar para coincidir.
Shield Standard
Protección gratuita y automática para todos los clientes de AWS contra ataques DDoS comunes de las capas de red y de transporte.
Shield Advanced
Servicio pago que agrega detección mejorada, el Shield Response Team, protección de costos, informes de ataques y mitigación automática en capa 7 para los recursos protegidos.
Shield Response Team
Expertos en DDoS de AWS disponibles 24/7 para los clientes de Shield Advanced durante los ataques.
DDoS cost protection (protección de costos por DDoS)
Función de Shield Advanced que otorga créditos por los cargos de escalado de los recursos protegidos causados por un ataque DDoS.
Health-based detection (detección basada en el estado)
Detección de Shield Advanced que usa health checks de Route 53 para juzgar si un evento está afectando a la aplicación.
Firewall Manager
Servicio que aplica políticas de WAF, Shield Advanced, security groups, Network Firewall y DNS Firewall en toda una organización.
Origin access control
Función de CloudFront que firma las solicitudes a un origen S3 con SigV4 para que el bucket pueda permitir solo esa distribución.
Signed URL
URL con expiración y firma que da acceso a un objeto de CloudFront.
Signed cookie
Conjunto de cookies que da acceso a varios objetos de CloudFront sin cambiar sus URLs.
Key group
Conjunto de claves públicas subidas a CloudFront en las que se confía para verificar signed URLs y signed cookies.
Response headers policy
Política de CloudFront que agrega encabezados, como los encabezados de seguridad, a las respuestas enviadas a los usuarios.
Field-level encryption
Cifrado de CloudFront de campos elegidos de la solicitud en el borde con una clave pública, legibles solo por quien tenga la clave privada.
Security group
Firewall stateful, solo de allow, asociado a interfaces de red, cuyas reglas pueden hacer referencia a otros security groups.
Network ACL
Firewall stateless de subred con reglas allow y deny numeradas que se evalúan en orden; gana la primera coincidencia.
Ephemeral ports (puertos efímeros)
Puertos temporales de número alto del cliente que se usan para el tráfico de retorno y que las network ACLs stateless deben permitir explícitamente.
AWS Network Firewall
Servicio administrado de firewall stateful y de prevención de intrusiones desplegado en subredes de la VPC, al que se llega mediante las tablas de rutas.
SNI
Server Name Indication: el nombre de host que un cliente envía en el handshake de TLS, que permite a los firewalls filtrar HTTPS por dominio sin descifrar.
DNS Firewall
Función del Route 53 Resolver que bloquea, alerta o permite las consultas DNS de los dominios listados.
Gateway endpoint
Endpoint gratuito basado en tablas de rutas para acceder de forma privada a S3 o DynamoDB desde dentro de una VPC.
Interface endpoint
Interfaz de red elástica con una IP privada que da acceso a un servicio mediante PrivateLink, protegida por security groups.
Endpoint policy
Política en un VPC endpoint que limita qué acciones y recursos se pueden alcanzar a través de él.
aws:SourceVpce
Condition key que contiene el ID del VPC endpoint por el que llegó una solicitud.
Endpoint service
Servicio que publicas mediante PrivateLink detrás de un Network Load Balancer para consumidores de otras VPC o cuentas.
Transit Gateway route table (tabla de rutas de Transit Gateway)
Tabla de enrutamiento de un Transit Gateway que controla qué attachments pueden comunicarse entre sí, lo que permite la segmentación.
Site-to-Site VPN
VPN IPsec con dos túneles entre un customer gateway on-premises y un virtual private gateway o un Transit Gateway.
Direct Connect
Conexión de red privada y dedicada a AWS que no está cifrada por defecto.
MACsec
Cifrado de capa 2 IEEE 802.1AE disponible en conexiones dedicadas compatibles de Direct Connect.
Client VPN
Servicio administrado basado en OpenVPN que permite que usuarios individuales se conecten a AWS y a redes on-premises.
Verified Access
Servicio zero trust que da acceso a aplicaciones en cada solicitud según la identidad y la postura del dispositivo.
Authorization rule (regla de autorización)
Ajuste de Client VPN que controla a qué CIDR de red puede llegar un grupo de usuarios.
Session Manager
Capacidad de Systems Manager que da acceso de shell auditado sin puertos de entrada abiertos ni claves SSH.
IMDSv2

Dominio 4: Identity and Access Management (20%)

Consejos para el examen

  • Los guardrails (SCP, RCP, boundaries, session policies) nunca otorgan nada; solo ponen un techo. Si todas las opciones de respuesta agregan un allow en un guardrail pero ninguna agrega un allow de identidad o de recurso, ninguna hará que la solicitud tenga éxito.
  • Las preguntas de ABAC a menudo incluyen una trampa en la que los usuarios podrían cambiar sus propias etiquetas o las de un recurso. La respuesta completa también restringe las acciones de etiquetado.
  • Proveedor externo que asume un rol: external ID. Service principal de AWS que escribe o publica en tu recurso: aws:SourceArn y aws:SourceAccount. Ambos evitan los problemas de confused deputy.
  • Muchas cuentas más un IdP corporativo existente: IAM Identity Center con SAML y SCIM. Los usuarios de IAM para personas, o las configuraciones SAML cuenta por cuenta, suelen ser la respuesta incorrecta a escala.
  • Inicio de sesión y tokens: user pool. Credenciales de AWS para usuarios de la app: identity pool. Reglas de negocio sobre quién puede hacer qué dentro de la app: Verified Permissions.
  • Fuera de AWS con certificados: Roles Anywhere. Pipelines con tokens OIDC: OIDC identity provider más un rol con condiciones estrictas sobre sub. Pods en EKS: Pod Identity o IRSA, nunca el rol del nodo.
  • Las access keys de root nunca deberían existir. Con muchas cuentas miembro, la respuesta moderna es la administración centralizada del acceso root, no un cajón lleno de dispositivos MFA.
  • Compartido fuera de la cuenta o de la organización: external access analyzer. Nunca usado: unused access analyzer. Construir una política a partir de lo que un rol hizo realmente: generación de políticas.
  • Con datos cifrados, el acceso necesita permiso tanto sobre los datos (S3, EBS, RDS) como sobre la clave de KMS. Muchas preguntas del tipo 'tengo s3:GetObject pero sigo recibiendo AccessDenied' son en realidad preguntas sobre la key policy de KMS o la VPC endpoint policy, y si el error nombra un tipo de política, te dice exactamente dónde buscar.

Dominio 5: Data Protection (18%)

Consejos para el examen

  • Para exigir TLS en S3, SQS o SNS, usa un Deny explícito cuando aws:SecureTransport es false; un Allow con true no basta, porque otras declaraciones aún podrían permitir HTTP. Recuerda también: los certificados de CloudFront viven en us-east-1, y los certificados importados en ACM nunca se renuevan solos.
  • Si un principal tiene kms:Decrypt en IAM pero se le sigue denegando, comprueba si la key policy permite a la cuenta o al principal. Primero la key policy, después IAM. Y si una pregunta plantea cómo cifrar más de 4 KB, la respuesta es envelope encryption con GenerateDataKey.
  • Descifrar en otra región sin volver a cifrar: clave multi-Region. HSM de un solo inquilino bajo tu control pero usado mediante KMS: CloudHSM key store. Claves nunca dentro de AWS: external key store. Destrucción instantánea del material de clave: material de clave importado.
  • Necesitas control y auditoría de la clave: SSE-KMS con una customer managed key. Necesitas menos costo de KMS a gran escala: Bucket Keys. El cliente debe guardar la clave y AWS no debe almacenarla: SSE-C. La normativa exige dos capas: DSSE-KMS. Nunca público, diga lo que diga la política: Block Public Access.
  • La diferencia clave: governance puede eludirse con un permiso; compliance no puede eludirlo nadie, ni siquiera root. Si la pregunta dice 'incluido el usuario raíz', elige compliance mode. Si la retención no tiene una fecha de fin fija, piensa en una legal hold.
  • Rotación automática de credenciales de bases de datos: Secrets Manager. Configuración cifrada y económica sin rotación: SecureString de Parameter Store. Certificados internos y TLS mutuo: AWS Private CA. Secreto entre cuentas: política de recursos más una customer managed key de KMS.
  • Encontrar datos sensibles en S3: Macie. Encontrar amenazas: GuardDuty. Encontrar vulnerabilidades: Inspector. Ocultar valores sensibles en los registros: protección de datos de CloudWatch Logs, con logs:Unmask para los pocos que necesitan los originales.
  • Ningún almacén de datos de AWS te permite convertir en el mismo lugar un volumen EBS, una instancia RDS o un sistema de archivos EFS existente sin cifrar en uno cifrado. La respuesta casi siempre es instantánea, copia cifrada, restauración o volumen nuevo (o DMS para un tiempo de inactividad mínimo). DynamoDB siempre está cifrado; solo cambia el tipo de clave.
  • Evitar que el modelo revele PII: Guardrails con filtros de información sensible. Bloquear jailbreaks: filtros de contenido con detección de ataques de prompt. Mantener el tráfico fuera de internet: interface VPC endpoint. Registrar qué se preguntó y qué se respondió: invocation logging. Limitar qué modelos se usan: IAM y SCP.

AWS Certificate Manager, que aprovisiona, despliega y renueva certificados TLS para los servicios de AWS integrados.

Dominio 6: Security Foundations and Governance (14%)

Consejos para el examen

  • La cuenta de administración debe estar casi vacía y usarse rara vez. Las respuestas que ejecutan herramientas de seguridad o cargas de trabajo en la cuenta de administración suelen ser incorrectas cuando existe la opción de un administrador delegado. Los registros van en la cuenta de log archive; las herramientas de seguridad se ejecutan desde la cuenta audit.
  • Limitar lo que nuestra gente puede hacer: SCP. Limitar quién puede tocar nuestros recursos, incluidas personas externas: RCP. Imponer un ajuste de servicio como IMDSv2 o el bloqueo del uso compartido público en todas las cuentas: declarative policy. Ninguna concede permisos y ninguna restringe la cuenta de administración.
  • Cuando la pregunta pide cómo administrar un servicio de seguridad para todas las cuentas, incluidas las futuras, la respuesta es un administrador delegado (normalmente la cuenta de herramientas de seguridad) con auto-enable, configurado en cada región, no scripts ni invitaciones.
  • Todas las cuentas, incluidas las futuras: StackSets con permisos service-managed y despliegue automático. Permitir que los usuarios desplieguen sin permisos amplios: launch constraints de Service Catalog. Detectar problemas antes del despliegue: Guard en la canalización, o Hooks y controles proactivos al desplegar. Encontrar cambios después del despliegue: drift detection y Config.
  • Controles de detección que informan de la configuración: reglas de Config. Un conjunto empaquetado de ellas para toda la organización: conformance packs. Una vista de todas las cuentas: aggregator. Corregir automáticamente: remediación con Systems Manager Automation. Bloquear la acción en primer lugar no es trabajo de Config.
  • Las palabras "informe de AWS" o "acuerdo con AWS" significan Artifact. "Recopilar evidencia sobre nuestros recursos para una auditoría" significa Audit Manager. Ninguno de los dos te hace cumplir por sí solo.
  • Las tag policies estandarizan, no exigen. Cuando una pregunta dice "impedir la creación sin una etiqueta", la respuesta es una SCP o una política de IAM con una condición aws:RequestTag y el operador Null. Cuando dice "impedir que los usuarios cambien las etiquetas de acceso", deniega las acciones de etiquetado sobre esas claves.
  • En las preguntas de responsabilidad compartida, pregúntate si el cliente puede siquiera llegar al componente. Si no puedes iniciar sesión en él, como el sistema operativo del host de RDS o el hipervisor, es trabajo de AWS. Revisión de diseño guiada: Well-Architected Tool. Comprobaciones automáticas de la cuenta: Trusted Advisor. Qué puede salir mal en nuestro diseño: modelado de amenazas con STRIDE.

Grupo de cuentas en AWS Organizations al que se le pueden asociar políticas.

Trusted access (acceso de confianza)
Ajuste de Organizations que permite a un servicio de AWS trabajar en las cuentas de la organización y crear los roles que necesita.
Administrador delegado
Cuenta miembro registrada para administrar un servicio específico en toda la organización.
Auto-enable (activación automática)
Ajuste que activa automáticamente un servicio de seguridad en las cuentas miembro nuevas de la organización, configurado por región.
Configuración central
Función de Security Hub para definir estándares y controles de muchas cuentas y regiones desde una región de origen mediante políticas de configuración.
Agregación entre regiones
Función de Security Hub que reúne los hallazgos de las regiones vinculadas en una sola región de agregación.
Cuenta de herramientas de seguridad
Cuenta miembro dedicada que aloja los servicios de seguridad y actúa como su administrador delegado.
StackSet
Función de CloudFormation que despliega una plantilla en varias cuentas y regiones.
Service-managed permissions (permisos administrados por el servicio)
Modo de StackSets que usa Organizations, apunta a OU y puede desplegar automáticamente en las cuentas nuevas que entren en ellas.
Launch constraint (restricción de lanzamiento)
Ajuste de Service Catalog que asigna el rol de IAM usado para lanzar un producto, de modo que los usuarios no necesitan permisos directos sobre los recursos subyacentes.
CloudFormation Guard
Herramienta de policy as code que valida plantillas y otros JSON o YAML contra reglas.
CloudFormation Hooks
Comprobaciones que se ejecutan antes de que CloudFormation aprovisione un recurso y pueden advertir o bloquear cambios no conformes.
Drift detection (detección de desviaciones)
Función de CloudFormation que informa de los recursos cuya configuración real difiere de la plantilla del stack.
Stack policy (política de stack)
Documento JSON que protege recursos concretos del stack frente a actualizaciones no deseadas.
Configuration item (elemento de configuración)
Registro en un momento dado de la configuración y las relaciones de un recurso, capturado por AWS Config.
Regla de Config
Comprobación que evalúa si los recursos cumplen una configuración deseada y los marca como COMPLIANT o NON_COMPLIANT.
Conformance pack (paquete de conformidad)
Colección de reglas de Config y acciones de remediación que se despliega e informa como una unidad.
Aggregator (agregador)
Recurso de Config que reúne datos de configuración y cumplimiento de varias cuentas y regiones.
Acción de remediación
Runbook de Systems Manager Automation adjunto a una regla de Config para corregir recursos no conformes de forma manual o automática.
Consulta avanzada
Consulta SELECT parecida a SQL sobre los datos actuales de Config, en una cuenta o en todo un aggregator.
AWS Artifact
Portal para descargar informes de cumplimiento de AWS y aceptar acuerdos como el BAA.
AWS Audit Manager
Servicio que recopila de forma continua evidencia de tu uso de AWS y la asocia a los controles de marcos de auditoría.
Framework (marco)
En Audit Manager, un conjunto de controles para un estándar o regulación, predefinido o personalizado.
Assessment report (informe de evaluación)
Salida de Audit Manager que agrupa la evidencia seleccionada, organizada por control, para los auditores.
Business Associate Addendum (BAA)
Acuerdo con AWS requerido antes de almacenar o procesar información de salud protegida bajo HIPAA.
Evidencia manual
Evidencia que cargas o introduces tú mismo en Audit Manager, como documentos de políticas, para los controles que no pueden comprobarse automáticamente.
Tag policy (política de etiquetas)
Política de Organizations que estandariza las claves de etiqueta, el uso de mayúsculas y los valores permitidos en todas las cuentas, y puede imponerlos para algunos tipos de recurso.
aws:RequestTag
Condition key para las etiquetas incluidas en una solicitud de creación o de etiquetado.
aws:TagKeys
Condition key que lista las claves de etiqueta de una solicitud, usada para limitar qué claves se pueden poner.
aws:ResourceTag
Condition key para las etiquetas ya adjuntas al recurso al que se accede, usada en ABAC.
Backup policy (política de copias de seguridad)
Política de Organizations que despliega planes de AWS Backup en todas las cuentas, a menudo seleccionando recursos por etiqueta.
Attribute-based access control (ABAC, control de acceso basado en atributos)
Enfoque de autorización que concede acceso comparando las etiquetas de los principales y de los recursos.
Shared responsibility model (modelo de responsabilidad compartida)
División de las tareas de seguridad entre AWS (seguridad de la nube) y el cliente (seguridad en la nube).
Security pillar (pilar de seguridad)
Sección del Well-Architected Framework con principios de diseño y buenas prácticas de seguridad.
AWS Well-Architected Tool
Herramienta de la consola que guía una revisión estructurada de una carga de trabajo, registra riesgos y hace seguimiento de los planes de mejora.
Trusted Advisor
Servicio de AWS que revisa las cuentas y recomienda mejoras, incluidas comprobaciones de seguridad.
Threat modeling (modelado de amenazas)
Proceso estructurado para identificar qué puede salir mal en un diseño y decidir cómo abordarlo.
STRIDE
Nemotécnico de modelado de amenazas: spoofing (suplantación), tampering (manipulación), repudiation (repudio), information disclosure (divulgación de información), denial of service (denegación de servicio) y elevation of privilege (elevación de privilegios).
Trust boundary (frontera de confianza)
Punto de un diseño donde los datos o el control pasan entre componentes con distintos niveles de confianza.
