Hoja de repaso de CKAD CKAD (Kubernetes v1.35 curriculum)

Cada consejo para el examen y término clave de las lecciones gratuitas de CKAD, por dominio. Usa la opción Imprimir de tu navegador para guardarla como PDF.

Dominio 1: Application Design and Build (20%)

Consejos para el examen

  • Recuerda la regla de combinación: ENTRYPOINT más CMD se ejecutan juntos, y los argumentos en tiempo de ejecución reemplazan solo a CMD. Las preguntas suelen pedir qué comando ejecuta realmente un contenedor, así que escríbelo palabra por palabra antes de responder.
  • Las tareas que piden un archivo de imagen quieren save (imagen con capas y metadatos), no export (el sistema de archivos plano de un contenedor). Lee dos veces el nombre, la etiqueta y la ruta de salida exactos, y verifica que el archivo existe antes de continuar.
  • Definir solo command descarta el CMD de la imagen en lugar de agregarlo al final. Y --command en kubectl run decide si las palabras que siguen a -- quedan en command o en args, así que siempre revisa el YAML generado.
  • Busca las palabras clave: 'uno por nodo' significa DaemonSet, 'identidad estable u ordenado' significa StatefulSet, 'se ejecuta hasta completarse' significa Job, 'según una programación' significa CronJob y 'aplicación sin estado escalable' significa Deployment.
  • Conoce los valores por defecto (completions 1, parallelism 1, backoffLimit 6) y que activeDeadlineSeconds se impone sobre backoffLimit. Recuerda también que Never crea Pods nuevos en cada reintento, mientras que OnFailure reinicia el mismo Pod.
  • El comando para disparar un CronJob a mano es kubectl create job <new-name> --from=cronjob/<cronjob-name>. Recuerda también que restartPolicy está en la plantilla de Pod más interna, dos niveles por debajo del schedule.
  • Si un Pod está atascado en un estado Init:, el problema es un init container: revísalo con kubectl logs <pod> -c <init-name>. Un sidecar nativo vive bajo initContainers, pero tiene restartPolicy: Always en el propio contenedor.
  • Los volúmenes secret usan secretName, no name, y las fuentes proyectadas usan name para ambos. Recuerda también que las variables de entorno no se actualizan cuando cambia un ConfigMap, pero los archivos montados (sin subPath) sí.
  • Los Pods referencian PVCs, no PVs. Para que un PV estático y un PVC se vinculen, storageClassName, el modo de acceso y la capacidad (el PV al menos tan grande como la solicitud) deben ser compatibles.
  • Un volumen necesita las dos mitades: una entrada en spec.volumes y una entrada volumeMounts correspondiente en cada contenedor. Los montajes con subPath no se actualizan automáticamente desde ConfigMaps ni Secrets.

Términos clave

Base image (imagen base)
La imagen indicada en FROM que aporta el sistema de archivos inicial y el runtime para tu build.
Layer (capa)
Un cambio de sistema de archivos de solo lectura y en caché, producido por una instrucción como RUN o COPY.
Build cache (caché de build)
La reutilización de capas anteriores cuando una instrucción y todo lo anterior no han cambiado.
Multi-stage build (build multietapa)
Un Dockerfile con varias etapas FROM en el que solo se copian artefactos seleccionados a la imagen final.
ENTRYPOINT
El ejecutable fijo que el contenedor ejecuta al iniciar.
CMD
Argumentos por defecto (o un comando por defecto si no hay ENTRYPOINT) que se reemplazan con los argumentos dados en tiempo de ejecución.
Exec form (forma exec)
La forma de arreglo JSON de ENTRYPOINT o CMD, que ejecuta el programa directamente como PID 1 para que reciba señales.
Build context (contexto de build)
El directorio enviado al builder cuyos archivos pueden alcanzar COPY y ADD.
.dockerignore
Un archivo en el contexto de build que lista las rutas que se excluyen del build.
Tag (etiqueta)
Un rótulo legible y movible, como 1.0, que apunta a una imagen.
Digest
El hash de contenido sha256 inmutable que identifica una imagen de forma única.
docker save / load
Comandos que exportan imágenes con todas sus capas y metadatos a un archivo tar y las vuelven a importar.
docker export / import
Comandos que trabajan sobre el sistema de archivos aplanado de un contenedor y descartan el historial y los metadatos de la imagen, como CMD.
imagePullPolicy
Campo del Pod (Always, IfNotPresent o Never) que controla cuándo el kubelet descarga una imagen de un registro.
command
Campo del contenedor que reemplaza el ENTRYPOINT de la imagen.
args
Campo del contenedor que reemplaza el CMD de la imagen.
$(VAR) expansion (expansión de $(VAR))
Sustitución que hace Kubernetes de las variables de entorno del contenedor dentro de command y args, sin usar un shell.
sh -c
Invocación de shell que ejecuta una sola cadena como script, lo que permite tuberías, bucles y variables.
--command flag (flag --command)
Opción de kubectl run que pone las palabras que siguen a -- en command en lugar de args.
Deployment
Controlador para réplicas sin estado e intercambiables, con rolling updates y rollback.
StatefulSet
Controlador que da a cada réplica un nombre estable, arranque ordenado y su propio almacenamiento persistente.
Headless Service (Service headless)
Un Service con clusterIP: None que da a cada Pod de un StatefulSet su propio nombre DNS estable.
DaemonSet
Controlador que ejecuta un Pod por cada nodo elegible.
Job / CronJob
Controladores para trabajo que se ejecuta hasta completarse, una vez o según una programación.
Bare Pod (Pod suelto)
Un Pod creado directamente, sin un controlador que lo reemplace si se elimina o si su nodo falla.
completions
Número de ejecuciones exitosas de Pod necesarias para que el Job termine (por defecto 1).
parallelism
Número máximo de Pods del Job ejecutándose a la vez (por defecto 1).
backoffLimit
Número de reintentos antes de que el Job se marque como Failed (por defecto 6).
activeDeadlineSeconds
Tiempo máximo de ejecución de todo el Job, tras el cual sus Pods se detienen y el Job falla con DeadlineExceeded.
ttlSecondsAfterFinished
Campo opcional que elimina un Job terminado y sus Pods después del número de segundos indicado.
job-name label (etiqueta job-name)
Etiqueta que el controlador del Job agrega a sus Pods, útil para seleccionar sus logs.
schedule
Expresión cron de cinco campos: minuto, hora, día del mes, mes, día de la semana.
concurrencyPolicy
Allow, Forbid o Replace: qué hacer si toca una ejecución mientras la anterior sigue activa.
History limits (límites de historial)
successfulJobsHistoryLimit (por defecto 3) y failedJobsHistoryLimit (por defecto 1), el número de Jobs terminados que se conservan.
startingDeadlineSeconds
Con cuánto retraso puede iniciar todavía una ejecución perdida antes de saltarse.
suspend
Booleano que pausa las ejecuciones futuras sin eliminar el CronJob.
jobTemplate
La especificación de Job que el CronJob genera en cada ejecución.
Init container
Un contenedor que se ejecuta hasta completarse, en orden, antes de que arranquen los contenedores de la aplicación.
Sidecar
Un contenedor auxiliar que se ejecuta junto al contenedor principal durante toda la vida del Pod.
Native sidecar (sidecar nativo)
Un init container con su propio restartPolicy: Always, que se inicia antes y se detiene después de los contenedores principales.
Adapter
Un auxiliar que convierte la salida del contenedor principal a un formato estándar.
Ambassador
Un auxiliar que hace de proxy para las conexiones de la aplicación hacia servicios externos a través de localhost.
-c flag (flag -c)
Opción de kubectl que selecciona a qué contenedor de un Pod se dirige un comando logs o exec.
emptyDir
Un volumen temporal que dura lo que el Pod, vacío al inicio y compartido por los contenedores del Pod.
medium: Memory
Convierte un emptyDir en un tmpfs respaldado en RAM que cuenta para el uso de memoria.
sizeLimit
Límite del tamaño de un emptyDir; superarlo puede hacer que el Pod sea desalojado.
configMap / secret volume (volumen configMap / secret)
Volúmenes que presentan cada clave como un archivo; el volumen secret usa secretName.
Projected volume (volumen proyectado)
Un volumen que combina fuentes configMap, secret, downwardAPI y serviceAccountToken en un solo directorio.
Ephemeral volume (volumen efímero)
Almacenamiento cuya vida está ligada al Pod y se elimina con él.
PersistentVolume (PV)
Un objeto de ámbito de clúster que representa una pieza de almacenamiento real.
PersistentVolumeClaim (PVC)
Una solicitud de almacenamiento con namespace que se vincula uno a uno a un PV compatible.
StorageClass
Un tipo de almacenamiento con nombre, con un provisioner usado para el aprovisionamiento dinámico.
Access mode (modo de acceso)
RWO, ROX, RWX o RWOP: cuántos nodos o Pods pueden montar el volumen y si pueden escribir.
Reclaim policy (política de recuperación)
Delete o Retain: qué ocurre con el almacenamiento de un PV después de que se elimina su claim.
WaitForFirstConsumer
Modo de vinculación de volúmenes que retrasa el aprovisionamiento hasta que se programa un Pod que usa el claim.
volumeMounts
Lista por contenedor que enlaza un volumen del Pod con una ruta dentro de ese contenedor.
mountPath
La ruta absoluta en el contenedor donde aparece el volumen, ocultando lo que ya hubiera allí.
subPath
Monta un solo archivo o subdirectorio de un volumen en lugar de toda su raíz; no recibe las actualizaciones de ConfigMaps ni Secrets.
subPathExpr
Como subPath, pero puede incluir referencias a variables de entorno con la forma $(VAR).
readOnly (solo lectura)
Opción de montaje que bloquea las escrituras de ese contenedor en el volumen.
readOnlyRootFilesystem
Ajuste del security context que hace que el sistema de archivos de la imagen del contenedor sea de solo lectura.

Dominio 2: Application Deployment (20%)

Consejos para el examen

  • Si kubectl apply falla con 'selector does not match template labels', haz que spec.selector.matchLabels sea un subconjunto de spec.template.metadata.labels. En apps/v1 el selector no se puede cambiar después.
  • Haz la aritmética: máximo de Pods = réplicas + maxSurge (redondeado hacia arriba), mínimo disponible = réplicas - maxUnavailable (redondeado hacia abajo). Elige Recreate cuando una tarea diga que la versión antigua y la nueva nunca deben ejecutarse juntas.
  • En kubectl set image, el lado izquierdo es el nombre del contenedor. Si no estás seguro, léelo con kubectl get deploy web -o jsonpath='{.spec.template.spec.containers[*].name}', y recuerda que solo los cambios de plantilla crean revisiones.
  • El cambio ocurre en el Service, no en los Deployments. Asegúrate de que la etiqueta de versión esté en la plantilla de Pod, de que el selector del Service la incluya, y confirma con las EndpointSlices que las direcciones pertenecen al color previsto.
  • El porcentaje para el canary es igual a las réplicas canary divididas entre las réplicas totales. El selector del Service debe coincidir con una etiqueta compartida por ambos Deployments y no debe incluir la etiqueta de track, mientras que el selector de cada Deployment sí debe incluirla.
  • Pasa siempre el namespace correcto con -n a helm list, upgrade, rollback y uninstall, y usa helm list -A cuando no sepas dónde está un release. Ejecuta helm repo update antes de buscar o instalar.
  • Encuentra la ruta exacta de la clave con helm show values antes de usar --set. Una clave equivocada se ignora en silencio, así que verifica con helm template antes de instalar o con helm get values después.
  • El name de images coincide con la imagen tal como está escrita en el manifiesto, no con el nombre del contenedor. Los ConfigMaps generados tienen un sufijo de hash, así que búscalos con kubectl get cm en lugar de adivinar el nombre, y prefiere labels al obsoleto commonLabels.
  • -k recibe un directorio, no un archivo, y kubectl kustomize (sin apply) es la vista previa segura. Usa kubectl diff -k para ver exactamente qué cambiará, y recuerda que las rutas de resources son relativas al archivo de kustomization.

Términos clave

ReplicaSet
Controlador que mantiene en ejecución un número fijo de Pods idénticos; normalmente lo gestiona un Deployment.
Pod template (plantilla de Pod)
Los metadatos y la spec de Pod dentro de un controlador a partir de los cuales se crea cada réplica.
Label selector (selector de etiquetas)
Una consulta sobre etiquetas, como matchLabels app: web, que decide qué Pods gestiona o apunta un objeto.
pod-template-hash
Etiqueta agregada por el Deployment para distinguir los Pods de distintos ReplicaSets.
revisionHistoryLimit
Número de ReplicaSets antiguos que se conservan para el rollback (por defecto 10).
RollingUpdate
Estrategia por defecto del Deployment que reemplaza los Pods gradualmente mientras la aplicación sigue atendiendo.
maxSurge
Cuántos Pods por encima del número deseado pueden existir durante una actualización (por defecto 25%, redondeado hacia arriba).
maxUnavailable
Cuántos Pods por debajo del número deseado pueden estar no disponibles durante una actualización (por defecto 25%, redondeado hacia abajo).
minReadySeconds
Cuánto tiempo debe permanecer listo un Pod nuevo antes de contar como disponible (por defecto 0).
progressDeadlineSeconds
Tiempo tras el cual un despliegue atascado se marca como fallido (por defecto 600); no hace rollback.
Recreate
Estrategia que termina todos los Pods antiguos antes de crear los nuevos, causando una breve inactividad.
Revision (revisión)
Una versión numerada de la plantilla de Pod de un Deployment, respaldada por un ReplicaSet y guardada para el rollback.
kubectl set image
Cambia la imagen de un contenedor con nombre en la plantilla de Pod de una carga de trabajo, lo que inicia un rolling update.
rollout undo
Devuelve el Deployment a la revisión anterior o a una elegida volviendo a aplicar su plantilla como una revisión nueva.
rollout pause / resume
Detiene y reanuda temporalmente los rollouts para que varios cambios de plantilla se apliquen como uno solo.
change-cause
La anotación kubernetes.io/change-cause que se muestra en la columna CHANGE-CAUSE de rollout history.
Blue/green deployment (despliegue azul/verde)
Ejecutar la versión antigua y la nueva a tamaño completo lado a lado y cambiar todo el tráfico entre ellas de una vez.
Service selector (selector del Service)
La consulta de etiquetas que decide qué Pods listos reciben el tráfico de un Service; todas las etiquetas listadas deben coincidir.
Cut-over (conmutación)
El momento en que el tráfico pasa de la versión antigua a la nueva.
Pod template labels (etiquetas de la plantilla de Pod)
Las etiquetas bajo spec.template.metadata.labels, las únicas etiquetas del Deployment que aparecen en los propios Pods.
EndpointSlice
Un objeto que lista las direcciones de los Pods que respaldan actualmente un Service, usado para verificar adónde va el tráfico.
Canary release (lanzamiento canario)
Enviar una pequeña parte del tráfico real a una versión nueva para probarla con usuarios reales antes de un despliegue completo.
Track label (etiqueta de track)
Una etiqueta como track: canary que distingue los Pods de los dos Deployments sin afectar al Service.
Replica weighting (ponderación por réplicas)
Usar la proporción de número de Pods para aproximar un reparto del tráfico detrás de un Service.
Promotion (promoción)
Pasar la versión del canary al Deployment stable y luego quitar el canary.
ClusterIP Service
El tipo de Service por defecto, que da una dirección interna estable y reparte las conexiones entre los Pods listos.
Chart
Un paquete de Helm con manifiestos de Kubernetes en plantillas más valores por defecto, con metadatos en Chart.yaml.
Repository (repositorio)
Un servidor que aloja un índice de charts, registrado localmente con helm repo add.
Release
Una instancia instalada y con nombre de un chart en un namespace, con su propio historial de revisiones.
helm rollback
Devuelve un release a una revisión anterior, registrada como una revisión nueva.
helm upgrade --install
Actualiza un release si existe o lo instala si no existe.
helm list -A
Lista los releases de todos los namespaces; agrega -a para incluir los releases fallidos o pendientes.
values.yaml
El archivo de configuración por defecto del chart, que sus plantillas leen a través de .Values.
--set
Sobrescritura de valores sueltos en la línea de comandos usando claves con puntos; gana a los archivos -f.
-f / --values
Proporciona un archivo YAML con valores a sobrescribir; se puede repetir, y ganan los archivos posteriores.
helm template
Renderiza localmente los manifiestos del chart sin contactar con el clúster ni crear un release.
helm get values
Muestra los valores proporcionados a un release instalado; --all agrega los valores por defecto calculados.
--reuse-values
En un upgrade, combina las nuevas sobrescrituras con los valores del release anterior en lugar de partir de los valores por defecto del chart.
kustomization.yaml
El archivo que lista los recursos y las transformaciones que Kustomize les aplica.
namePrefix
Texto agregado al inicio del nombre de cada recurso, con las referencias a esos nombres actualizadas.
labels / commonLabels
Campos que agregan etiquetas a todos los recursos; commonLabels también cambia los selectores y está obsoleto.
images
Transformador que cambia el nombre, la etiqueta o el digest de una imagen, haciendo coincidir el nombre de la imagen en el manifiesto.
patches
Cambios parciales, strategic merge o JSON 6902, aplicados a los recursos elegidos con target.
configMapGenerator
Crea ConfigMaps a partir de literales, archivos o archivos env, con un hash del contenido agregado al nombre.
Base
Un directorio de kustomization con manifiestos compartidos sobre los que se construyen los overlays.
Overlay
Una kustomization que referencia una base y agrega cambios específicos del entorno.
kubectl apply -k
Construye la kustomization de un directorio y aplica el resultado al clúster.
kubectl kustomize
Construye una kustomization e imprime el YAML resultante sin aplicarlo.
kubectl diff -k
Construye una kustomization y muestra en qué se diferencia de los objetos en vivo del clúster.
kubectl delete -k
Elimina todos los objetos que crearía la kustomization de un directorio.

Dominio 3: Application Observability and Maintenance (15%)

Consejos para el examen

  • 'no matches for kind X in version Y' casi siempre significa que se eliminó la versión de API. kubectl api-resources | grep -i <kind> te da la correcta en segundos, y kubectl explain <kind>.<field> --recursive te da la estructura.
  • En Ingress, cambiar solo el apiVersion no basta: corrige el formato del backend, agrega pathType y usa ingressClassName. En CronJob, el cambio de apiVersion suele ser todo lo necesario. En HPA, anida el objetivo dentro de metrics.
  • Conoce los valores por defecto: period 10s, timeout 1s, failureThreshold 3, successThreshold 1, initialDelay 0. Para arranques lentos, la respuesta preferida es un startup probe dimensionado como failureThreshold por periodSeconds, no un initialDelaySeconds enorme.
  • Si falla liveness: el contenedor se reinicia. Si falla readiness: el Pod sale del Service, pero sigue en ejecución. Si una pregunta menciona reinicios en aumento, piensa en liveness o startup; si menciona que no hay tráfico pero tampoco reinicios, piensa en readiness.
  • get te dice qué, describe y los eventos te dicen por qué, top te dice cuánto. Si kubectl top da error, falta metrics-server o todavía no está listo, y recuerda ordenar los eventos por creationTimestamp.
  • Para contenedores que fallan, usa primero --previous. En Pods multicontenedor, -c es necesario para obtener el contenedor correcto. Para muchas réplicas, usa -l con --prefix, no deploy/<name>.
  • Asocia cada estado con el siguiente comando: Pending e ImagePullBackOff llevan a describe, CrashLoopBackOff lleva a logs --previous y OOMKilled lleva al límite de memoria. Recuerda que 127 es comando no encontrado, 137 es SIGKILL y 143 es SIGTERM.
  • Recuerda --rm -it --restart=Never para los Pods de prueba desechables, pon -- antes del comando en exec y en run, y recuerda que port-forward a un Service igual llega a un solo Pod.
  • Para kubectl get pods (una lista), jsonpath empieza en .items, pero las rutas de --sort-by y de custom-columns son relativas a cada elemento. Pon siempre las expresiones jsonpath entre comillas simples y haz cat del archivo que escribiste.

Términos clave

apiVersion
El grupo de API y la versión de un objeto, como apps/v1; los objetos core usan solo v1.
Deprecation (obsolescencia)
Una versión de API se marca para eliminarse en el futuro; todavía funciona, pero produce advertencias.
Removal (eliminación)
El servidor de API deja de servir una versión, así que los manifiestos que la usan fallan con 'no matches for kind'.
kubectl api-resources
Lista los tipos de recursos con nombres cortos, versión de API, indicador de namespace y kind.
kubectl api-versions
Lista cada par grupo/versión que el servidor de API sirve actualmente.
kubectl explain
Muestra la documentación y la estructura de campos de un tipo de recurso y versión, con --recursive para el árbol completo.
networking.k8s.io/v1
Grupo/versión de API estable para Ingress, IngressClass y NetworkPolicy.
pathType
Campo obligatorio de las rutas de Ingress en v1: Prefix, Exact o ImplementationSpecific.
ingressClassName
Campo de la spec de Ingress v1 que nombra la IngressClass y reemplaza a la antigua anotación kubernetes.io/ingress.class.
autoscaling/v2
Versión estable de HPA con una lista de métricas que admite métricas resource, pods, object y external.
batch/v1
Grupo/versión estable para Job y CronJob.
averageUtilization
Valor objetivo del HPA v2, como porcentaje de los requests de los Pods, usado con el tipo de objetivo Utilization.
Liveness probe
Verifica si un contenedor debe reiniciarse.
Readiness probe
Verifica si un contenedor debe recibir tráfico del Service.
Startup probe
Verifica si un contenedor lento ya arrancó, dejando en espera los otros probes hasta que lo haga.
Probe handler
El método de verificación: httpGet, tcpSocket, exec o grpc.
failureThreshold
Fallos consecutivos necesarios antes de considerar que el probe falló (por defecto 3).
successThreshold
Éxitos consecutivos necesarios después de un fallo (por defecto 1; debe ser 1 para liveness y startup).
Restart (reinicio)
La acción ante un fallo de liveness/startup: el kubelet mata el contenedor y lo vuelve a iniciar en el mismo Pod.
Not ready (no listo)
El estado ante un fallo de readiness: el Pod sigue en ejecución, pero se quita de los endpoints del Service.
Ready condition (condición Ready)
Condición de estado del Pod mostrada en la columna READY que decide si el Pod recibe tráfico del Service.
CrashLoopBackOff
Estado que se muestra cuando un contenedor sigue fallando y el kubelet espera cada vez más entre reinicios.
Available (disponible)
El término de un Deployment para un Pod listo; los rollouts avanzan solo a medida que los Pods nuevos pasan a estar disponibles.
kubectl get
Resúmenes de una línea de los objetos y su estado, con opciones para etiquetas, namespaces, salida ampliada y observación en vivo.
kubectl describe
Vista detallada de un objeto, incluido su estado relacionado y los eventos recientes.
Event (evento)
Un registro de corta duración de algo que le ocurrió a un objeto, como un fallo de scheduling o la descarga de una imagen.
metrics-server
Complemento del clúster que recopila el uso de CPU y memoria de los kubelets para kubectl top y el HPA.
kubectl top
Muestra el uso actual de CPU y memoria de nodos o Pods a partir de la Metrics API.
Millicore (milicore)
Una milésima parte de un núcleo de CPU, escrita con m, así que 500m es medio núcleo.
-c
Selecciona de qué contenedor mostrar los logs en un Pod multicontenedor.
--previous (-p)
Muestra los logs de la última instancia terminada del contenedor, la clave para diagnosticar fallos.
-f
Sigue el flujo de logs e imprime las líneas nuevas a medida que se escriben, hasta que lo interrumpes.
--tail / --since
Limitan la salida a las últimas N líneas o a una ventana de tiempo reciente, como 10m o 1h.
-l
Selecciona Pods por etiqueta para mostrar logs de varios Pods a la vez; combínalo con --prefix para ver qué Pod escribió cada línea.
deploy/<name>
Nombra un controlador en lugar de un Pod; kubectl muestra los logs de un Pod que le pertenece.
Pending
Pod aceptado pero con contenedores que aún no se ejecutan, a menudo sin programar o todavía creando contenedores y volúmenes.
ImagePullBackOff
La imagen no se puede descargar y Kubernetes espera cada vez más entre reintentos.
OOMKilled
El contenedor fue terminado por superar su límite de memoria, normalmente con código de salida 137.
CreateContainerConfigError
El contenedor no se puede crear porque falta configuración referenciada, como una clave de ConfigMap o Secret usada en env.
Exit code 128+n (código de salida 128+n)
Un proceso terminado por la señal n, como 137 para SIGKILL o 143 para SIGTERM.
kubectl exec
Ejecuta un comando, o un shell interactivo con -it, dentro de un contenedor en ejecución que tenga la herramienta necesaria.
Ephemeral container (contenedor efímero)
Un contenedor temporal de depuración que kubectl debug agrega a un Pod en ejecución; comparte la red del Pod y no se puede eliminar ni reiniciar.
--target
Opción de kubectl debug que comparte el namespace de procesos de un contenedor indicado para que puedas ver sus procesos.
kubectl debug --copy-to
Crea una copia modificada de un Pod, por ejemplo con un comando distinto, para diagnóstico.
kubectl port-forward
Crea un túnel desde un puerto local hasta un puerto de un Pod a través del API server.
--rm -it --restart=Never
Opciones de kubectl run que crean un Pod simple e interactivo que se elimina al salir.
-o wide
Agrega columnas adicionales como la IP del Pod, el nodo, las imágenes de los contenedores y el selector.
-o yaml
Imprime el objeto completo, incluido el status y los campos con valores por defecto.
jsonpath
Plantilla de salida que extrae campos específicos del árbol del objeto, empezando en .items para las listas.
--sort-by
Ordena la salida de una lista por un campo dado como expresión JSONPath relativa a cada elemento.
custom-columns
Formato de salida que construye una tabla a partir de nombres de encabezado y rutas de campos.
--show-labels / -L
Agregan una columna con todas las etiquetas, o una columna por cada clave de etiqueta indicada.

Dominio 4: Application Environment, Configuration and Security (25%)

Consejos para el examen

  • El nombre de la CRD es <plural>.<group>, y los recursos personalizados usan apiVersion: <group>/<version>. kubectl api-resources te dice el plural y los nombres cortos exactos que debes usar, y kubectl explain muestra los campos cuando existe un esquema.
  • Orden: autenticación, autorización, admisión mutating, validación, admisión validating. 401 significa identidad, 403 con 'cannot' significa RBAC, y los mensajes de cuota o PodSecurity significan admisión. Para Deployments, revisa los eventos del ReplicaSet.
  • Los recursos core usan apiGroups [""], y --serviceaccount recibe namespace:name. Un ClusterRole vinculado con un RoleBinding solo otorga acceso en el namespace de ese binding. Prueba con auth can-i --as tanto en el namespace permitido como en uno prohibido.
  • Guaranteed necesita requests iguales a limits tanto de CPU como de memoria en todos los contenedores. CPU por encima del limit significa estrangulamiento; memoria por encima del limit significa OOMKilled. Usa Mi y Gi para la memoria, nunca m minúscula.
  • Una cuota de cómputo obliga a cada Pod nuevo a declarar ese recurso; un valor por defecto en un LimitRange es la solución habitual. Los errores de cuota de los Deployments aparecen en el ReplicaSet, no en el Deployment. En un LimitRange, default es el limit y defaultRequest es el request.
  • --from-file=app.env crea una clave que contiene todo el archivo; --from-env-file=app.env crea una clave por línea. Los valores de env no se actualizan hasta que el Pod se reinicia, mientras que los archivos montados sí se actualizan salvo que usen subPath.
  • Base64 es codificación, no cifrado. Conoce los tres tipos de create (generic, docker-registry, tls), que los volúmenes de Secret usan secretName y que echo -n evita codificar un salto de línea final.
  • El campo del Pod es serviceAccountName (el antiguo serviceAccount está obsoleto), la opción de automount a nivel de Pod tiene prioridad sobre la de la ServiceAccount, y no puedes cambiar la ServiceAccount de un Pod en ejecución. Usa kubectl create token para tokens de corta duración.
  • fsGroup es solo a nivel de Pod; readOnlyRootFilesystem, allowPrivilegeEscalation, capabilities y privileged son solo a nivel de contenedor. runAsUser, runAsGroup y runAsNonRoot pueden ir en cualquiera de los dos niveles, y los valores del contenedor sobrescriben los del Pod. Verifica con kubectl exec -- id y una escritura de prueba.
  • Las capabilities son solo a nivel de contenedor y se escriben sin CAP_. Los errores de PSA de los Deployments aparecen en el ReplicaSet y en los eventos. Restricted exige drop ALL, runAsNonRoot en true, allowPrivilegeEscalation en false y un perfil seccomp RuntimeDefault o Localhost.

Operator
Un controlador más CRD que automatizan la operación de una aplicación específica, como una base de datos.

Establecer quién hace la solicitud; un fallo devuelve 401 Unauthorized.
Authorization (autorización)
Decidir si la identidad puede realizar el verbo sobre el recurso; un fallo devuelve 403 Forbidden.
RBAC
El autorizador habitual; puramente aditivo, sin reglas de denegación, así que todo lo que no se otorga se rechaza.
Mutating admission (admisión mutating)
Paso de admisión que puede modificar un objeto, por ejemplo agregando valores por defecto o sidecars, antes de guardarlo.

Verifica si un usuario o ServiceAccount puede realizar una acción, usando suplantación.

Recursos reservados para un contenedor, que el scheduler usa para decidir la ubicación; no pone tope al uso.
Limit (límite)
Recursos máximos que puede usar un contenedor; la CPU por encima del límite se estrangula y la memoria por encima del límite provoca su terminación.
Millicore (m) (milinúcleo)
Una milésima de núcleo de CPU; 500m es medio núcleo.

Unidades binarias de memoria basadas en potencias de 1024; M y G son decimales.
QoS class (clase de QoS)
Guaranteed, Burstable o BestEffort, derivada de los requests y limits y usada para el orden de desalojo.
OOMKilled
Motivo de terminación cuando un contenedor supera su límite de memoria, normalmente con código de salida 137.
ResourceQuota
Tope a nivel de namespace sobre el uso total de recursos, como requests.cpu o limits.memory, y sobre el número de objetos.
LimitRange
Política del namespace que define recursos por defecto y mínimos o máximos por contenedor, Pod o PVC.
defaultRequest / default
Campos de LimitRange que dan el request y el limit que se aplican cuando un contenedor los omite.
count/<resource>.<group>
Clave de cuota que limita cuántos objetos de un tipo pueden existir en el namespace, como count/deployments.apps.
kubectl describe quota
Muestra cada recurso de la cuota con sus valores Used y Hard.
ConfigMap
Un objeto que contiene configuración no secreta como pares clave-valor, usado por los Pods del mismo namespace.
--from-file
Crea una clave por archivo, con el nombre del archivo (o un nombre elegido), que contiene todo el archivo como valor.
--from-env-file
Crea una clave del ConfigMap por cada línea KEY=value de un archivo.
configMapKeyRef
Define una variable de entorno a partir de una clave de un ConfigMap.
envFrom
Importa todas las claves de un ConfigMap o Secret como variables de entorno, opcionalmente con un prefijo.
immutable (inmutable)
Opción de un ConfigMap que bloquea las ediciones; los cambios requieren un ConfigMap nuevo.
Opaque
Tipo de Secret por defecto para datos arbitrarios del usuario, creado con kubectl create secret generic.
kubernetes.io/dockerconfigjson
Tipo de Secret que contiene credenciales de registry, usado mediante imagePullSecrets.
kubernetes.io/tls
Tipo de Secret que contiene tls.crt y tls.key para certificados, al que suelen hacer referencia los Ingresses.
Base64
Codificación de texto reversible usada para los datos de un Secret; no aporta confidencialidad.
stringData
Campo de un Secret que acepta texto plano, que el API server codifica en data.
secretKeyRef
Define una variable de entorno a partir de una clave de un Secret.
ServiceAccount
Una identidad con namespace para los procesos que se ejecutan en Pods; cada namespace tiene una llamada default.

Campo de la spec del Pod que elige con qué ServiceAccount se ejecuta el Pod; no se puede cambiar en un Pod en ejecución.

Comando que emite un token de corta duración para una ServiceAccount, con --duration y --audience opcionales.

El nombre de usuario que presenta una ServiceAccount ante el API server, usado en --as y en los logs de auditoría.

ID numérico del grupo principal de los procesos del contenedor; nivel de Pod o de contenedor.

Cuando es true, el kubelet se niega a iniciar un contenedor que se ejecutaría como UID 0 o cuyo usuario no puede verificar que no sea root.

Grupo suplementario exclusivo del nivel de Pod que se aplica a todos los contenedores y a la propiedad de los volúmenes compatibles.

Ajuste exclusivo del nivel de contenedor que hace de solo lectura el sistema de archivos raíz del contenedor.

Ajuste exclusivo del nivel de contenedor que, en false, activa no_new_privs para que los procesos no obtengan más privilegios que su padre.

Estado del Pod que aparece cuando el kubelet no puede crear un contenedor a partir de su configuración, por ejemplo por una infracción de runAsNonRoot.

Una porción con nombre del privilegio de root, como NET_BIND_SERVICE, que se puede agregar a un contenedor o quitarle; se escribe sin el prefijo CAP_.

Ajuste que limita qué llamadas al sistema puede hacer un contenedor; RuntimeDefault usa el filtro por defecto del runtime de contenedores.

Nivel de Pod Security sin restricciones, para cargas de trabajo de sistema de confianza.

Nivel de Pod Security que bloquea escaladas de privilegios conocidas, como contenedores privileged, namespaces del host y volúmenes hostPath.

El nivel de Pod Security más estricto: exige no root, sin escalada de privilegios, quitar todas las capabilities (ALL) y un perfil seccomp RuntimeDefault o Localhost.

Modos de PSA que rechazan los Pods que incumplen, los registran en el log de auditoría o devuelven una advertencia al usuario.

Dominio 5: Services and Networking (20%)

Consejos para el examen

  • Cada tipo se construye sobre el anterior: LoadBalancer incluye un NodePort, que incluye un ClusterIP. ExternalName y headless son los casos aparte, sin IP virtual y sin proxy. Un LoadBalancer atascado en pending sigue siendo accesible a través de su node port.
  • port es lo que llaman los clientes, targetPort es donde escucha el Pod y nodePort está en los nodos. Si hay endpoints pero las conexiones se rechazan, apunta al targetPort; si no hay endpoints, apunta al selector o a la readiness. Los Services con varios puertos necesitan un nombre en cada puerto.
  • Endpoints vacíos significa una de dos cosas: ningún Pod coincide con el selector, o los Pods que coinciden no están listos. Revisa kubectl get pods -l <selector> y la columna READY. Si hay endpoints pero las conexiones fallan, apunta al targetPort, a la dirección de escucha o a una NetworkPolicy.
  • Un nombre corto de Service solo se resuelve desde el mismo namespace. Entre namespaces, usa al menos <service>.<namespace>. Prueba con nslookup desde un Pod busybox temporal, y si la resolución falla justo después de que aparece una política de egress, comprueba que el DNS en el puerto 53 esté permitido.
  • expose copia el selector real; create service supone app=<name>. expose no tiene un flag para un nodePort concreto, así que genera el YAML con --dry-run=client -o yaml y agrégalo. Revisa siempre los endpoints después de crear un Service.
  • Las políticas solo agregan permisos; lo que aísla es ser seleccionado. podSelector: {} significa todos los Pods, mientras que ingress: [{}] significa permitir todo, lo contrario de no tener reglas. Permite el puerto del Pod, no el del Service, y prueba con Pods temporales etiquetados.
  • Un guion con ambos selectores significa AND; dos guiones significan OR. Dentro de una regla, from y ports se combinan con AND; las reglas separadas se combinan con OR. Después de agregar una política de egress, permite siempre el puerto 53 por UDP y TCP para el DNS.
  • Si una pregunta de estilo examen pregunta por qué una NetworkPolicy correcta no tiene efecto, la respuesta es que el plugin CNI del clúster no aplica NetworkPolicy. Prueba siempre el tráfico antes y después de aplicar una política.
  • Prefix coincide con segmentos completos de la ruta (/api no coincide con /apiv2); Exact coincide con una sola ruta. Gana la ruta coincidente más larga. En kubectl create ingress, un * al final significa Prefix. Los backends y el Secret TLS deben estar en el namespace del Ingress.
  • Un 404 del controller significa que ninguna regla coincidió (host, ruta o clase); un 503 significa que la regla coincidió pero el Service no tiene endpoints listos. Define siempre la cabecera Host al probar por IP, y usa --resolve para HTTPS.

Términos clave

ClusterIP
Tipo de Service por defecto, con una IP virtual interna alcanzable solo dentro del clúster.
NodePort
Tipo de Service que agrega un puerto, por defecto del rango 30000 a 32767, abierto en cada nodo.
LoadBalancer
Tipo de Service que aprovisiona un balanceador de carga externo a través del proveedor de nube o de un complemento; se construye sobre NodePort.
ExternalName
Tipo de Service que devuelve un CNAME de DNS hacia un nombre de host externo, sin selector y sin proxy.
Headless Service (Service headless)
Service con clusterIP: None cuyo nombre DNS devuelve las IPs de los Pods listos individuales.
kube-proxy
Componente del nodo que programa reglas de reenvío para que el tráfico hacia la IP de un Service llegue a los Pods de backend.
selector
Mapa de etiquetas basado en igualdad; el Service apunta a los Pods de su namespace cuyas etiquetas incluyen cada par.
port
El puerto en el que escucha el Service en su cluster IP y su nombre DNS.
targetPort
El puerto del Pod al que se reenvía el tráfico; por defecto es igual a port y puede ser un puerto con nombre.
Named port (puerto con nombre)
Un containerPort con nombre que un Service puede referenciar como su targetPort.
protocol
TCP por defecto; también se admiten UDP y SCTP en cada entrada de puerto.
EndpointSlice
Un objeto que lista las direcciones, los puertos y las condiciones de los Pods que respaldan un Service.
EndpointSlice controller
Componente del plano de control que mantiene las EndpointSlices sincronizadas con los Pods que coinciden con el selector de cada Service.
kubernetes.io/service-name
Etiqueta que vincula una EndpointSlice con su Service.
Ready condition (condición ready)
Indicador del endpoint que muestra si un Pod de backend debe recibir tráfico, según su readiness.
Endpoints (legacy, heredado)
La antigua lista de backends de un Service en un único objeto, reemplazada por las EndpointSlices por motivos de escalabilidad.
CoreDNS
El servidor DNS que normalmente proporciona el DNS del clúster para Services y Pods; se ejecuta en kube-system detrás del Service kube-dns.
Service FQDN (nombre completo del Service)
El nombre de Service totalmente calificado <service>.<namespace>.svc.cluster.local.
Cluster domain (dominio del clúster)
El sufijo DNS del clúster, cluster.local por defecto.
Search domains (dominios de búsqueda)
Sufijos en el resolv.conf de un Pod que permiten que nombres cortos como web se resuelvan dentro de su propio namespace.
ndots
Opción del resolver que indica cuántos puntos necesita un nombre para probarse primero tal como está escrito; Kubernetes usa 5.
SRV record (registro SRV)
Registro DNS que publica el número y el destino de un puerto con nombre, como _http._tcp.web.shop.svc.cluster.local.
kubectl expose
Crea un Service para un recurso existente, copiando su selector.
kubectl create service
Crea un Service de un tipo dado desde cero, con el selector definido como app=<name>.
--tcp=port:targetPort
Flag de create service que define el puerto del Service y el puerto de destino.
--dry-run=client -o yaml
Muestra el objeto que kubectl crearía sin crearlo, para que puedas editarlo y aplicarlo.
kubectl port-forward
Túnel temporal desde un puerto local, a través del API server, hasta un Pod; no crea ningún Service.
NetworkPolicy
Objeto con namespace que restringe el tráfico hacia y desde los Pods seleccionados usando etiquetas.
podSelector
Elige los Pods a los que se aplica una política; {} selecciona todos los Pods del namespace de la política.
policyTypes
Ingress, Egress o ambos: las direcciones que aísla la política.
Isolated Pod (Pod aislado)
Un Pod seleccionado por una política para una dirección, que entonces solo permite el tráfico que alguna política autoriza explícitamente.
Default deny (denegación por defecto)
Una política que selecciona todos los Pods sin reglas de permiso, y bloquea todo el tráfico en las direcciones indicadas.
Additive policies (políticas aditivas)
Los permisos de todas las políticas que seleccionan un Pod se combinan; no hay reglas de denegación.
podSelector peer (peer podSelector)
Coincide con los Pods que tienen las etiquetas indicadas en el namespace de la propia política.
namespaceSelector
Peer que coincide con los Pods de los namespaces que tienen las etiquetas indicadas; {} coincide con todos los namespaces.
ipBlock
Peer que coincide con un rango CIDR, con rangos except opcionales, normalmente para tráfico fuera del clúster.
AND semantics (semántica AND)
namespaceSelector y podSelector en el mismo elemento de peer deben coincidir ambos.
OR semantics (semántica OR)
Elementos de peer separados, o reglas separadas, permiten el tráfico cada uno de forma independiente.
kubernetes.io/metadata.name
Etiqueta automática del namespace que contiene su nombre.
CNI (Container Network Interface, interfaz de red de contenedores)
La interfaz estándar que usa Kubernetes para que un plugin configure la red de los Pods.
Network plugin (plugin de red)
La implementación de CNI que proporciona la red de los Pods y, si lo admite, aplica NetworkPolicy.
Calico / Cilium
Plugins de red muy usados que aplican NetworkPolicy.

Tecnología del kernel Linux para ejecutar pequeños programas verificados, que algunos plugins usan para filtrar el tráfico.
DaemonSet
Carga de trabajo que ejecuta un Pod por nodo; los agentes de los plugins de red suelen ejecutarse así en kube-system.
Ingress
Un objeto que define reglas de enrutamiento HTTP(S) por host y ruta hacia Services del mismo namespace.

Campo que elige qué IngressClass, y por lo tanto qué controller, implementa el Ingress.
pathType Prefix
Coincide con la ruta y todo lo que está debajo, elemento por elemento separado por /.

defaultBackend
Service que recibe las peticiones que no coinciden con ninguna regla.
TLS Secret (Secret TLS)
Un Secret de tipo kubernetes.io/tls que contiene tls.crt y tls.key, referenciado por la sección tls de un Ingress.

El componente que observa los objetos Ingress y ejecuta el proxy inverso que dirige el tráfico.
IngressClass
Objeto que identifica un controller y que los Ingresses eligen con ingressClassName; se puede marcar una como la predeterminada del clúster.

Cabecera HTTP que nombra el host solicitado, con la que coinciden las reglas de host del Ingress.

Hace que curl se conecte a una IP elegida para un nombre de host y un puerto, manteniendo el nombre correcto para TLS.

El nombre de host que un cliente envía durante el handshake TLS para que el servidor pueda elegir el certificado correcto.
